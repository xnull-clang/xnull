# XNull

[English](../README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | **Русский** | [العربية](README.ar.md) | [Italiano](README.it.md) | [Deutsch](README.de.md)

> Этот перевод ещё не синхронизирован с последней версией. Актуальная версия — [English README](../README.md).

**Пишите код, а не ритуалы.**

Никаких lifetimes. Никаких аннотаций владения. Никакого `@Override`. Никакого `try/catch`. Никаких геттеров и сеттеров. Никакой рефлексии.

XNull — новый язык программирования, в котором компилятор выбирает для каждого объекта стек, ARC или GC по таблице решений, записанной в спецификации. Вы пишете данные и поведение; среда выполнения исполняет выбор. Управление памятью без аннотаций владения — и без скрытой магии компилятора.

Ошибки — значения. Полиморфизм — протоколы. Поля — это поля. Спецификация фиксирует каждое решение, включая каждую отклонённую возможность и причину.

```x
class Counter {
    Int n = 0

    Int add(Int v) {
        self.n = self.n + v
        return self.n
    }
}

static Int main() {
    Counter c = new Counter()
    print(c.add(2))
    return 0
}
```

| Вы больше не пишете | XNull даёт |
| --- | --- |
| `Arc<Mutex<T>>`, lifetimes | память выбирает компилятор (стек / ARC / GC) |
| `getX()` / `setX()` | прямые поля |
| `extends` + `@Override` | протоколы |
| `try/catch` | `Result<T,E>` + `try` |
| рефлексия | невыразима |

## Почему XNull

- **Управление памятью решает компилятор.** Исходный код не выражает силу ссылок. Компилятор выбирает для каждого объекта стек, ARC или GC по таблице решений DET-01; среда выполнения исполняет это решение.
- **Никакого паттерна доступа.** Поля — это данные; поведение — методы с глагольными именами. Геттеры и сеттеры невыразимы в синтаксисе.
- **Композиция вместо наследования.** Классы не поддерживают наследование с переопределением. Полиморфизм выражается только через протоколы.
- **Ошибки — это значения.** `Result<T,E>`, `try`, `defer`/`errdefer`. Никаких исключений и неявного разматывания стека.
- **Никакой рефлексии.** Если исходный код и спецификация не определяют поведение, его нет в языке.
- **Каждое решение задокументировано.** Спецификация фиксирует, что XNull поддерживает, что отклоняет и почему. Китайские оригиналы с английскими переводами; новые переводы приветствуются.

## Структура репозитория

```text
assets/               логотип и ресурсы проекта
docs/                 документы по архитектуре, языку и дизайну
README/               переводы README
ide/                  расширение VS Code и веб-IDE
src/                  дерево разработки
  cli/xnull           единый CLI
  mini/               самостоятельно собираемый минимальный компилятор
  runtime/            исходники и заголовки C-среды выполнения
  xdk/                исходники XDK
  ffi/                raw FFI-мосты (.xfb)
  toolchain/          скрипты сборки и упаковки
  examples/           запускаемые примеры

xdk/                  пакет поставки XDK
  lib/xdk/            исходники пакетов XDK
  runtime/            исходники и заголовки C-среды выполнения
  ffi/                raw FFI-мосты
  install.sh          POSIX sh установщик
```

`src/` — точка изменения; `xdk/` — копия для поставки. После изменения `src/xdk/` синхронизируйте её с `xdk/lib/xdk/`.

## Разработка

`src/` — дерево разработки, `xdk/` — готовый к поставке пакет. После изменения `src/xdk/` синхронизируйте его с `xdk/lib/xdk/`.


### Установка XDK

```sh
cd xdk
./install.sh --prefix "$HOME/.local"
```

Устанавливается:

```text
<prefix>/share/xnull/xdk
<prefix>/share/xnull/runtime
<prefix>/share/xnull/ffi
```

Для упаковки используйте `DESTDIR`:

```sh
DESTDIR=/tmp/xdk-pkg ./install.sh --prefix /usr/local
```

## Что явно не поддерживается (по замыслу)

| Возможность | Причина |
| --- | --- |
| Переопределение методов | На вопрос «какой метод реально выполнился?» нужно отвечать по статическим типам; динамическая диспетчеризация существует только через протоколы |
| Геттеры / свойства | Разделение на уровне грамматики: поля — данные, поведение — методы с глагольными именами |
| Рефлексия | Нарушает аксиому «исходный код + спецификация определяют всё» |
| Исключения | Ошибки — значения: `Result` + `try`; `throw` только фатальный и не разматывает стек |

## План развития

1. Нативный C-бэкенд: один файл компилируется в C, C — в бинарник, бинарник выдаёт результат.
2. Постепенное расширение: по исполняемым сценариям, а не по списку возможностей.
3. Самохостинг: компилятор, переписанный на XNull.

## Ангельское финансирование

XNull ищет небольшой ангельский раунд или поддержку без размывания долей для 12–18 месяцев работы над компилятором, самохостингом, средой выполнения и XDK. Цель узкая: сначала сделать существующий инструментарий корректным, быстрым и пригодным к использованию, а затем расширять язык.
