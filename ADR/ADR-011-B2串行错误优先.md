# ADR-011 B2/B3/B4 串行实施，错误优先

> 日期：2026-11-08 16:30
> 状态：生效
> 依据：用户裁决「怎么少错误怎么来，少出错才是最快的」

## 背景

B2 计划存在两种执行方式：
- A 串行：B2-00 → 01 → 02 → 03 → 04，一次一张实现卡；
- B 并行压缩：B2-00 冻结后 lexer / parser 表达式 / parser 声明三线并行。

并行能把 B2 从 2–3 天压到 1–2 天，但会增加 AST 对齐返工与合并冲突风险。用户明确选择错误优先。

## 决定

1. **B2/B3/B4 一律串行实施**，一次只允许一张实现卡在途（QA 验收可并行）。
2. **B2 顺序固定**：B2-00（oracle/格式冻结）→ B2-01（lexer）→ B2-02（表达式/语句）→ B2-03（声明/类型）→ B2-04（差分接入与工具链切换）。
3. 每卡完成必须：先红后绿、全量测试绿、差分器对该卡语料逐字节一致、验收文件落盘。
4. **B2-00 未冻结 AST 格式前，不得开始任何 XNull 前端实现。**
5. 合并仍走 INTEG 单写者 + `handoff/merge.lock`；生产线只提交 `pod/*`。
6. 若用户未来要求加速，需以新 ADR 覆盖本决定，不在执行中自行改回并行。

## 后果

- B2 计划 24h，现实按 2–3 天估；B3/B4 同口径；
- 返工与冲突应显著低于并行方案；
- 交付节奏变慢，但每步可验证、可回退；
- 「少错」优先于「快」，不再用并行度换时间。
