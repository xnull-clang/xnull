## 0. 阅读与使用方式

本文按“一个包 = 一个实现阶段”组织：

1. 每个包先给 **定位/依赖/非目标**；
2. 再给 **文件清单**（每个文件的职责、公开符号、内部符号）；
3. 再给 **类型与函数契约**（签名、语义、错误、所有权、取消点、复杂度）；
4. 最后给 **阶段出口**（代码、场景、回归、差分/缺口、提交）。

实现时只允许依赖已经完成的阶段；T0 包不得反向依赖 T1/T2，也不得绕过 L2
直接调用 L3。新增 API 必须同时给出：稳定性标记、错误面、资源面、取消面
（若可阻塞）、场景名。

## 1. 设计目标与语言能力边界

### 1.1 目标（来自 S0 §1、§3）

T0 要支撑四类主工作：

- **应用与服务主逻辑**：状态、协议、任务编排、对象协作；
- **数据/规则/算法引擎**：清洗、聚合、索引、图算法、回测、模拟；
- **本地工具与语言工具**：CLI、配置、解析器、编译器、代码分析；
- **长生命周期对象系统**：连接表、设备树、任务图、观察者、会话状态。

T0 不追求“领域语法”，只提供通用构造：标量、`struct`、`class`、容器、
`protocol`、闭包、`Result`/`try`、泛型、任务组/`Context`、FFI。

### 1.2 语言能力基线

本设计只使用 S0 §2 已承诺的构造：

| 构造 | 在 T0 中的用途 | 约束 |
| --- | --- | --- |
| 标量 / 简单枚举 | 数值、标志、错误码、日志级别 | 不依赖隐式转换 |
| `struct` | 值语义的小对象（Duration、Field、Instant） | 复制即值复制，不持有 OS 资源 |
| `class` | 有身份/共享状态/资源句柄（Logger、File、TaskGroup） | 持资源必须有 `close()` |
| 数组/容器 | 批量数据、索引、缓冲区 | `List/Map/Set` 字面量由编译器脱糖 |
| `protocol` | Reader/Writer/Sink/Error/Clock 等能力面 | 运行期替换，依赖倒置 |
| 闭包 | 回调、比较器、映射、清理 | 不得隐式捕获可变全局状态 |
| `Result` / `try` | 所有可恢复失败 | 禁止用 panic 表达可恢复错误 |
| 泛型 | 容器算法、Task<T>、Mutex<T> | 以单态化为第一实现策略 |
| `TaskGroup` / `Context` | 结构化并发、取消、超时 | 可阻塞 API 首参带 `Context` |
| FFI | L2 原语进入 XDK | 只经 L3 契约，不直接裸调 |

### 1.3 明确不做（来自 S0 §3.2、§8）

- 不做内核/驱动/裸机、地址与指针语义；
- 不做硬实时承诺；
- 不做默认 C 布局共享；
- 不提供自定义分配器/手动释放；
- 不承诺动态插件、GPU 设备代码、完整训练栈；
- 不用“实现进度”替代规范：未实现 ≠ 语言没有；已实现 ≠ 规范覆盖。

### 1.4 编译器/运行时/库的分工

- **编译器**：语法、类型检查、字面量脱糖（`[...]`/`[k:v]`）、`for-in` 脱糖、
  代码生成；不维护库类型成员表。
- **运行时（L2）**：内存、句柄、调度、诊断、时钟、FFI 原语；不实现集合/文本/
  文件/网络算法。
- **XDK（L1）**：全部公开类型与算法；包名只是源码组织，不是编译器内建类型。

因此本文的每个类型都必须能由 XNull 源码表达；不能表达的，登记为“编译器依赖”，
不得偷偷放进运行时。

## 2. 跨包统一契约

### 2.1 错误契约（S4 / S6 §3.1）

1. 可恢复失败统一 `Result<T, E>`；无成功值用 `Result<Unit, E>`。
2. 错误类型实现 `Error` 协议；跨包边界优先使用 `Error`，包内可用更具体的错误类。
3. `ErrorKind` 是跨包分类，不得随意扩展；新增分类需回改 S4。
4. 禁止用 `throw`/panic 表达“文件不存在”“解析失败”“通道关闭”等可恢复情况。
5. 错误值必须可观察：至少 `kind()` 与 `describe()`；需要结构化上下文时用
   `ErrorReport`，不得把上下文拼进 `kind`。

`ErrorKind` 建议全集（与当前 `xdk.errors` 对齐）：

```text
InvalidArgument, NotFound, AlreadyExists, PermissionDenied, Io,
Network, Timeout, Cancelled, Busy, Unavailable, DataCorrupted,
Unsupported, OutOfMemory, Internal
```

### 2.2 资源契约（S3 §18 / S6 §3.2）

1. 持有 OS 资源（文件、目录、进程、通道、锁、任务组）的类型必须有 `close()`。
2. `close()` 必须幂等（重复关闭不致命），并返回 `Result<Unit, Error>`；
   “关闭失败”与“未关闭”是两种状态，调用方必须能区分。
3. `deinit` 只能作为兜底，不得是唯一关闭路径。
4. 资源关闭后，除 `isClosed()` 与再次 `close()` 外，其他操作返回
   `Err(InvalidArgument)` 或包内定义的“已关闭”错误。
5. 所有权转移必须在文档中写明（如 `Task.join` 消费结果、`Channel.send`
   成功消费值）。

### 2.3 取消契约（S5 / S6 §3.3）

1. 可阻塞操作首参为 `Context`；包括文件 I/O、流读写、任务等待、通道收发、
   锁等待。
2. 取消返回 `Err(CancelledError)`（`kind == ErrorKind.Cancelled`）。
3. 取消是协作式的：实现必须在进入阻塞前后检查 `Context`，并在等待循环中
   周期性检查；不得吞掉取消。
4. 取消不导致资源泄漏；取消路径与成功路径走同一套 `close`/句柄释放。
5. 超时是截止时间（deadline）而非取消：`joinDeadline` 超时返回 `Timeout`，
   且不消费任务结果（当前实现即如此）。

### 2.4 命名与可见性（S6 §3.4、§7）

- 类型 `PascalCase`；方法 `lowerCamelCase` 动词开头；布尔读取 `isX`/`hasX`；
- 私有成员 `_name`；包内辅助函数 `lowerCamelCase`，必要时 `static`；
- 一个包一个责任；包内文件按能力拆分，不按“类型/函数”拆；
- 公开签名不得暴露 `internal` 类型；跨包只使用公开类型。

### 2.5 稳定性标记（S6 §3.6）

每个公开符号标记：

- `stable`：T0 稳定面，破坏性变更需主版本；
- `preview`：可小幅变更；
- `internal`：非承诺，不属于公开 API。

本文默认新 T0 API 为 `preview`，完成两个发布周期且场景稳定后升 `stable`。
`xdk.runtime`、`xdk.errors`、`xdk.meta` 的核心符号优先 `stable`。

### 2.6 不变量

- 无全局可变单例；无隐式初始化/清理钩子；无线程局部隐式状态。
- 不提供“裸 lock/unlock”：锁只能通过作用域回调使用。
- 不提供“隐式缓冲刷新”：需要 flush 的 Writer 必须先 `flush()` 再 `close()`。
- 算法不改变容器语义；库容器与语言内建容器不互相冒充。

## 4. `xdk.errors` —— 错误协议与分类

**层级**：T0　**稳定性**：`stable`（核心）　**依赖**：L2 诊断
**非目标**：不做日志、不做重试调度、不做异常栈、不做跨语言异常传播。

### 4.1 文件清单

| 文件 | 职责 | 公开符号 | 状态 |
| --- | --- | --- | --- |
| `core/errors/Errors.x` | 分类、协议、组合与报告 | `ErrorKind`、`Error`、`wrap`、`mapErr`、`report`、`isRetryable` | 部分（ErrorKind/Error DONE；wrap/mapErr/report NEW） |
| `core/errors/BasicError.x` | 默认错误实现 | `BasicError`、`ErrorDetail` | BasicError DONE；Detail NEW |
| `core/errors/ErrorReport.x` | 结构化错误链 | `ErrorReport`、`report` | NEW |

### 4.2 `ErrorKind`（enum，stable）

```text
InvalidArgument, NotFound, AlreadyExists, PermissionDenied, Io,
Network, Timeout, Cancelled, Busy, Unavailable, DataCorrupted,
Unsupported, OutOfMemory, Internal
```

语义：

- `Cancelled` 只由 `Context`/取消路径产生；普通业务失败不得复用。
- `Timeout` 只由截止时间产生；`joinDeadline` 超时不得伪装成 `Cancelled`。
- `Internal` 表示实现不变量被破坏；不得用于“暂时没实现”（用 `Unsupported`）。

### 4.3 `Error`（protocol，stable）

```text
protocol Error {
    ErrorKind kind()
    String describe()
}
```

- `kind()` 必须是纯读取，不得有副作用。
- `describe()` 返回可读文本，不含敏感数据；结构化字段通过 `ErrorReport` 获取。
- 任何跨包错误边界只依赖这两个方法；不得对具体错误类做类型判断。

### 4.4 `BasicError`（class，stable）

```text
class BasicError implements Error {
    final ErrorKind kind
    final String message
    List<ErrorDetail> details

    BasicError(ErrorKind kind, String message)
    ErrorKind kind()
    String describe()
    Bool isRetryable()
    BasicError withDetail(String key, String value)
}
```

- 不可变 `kind`/`message`；`details` 仅追加，`withDetail` 返回新实例（避免共享可变）。
- `isRetryable()`：`Network/Timeout/Busy/Unavailable` 为 true，其余 false；
  重试策略由调用方决定，包内不做退避。
- 不持有资源，无需 `close()`。

### 4.5 `ErrorDetail` / `ErrorReport`

```text
struct ErrorDetail { String key; String value }

class ErrorReport implements Error {
    final Error root
    final List<ErrorDetail> context
    ErrorReport(Error root)
    ErrorKind kind()
    String describe()
    ErrorReport wrap(String step)
    String chainText()
}
```

- `wrap` 只追加“步骤”，不改变 `kind`；`describe()` 输出
  `step: ... -> root.describe()`。
- `chainText()` 供 CLI/日志使用；不含堆栈（语言不承诺异常栈）。
- `ErrorReport` 可作为 `Err` 的值跨包传递，但调用方仍只按 `kind()` 分类。

### 4.6 顶层函数

```text
Error wrap(Error err, String step)
Result<T, Error> mapErr<T, E>(Result<T, E> result, Error(Error) transformError)
ErrorReport report(Error err)
Bool isRetryable(Error err)
```

> `mapErr` 是泛型函数 + 函数值参数；依赖 W4 的泛型特化。若目标引擎尚不支持
> 双类型参数，先提供 `Result<T, Error>` 的窄版本，并在阶段出口登记。

### 4.7 阶段出口

- 场景：`tests/xdk_errors.x` 扩展 wrap/mapErr/report；错误分类不得漂移。
- 回归：`xdk.sh` 差分（mini + legacy）。
- 验收：不存在用 panic 表达可恢复错误的路径；所有 T0 包错误都能映射到
  `ErrorKind`。

## 5. `xdk.runtime` —— 诊断、退出、时钟

**层级**：T0　**稳定性**：`stable`　**依赖**：L2
**非目标**：不做日志格式、不做任务调度、不做平台探测（属于 sys）。

### 5.1 文件清单

| 文件 | 职责 | 公开符号 | 状态 |
| --- | --- | --- | --- |
| `core/runtime/Runtime.x` | 诊断、退出、单调/墙钟、毫秒睡眠 | `diagnose`、`exit`、`nowMono`、`nowWall`、`sleepMs`、`sleepUntilMono` | 诊断/退出/时钟 DONE；sleep NEW |

### 5.2 契约

```text
void diagnose(String message)
void exit(Int code)
Long nowMono()
Long nowWall()
void sleepMs(Long milliseconds)
void sleepUntilMono(Long monoDeadlineMs)
```

- `diagnose`：写 stderr 诊断通道；不得改变程序控制流；返回 `void`。
- `exit`：终止进程；`code` 为 0–255 的有效退出码；非 0 由 shell 观察。
- `nowMono`：单调时钟毫秒，不受墙钟调整影响；用于超时/耗时。
- `nowWall`：UNIX epoch 毫秒；仅用于展示与日历换算。
- `sleepMs`：阻塞当前执行体；`ms` 为负视为 0；取消面由调用方在上层处理
  （T0 的 sleep 不接受 `Context`，阻塞不可取消，文档必须写明）。
  `xdk.time.sleep(Duration)` 只是本函数的类型安全包装。
- `sleepUntilMono`：按单调截止时间睡眠；已过期立即返回。

### 5.3 设计说明

- 不提供 `setenv`/全局钩子；运行时状态只读。
- 不提供“隐式退出钩子”；资源清理必须显式。
- 时钟不保证硬实时；睡眠精度是调度器粒度，不承诺微秒级。

### 5.4 阶段出口

- 场景：`tests/xdk_runtime.x` 扩展 sleep/截止时间。
- 回归：`xdk.sh`；诊断/退出码差分。
- 验收：时钟单位统一为毫秒；不存在秒/毫秒混用。

## 6. `xdk.meta` —— 版本、构建与目标平台

**层级**：T0　**稳定性**：`stable`　**依赖**：无（编译期常量）
**非目标**：不做包管理、不做构建、不做运行时探测。

### 6.1 文件清单

| 文件 | 职责 | 公开符号 | 状态 |
| --- | --- | --- | --- |
| `core/meta/Meta.x` | 语言/XDK/编译器版本、目标平台、构建模式 | `languageVersion`、`xdkVersion`、`compilerVersion`、`targetPlatform`、`targetArch`、`buildMode`、`BuildInfo` | 基础版本/平台 DONE；BuildInfo NEW |

### 6.2 契约

```text
String languageVersion()
String xdkVersion()
String compilerVersion()
String targetPlatform()
String targetArch()
String buildMode()

struct BuildInfo {
    String languageVersion
    String xdkVersion
    String compilerVersion
    String platform
    String arch
    String mode
}

BuildInfo buildInfo()
```

- 所有函数返回编译期确定的字符串，不得在运行时探测文件系统/环境。
- `targetPlatform`/`targetArch` 是构建目标，不是宿主；交叉编译时必须反映目标。
- `buildMode`：`debug` / `release` / `test` 之一；未知返回 `unknown`。
- `BuildInfo` 是值语义快照，构造后不可变；用于诊断/日志/健康检查。

### 6.3 阶段出口

- 场景：`tests/xdk_meta.x` 扩展 `buildInfo()` 与目标字段。
- 回归：mini/legacy 输出一致（版本字符串相同）。
- 验收：版本号只有一个来源；不得在各包内硬编码。

## 7. `xdk.bytes` —— 字节缓冲区与位操作

**层级**：T0　**稳定性**：`preview`　**依赖**：`xdk.errors`
**非目标**：不做文件/网络 I/O（属于 io/sys）、不做编码（属于 text/codec）、
不承诺零拷贝之外的性能排名。

### 7.1 文件清单

### 7.2 顶层函数契约

```text
Bytes fromUtf8(String text)                  // UTF-8 编码；不失败
String toUtf8(Bytes data)                    // 非法字节以替换字符处理
Bytes fromHex(String hex)                    // 非法/奇数长度 → 空/截断（文档写明）
String toHex(Bytes data)                     // 小写十六进制
Int byteLength(Bytes data)
Bool isEmpty(Bytes data)
Bytes concatBytes(Bytes a, Bytes b)          // 返回新值，不修改入参
Bytes slice(Bytes data, Int start, Int end)  // [start,end)；越界按钳制
Int compare(Bytes a, Bytes b)                // 字典序；返回 <0/0/>0
```

设计调整（本阶段）：

- 新增 `Result<Bytes, Error> fromHexChecked(String hexadecimal)`，非法输入返回
  `InvalidArgument`；保留 `fromHex` 的宽松行为以兼容现有场景。
- `slice` 越界仍是钳制（当前语义），但文档必须写明；严格版本
  `sliceChecked` 返回 `Result`。
- `Bytes` 是运行时值类型（非 class），无 `close()`；所有权按值传递。

### 7.3 `ByteReader`（class）

```text
class ByteReader {
    Bytes data
    Int position

    ByteReader(Bytes source)
    Int remaining()
    Bool hasRemaining()
    Int readU8()             // 越界返回 0（兼容）；严格版 readU8Checked
    Int shortBE() / shortLE()
    Int intBE() / intLE()
    Long longBE() / longLE() // NEW
    Bytes readBytes(Int count) // 最多读到末尾
    Result<Bytes, Error> readExact(Int count) // NEW；不足 → DataCorrupted
}
```

- 游标只前进，不回退；需要回退用 `position` 显式设置（提供 `seek(Int offset)`）。
- 读取不足时，宽松方法不报错；严格方法必须报错，避免静默截断。
- 无资源句柄；不需要 `close()`。

### 7.4 `ByteWriter`（class）

```text
class ByteWriter {
    Bytes data
    ByteWriter()
    Int length()
    Bytes toBytes()
    void writeU8(Int value)
    void writeBytes(Bytes value)
    void writeU16BE/LE(Int value)
    void writeU32BE/LE(Int value)
    void writeU64BE/LE(Long value)   // NEW
    void clear()                     // NEW
}
```

- `writeU8` 取低 8 位（`value % 256` 对负数需定义为 `value & 0xFF`；
  实现应改为位掩码，避免负数取模差异）。
- `toBytes()` 返回当前快照；后续写入不应改变已返回的 `Bytes`（值语义）。

### 7.5 `ByteBuffer`（class）

```text
class ByteBuffer {
    Bytes data
    ByteBuffer()
    ByteBuffer(Bytes initial)
    Int length()
    Bytes toBytes()
    void push(Int value)
    void append(Bytes more)
    void clear()                 // NEW
}
```

设计目标（NEW）：增加 `position`/`limit`/`remaining()`/`flip()`/`compact()`，
对齐行业 ByteBuffer（Java NIO、Go `bytes.Buffer`）语义；首版先保持当前
“只追加”模型，新增方法在 T0-04 阶段补齐。

### 7.6 位与字节序

- 位运算只对 `Int`（64 位有符号）定义；移位量 `0..63`，越界按语言规则。
- `popCount`/`leadingZeros`/`trailingZeros` 返回 `Int`；`popCount(0)=0`。
- 端序函数不改变输入；`u16BE` 返回 2 字节，`u32BE` 返回 4 字节，
  `u64BE` 返回 8 字节。
- 跨边界读取必须显式指定端序，不提供“宿主端序”隐式默认。

### 7.7 阶段出口

- 场景：`tests/xdk_bytes.x`、`xdk_bytes_extra.x` 扩展 u64/位计数/严格读取。
- 回归：`xdk.sh` mini + legacy 差分。
- 验收：不存在静默截断的“严格”API；所有越界行为在文档中写明。

**非目标**：不做正则引擎的完整 PCRE 兼容、不做本地化（i18n 是 T1）、

### 8.1 文件清单

### 8.2 文本值决策（ADR-TEXT-1）

S6 目录写 `Text` 作为 key type，但语言已内建 `String`，当前源码层没有 `Text`
类。设计决定：

- **`String` 是唯一规范文本值**；`xdk.text` 的公开面是“作用于 `String` 的
  顶层函数 + 状态类型（StringBuilder/Format/Utf16/Regex）”。
- 不再引入包装 `Text` 值类型，避免双重表示、复制开销与相等性歧义。
- S6 §4.1 的 `Text` 行需要在下一版澄清为“文本能力”而非具体类；
  本设计记录为规范注记，不偷偷新增类。

### 8.3 文本函数契约（节选）

```text
String trim(String text)
String trimStart(String text) / trimEnd(String text)
Bool isBlank(String text)
String toLower(String text) / toUpper(String text)
Bool startsWith(String text, String prefix)
Bool endsWith(String text, String suffix)
Bool contains(String text, String searchText)
Int indexOf(String text, String searchText)          // 未找到 -1
String replace(String text, String searchText, String replacementText)
List<String> split(String text, String separator)      // 保留空段语义需文档化
List<String> lines(String text)                  // 去 \r，保留末行规则
String repeatText(String text, Int repetitions)     // repetitions <= 0 → ""
String padLeft(String text, Int width, String padding)
String padRight(String text, Int width, String padding)
```

- 所有函数按 Unicode 码点还是字节处理必须逐函数写明；当前实现多为码点/字节
  混合，T0-05 阶段统一为“码点语义，索引为码点位置”。
- `split` 的空段规则固定：`"a,,b"` → 3 段；尾部空段保留。
- `pad` 只接受单码点字符串；多码点参数返回 `InvalidArgument`（严格版）。

### 8.4 `StringBuilder`（class，NEW）

```text
class StringBuilder {
    List<String> parts

    StringBuilder()
```

- `toString()` 不消耗内容；`clear()` 后长度归零。

```text
class Format {
```

- 链式构造不可变；`build()` 左填充到 `width`。
- 负数/小数宽度规则在 T0-05 补文档与场景；不承诺本地化数字格式。

### 8.6 `Parse`（函数）

```text
Result<Int, Error> parseInt(String text)
Result<Double, Error> parseFloat(String text)
Result<Bool, Error> parseBool(String text)
Result<Bytes, Error> parseHex(String text)
Result<UInt64, Error> parseUInt(String text, Int radix)
```

- 不接受千分位、本地化小数点；`parseFloat` 接受 `inf`/`nan` 需明确。
- 解析不修改输入，不跳过隐式空白（除文档声明）。

### 8.7 `Utf16` 与转换（class，DONE）

```text
Result<List<UInt16>, Error> utf8ToUtf16(Bytes b)
Result<Bytes, Error> utf16ToUtf8(List<UInt16> units)

class Utf16 {
```

### 8.8 `Regex`（class，preview）

```text
Result<Regex, Error> Regex.compile(String pattern)
class Regex {
    Bool isMatch(String text)
    Match? find(String text)
    List<Match> findAll(String text)

class Match {
```

- 编译失败是可恢复错误（`InvalidArgument`），不得 panic。
- 匹配语义、量词/分组能力以 `text/full` 实现为准；未支持语法必须报错而非静默。

## 9. `xdk.collections` —— 容器算法与迭代

**层级**：T0　**稳定性**：`preview`　**依赖**：`xdk.errors`
**非目标**：不做并发容器（sync）、不做持久化、不做数据库索引。

### 9.1 文件清单

| 文件 | 职责 | 公开符号 | 状态 |
| --- | --- | --- | --- |
| `core/collections/Collections.x` | 通用算法 | `sortBy`、`dedup`、`find`、`groupByInt`、`groupBy`、`chunks`、`flatten`、`zip` | 部分（sortBy/dedup/find DONE；groupBy* 受 Map 限制） |
| `core/collections/Iterator.x` | 迭代协议与适配 | `Iterator<T>`、`Iterable<T>` | NEW |
| `core/collections/BTreeMap.x` | Int 键有序映射 | `BTreeMap<V>` | 源码存在；受泛型容器运行时限制 |
| `core/collections/OrderedMap.x` | 插入序映射 | `OrderedMap<V>` | 源码存在；受限制 |
| `core/collections/PriorityQueue.x` | 最小堆 | `PriorityQueue<T>` | 源码存在；受限制 |
| `core/collections/RingBuffer.x` | 环形缓冲 | `RingBuffer<T>` | 源码存在；受限制 |

### 9.2 内建容器契约（编译器脱糖目标）

| 类型 | 字面量 | 核心方法 | 语义 |
| --- | --- | --- | --- |
| `List<T>` | `[a, b]` | `length`、`get`、`set`、`push`、`insert`、`remove`、`join` | 有序、可重复、可变 |
| `Map<K,V>` | `[k: v]` | `length`、`has`、`getOr`、`put`、`keys`、`values` | 键唯一；`getOr` 不插入 |
| `Set<T>` | `Set.of(...)` | `length`、`has`、`add` | 元素唯一 |

设计约束：编译器只识别字面量/`for-in` 的**形状**，成员表仍由库/运行时决定；
`Map<K,V>` 的键/值类型扩展是 T0 阶段的硬前置（当前运行时只有 `Map<String,Int>`）。

### 9.3 算法契约

```text
// 所有算法不修改入参，除非名称含 inPlace。
List<T> sortBy<T>(List<T> items, Bool(T, T) lessThan)        // 稳定插入排序；返回新列表
List<T> sortInPlaceBy<T>(List<T> items, Bool(T, T) lessThan) // 原地；返回同一列表
List<T> dedup<T>(List<T> items, Bool(T, T) equals)           // 保持首次出现顺序
T? find<T>(List<T> items, Bool(T) predicate)
Int? findIndex<T>(List<T> items, Bool(T) predicate)
Map<Int, List<T>> groupByInt<T>(List<T> items, Int(T) keySelector)
Map<K, List<T>> groupBy<T, K>(List<T> items, K(T) keySelector)   // 需要 Map<K,...>
List<List<T>> chunks<T>(List<T> items, Int chunkSize)
List<T> flatten<T>(List<List<T>> nestedItems)
struct Pair<A, B> { A first; B second }
List<Pair<A,B>> zip<A,B>(List<A> a, List<B> b)
```

- `less`/`eq` 必须是纯函数；库不缓存结果。
- 排序稳定性：`sortBy` 稳定；`PriorityQueue` 不保证稳定。
- `chunks` 的 `size <= 0` → `InvalidArgument`（或空列表，逐函数写明）。
- 复杂度：`sortBy` O(n²) 首版，后续可换归并；`dedup` O(n²)；
  `groupByInt` O(n) 均摊（依赖 Map 实现）。

### 9.4 `Iterator<T>` 协议（NEW）

```text
protocol Iterator<T> {
    Bool hasNext()
    T next()
}

protocol Iterable<T> {
    Iterator<T> iterator()
}
```

- 编译器 `for-in` 脱糖为 `iterator()` + `hasNext()`/`next()`；
  在脱糖稳定前，源码层显式使用迭代器。
- `next()` 在无元素时行为必须由协议文档固定：返回默认值还是报错；
  建议 `hasNext()` 为 false 时不得调用 `next()`（合同错误）。
- 迭代器不持有资源；流式迭代的资源释放由流类型负责。

### 9.5 特化容器（源码存在，需泛型容器运行时）

`BTreeMap<V>`（Int 键）：

```text

    BTreeMap()
    Int length()
    Bool has(Int k)
    void put(Int key, V value)
    V? get(Int k)
    Bool remove(Int k)
    List<Int> keys()
    List<V> values()
    void clear()
}
```

`OrderedMap<V>`（Int 键，插入序）：`length`、`has`、`put`、`get`、`remove`、
`keys`、`values`、`clear`。

`PriorityQueue<T>`：

```text
class PriorityQueue<T> {
    PriorityQueue(Bool(T, T) less)
    Int length()
    Bool isEmpty()
    void push(T value)
    T? peek()
    T? pop()
    void clear()
}
```

`RingBuffer<T>`：`RingBuffer(Int capacity)`、`length`、`capacity`、`isFull`、
`isEmpty`、`push`、`pop`、`peek`、`clear`。

### 9.6 阶段出口

- 场景：`tests/xdk_collections_algo.x` 扩展 findIndex/chunks/zip；

- 回归：mini 算法场景 + legacy 缺口记录；`groupBy` 待 `Map<K,V>`。
- 验收：算法不改变入参；泛型函数单态化不泄漏到公开签名。

## 10. `xdk.math` —— 数值函数与 Int128

**层级**：T0　**稳定性**：`preview`（`Int128` 为 preview）　**依赖**：`xdk.errors`
**非目标**：不做任意精度大数、不做复数、不做 GPU/张量（T2）。

### 10.1 文件清单

| 文件 | 职责 | 公开符号 | 状态 |
| --- | --- | --- | --- |
| `core/math/Math.x` | 常量、舍入、幂/指/对数、三角、插值、整数数论、基础统计 | `PI/E/TAU`、`abs`、`clamp`、`floor/ceil/round/trunc`、`pow/sqrt/exp/log*`、`sin..atan2`、`lerp/mapRange`、`gcd/lcm`、`factorial`、`sum/mean/median/variance/stddev/quantile` | DONE |
| `core/math/Int128.x` | 128 位有符号整数 | `Int128`、`add/sub/mul/div/rem/compare/toString/parse` | NEW |
| `core/math/Random.x` | 可复现伪随机 | `Random`、`seedRandom`、`randomNext`、`randomDouble` | DONE |

### 10.2 `Math` 契约要点

- 常量返回 `Double`；`Inf()`/`NaN()` 是显式函数，不用异常。
- `min/max/clamp` 对 `Double` 与 `Int` 分开（`minI/maxI/clampI`），
  避免隐式转换。
- `mod` 对负数遵循“结果与除数同号”（欧几里得/地板语义需固定并测试）。
- `pow` 的域错误（如负数开偶次方）返回 `NaN`，不 panic。
- `factorial(n)` 对 `n < 0` 返回 0 或报错需固定；当前返回 0，设计建议
  `InvalidArgument`（阶段内统一）。
- 统计函数对空列表：`mean/median` 返回 `NaN` 或 0 需固定；建议 `NaN` 并文档化。

### 10.3 `Int128`（struct，NEW）

```text
struct Int128 {
    Int64 hi
    UInt64 lo

    static Int128 fromInt(Int value)
    static Result<Int128, Error> parse(String text)
    Int128 add(Int128 other)
    Int128 sub(Int128 other)
    Int128 mul(Int128 other)
    Result<Int128, Error> div(Int128 other)   // 除零 → InvalidArgument
    Result<Int128, Error> rem(Int128 other)
    Int compare(Int128 other)
    Bool isNegative()
    String toString()
}
```

- 溢出按二补码回绕（与定长整数一致），不静默升为任意精度。
- 除法向零截断；除零/`MIN/-1` 溢出必须报错或按文档回绕。
- `UInt64` 是新基础类型；若编译器/运行时不支持，`Int128` 阶段暂停，
  不得用 `Double` 冒充。

### 10.4 `Random`

```text
class Random {
    Random(Int64 seed)
    Int nextInt(Int bound)       // [0,bound)
    Double nextDouble()          // [0,1)
    Bool nextBool()
    void shuffle(List<String> items)
    String choice(List<String> items)
    void shuffleInts(List<Int> items)
    Int choiceInt(List<Int> items)
}
```

- 同一 seed + 平台 → 同一序列（可复现性契约）；跨平台不保证。
- `bound <= 0` → `InvalidArgument`；空列表 `choice` → `InvalidArgument`。
- 非加密随机；安全场景必须用 T1 `xdk.crypto`。

### 10.5 阶段出口

- 场景：`tests/xdk_math.x` 扩展域错误/空统计；`xdk_math_int128.x`（新）。
- 回归：mini + legacy 差分（Int128 视 legacy 能力记录缺口）。
- 验收：所有域错误有明确返回值；不存在未文档化的 NaN 传播。

## 12. `xdk.io` —— 流与缓冲

**层级**：T0　**稳定性**：`preview`　**依赖**：`xdk.bytes`、`xdk.errors`
**非目标**：不做文件系统（fs）、不做网络（T1 net）、不做终端（T1 terminal）。

### 12.1 文件清单

| 文件 | 职责 | 公开符号 | 状态 |
| --- | --- | --- | --- |
| `io/IO.x` | 流协议与通用拷贝 | `Reader`、`Writer`、`readAll`、`copy` | 当前是内存类；协议化 NEW |
| `io/Memory.x` | 内存流实现 | `MemoryReader`、`MemoryWriter` | 由现有 Reader/Writer 迁移 |
| `io/Buffered.x` | 带缓冲读写 | `BufferedReader`、`BufferedWriter` | NEW |
| `io/Stream.x` | 字节流/字节管道 | `Stream`、`ByteStream` | NEW |

### 12.2 协议（NEW）

```text
protocol Reader {
    Result<Int, Error> read(Bytes buffer)   // 返回写入 buffer 的字节数；0 = EOF
}

protocol Writer {
    Result<Int, Error> write(Bytes data)    // 返回消费字节数
    Result<Unit, Error> flush()
}

protocol Closer {
    Result<Unit, Error> close()
}
```

- `read` 允许短读；调用方必须循环直到 EOF/满足需求。
- `write` 允许短写；`flush` 失败必须返回错误，不得吞掉。
- 流的 `close()` 幂等；关闭后读写返回 `Unavailable`。
- 可阻塞流的方法首参带 `Context`（本设计在 fs/网络实现中加；内存流不需要）。

### 12.3 `MemoryReader` / `MemoryWriter`

现有 `Reader`/`Writer` 的语义保留：

```text
class MemoryReader implements Reader {
    MemoryReader(Bytes source)
    Int remaining()
    Bool hasRemaining()
    Result<Int, Error> read(Bytes buffer)
    Int readU8()                 // 兼容便利方法；越界 0
    Bytes readBytes(Int count)
    Result<Unit, Error> seek(Int offset)
}

class MemoryWriter implements Writer {
    MemoryWriter()
    Int length()
    Bytes toBytes()
    Result<Int, Error> write(Bytes data)
    Result<Unit, Error> flush()  // 无操作，返回 Ok
    void writeU8(Int value)      // 兼容
    void clear()
}
```

迁移：保留 `Reader`/`Writer` 作为协议名；现有类改名为 `MemoryReader`/
`MemoryWriter`，并在同一提交提供顶层工厂 `reader(Bytes source)`/`writer()`，
避免场景一次性重写。

### 12.4 `BufferedReader` / `BufferedWriter`

```text
class BufferedReader implements Reader {
    BufferedReader(Reader inner, Int capacity)
    Result<Int, Error> read(Bytes buffer)
    Result<Bytes, Error> readLine(Int maxBytes)
    Result<Unit, Error> close()
}

class BufferedWriter implements Writer {
    BufferedWriter(Writer inner, Int capacity)
    Result<Int, Error> write(Bytes data)
    Result<Unit, Error> flush()
    Result<Unit, Error> close()   // 先 flush 再 close
}
```

- 关闭 `BufferedWriter` 必须先 `flush`；flush 失败时 `close` 返回该错误，
  但仍标记关闭（避免二次泄漏）。
- `readLine` 上限 `maxBytes` 防止无界内存。

### 12.5 通用函数

```text
Result<Bytes, Error> readAll(Reader reader, Int maximumBytes)
Result<Int, Error> copy(Reader source, Writer destination, Int bufferSize)
```

- `readAll` 超过 `maxBytes` → `InvalidArgument` 或 `Unsupported`（固定）。
- `copy` 返回总字节数；任一侧错误立即停止并返回。

### 12.6 阶段出口

- 场景：`tests/xdk_io.x` 扩展协议/缓冲/短读短写。
- 回归：mini + legacy 差分（内存流）。
- 验收：不存在“只有 close 才能 flush”的隐式行为；短读/短写有测试。

### 13.2 `Path`（class，DONE）

### 13.3 `File`（class，DONE，需补 Context）

```text
class File {
    File(String path, Bool writable)
    Bool isOpen()
    Bool isWritable()

    Result<Int, Error> size()

    Result<String, Error> readText()

    Result<Int, Error> writeText(String text)
    Result<Int, Error> writeLine(String line)
    Result<Unit, Error> close()
}
```

T0-10 增补：

- 可阻塞重载 `read(Context context, Int maximumBytes)`、`write(Context context, Bytes data)`；旧重载保留。
- `close()` 幂等；关闭后再读写返回 `Unavailable`。
- `write` 语义固定：当前实现“总是追加到文件尾”，设计建议改为“从 position

- 不提供隐式缓冲；需要缓冲用 `BufferedWriter`。

### 13.4 `Dir`（class，DONE）

```text
class Dir {
    Bool isOpen()
    String next()                       // 空串 = 结束
    Result<List<String>, Error> entries()
    Result<Unit, Error> close()
}
```

- 迭代顺序依赖文件系统，不排序；需要排序由调用方 `sortBy`。
- 目录句柄必须显式 `close()`；`entries()` 不自动关闭。

### 13.5 `Temp` 与 `Atomic`（NEW）

```text
Result<File, Error> createTempFile(String prefix, String suffix)
Result<String, Error> createTempDir(String prefix)
Result<T, Error> withTempFile<T>(String prefix, String suffix, T(File) body)

```

- `withTempFile` 在 body 返回/失败后都删除临时文件；body 的 `Result` 优先。
- `writeAtomic`：同目录临时文件 + flush + rename；失败清理临时文件。

## 15. `xdk.tasks` —— 任务、任务组与上下文

**层级**：T0　**稳定性**：`preview`　**依赖**：`xdk.errors`、`xdk.runtime`
**非目标**：不做线程池调优（T1 executor）、不做定时器（T1 timer）、不做 async/await 语法。

### 15.1 文件清单

| 文件 | 职责 | 公开符号 | 状态 |
| --- | --- | --- | --- |
| `concurrent/tasks/Tasks.x` | 任务结果、任务组、上下文 | `Task<T>`、`TaskGroup`、`Context`、`TaskError` | 能力由 mini 编译器/Runtime 提供；源码面为骨架 |
| `concurrent/tasks/Cancellation.x` | 取消错误与令牌 | `CancelledError`、`CancelToken`、`cancelled()` | NEW（错误类/令牌） |
| `concurrent/tasks/Deadline.x` | 截止时间辅助 | `deadlineAfter`、`isExpired` | NEW |

### 15.2 `Context`（class，DONE 能力，源码待固化）

```text
class Context {
    static Context background()
    Context child()
    Context withDeadline(Long monoDeadlineMs)
    Bool isCancelled()
    Result<Unit, CancelledError> checkCancel()
    Long deadlineMonoMs()          // 0 = 无截止时间
    void cancel()                  // 幂等
}
```

- `background()` 只用于 main/测试；库代码应接受调用方传入的 `Context`。
- 子上下文取消向父传播，父取消向所有子传播；取消不可逆。
- `checkCancel()` 在进入阻塞前调用；等待循环必须周期性复查。
- `withDeadline` 使用单调毫秒；到期等价于取消，但错误分类仍是 `Cancelled`
  （截止时间超时在 `joinDeadline` 处映射为 `Timeout`，两者不混用）。

### 15.3 `Task<T>`（class）

```text
class Task<T> {
    Result<T, TaskError> join()
    Result<T, TaskError> joinDeadline(Long monoDeadlineMs)
    Bool isDone()
    void cancel()
}
```

- `join()` 消费结果；重复 join 是合同错误（返回 `Unavailable` 或 fatal，
  需固定并测试）。
- `joinDeadline`：超时返回 `Err(TaskError(Timeout))`，**不消费**结果；
  之后仍可 `join()`。
- `cancel()` 请求取消任务上下文；不等待完成。
- `T` 由 spawn 的 lambda 返回类型推断；当前实现通过语法推断。

### 15.4 `TaskGroup`（class）

```text
class TaskGroup {
    static TaskGroup create(Context parent)
    Task<R> spawn<R>(Result<R, TaskError>())
    void cancel()
    Result<Unit, TaskError> close()
    Int activeCount()
}
```

- `create` 保留父 `Context`；`close()` 取消组上下文并等待全部任务结束。
- `close()` 返回首个非取消错误（`first-error` 语义）；任务自身结果仍归 `join`。
- 重复 `close()` 是合同错误；实现可返回 `AlreadyExists`，不得静默成功。
- `spawn` 的闭包环境必须存活到任务结束（当前实现堆复制闭包）。

### 15.5 `TaskError` / `CancelledError`

```text
class TaskError implements Error {
    final ErrorKind kind
    final String message
    TaskError(ErrorKind kind, String message)
    ErrorKind kind()
    String describe()
    Bool isCancelled()
}

class CancelledError implements Error {
    ErrorKind kind()        // Cancelled
    String describe()
}
```

- `TaskError` 是任务边界错误；`CancelledError` 只用于取消面。
- `join` 的 `Err` 必须保留原任务错误分类；不得一律变成 `Internal`。

### 15.6 阶段出口

- 场景：`tests/xdk_tasks.x`、`xdk_cancel.x` 扩展重复 join/close、activeCount。
- 回归：mini 场景 + base/full 一致；legacy 适配器缺口记录。
- 验收：取消/超时/错误三条路径都有断言；无资源泄漏。

## 16. `xdk.sync` —— 互斥、通道与原子

**层级**：T0　**稳定性**：`preview`　**依赖**：`xdk.errors`、`xdk.tasks`
**非目标**：不做无锁数据结构承诺、不做分布式锁、不做线程亲和（T1 executor）。

### 16.1 文件清单

| 文件 | 职责 | 公开符号 | 状态 |
| --- | --- | --- | --- |
| `concurrent/sync/Sync.x` | 包头与兼容入口 | `Mutex`、`Channel`、`Atomic*` | 能力由编译器/Runtime 提供；源码为骨架 |
| `concurrent/sync/Mutex.x` | 数据+锁 | `Mutex<T>` | DONE（mini + legacy） |
| `concurrent/sync/Channel.x` | 有界通道 | `Channel<T>` | Int 通道 DONE；泛型 NEW |
| `concurrent/sync/Atomics.x` | 原子标量/引用 | `AtomicInt`、`AtomicBool`、`AtomicRef<T>` | DONE |

### 16.2 `Mutex<T>`（class，DONE）

```text
class Mutex<T> {
    Mutex(T data)
    Result<Unit, TaskError> withLock(Unit(T) body)
    Result<R, TaskError> withLockResult<R>(R(T) body)
}
```

- 不提供 `lock()/unlock()`；数据只能通过作用域回调访问。
- 回调在持锁状态执行；回调抛错/提前返回仍必须释放锁。
- 不提供递归锁语义；同一任务嵌套 `withLock` 是合同错误（需测试/文档）。
- 等待可被 `Context` 取消的设计在后续重载加入；当前 API 无 Context。

### 16.3 `Channel<T>`（class）

```text
class Channel<T> {
    Channel(Int capacity)                       // capacity > 0
    Result<Unit, CancelledError> send(Context context, T value)
    Result<T, CancelledError> receive(Context context)
    Result<Unit, CancelledError> trySend(T value)
    Result<T, CancelledError> tryReceive()
    Result<Unit, Error> close()                 // 幂等
    Bool isClosed()
    Int length()
}
```

- `capacity <= 0` → `InvalidArgument`（构造函数可 fatal 或工厂返回 Result；
  设计采用 `Result<Channel<T>, Error> open(Int capacity)` 工厂，构造器保持内部）。
- `send` 成功消费值（所有权转移）；`Cancelled`/`Closed` 不消费。
- `receive` 成功取得 +1 所有权；关闭后返回 `Closed`（状态域，不是 ErrorKind）。
- `close` 唤醒所有等待者；队列剩余元素按当前运行时语义丢弃（文档固定）。
- `trySend/tryReceive` 不阻塞，满/空返回 `Busy` 或 `Unavailable`（固定）。

### 16.4 原子类型（DONE）

```text
class AtomicInt {
    AtomicInt(Int initial)
    Int load()
    void store(Int value)
    Bool compareExchange(Int expected, Int next)
    Int fetchAdd(Int delta)        // NEW
    Int fetchSub(Int delta)        // NEW
}

class AtomicBool { ... load/store/compareExchange }
class AtomicRef<T> { ... load/store/compareExchange }
```

- 顺序语义统一为 sequentially consistent（首版）；后续可加显式内存序枚举。
- `AtomicRef` 不管理对象生命周期；持有引用不等于 retain（需文档写明）。
- 不提供原子指针/地址运算。

### 16.5 阶段出口

- 场景：`xdk_sync_atomic.x`、`xdk_sync_ref.x`、`xdk_mutex.x`、`xdk_channel.x`。
- 回归：mini + legacy（Mutex/Atomic 差分；Channel 记录 legacy 缺口）。
- 验收：无裸锁；关闭/取消路径有竞态测试。

## 17. `xdk.log` —— 结构化日志

**层级**：T0　**稳定性**：`preview`　**依赖**：`xdk.errors`、`xdk.runtime`、`xdk.text`、`xdk.time`
**非目标**：不做日志采集/传输（T1）、不做全局 logger 单例、不做隐式初始化。

### 17.1 文件清单

| 文件 | 职责 | 公开符号 | 状态 |
| --- | --- | --- | --- |
| `log/Log.x` | 级别与入口 | `Level`、`levelName`、`levelRank`、`parseLevel` | DONE（基础） |
| `log/Logger.x` | 记录器 | `Logger` | DONE（基础）；字段/多 sink NEW |
| `log/Sink.x` | 输出端与记录模型 | `Sink`、`LogRecord`、`Field`、`ConsoleSink`、`MemorySink` | NEW |

### 17.2 `Level` 与解析

```text
enum Level { Debug, Info, Warn, Error }

String levelName(Level level)
Int levelRank(Level level)
Result<Level, Error> parseLevel(String name)   // 大小写不敏感
```

- 级别顺序固定：Debug < Info < Warn < Error。
- 未知名称 → `InvalidArgument`，不得默认成 Info。

### 17.3 `Field` / `LogRecord` / `Sink`

```text
struct Field { String key; String value }

struct LogRecord {
    Level level
    Long timeMono
    String logger
    String message
    List<Field> fields
}

protocol Sink {
    void write(LogRecord record)
}

class ConsoleSink implements Sink {
    ConsoleSink()
    void write(LogRecord record)
}

class MemorySink implements Sink {
    MemorySink()
    void write(LogRecord record)
    List<String> lines()
    void clear()
}
```

- `Sink.write` 不返回错误：sink 失败不得中断业务；生产 sink 需自行降级。
- `LogRecord` 是值快照；sink 不得修改调用方字段列表。
- 输出格式由 sink 决定；`ConsoleSink` 固定 `[LEVEL] logger: message k=v`。

### 17.4 `Logger`（class）

```text
class Logger {
    Logger(String name, Level min)
    Logger withSink(Sink sink)
    Logger withField(String key, String value)
    Logger withMinLevel(Level level)
    Bool enabled(Level level)
    void log(Level level, String message)
    void debug(String message)
    void info(String message)
    void warn(String message)
    void error(String message)
}
```

- `with*` 返回新实例，不修改原实例（避免共享可变）。
- 默认 sink 为 `ConsoleSink`；默认字段为空。
- `enabled` 只按级别过滤；字段/sink 不影响判定。
- 不提供包级 `Logger.get("name")` 全局注册表。

### 17.5 阶段出口

- 场景：`tests/xdk_log.x` 扩展字段、MemorySink、级别解析。
- 回归：mini + legacy 差分（基础输出）；sink 场景 mini。
- 验收：无全局 logger；sink 失败不改变控制流。

## 18. `xdk.config` —— 配置快照与覆盖

**层级**：T0　**稳定性**：`preview`　**依赖**：`xdk.fs`、`xdk.text`、`xdk.sys`（T0 不依赖 codec）
**非目标**：不做 JSON/TOML/YAML 解析（T1 codec）、不做热更新、不做全局配置单例。

### 18.1 文件清单

| 文件 | 职责 | 公开符号 | 状态 |
| --- | --- | --- | --- |
| `config/Config.x` | 不可变快照 + 覆盖 | `Config`、`ConfigEntry` | DONE（基础） |
| `config/Source.x` | 配置来源 | `ConfigSource`、`MapSource`、`EnvSource`、`FileSource` | NEW |
| `config/Profile.x` | profile 选择 | `Profile`、`activeProfile` | NEW |

### 18.2 `Config`（class）

```text
struct ConfigEntry { String key; String value }

class Config {
    Config(String profile)
    String profile()
    Bool has(String key)
    String getOr(String key, String fallback)
    Result<String, Error> get(String key)
    Config set(String key, String value)       // 返回新快照
    Config remove(String key)
    List<String> keys()
    Config overlay(Config other)               // other 覆盖 self
    void loadEnv(List<String> allowlist)       // 兼容当前可变 API
    String render()                            // 稳定排序的 key=value
}
```

- 快照语义：`set/remove/overlay` 返回新实例；`loadEnv` 是兼容例外，
  后续改为 `withEnv` 并保留旧名。
- 键比较大小写敏感；键/值不得包含换行；`render` 排序保证确定性。
- 不提供隐式环境导入：必须显式传 allowlist。

### 18.3 `ConfigSource`（protocol，NEW）

```text
protocol ConfigSource {
    Result<List<ConfigEntry>, Error> load(Context context)
}

class MapSource implements ConfigSource {
    MapSource(List<ConfigEntry> entries)
    Result<List<ConfigEntry>, Error> load(Context context)
}

class EnvSource implements ConfigSource {
    EnvSource(List<String> allowlist)
    Result<List<ConfigEntry>, Error> load(Context context)
}

class FileSource implements ConfigSource {
    FileSource(String path)                    // key=value, # 注释
    Result<List<ConfigEntry>, Error> load(Context context)
}
```

- source 只负责“读并解析为条目”，不做 overlay；overlay 由 `Config` 负责。
- `FileSource` 语法：`key=value`，`#` 行注释，空行忽略；重复键后者覆盖前者。
- 文件读取可阻塞，`load(Context context)` 必须可取消。
- 结构化格式通过 T1 codec 的适配器实现 `ConfigSource`，T0 不引入 codec。

### 18.4 `Profile`（NEW）

```text
struct Profile {
    String name
    List<String> activeKeys
}
```

- profile 只做“选择/命名”，不引入隐式多文件合并；合并策略由调用方显式执行。

### 18.5 阶段出口

- 场景：`tests/xdk_config.x` 扩展 Source/overlay/FileSource。
- 回归：mini + legacy 差分（env/内存）；FileSource mini + legacy。
- 验收：无全局配置；render 确定性；allowlist 外的环境变量不可见。

## 19. `xdk.cli` —— 参数、命令与用法

**层级**：T0　**稳定性**：`preview`　**依赖**：`xdk.text`、`xdk.sys`
**非目标**：不做 GUI、不做 shell 补全生成（可后续）、不做隐式退出。

### 19.1 文件清单

| 文件 | 职责 | 公开符号 | 状态 |
| --- | --- | --- | --- |
| `cli/Args.x` | 参数列表解析 | `Args` | DONE（基础） |
| `cli/Command.x` | 选项规格与命令匹配 | `OptionSpec`、`Command`、`CommandMatch` | NEW |
| `cli/Usage.x` | 用法/帮助渲染 | `usage`、`helpText` | 部分 |
| `cli/Cli.x` | 退出码映射与兼容入口 | `exitCodeFor`、`usage` | DONE |

### 19.2 `Args`（class，DONE）

```text
class Args {
    Args(List<String> raw)
    Int length()
    String get(Int index)
    Bool has(String flag)
    String value(String flag)                 // 缺失 → ""
    String valueOr(String flag, String fallback)
    Result<Int, Error> intValue(String flag)  // NEW
    List<String> positionals()
}
```

- 支持 `--k v` 与 `--k=v`；`value` 对缺失/缺值返回空串，严格版返回 `Result`。
- `positionals` 跳过“看起来是值”的参数；规则必须文档化。
- 不支持组合短选项（`-abc`）除非后续显式设计。

### 19.3 `OptionSpec` / `Command`（NEW）

```text
struct OptionSpec {
    String name          // "--output"
    Bool takesValue
    String help
    Bool required
}

class Command {
    Command(String name, String summary, List<OptionSpec> options)
    Result<CommandMatch, Error> parse(Args arguments)
    String help()
}

struct CommandMatch {
    Args args
    String command
}
```

- `parse` 只做结构与必填校验；类型转换由调用方用 `Args.intValue` 等完成。
- 未知选项 → `InvalidArgument`，错误文本包含 `help()` 提示。
- 子命令注册是后续能力；首版一个 `Command` 一个命令。

### 19.4 用法与退出码

```text
String usage(String program, String summary)
String helpText(String program, String summary, List<OptionSpec> options)
Int exitCodeFor(String outcome)   // ok=0, usage=2, 其他=1
```

- 退出码映射稳定：成功 0、用法错误 2、运行错误 1；不得随意扩展。
- `usage/helpText` 不写 stdout/stderr；只返回字符串，输出由调用方决定。

### 19.5 阶段出口

- 场景：`tests/xdk_cli.x` 扩展 Command/help/intValue；真实 argv 运行。
- 回归：mini base/full；legacy String 元素读取缺口继续记录。
- 验收：无隐式 exit；错误文本包含用法提示。

## 23. 开放问题与风险

1. **config → codec 的层级冲突**：S6 目录标注 config 依赖 T1 codec，违反 T0 规则。
   本设计用 `ConfigSource` 依赖倒置解决；需要 S6 下一版澄清。
2. **`Text` 名称**：S6 写 `Text`，但语言已有 `String`。本设计以 `String` 为唯一
   文本值；需要 S6 把 `Text` 解释为能力而非类型。
3. **`Map<K,V>` 运行时**：当前只有 `Map<String,Int>`；`groupBy`、`BTreeMap<V>`
   等依赖它。必须先把 Map 泛型化，否则 T0-06 只能部分完成。
4. **泛型类运行时**：`Task<T>`/`Mutex<T>` 目前部分由编译器内建；`BTreeMap<V>`
   需要真正的泛型类单态化。编译器与库的边界需一次明确。
5. **可选引用类型**：`String?` 在 legacy 代码生成有缺口；T0 公开面应尽量避免
   可空引用，改用 `Result`/`getOr`。
6. **静态类方法**：现有实现支持不完整；工厂函数暂用顶层函数，待静态方法稳定
   后再收进类。
7. **`for-in` / `Iterator<T>` 脱糖**：编译器尚未固定迭代协议形状；T0-06 的
   Iterator 必须与脱糖同步落地。
8. **文件/目录所有权迁移**：`io/system/*` 与目标 `fs`/`sys` 布局重叠；迁移需
   保持兼容入口，避免一次性破坏场景。
9. **协议调度性能**：Reader/Writer 作为 protocol 会引入动态派发；首版接受，
   热点路径可用具体类型重载优化，但不得改变语义。
10. **阻塞与 Context**：现有文件/进程/通道 API 部分没有 Context；T0-09~13
    需补可取消重载，旧签名保留并文档标注“不可取消”。
11. **确定性**：`Random` 只保证同 seed 同平台可复现；跨平台差异必须文档化。
12. **正则范围**：不承诺 PCRE 全兼容；未支持语法必须编译期/运行期报错。
