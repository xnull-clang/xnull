# Annotation Processor Manifest v1

| 项 | 值 |
| --- | --- |
| 版本 | `manifestVersion = 1` |
| 工具 | `src/toolchain/annotation_platform.py` |
| 子命令 | `check-manifest` / `generate` |
| 状态 | P0-03–P0-07 implemented（M0.2/M0.3/M0.4）；Darwin sandbox-exec，其他平台 limits-only |

## 1. Manifest schema

```json
{
  "manifestVersion": 1,
  "processors": [
    {
      "name": "toy",
      "phases": ["Generate"],
      "command": ["python3", "relative/or/absolute/processor.py"],
      "outputs": ["toy_generated.x"],
      "timeoutSeconds": 30,
      "priority": 0
    }
  ]
}
```

校验：

- `processors` 非空；`name` 非空且唯一。
- `phases` 非空、无重复，只允许 `Resolve`/`Validate`/`Generate`/`Finalize`。
- `command` 非空字符串数组；相对脚本路径相对 manifest 目录解析。
- `outputs` 是相对路径，禁止绝对路径与 `..`。
- `timeoutSeconds` 为 1–120；`priority` 为整数。

## 2. 处理器协议 v0

```text
<command...> --phase <Phase> --ir <ir.json> --out <outdir>
```

- `ir.json`：`mini --dump-annotations` 输出。
- `outdir`：本次调用唯一可写目录。
- 可写生成文件（`.x`）与可选 `diagnostics.json`。
- stdout/stderr 由平台收集到 `report.json`，不直接污染编译器输出。
- 退出码非零 → 平台失败；超时 → `processor <name> timeout in <phase>`。

## 3. diagnostics.json

```json
[
  {"code":"AN1001","severity":"Error","message":"...","line":1,"col":1,"target":"app.X"}
]
```

- `code` 匹配 `AN[0-9]{4}`，且属于 `AN0100–AN0199`（平台）或 `AN1000–AN1999`（领域）。
- `severity` 只允许 `Error`/`Warning`/`Note`。
- `line`/`col` 为正整数；`message` 字符串。
- 合并按 severity（Error→Warning→Note）、code、line、col、message 排序。
- 去重键：`code + line + col + message`。
- 有 Error → `generate` exit 非零；输出 `<out>/diagnostics.json` 并打印摘要到 stderr。

## 4. 调度与固定点

```text
Resolve → Validate → Generate（≤3 轮）→ Finalize
```

- 同阶段按 `priority`、`name` 稳定排序。
- 每轮 Generate 只有产生新文件/内容变化才继续；连续无新文件停止。
- 3 轮仍变化 → 不收敛错误。
- Finalize 阶段任何新文件 → 平台错误。
- 每个处理器调用独立 outdir：`<out>/.processors/<phase>/<round>/<name>`。
- 平台产物：`<out>/ir.json`、生成文件、`<out>/diagnostics.json`、`<out>/report.json`。

## 5. 玩具处理器

`src/toolchain/processors/toy_processor.py`：

- 检测 IR 中 `app.Toy` / `Toy` 使用。
- Generate 阶段生成 `toy_generated.x`：

```x
// generated by toy_processor; DO NOT EDIT
package app
String toyValue() { return "toy"; }
```

- 参数 `true`（`@Toy(true)`）写 `AN1001` Error，平台 exit 非零。
- 只写平台给的 outdir；不读网络/不写其他路径。

## 6. 边界

- M0.2 不做源码落盘/加载/`--check-generated`（M0.3）。
- 不做进程沙箱、网络/文件越界隔离（M0.4）。
- 不改变 A8/领域注解语义。
- 当前处理器协议通过命令参数传 IR；不传编译器内部对象。

## 7. M0.3 generated-dir / check

`generate --generated-dir <dir>`：

- 处理器先写临时 staging；全部成功后才原子替换目标目录；失败保持旧目录。
- 每个 `.x` 输出必须属于 manifest `outputs`，首 200 字节含 `generated` 与 processor 名；否则 `AN0101`。
- Generate 每轮后尝试重新 `--dump-annotations`；无新文件停止，最多 `--max-rounds`（默认 3）。
- 第一轮缺失 `generated` import 时，平台为声明 outputs 建 inert 占位文件；未替换的占位文件在成功后删除。
- Finalize 写文件仍为错误。

`check --generated-dir <dir>`：

- 重新生成到临时目录，只比较 `.x`；
- 缺失/额外/内容不同/无标记 → 非零；
- 成功输出 `annotation_platform: generated sources match`；
- 不修改目标目录。


## 8. Sandbox（M0.4）

processor 可选字段：

```json
"sandbox": {
  "enabled": true,
  "allowNetwork": false,
  "maxMemoryMB": 256,
  "maxCpuSeconds": 30
}
```

- `enabled` 默认 true；`allowNetwork` 只允许 false（true 直接 manifest reject）。
- `maxMemoryMB` 32–4096；`maxCpuSeconds` 1–120，默认 timeoutSeconds。
- 不接受 sandbox 额外字段。

Backend：

| 平台 | backend | 能力 |
| --- | --- | --- |
| macOS + `/usr/bin/sandbox-exec` | `darwin-sandbox-exec` | deny default；file-read 允许；write 限 outdir；network deny；process/sysctl/mach 最小放行 |
| 其他 | `limits-only` | RLIMIT_CPU/AS/NOFILE + 最小 env + cwd=temp；**不宣称网络隔离** |

运行后：

- 拒绝 outdir 内 symlink；
- 拒绝 `..`、绝对路径、未在 manifest outputs 的文件；
- 超时/CPU/内存/越界 → 平台错误，exit 非零；
- 失败保留 `report.json`（generated-dir 模式下写 `<dir>.report.json`）。

`report.json` 顶层：

```json
{
  "sandboxBackend": "darwin-sandbox-exec",
  "sandboxProfile": "...",
  "limits": {"maxMemoryMB": 256, "maxCpuSeconds": 30},
  "processors": [...]
}
```

测试必须打印实际 backend；Darwin 要求 `sandbox-exec` 路径 PASS。非 Darwin 的 escape/network 检查标记 SKIP，不假 PASS。
