`grep -v entryFile\|dependencies` 后与 `tests/b4/fixtures/proj02/expected-app-main.xmeta`（Go 产物）
**逐字节一致**，包括 `resourcesSha256` 和 `inputs`（都按 Go 的算法复算）。

| 项 | 说明 |
|---|---|
| 字段名/顺序/缩进 | 与 Go 完全一致（16 字段） |
| `resourcesSha256` | 复刻 Go：`sha256(join(sort("resources/<name>\0"+sha256(data)), "\n"))` |
| `inputs` | 复刻 Go：`sha256(manifest + \0 + entry + \0 + lock + \0 + version + \0 + res+cfg+plugin)`，manifest 取 **app 模块**原文 |
| `entryFile` / `dependencies` | XNull 扩展（Go 无），已列在 diff 中 |
| 覆盖范围 | 本卡为 4 模块 + 聚合根各生成一份；Go 只对 app 写 `.xmeta`（library 只进 `.xlib`） |
| library 的 `resourcesSha256` | 复用 app 的资源摘要（Go 不给 library 写此文件），属扩展语义 |

## 5. 实现要点

- `xmeta.x`：读 `meta.tsv`（platform/toolchain/四个摘要/inputs）+ 各模块清单 TSV，按 Go 的字段顺序
  写 `<artifactId>-<version>.xmeta`。
- 摘要计算放在 shell 侧的 `gen_meta`（python3）：资源摘要与 inputs 都按 Go 的算法逐字节复刻；
  `tools/bootstrap-tools` 现在同时自举 `resman/artifact/config/deps/xmeta`。
- `repro`：`run_reactor` 跑两次（独立输出目录），对 `*.c`、`*.o`、`app` 取 `shasum -a 256` 比对。

## 6. plugin：边界与设计（本卡不实现）

`xnull plugin` / 插件校验属于 B4b-04b-3，本卡只记录边界：

- Go 侧语义：`build.plugins.plugin` 声明（`coordinate`/`version`/`phase`/`goal`/`config`）→
  `internal/plugin.LoadMetadata(.xplugin)` → `plugin.Validate(meta, decl, toolchainVersion)`，
  失败即停；`.xmeta` 里额外写 `plugins` 与 `pluginsSha256`。
- XNull 侧所需：`.xplugin` 元数据解析（XPD DSL 子集）、GAV 与阶段/目标校验、配置键类型校验、
  与聚合根 `dependencyManagement` 的版本一致性；`pluginsSha256 = sha256(join(sorted("coord@ver:goal"), "\n"))`。
- 依赖前提：`.xlib`/`.xmeta` 的打包与安装（B4b-03c）先落地，否则插件元数据没有分发载体。
- 本卡不动：`plugin`/`repro` 之外的插件域、`xpd` 增强仍归 B4b-04b-3 / B4b-04b-4。
