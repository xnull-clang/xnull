## 2. reactor.x 流程

1. `xpd` 解析根清单 → `root.tsv`，读出 `module` 行（声明顺序）；
2. 逐模块 `xpd` → `m-<rel>.tsv`；
3. `xmanifest` 合成 `model.tsv`（模块/依赖边/拓扑序，版本按 03a 规则兜底）；
4. 按 `order` 行（Kahn 拓扑）逐模块：
   - 入口固定 `<dir>/<rel>/src/main/x/main.x`；
   - `xnast --ast` → `*.ast`；原生 `xnullc <entry> --ast-file … --project ""` → `*.c`；
   - `library` → `cc -c -Dmain=xn_unused_<id>` → `*.o`；
   - `app` → 记录 C，稍后链接；
5. 链接：`cc -std=c11 -O2 -pthread -I <runtime> -o <out>/app <app.c> <全部 library .o> <14 个 runtime C 源> <空资源表>`。

所有外部命令通过 `xdk.sys.procStatus` 执行（XNull 侧没有 fork/exec API，这是当前唯一可用路径）。

## 3. 产物与链接参数（proj02）

| 模块 | packaging | 产物 |
|---|---|---|
| lib-core | library | `/tmp/b4-proj-proj02/lib_core.o`（776 B） |
| lib-codec | library | `/tmp/b4-proj-proj02/lib_codec.o`（776 B） |
| app-main | app | `/tmp/b4-proj-proj02/app_main.c` → `/tmp/b4-proj-proj02/app`（67 KB） |

库对象编译命令：

```bash
cc -std=c11 -O2 -pthread -I <impl/runtime> -c -Dmain=xn_unused_lib_core lib_core.c -o lib_core.o
```

`-Dmain=xn_unused_<id>` 的原因：XNull codegen 对任何源文件都会发射 `int main(void)` 包装（即使模块没有真正的入口），
库对象里保留它会与 app 的 `main` 冲突；用宏改名把库侧入口符号隔离（实现细节见 `reactor.x` 注释）。

链接顺序：app C → 库对象（拓扑序）→ 运行时 C 源 → 空资源表（`res.c`，与 B4b-01 的空表一致）。

## 5. 与 Go 的差异（明确记录）

| 项 | 差异 | 影响 |
|---|---|---|
| library 产物 | Go 打 `.xlib`（源码包 + `xlib.meta`）；本卡编成 `.o` | 不能作为依赖被其他工程解析；B4b-03c 补 `.xlib` |
| 跨模块调用 | 不支持（无 import 语法/符号解析） | 库对象只验证"可编译、可链接"；app 不调用库函数 |
| 入口解析 | 固定 `src/main/x/main.x`；未读 `build.entryFile`/`sourceRoot` | 与 Go 的入口解析规则不同（fixtures 恰好一致） |
| FFI 投影 | 每模块 `--project ""`（同 B4b-01 的 examples 口径） | 模块 `import xdk.*` 会缺 `xn_ffi_*`（B4b-03b-2 处理） |
| 资源表 | 固定空表 | 不使用 resman（下一卡） |
| `.xmeta`/`lock`/`config` | 无 | 下一卡 |
| 多 app | 只支持单入口 app | 多 app 聚合未覆盖 |
| 失败即停 | 有（任一步非 0 即退出 1） | 与 Go 一致 |

## 6. 途中发现的原生 codegen 缺陷（新增，交 E4/E5）

在 `reactor.x` 里踩到 3 个会让生成 C 直接编译失败的问题（均有最小复现，已规避）：

1. **调用结果/数组元素上的方法调用**：`readFileText(p).split("\n")`、`rl[i].split("\t")`
   被发射成 `ptr.split(...)`（`.` 而非 `->`）→ `no member named 'split'`。规避：先赋给局部 `String`。
2. **多操作数拼接赋给类字段**：`m.entry = a.d + "/" + m.rel + "/x"` 被发射成
   `rt_string* + rt_string*`（`invalid operands`），同样的表达式赋给局部变量则正常。规避：先算到局部再赋值。
3. **`out` 是保留字**：字段名 `out` 报 `SYN-101 期望类成员`（定位在类体）。

前作已记录：`&&` 右侧下标提前求值、自由函数不能 `new` 类、`in` 关键字。
