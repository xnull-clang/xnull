## 2. `xpd.x`：清单 → 规范化 TSV

- 输入：`xpd <path>` 或 `xpd --text <源码>`。
- 输出（制表符分隔）：

| 行 | 含义 |
|---|---|
| `field <name> <值>` | `groupId`/`artifactId`/`version`/`packaging`，固定顺序 |
| `module <相对目录>` | `modules { module … }`，**保持声明顺序**（拓扑/配对依赖它） |
| `managed <coord> <版本>` | `dependencyManagement.dependencies`，按坐标排序 |
| `dep <coord> <版本|空>` | `dependencies`，按坐标排序；版本为空表示交给 management |

- 支持的语法子集：
  - `project { groupId/artifactId/version/packaging }`
  - `modules { module a/b }`（无花括号块）
  - `dependencies { dependency g:a { version = v } }`
  - `dependencyManagement { dependencies { … } }`
  - `#` 行注释、`"…"` 字符串（`\"`、`\\` 等简单转义）、空行
- 未支持（按卡要求记录）：
  - `parent`/`relativePath` 继承链、`properties` 变量替换、`profiles` 激活；
  - `scope`/`exclusions`、`build.*`（entryFile/sourceRoot 等）、`plugins`、`resources`；
  - `starter` 展开、版本仲裁（属于 B4b-03b）；
  - XPD 诊断码与位置（当前只保证"能解析/不能解析"，见 §4 限制）。

## 3. `manifest.x`：TSV → 工程模型

- 输入：`xmanifest <root.tsv> [<module.tsv> …]`（第 1 个是聚合根，其余按 `modules` 声明顺序对应）。
- 输出：`project` / `module` / `edge`（`from→坐标@版本`）/ `order`（拓扑序）/ `error`。
- 版本解析：模块自身声明优先，其次根的 `dependencyManagement`；两边都没有 → 版本 `?` 并退出 1。
- 拓扑：Kahn，只统计指向本聚合内模块的边；同层按声明顺序（与 Go `reactor.Load` 的稳定排序一致）。
- 根工程自身的依赖也会输出 `edge`（单工程 app/library 同样可校验）。

## 6. 途中发现的原生工具链缺陷（交 E4/E5，非本卡范围）

写 `xpd.x` 时踩到三个会静默产出错误结果的问题，均已用最小片段复现：

1. **`&&` 右侧的下标被提前求值**（C 发射器）：`while j >= 0 && cmpStr(xs.get(j), v) > 0` 被发射成
   先 `xn_arr_s_get(xs, j)` 再判断 `j >= 0`，`j=-1` 时容器越界 fatal。
   复现：4 元素字符串列表做插入排序即崩。本卡改为显式 `if`/`break` 规避（`sortLines`、词法扫描循环）。
2. **自由 `static` 函数里不能 `new` 类**：报 C 错误 `incomplete definition of type 'xn_Cls_X'`
   （类结构体定义在自由函数之后发射）。本卡把词法/语法/TSV 装载放进类方法（`class Ctx`/`class Loader`）规避。
3. **`out`/`in` 是保留字**：作为变量名会报 `SYN-102 比较运算不可链式使用`（错误定位偏差很大）。
   本卡改名为 `toks`/`bi`/`bo`。
