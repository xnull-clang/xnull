# P1 派工追责（执行细则）

> 依据：ADR-010；SLA P1 当日（AGENTS §6）
> 对象：派工方（董事会/总控），不是生产线

## 一、什么算 P1 派工违规（四条，客观可判）

| 编号 | 条件 | 判定证据 |
|---|---|---|
| V1 | 两张在途卡的文件/包边界相交，且未先冻结接口 | 派工记录 + `git log --name-only` 交集 |
| V2 | 派工单没有文件边界（只写功能，不写路径/包） | 派工消息或卡文件缺「文件边界」栏 |
| V3 | 跨线卡未出接口文档就并行开工 | 无 `handoff/*接口*` 或 ADR 记录 |
| V4 | 允许生产线自行 merge main，或出现 main 双写者 | main reflog 出现非 INTEG 的 merge/reset |

## 二、发现机制

1. **派工前**：每波开工先写「卡 → 文件/包」矩阵；有交集则串行或先出接口卡。
2. **合并时**：INTEG 合并前检查 `handoff/merge.lock`；冲突文件回查两张卡的派工记录。
3. **每日审计**：`git log --name-only` 按 owner 聚合，找同文件多 owner 时间重叠。

## 三、追责动作（对派工方）

| 级别 | 触发 | 动作 |
|---|---|---|
| 一级 | 首次 V1–V4 | 书面记录入 `handoff/dispatch-violations.tsv`；该卡立即停派，重排边界；当轮报告向用户披露 |
| 二级 | 同一阶段第二次 | 该阶段**强制串行**：一次只允许一张实现卡在途；并行权收回，直到该门关闭 |
| 三级 | 同一阶段第三次 | 该阶段全部新卡冻结，须用户批准后才能恢复派工；相关预算按已消耗计，不得追加 |

补充：
- 因派工违规造成的返工工时，计入**该阶段预算**（如 B2 24h），不算产线责任；
- 生产线按错误指令执行不追责；生产线自行 merge main 属产线违规，另行处理；
- 所有记录公开在仓库，不写“内部掌握”。

## 四、记录格式

`handoff/dispatch-violations.tsv` 字段：

```
编号	时间	级别	条款	涉及卡	owner	冲突文件/证据	处置	状态
```

## 五、降级不是无限降：状态机与恢复条件

级别最高只到三级，没有四级；每级都有明确的退出条件，满足即自动恢复，不靠人点头。

| 级别 | 进入条件 | 状态 | 恢复条件 | 恢复到 |
|---|---|---|---|---|
| L0 正常 | 无违规 | 按 WIP 并行 | — | — |
| L1 记录 | 首次 V1–V4 | 停涉事卡、重排边界，其余照常 | 重排完成 + 文件矩阵 + 接口文档（如适用） | L0 |
| L2 强制串行 | 同一阶段第二次违规 | 该阶段一次只允许 1 张实现卡在途 | 连续 2 个波次零违规（合并锁使用、文件矩阵无交集、卡按时提交） | L1 |
| L3 阶段冻结 | 同一阶段第三次违规 | 该阶段新卡全停 | 仅用户可解冻 | L2（不是直接回 L0） |

补充规则：

1. **作用域**：级别只作用于当前阶段（如 S8、B2），不跨阶段永久继承。
2. **衰减**：阶段关闭时若已恢复且无新增违规，下一阶段从 L0 开始；若同一根因跨阶段复发，下一阶段从 L1 起步。
3. **不叠加**：L2 期间再违规只升到 L3，不因次数叠加出“永久冻结”。
4. **不影响交付**：降级只减少并行度，工作继续串行推进，不停工（L3 也仅停新卡，在途卡收尾）。
5. **用户可覆盖**：你可随时指定某阶段回到 L0 或解除 L3，无需等待条件满足。
