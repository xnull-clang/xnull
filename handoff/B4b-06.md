## 1. 入口设计

`bin/xnull` 只做入口层，仓库根按脚本自身位置推导（`bin/xnull` → `../`），与调用者 cwd 无关；
内部全部转发到 `tests/b4/xnull-build.sh`（不依赖 Go CLI）。

| 命令 | 行为 |
|---|---|
| `build <entry.x> [-o out]` | 单文件构建（C → cc） |
| `build <工程目录>` | 自动分发到聚合构建（`build-project`） |
| `run <entry.x> [-- 参数]` | 单文件构建并运行 |
| `run <工程目录>` | 构建 + 运行 app（`run-project`） |
| `validate <工程目录>` | 清单校验（模块/依赖边/拓扑） |
| `tree <工程目录>` | 依赖树 |
| `why <工程目录> <coord>` | 依赖理由 |
| `install <工程目录> [--repo d]` | 构建 + 安装 `.xlib` 到本地仓库 |
| `repro <工程目录>` | 连续两次构建，比较 C/对象/app SHA-256 |
| `xmeta <工程目录>` | 生成模块 `.xmeta` |
| `fmt [--check] <文件…>` | 格式化（xnfmt） |
| `clean [目录] [--all]` | 清理 target（`--all` 另清仓库缓存） |
| `version` / `-v` / `--version` | 版本信息（含 `specs:` 行） |
| `doctor [目录]` | 环境自检（cc/runtime/repo/manifest/lock） |
| `examples` | 9 个示例全量验收 |
| `bootstrap-model` / `bootstrap-tools` / `bootstrap-reactor` | 自举内置工具（保留内部命令） |

`build`/`run` 的工程判定：参数是目录且含 `xnull.project` → 工程模式；否则按文件处理。
未列出的子命令原样转发（保留 `build-project`/`run-project` 等内部名）。
