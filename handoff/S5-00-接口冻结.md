## 一、对象模型

| 类型 | 生命周期 | 说明 |
|---|---|---|
| `xrt_task` | ARC 句柄 | 任务票据；`join` 只能成功一次；由组拥有 |
| `xrt_task_group` | ARC 资源 | 任务组；`close` 是唯一终结路径 |
| `xrt_context` | ARC 句柄 | 取消信号 + 截止时间；显式传参 |
| `xrt_cancel_token` | 借用（内嵌于 context） | 供调度器/子上下文共享的取消位 |
| `xrt_channel` | ARC 资源 | 有界通道；`close` 幂等 |
| `xrt_mutex` | ARC 资源 | 数据携锁；作用域回调 |
| `xrt_atomic_*` | ARC 资源 | 顺序一致原子单元 |

- 句柄本身是 ARC 对象（显式释放/关闭）；任务闭包 `env` 是 GC 对象，由运行时在任务存活期登记根。
- 首版调度器可单载体线程实现；本 ABI 不假设线程数（S5 §2.1）。

## 二、Closure / 结果 ABI

```c
typedef struct xrt_task_result {
    int32_t        ok;     /* 1 = Ok；0 = Err */
    void          *value;  /* Ok：+1/拥有；类型由 codegen 与语言层约定 */
    xrt_error_kind kind;   /* Err：S4 ErrorKind（业务错误原样 kind） */
    void          *error;  /* Err：错误值 +1（可为 NULL，如纯 kind 错误） */
} xrt_task_result;

/* 任务闭包：执行体。返回 0 表示 out 已填；非 0 保留给运行时基础设施错误。 */
typedef int32_t (*xrt_task_body)(void *env, xrt_context *ctx, xrt_task_result *out);
```

- 业务 `Err`：`ok=0`，`kind`/`error` 由闭包返回原样保留（S5 §3.4，不包装/不降级）。
- 取消/超时：`kind = XRT_ERR_CANCELLED` / `XRT_ERR_TIMEOUT`（§六）。
- `value`/`error` 的所有权：任务闭包以 +1 交出；`join` 把所有权移交调用方。

## 三、Task / TaskGroup

```c
xrt_task_group *xrt_task_group_new(xrt_context *parent);        /* +1；parent 可为 NULL=background */
int32_t xrt_task_group_spawn(xrt_task_group *g, xrt_task_body body, void *env, xrt_task **out);
void    xrt_task_group_cancel(xrt_task_group *g);                /* 幂等；不等待 */
int32_t xrt_task_group_close(xrt_task_group *g, xrt_task_result *first_error);
int32_t xrt_task_join(xrt_task *t, xrt_task_result *out);
int32_t xrt_task_join_deadline(xrt_task *t, int64_t deadline_mono_ms, xrt_task_result *out);
```

- `spawn`：唯一创建方式（S5 §4）；`env` 调 `xrt_task_root_bind(env)`；任务归组所有。
  返回 0 且 `*out` +1；提交失败（如组已关闭）返回非 0（保留状态码，见 §六）。
- `join`：等待终结；成功返回 0 并填 `out`；**重复 join = 合同错误 → `xrt_fatal`**。
- `join_deadline`：到期返回 `XRT_ERR_TIMEOUT`（不改 `out`，任务继续执行，S5 §3.1）。
- `group.cancel`：向下取消；`group.close`：取消 → 等待全部终结（含清理）→
  `first_error` 返回首个非取消类子任务错误（无不填）；**close 一次，重复 close = fatal**。
- close 与 join 的关系：close 只等待、不消费 join；close 后仍可对任务执行一次 join（§九 待确认 7）。
- `@tasks` 块外使用任务 API = 编译错误（S5 §2.3；E2/E4 实现）。

## 四、Context / 取消 / 超时

```c
xrt_context *xrt_context_background(void);                        /* +1；仅 main/测试 */
xrt_context *xrt_context_child(xrt_context *parent);              /* +1；子上下文 */
xrt_context *xrt_context_with_deadline(xrt_context *parent, int64_t deadline_mono_ms);
int32_t      xrt_context_check_cancel(const xrt_context *ctx);    /* 0 或 XRT_ERR_CANCELLED */
int32_t      xrt_context_cancelled(const xrt_context *ctx);       /* 0/1 */
xrt_cancel_token *xrt_context_token(xrt_context *ctx);            /* 借用；调度器用 */
void         xrt_context_cancel(xrt_context *ctx);                /* 显式取消；幂等 */
int64_t      xrt_clock_mono_ms(void);                             /* 单调时钟（deadline 单位） */
```

- 取消协作式：`check_cancel` 只在检查点返回 `XRT_ERR_CANCELLED`；不立即中断。
- `with_deadline` 到期等效取消（`Cancelled`）；`join_deadline` 超时是 `Timeout`（S5 §6）。
- 取消传播：父 token 置位 → 子上下文检查沿链可见；清理路径不受取消影响（`defer` 由 codegen 保证）。
- deadline 为单调毫秒绝对值；`xrt_clock_mono_ms` 是新增 ABI（§九 待确认 6）。

## 五、Channel / Mutex / Atomic

```c
typedef void *(*xrt_ref_retain_fn)(void *v);
typedef void  (*xrt_ref_release_fn)(void *v);
typedef struct xrt_channel_ops { xrt_ref_retain_fn retain; xrt_ref_release_fn release; } xrt_channel_ops;

xrt_channel *xrt_channel_new(size_t capacity, const xrt_channel_ops *ops); /* capacity > 0 */
int32_t xrt_channel_send(xrt_channel *ch, void *value, xrt_context *ctx);
int32_t xrt_channel_receive(xrt_channel *ch, void **value, xrt_context *ctx);
void    xrt_channel_close(xrt_channel *ch);  /* 幂等 */

typedef int32_t (*xrt_with_lock_body)(void *data, void *env, xrt_context *ctx);
xrt_mutex *xrt_mutex_new(void *data, const xrt_channel_ops *ops);
int32_t    xrt_mutex_with_lock(xrt_mutex *m, xrt_with_lock_body body, void *env, xrt_context *ctx);

xrt_atomic_int  *xrt_atomic_int_new(int64_t v);   /* +1 */
int64_t          xrt_atomic_int_load(const xrt_atomic_int *a);
void             xrt_atomic_int_store(xrt_atomic_int *a, int64_t v);
int32_t          xrt_atomic_int_cas(xrt_atomic_int *a, int64_t expect, int64_t desired);
/* AtomicBool / AtomicRef 同形；AtomicRef 用 void* + ops（§九 待确认 10） */
```

- **Channel 所有权**：`send` 消费 +1（队列用 `ops.retain` 持有），`receive` 取得 +1；
  `close` 唤醒挂起者并释放队列剩余元素；关闭后再 `receive` 返回 `XRT_STATUS_CLOSED`（终态）。
- 标量元素：`ops` 可为 NULL（不持有）。引用元素：ARC 用 `rt_retain/rt_release`，
  GC 用 `xrt_task_root_bind/unbind`（或等价 ops 实现）。
- `send/receive` 是可取消挂起点：取消返回 `XRT_ERR_CANCELLED`。
- `Mutex.with_lock`：作用域回调，锁在回调返回/异常终止（fatal）时释放；`data` 由 mutex 持有 +1
  （创建时接管）；锁对象不可逃逸出回调（语言层拒绝，SYNC-01）。
- 原子：顺序一致（seq_cst），不暴露内存序参数；`AtomicRef` 的 GC 发布点见 §七。

## 六、错误交付与状态码

- 业务错误：`xrt_task_result.ok=0`，`kind`/`error` 原样；不包装、不降级（S5 §3.4）。
- 取消：`XRT_ERR_CANCELLED`；超时（joinDeadline）：`XRT_ERR_TIMEOUT`；未知码绝不映射为 Ok。
- 函数返回状态（int32）：
  - `0` = 成功；
  - `XRT_ERR_CANCELLED` / `XRT_ERR_TIMEOUT` / 其他 `xrt_error_kind` = 错误面；
  - `XRT_STATUS_CLOSED`（`#define XRT_STATUS_CLOSED 100`，状态域，非 ErrorKind）= 通道关闭终态；
  - 其余非 0 保留给实现（调用方按错误处理，不假设具体值）。
- 合同错误（重复 join/close、已关闭组 spawn、guard 逃逸）→ `xrt_fatal`（进程终止，
  无静默；与 S4 诊断通道同路径）。

## 七、与 S3 根/安全点的边界（冻结）

1. 任务 `env`：`spawn` 时 `xrt_task_root_bind(env)`；任务终结（join/close 完成）后
   `xrt_task_root_unbind(env)`（S5 §2.1、S3 §11.1）。
2. 挂起点：调度器在任务挂起前/恢复后调用 `xrt_safepoint()`；栈根由 codegen 的
   `xn_root_*` 帧维护（S3-02）。挂起路径不得持有未登记的 GC 引用。
3. 队列中的值：Channel/任务结果里的引用由 `ops` 或 task root 持有；调度器不得在
   GC 会合期间移动/释放队列元素。
4. ARC：任务/组/Context/Channel/Mutex 为 ARC 对象；跨线程释放使用原子计数（已有）。
5. 并发化门槛：弱表原子化与写屏障（S3-06）是调度器多线程化的前置；单载体线程实现可先用现有单线程运行时。
6. 发布点：跨任务写入 GC 引用必须经 `xrt_safepoint`/根登记发布；写屏障 S3-06 前不承诺多线程可见性。

## 八、与 S4 错误面的边界（冻结）

- 复用 `xrt_error_kind`（S4-E5）：`Timeout=6`、`Cancelled=7`；**不新增枚举项**。
- `check_cancel → XRT_ERR_CANCELLED`；`join_deadline → XRT_ERR_TIMEOUT`；
  组取消产生的任务结果 `kind = XRT_ERR_CANCELLED`。
- 禁止把取消/超时降级为 `Internal` 或业务错误；业务错误 kind 原样交付。
- fatal 诊断沿用 S4-06：单行、无堆、只含调用方文本（任务名/等待点由实现附加时仍需无堆）。
