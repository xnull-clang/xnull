- 卡片：B4b-05（全命令对拍，作为 B4b 门证据）
- 日期：2026-11-11
- 被测对象：Go CLI（`impl/cmd/xnull`，main）vs XNull 原型 CLI（`tests/b4/xnull-build.sh`）
- 范围：proj02（聚合工程）+ 9 个示例（`tests/b2/corpus/examples/*.x`）
- 复现：`tests/b4/cli-parity.sh`（约 80s；`--quick` 只跑 proj02）

## 1. 结论（四数）

```text
PASS=6  DIFF=2  NA=12  total=20
```

- **PASS 6**：`build proj02`、`tree proj02`、`why proj02`、`xmeta proj02`、`build examples`、`run examples`；
- **DIFF 2**：`install proj02`（library 制品 `.o` vs `.xlib`，且 XNull 另装 app）、`version`（缺 Go 的 specs 行）；
- **NA 12**：Go 或 XNull 单侧缺失的命令/语义（见 §2 说明）。

**判定建议：B4b 仍为 PARTIAL，不能判 PASS、B4c 不得启动**（理由见 §4）。

## 3. 对拍判据

- **PASS**：两路输出逐字节相同，或运行结果（stdout + 退出码）相同且差异不影响合同
  （如 `build` 的 library 产物格式已在 B4b-03b-1 明确为 `.o`）；
- **DIFF**：可比较但结果不同（install 制品集合、version 的 specs 行）；
- **NA**：一侧没有该命令或该语义（Go 无 validate/repro；XNull 无 fmt/clean/doctor）。

## 4. 为什么仍判 B4b PARTIAL

按 `handoff/B4b-c-plan.md` 的 B4b 范围（CLI/devtool 接管）逐项对照：

| 计划项 | 状态 | 缺口 |
|---|---|---|
| B4b-01 CLI 引导（build/run + 9 示例） | 完成 | — |
| B4b-02 native xparser 接管 | PARTIAL | 大文件（xparser.x/xlex.x/xnfmt.x）native 段错误，仍回退 `xnast` |
| B4b-03 工程模型 | PARTIAL | 已有 xpd 子集/manifest/reactor/resman/config/artifact 最小实现；缺 `.xlib` 打包、`.xmeta` 之外的制品分发、递归资源、六层配置 |
| B4b-04 工具 | PARTIAL | install/repro/xmeta 已有；**plugin 未实现**（仅设计）、xpd 增强未做 |
| B4b-05 全命令对拍 | 本卡 | PASS 6 / DIFF 2 / NA 12，尚未全绿 |

**结论**：B4b 不能判 PASS。至少还差：

1. 修 native xparser 大文件（E4/E5，B4b-02 的残留）；
2. `plugin`（B4b-04b-3 子卡 a/b/c；d 需 E5 的受限执行能力）；
3. `.xlib`/`.xmeta` 打包与仓库分发，使 `install` 与 Go 一致；
4. `fmt`/`clean`/`doctor`（若 B4c 删除 Go CLI，这些必须由 XNull 接管）；
5. `version` 的 specs 行（需要规格版本清单的 XNull 来源）。

B4c 前置（冻结 golden、删除 Go）在以上完成前不得启动。
