# B4b-01 CLI bootstrap 原型（构建/运行管线不依赖 Go CLI）

- 卡片：B4b-01（CLI 引导：build/run 调 xnullc + xparser/xlex）
- 日期：2026-11-11
- 基线：main `1c0e42d`（B3-10 固定点 + B4a PASS）
- 交付：`tests/b4/xnull-build.sh`（新增，唯一代码改动）、本文件
- 验收：**9/9 PASS**（C 与 Go `--emit-c` 逐字节一致、二次生成一致、native/Go/interp 三路运行一致）

## 1. 管线

```text
<entry.x>
  ├─ xnast --ast ------------------------------> ast.txt      （Go oracle，B4c 前允许）
  ├─ xnull --emit-ast-bundle ------------------> bundle.json  （仅多文件入口使用）
  └─ tests/b3/xfb-projection.py <dir> ---------> project.txt  （FFI 注册表投影）
                    ↓
        native xnullc <entry> --ast-file … --project … [--bundle-file …]  →  <out>.c
                    ↓
        cc -std=c11 -O2 -pthread -I impl/runtime
           <out>.c  impl/runtime/{14 个 C 源}  <out>.res.c（空资源表）
                    ↓
                 <out> 可执行文件
```

`<out>.res.c` 与 `impl/internal/codegen/build.go` 的 `emptyResourceTableC` 等价（零资源工程空表）。
运行时 C 源顺序与 `impl/internal/codegen/build.go:36` 的 `runtimeCSources` 完全一致（顺序影响确定性）。

### 命令

```bash
tests/b4/xnull-build.sh build <entry.x> [-o out] [--emit-c-only]
tests/b4/xnull-build.sh run   <entry.x> [-- 程序参数...]
tests/b4/xnull-build.sh verify <entry.x>     # C 对比 + 二次生成 + 三路运行
tests/b4/xnull-build.sh examples             # 9 示例全量验收
tests/b4/xnull-build.sh bootstrap-xnullc -o /tmp/xn-s1   # 解释器自举原生 xnullc
tests/b4/xnull-build.sh info
```

### 原生 xnullc 的来源（按优先级）

1. `XNULLC_BIN=/path/to/xnullc`；
2. `/tmp/xn-s4`（B3-10 固定点二进制，sha256 `fc55fccb…67c2d`）；
3. `/tmp/xn-s1`；
4. `bootstrap-xnullc`：`xnull run --interp impl/lib/b3/xnullc.x -- impl/lib/b3/xnullc.x --ast-file … --project … --bundle-file …` 生成 C 后 `cc` 成二进制（解释器路径，138s，可复现）。

自举实测：`tests/b4/xnull-build.sh bootstrap-xnullc -o /tmp/xn-b4b01` → 138.15s，产出 1,723,552 字节；
用它跑 `XNULLC_BIN=/tmp/xn-b4b01 tests/b4/xnull-build.sh examples` → **9/9 PASS，C sha256 与 `/tmp/xn-s4` 完全一致**。

## 3. 依赖

| 依赖 | 用途 | B4c 后 |
|---|---|---|
| `xnast --ast`（Go oracle） | 生成 AST | 换 native xparser（B4b 后续卡） |
| `xnull --emit-ast-bundle`（Go oracle） | 多文件闭包 | 换 native xparser bundle |
| `python3 tests/b3/xfb-projection.py` | FFI 注册表 | 保留（非 Go） |
| native xnullc（`/tmp/xn-s4` 或自举） | AST→C | 保留 |
| `cc`（系统 C 工具链） | 链接 | 保留 |
| `impl/runtime/` 14 个 C 源 | 运行时 | 保留 |

Go 只出现在 AST 与验收对比两处，**不参与 C 生成与链接**。

## 4. 与 Go CLI 的差异

| 能力 | Go `xnull build` | `tests/b4/xnull-build.sh build` |
|---|---|---|
| 参数解析 | 完整命令树（run/build/install/…） | 仅 `build`/`run`/`verify`/`examples` |
| AST | 进程内 Go 前端 | `xnast --ast` 文件通道（oracle） |
| bundle | 进程内 | `xnull --emit-ast-bundle` 文件通道 |
| C 生成 | Go codegen | **native xnullc** |
| 资源表 | 支持 `--resources` / manifest | 固定空表（零资源工程） |
| 链接选项 | 支持 `--link-args`/`--mode`/`--runtime` | 固定 `-O2 -pthread` + 默认 runtime |
| 工程/manifest/.xlib | 支持 | 不支持（B4b-03 范围） |
| 输出 | `-o` 可执行 + `.c` + `.res.c` | 相同布局 |
| 诊断 | `xnull: …` 文本 + 退出码 | 透传 native xnullc stderr，退出码 1/2 |
| FFI 投影 | 进程内注册表 | `xfb-projection.py`；整仓投影会撞上 `impl/xnfmt`、`evidence/` 下同名 `.xfb` 造成 `xn_ffi_*` 重复定义，自举时改用 `bindings/` |

结论：C 生成已完全脱离 Go；AST 与工程层仍依赖 oracle/Go，这正是 B4b 后续卡（native xparser、dev test、工程模型）的替换对象。
