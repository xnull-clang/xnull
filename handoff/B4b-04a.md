## 3. 实现要点

- **图模型**：把「根（查询工程）的直接依赖」与「聚合内各模块自身的依赖」展平成边表；
  从根做 BFS，最近优先、同深度先到先得（与 Go `ResolveGraph` 的 nearest-wins 一致）；
  记录坐标→版本/父节点/深度。
- **tree**：根坐标 `g:a@v` 一行，子节点按坐标字节序、每层 2 空格缩进。
- **why**：沿父链回溯并反转成 `a@v -> b@v`；来源判定与 Go 相同（深度 1=直接依赖；
  版本等于根 `dependencyManagement` 固定值=`dependencyManagement 固定`；否则=最近优先）。
- **聚合发现**（`prepare_graph`）：从查询目录向上找 `packaging = pom` 的工程，把其
  `modules` 全部 `xpd` 成 TSV 一并喂给 `deps`；等价于 Go 从本地仓库读取传递依赖清单
  （但不需要 `XNULL_REPO`）。

## 4. 夹具变更（为覆盖传递依赖）

- 新增 `lib-util`（library，仅被 `lib-codec` 依赖），proj02 现为 `pom + 3 library + app`；
- 模块依赖改为**显式版本**（`lib-codec → lib-core/lib-util`、`app-main → lib-core/lib-codec`）：
  Go 的 `tree/why` 对单个模块不继承聚合根的 `dependencyManagement`，不写版本会直接 XPD-401；
- 同步更新 `expected.model.tsv`（03a golden）、`reactor-check.sh`（多一个 `lib_util.o`）。
  03a 自检 4/4、03b-2 自检 8/8 均仍全绿。

## 5. 与 Go 的差异 / 未支持

| 项 | 本卡 | Go |
|---|---|---|
| 传递依赖来源 | 聚合内兄弟模块清单 | 本地仓库 `<repo>/<g>/<a>/<v>/xnull.project`（支持外部依赖） |
| 冲突诊断 | 无（先到先得） | 同深度多版本报 `XPD-403` 并列出全部路径 |
| scope / exclusions | 忽略 | 参与图构建 |
| 插件边 | 不展示 | `xnull tree` 同样不展示插件（一致），但 `lock`/`install` 会用 |
| 输出流 | 错误走 stdout（`未被解析`），退出 2 | 错误走 stderr，退出 2 |
| 版本兜底 | 根 `dependencyManagement` | 同（含 profile 合并与 properties 替换） |

## 6. 途中踩到的实现约束

1. `Tsv[] mods = new Tsv[n]` 这类「类数组」不可靠 → 改为把边展平进 `Ctx` 的并行列表；
2. 长 `+` 链返回会被截断（见 B4b-03b-2）→ 一律改成逐行 `s = s + …`；
3. `deps` 的参数下限要按子命令算（`tree` 只有 1 个 TSV 时不能按 3 个参数校验）。
