## 1. 每个命令做了什么

### 1.1 `version`

Go 的 `specs:` 行是 `version.SpecSet` 常量；XNull 侧改为**从仓库根规范文件名推导**
（`XNull解决方案-第N部分-…-vX.Y.Z.md`，按 N 排序拼 `S1 v3.3.0, …`，排除「修订说明」文件），
输出与 Go `-v` **逐字节一致**（5 行：版本/commit/build date/specs/abi）。

### 1.2 `clean [dir] [--all]`

与 Go 同语义：删除 `<dir>/target` 并打印 `已清理 <target>`（`--all` 另删本地仓库缓存）。
对拍：同一目录下两路执行，目录效果与输出一致。

### 1.3 `doctor [dir]`

字段与 Go 完全一致、顺序一致：`cc` / `runtime` / `repo` / `manifest` / `lock`，级别 `[ok]/[warn]/[fail]`，
`fail` 时退出 1。对拍按「字段名 + 级别」比较（值含路径，随环境不同）。

### 1.4 `install`（库制品对齐 `.xlib`）

新增 `tests/b4/pack_xlib.py`：

- 内容：`xnull.project` + `src/**`（递归、排除 `target/`）+ `xlib.meta`；
- `xlib.meta` 文本与 Go `internal/artifact.Build` **逐字节一致**（GAV/packaging/依赖/files 摘要）；
- zip：Store、条目按名称排序、时间戳 1980-01-01（Go 零时间戳的等价物）。

安装集合与 Go 对齐：

```text
<repo>/io/xnull/lib-core/1.0.0/{lib-core-1.0.0.xlib, xnull.project}
<repo>/io/xnull/lib-codec/1.0.0/{lib-codec-1.0.0.xlib, xnull.project}
<repo>/io/xnull/lib-util/1.0.0/{lib-util-1.0.0.xlib, xnull.project}
<repo>/io/xnull/proj02/1.0.0/{reactor-summary.txt, xnull.project}
```

不再安装 app-main（Go 的 pom 根 install 只装库与 summary）；app 可执行仍在构建输出目录。

**已知差异（不计入矩阵）**：`.xlib` 的 zip **字节**不同——Go 用 `archive/zip`（creator/flags 字段不同），
Python `zipfile` 写出的中央目录字节不同；条目名、顺序、`xlib.meta` 文本一致。

### 1.5 `fmt [--check] <file…>`

`impl/xnfmt/xnfmt.x` 原生可构建（`/tmp/xnfmt`），直接包装：

- 直接格式化：调用 xnfmt in-place；
- `--check`：复制到临时文件格式化后 `cmp`，不同则打印 `xnull: 需要格式化 <path>` 并退出 1
  （xnfmt 自身没有 `--check`，这层包装在脚本侧）。

对拍：同一未格式化文件两路格式化结果**逐字节一致**；已格式化文件 `--check` 两路均退出 0。
