## 1. 三个工具

| 工具 | 用法 | 输出 |
|---|---|---|
| `resman` | `resman <out.c> <资源目录> [<文件>…]` | 资源表 C（与 `internal/devtool` 的 `renderResources` 逐字节一致）；stdout 打印 `resource\t<名>` |
| `config` | `config <xnull.project>` | `build.<key>\t<value>`（只取 `build { … }` 顶层标量，如 `build.entryFile`） |
| `artifact` | `artifact <产物> <目标目录> <产物名>` | `cp` 到目标并打印 `artifact\t<目标路径>` |

`build-project` 现在会：入口取 `config` 的 `build.entryFile`（缺省 `src/main/x/main.x`）→
用 `resman` 生成 `<out>/res.c` → 链接时带上 → 链接成功后用 `artifact` 把 app 复制到
`<project>/target/<artifactId>-<version>`。

自举：`tests/b4/xnull-build.sh bootstrap-tools -o /tmp`（约 20s，产出 `/tmp/{resman,config,artifact}`）。

## 4. 与 Go 的差异 / 未支持

| 项 | 本卡 | Go |
|---|---|---|
| 资源收集 | 单层目录，shell glob 展开文件列表 | 递归 + includes/excludes + 符号链接校验 + 冲突诊断（XPD-8xx） |
| 资源读取 API | 语言面**没有** `readResource/listResources` 绑定，app 无法在 XNull 代码里读资源 | 运行时已有 `xrt_resource_*`，Go 侧由 xdk 暴露 |
| 产物落盘 | 只把 app 复制到 `target/<name>-<version>` | 另写 `.xmeta`、library `.xlib`、本地仓库安装 |
| 配置 | 只解析 `build {}` 顶层标量（行扫描），无变量替换/profile/六层覆盖 | `internal/config` 五/六层 + 类型/密钥校验 |
| 二进制资源 | `readFileText` 读入，非 UTF-8 安全 | `os.ReadFile` 任意字节 |

资源"运行时可读"的验证改用：资源表 C 逐字节一致 + `xrt_resource_*` 符号已链接（卡片允许"或输出资源表内容"）。

## 5. 本轮踩到的 codegen/工具链问题（已规避，交 E4/E5）

1. **缺失 `xn_arr_s` 前置声明**：只使用 `String[] args` 或只在函数体内用 `List<String>` 时，
   生成的 C 引用 `xn_arr_s*` 却没有对应 typedef。规避：工具里放一个最小 `class`（触发完整前置）——
   `artifact.x`/`config.x` 顶部保留了 `class ArtifactCtx/ConfigCtx`。
2. **长 `+` 链返回值被截断**：`return "a" + "b" + …`（十余个操作数）生成时丢失尾部；
   `resman` 的表头/空表改为逐行 `s = s + …` 拼接后恢复正常。
3. **native xparser 对个别输入挂起**：`xparser --file impl/lib/b4/resman.x` 曾 >5 分钟不返回
   （去掉误写的类体顶层语句后恢复）。脚本 `ast_dump` 已加 60s 超时 + 首行 `(xnast v1` 校验，
   失败自动回退 `xnast`，避免整条构建挂死。
4. `String[]` 与 `List<String>` 混用、`build.entryFile` 缺省路径等细节按 03b-1 约定处理。
