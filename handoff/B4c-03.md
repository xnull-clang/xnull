# B4c-03 无 Go 验证

- 卡片：B4c-03（删除后的无 Go 验证与残余风险盘点）
- 日期：2026-11-12
- 脚本：`tests/b4/verify-golden.sh`；报告：`evidence/B4c/golden/verify-entries.tsv`
- 结论：**不全绿**。核心构建链（bootstrap、build/run、9 示例）通过；
  冻结 golden 的 142 入口里有 10 条单文件入口无法用原生工具复现，23 条多文件入口无法生成 bundle。
  这些缺口均源于 **Go 前端被删除后的原生能力缺口**（bundle、sema/entry 诊断、部分 codegen 路径），
  不是脚本问题。

## 1. 无 Go 验证结果（`PATH` 不含 go）

```text
bootstrap/build.sh          PASS（79s，仅 cc）
bin/xnull build/run         PASS（自动引导模式）
verify-golden.sh：
  入口 C：PASS=109 FAIL=10 BLOCKED=23
  负例：  PASS=0   FAIL=0  BLOCKED=97
  示例：  PASS=9   FAIL=0
  合计：FAIL=10
```

| 维度 | 通过 | 失败 | 阻塞 | 说明 |
|---|---|---|---|---|
| 入口 C（142） | 109 | 10 | 23 | 多文件需 bundle（原生无生成器）；10 条单文件原生 C 与 golden 不一致 |
| 负例（97） | 0 | 0 | 97 | 原生 xparser 只实现部分 LEX/SYN，sema/entry/codegen 诊断随 Go 删除而缺失 |
| 示例（9） | 9 | 0 | 0 | C 哈希与 golden 一致、运行输出正确 |

## 2. 10 条失败入口（`verify-entries.tsv` 中 FAIL(sha)）

```text
tests/b3/ffi-cases/basic/add.x
tests/b3/ffi-cases/err/wrap.x
tests/b3/ffi-cases/comp/exec.x
tests/b3/fixtures/obj3/extension.x
impl/xnfmt/xnfmt.x
tests/b3/fixtures/tuple/eq_interp.x
tests/b3/fixtures/obj/class_primary.x
tests/b3/fixtures/type/is_as.x
difftest/golden/cases/TYPE-01/src.x
difftest/s2/pctor01/a01_primary.x
```

特征：FFI 夹具（4）与若干 codegen 路径（tuple / class primary / is-as / 扩展方法）；
`impl/xnfmt/xnfmt.x` 还触发了原生 xparser 的大文件挂起（15s 上限）。
这些入口在 B4c-01 里要么依赖 FFI 投影，要么依赖 interp 版 `xnullc` 才能复现 Go C；
原生路径缺这两样能力。

## 3. 23 条多文件入口（BLOCKED）

原 bundle 由 Go 的 `--emit-ast-bundle` 生成（依赖 Go 前端与 import 解析）。删除 Go 后没有等价的原生实现，
因此这 23 条无法生成 C。B4c-01 的 golden 里其中 6 条还是 `via=interp` 生成的。

## 4. 负例（97）为何全部 BLOCKED

`negatives.tsv` 的码段分布：TY 48、ENTRY 18、`-` 12（codegen 失败）、SYN 8、RES 6、LEX 5。
原生 xparser 只覆盖 LEX/SYN 的一部分，且实测对 8 条 SYN 也**不产出诊断**（输出仅表头）。
Go 前端删除后，sema/entry 级诊断没有替代实现，因此统一记 BLOCKED，而不是伪装 PASS。

## 5. 结论与建议

- 删除本身是成功的：仓库 **0 个 Go 文件**，核心构建链（bootstrap → build/run → 9 示例）在无 Go 环境下可用；
- 但“用原生工具逐字节复现 B3-09 全部 golden”**尚未达成**：
  - 需要原生 bundle 生成器（多文件 23 条）；
  - 需要原生 sema/entry 诊断（负例 97 条）；
  - 需要修复原生 codegen 与 FFI 投影（10 条）；
- 因此 **B4c 门不能判 PASS**；B4c-02c/04 应把上述三项列为先决条件；
- `ci/run.sh` 的 golden 步骤当前会因 `verify-golden` 非零退出而 FAIL（这是期望的诚实行为），
  其余步骤（fmt / 运行时 / 示例 / 文件名 / 发布）为 PASS。
