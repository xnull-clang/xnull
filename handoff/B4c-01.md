## 2. 方法

1. **入口清单**：取 `evidence/B3-09/final-v3/results.tsv` 中 `status=PASS0` 的 142 条（B3-09 基线）。
2. **Go C**：`XNULL_FRONTEND=go xnull build --emit-c <rel>`。
3. **XNull C**：`xnast --ast --dump-depth 100000` 产 AST → 原生 `xnullc`（`/tmp/xn-s4`）生成 C；
   FFI 投影按两种候选尝试：
   - **A**：入口目录自带 `.xfb` 则按目录投影，否则空投影（B3-09 口径）；
   - **B**：入口 `import xdk.*` 时，按「入口 + 被 import 模块源码」实际引用到的绑定条目投影。
4. **回退**：原生输出与 Go 不一致时，用 **interp 跑同一个 `xnullc.x`**（B3-09 的路径）重试，记录 `via=interp`。
5. `cmp` 后写入 hashes；负例记录 Go 退出码/诊断码/首行；示例额外比较两路二进制运行 stdout 与退出码。

## 4. 原生 codegen 缺陷（6 条 interp 回退的根因，交 E4/E5）

`impl/lib/b3/xnullc.x` 在原生执行下，把 `return new Cls(a, b, null)` 生成成
`return xn_Cls_X_new(a, b, NULL;`（**丢一个右括号**），C 编译不过；同一个 `xnullc.x` 走 interp 时输出正确。
受影响的入口（都经由 `xdk.text` 的 `textErr`）：

```text
tests/b2/corpus/tests/b0-07c-numeric/cases/t04_bytes_surface/case.x
tests/b0-07c-numeric/cases/t04_bytes_surface/case.x
tests/b3/fixtures/bundle/app.x
tests/b3/fixtures/bundle_text/app.x
difftest/anchors/cases/pkg/f2.x
impl/lib/b2/xlex.x
```

最小复现：任一 import `xdk.text` 的多文件入口，用 `/tmp/xn-s4` 生成 C 后 `cc -fsyntax-only` 即报
`expected ')'`。B4b-02 期间同样的现象曾在 `import xdk.text` 的 xparser.x 上出现过（当时以移除该 import 规避）。
