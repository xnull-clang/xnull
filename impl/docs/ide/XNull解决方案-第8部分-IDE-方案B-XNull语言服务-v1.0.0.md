## 0. 定位

### 0.1 目标

为方案 A 及方案 C 提供语义级编辑能力：

- 诊断；
- 补全；
- hover；
- 跳转定义；
- 引用查找；
- 文档/工作区符号；
- 格式化（接后续 formatter）。

### 0.2 不做

- 不实现 C 代码生成；
- 不实现构建/运行；
- 不替代第 7 部分 CLI；
- 不引入第二套解析器；
- 不把 LSP 响应格式变成语言规范。

### 0.3 前置

| 前置 | 原因 |
| --- | --- |
| B2 前端自举 | lexer/parser/AST 由 XNull 实现 |
| B3 编译器 | 语义/类型/策略信息可由 XNull 复用 |
| XNull stdio/文件能力 | LSP 通过 stdio 读写 |
| JSON 序列化 | LSP 消息编解码 |
| 工程根解析 | 工作区/import 闭包 |

未满足前置前，方案 A 继续使用 CLI JSON 诊断；**不要用 Go/TypeScript 先写临时 LSP**。

## 1. 架构

```text
VS Code / 独立 IDE
  │  LSP over stdio
  ▼
xnull lsp（XNull 实现）
  ├─ 文档管理（didOpen/didChange/didClose）
  ├─ 解析缓存（xfront 前端）
  ├─ 语义分析（sema）
  ├─ 符号索引（包/类型/函数/字段）
  ├─ XDK 索引（第 6 部分）
  └─ 诊断/补全/hover/定义/引用
```

### 1.1 进程模型

- 客户端启动 `xnull lsp`；
- stdio JSON-RPC；
- 单进程单工作区；
- 文档变更增量/全量；
- 构建/运行仍由客户端调用 `xnull build/run`。

### 1.2 不依赖网络

LSP 不需要 socket；只使用 stdin/stdout。

## 3. 文档同步

### 3.1 打开/变更/关闭

- `didOpen`：保存文本 + 版本；
- `didChange`：全量替换优先，后续增量；
- `didClose`：移除缓存与诊断；
- `didSave`：可选触发全量诊断。

### 3.2 解析缓存

- 每文档保留 AST + 诊断；
- 变更后重新解析；
- 依赖文件变更时失效 import 闭包；
- 缓存键包含文件路径 + 版本 + 内容哈希。

### 3.3 工作区

- 从 `xnull.project` 或打开文件向上找工程根；
- 加载 import 闭包；
- 建立包/符号索引；
- 外部文件变更（文件监听）触发重建。

---

## 4. 诊断

- 复用第 7 部分前端/语义诊断；
- 转换为 LSP `Diagnostic`；
- `source = "xnull"`；
- 码映射到 `code`；
- `relatedInformation` 放 hint；
- 不新增语言语义诊断；
- 构建/链接错误不属于 LSP（由 CLI 返回）。

---

## 5. 补全

### 5.1 场景

- 顶层函数/字段；
- 局部变量/参数；
- 类型名；
- 成员访问；
- 容器/String/Result 内建成员；
- XDK 包符号；
- 关键字/snippets。

### 5.2 数据

- 作用域符号表；
- 包符号表；
- 类型成员表；
- XDK 索引；
- 关键字/保留字表。

### 5.3 规则

- 只返回当前上下文可见符号；
- 私有/受保护成员按可见性过滤；
- 不猜测未定案 API；
- 排序稳定：精确匹配 > 前缀 > 模糊；
- 不把补全当类型检查。

---

## 6. Hover / 定义 / 引用

### 6.1 Hover

- 标识符：类型 + 声明位置 + 文档；
- 函数：签名 + 返回类型 + 文档；
- 类型：种类 + 字段/方法摘要；
- XDK：包/API 文档；
- 无信息时返回空，不编造。

### 6.2 定义

- 局部/参数 → 声明；
- 顶层函数/字段 → 声明；
- 类型 → 声明；
- 导入符号 → 被导入文件声明；
- XDK → 索引中的文档位置（无源码则返回索引位置）。

### 6.3 引用

- 工作区符号索引；
- 跨文件；
- 只读结果；
- 排序稳定。

---

## 7. 格式化

- 接后续 formatter；
- 使用 `textDocument/formatting`；
- 不改变语义；
- 失败返回空编辑，不破坏文件；
- 不把格式化结果写回源文件以外的位置。

---

## 8. XDK 索引

- 来源第 6 部分；
- 结构同方案 A 的 `ide/xdk/index.json`；
- LSP 只读；
- 包/API 未定案不进入索引；
- 索引版本与 XDK 版本绑定；
- 补全/hover 使用同一索引。

---

## 9. 错误与降级

| 场景 | 行为 |
| --- | --- |
| 文档解析失败 | 发布诊断；补全/hover 尽力使用旧 AST 或返回空 |
| 工程根缺失 | 单文件模式；不加载跨文件符号 |
| XDK 索引缺失 | 不提供 XDK 补全；不崩溃 |
| 请求超时 | 返回空结果；客户端可重试 |
| 未知方法 | 标准 LSP 错误 |
| 内部错误 | 记录日志；不返回伪造结果 |

---

## 10. 安全与性能

- 不执行用户代码；
- 不访问网络；
- 文件读取限制在工程根/打开文件；
- 大文件限制（可配置）；
- 解析缓存避免全量重解析；
- 补全请求可取消；
- 不在主线程做长时间构建。

## 12. 边界与建议

### 12.1 边界

- 依赖 B2/B3；
- 不提供 C 后端/构建；
- 不提供调试器；
- 不承诺所有 XDK API 都有补全；
- 不承诺跨工作区多根；
- 不承诺语义补全在宏/注解未定案面。

### 12.2 建议

1. 先做诊断 + 补全 + hover + 定义，再做引用/重命名。
2. 复用第 7 部分 AST/符号表，不复制逻辑。
3. 为 LSP 响应建立 golden 用例，避免客户端/服务端漂移。
4. 把 XDK 索引与第 6 部分版本绑定。
5. 方案 B 完成前，方案 A 不引入临时语言服务。
