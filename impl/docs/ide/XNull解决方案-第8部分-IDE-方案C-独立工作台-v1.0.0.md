## 0. 定位

### 0.1 目标

提供自有品牌桌面 IDE：

- 多工程/工作区；
- Monaco 编辑器；
- 终端/日志/问题面板；
- 工程创建/配置；
- 标准库浏览/补全；
- Build/Run/Package Binary；
- 可选调试。

### 0.2 不做

- 不实现编译器/构建；
- 不实现 XNull 原生 GUI（等 `xdk.ui`）；
- 不把方案 A/B 重写一遍；
- 不引入第二套语言服务；
- 不承诺与 VS Code 扩展功能完全一致。

### 0.3 为什么是 TypeScript + 壳

- 编辑器 UI 用 Monaco（TypeScript）；
- 桌面壳负责窗口/文件对话框/进程/打包；
- 语言服务复用方案 B；
- 构建/运行复用第 7 部分 CLI；
- 不把 UI 逻辑塞进 XNull 编译器。

## 1. 架构

```text
┌──────────────────────────────────────────────┐
│ 桌面壳（Tauri/Electron）                      │
│  ├─ 窗口/菜单/文件对话框/进程/更新（非承诺）   │
│  └─ 前端资源打包                               │
├──────────────────────────────────────────────┤
│ 前端（TypeScript + Monaco）                    │
│  ├─ 编辑器/标签/文件树                         │
│  ├─ 工程向导/配置                              │
│  ├─ 标准库/文档                                │
│  ├─ 问题面板/终端/日志                         │
│  └─ LSP 客户端                                 │
├──────────────────────────────────────────────┤
│ 后端进程                                       │
│  ├─ xnull lsp（方案 B，XNull）                 │
│  └─ xnull CLI（第 7 部分）                     │
└──────────────────────────────────────────────┘
```

### 1.1 壳选择

| 壳 | 语言 | 优点 | 代价 |
| --- | --- | --- | --- |
| Tauri | Rust + WebView | 体积小、原生窗口、权限模型 | 引入 Rust 工具链 |
| Electron | TypeScript/Node | 全 TS、生态成熟 | 体积大、内存高 |

推荐 **Tauri**：

- Rust 只做壳，不承载语言/编译逻辑；
- 前端仍是 TypeScript；
- 打包体积更可控；
- 但需接受 Rust 构建链。

如果团队不接受 Rust，选 Electron，但必须控制运行时体积/安全。

### 1.2 目录

```text
ide/desktop/
├── src/                 # TypeScript/Monaco 前端
├── src-tauri/           # Tauri（若选）
├── package.json
├── vite.config.ts
└── README.md
```

## 2. 功能

### 2.1 工作区

- 打开文件夹/工程；
- 最近工程；
- 多根工作区（后续）；
- 文件树、搜索、替换；
- 保存/自动保存；
- 外部文件变更检测。

### 2.2 编辑器

- Monaco；
- XNull 语法高亮（TextMate/ Monarch）；
- snippets；
- 括号/注释/缩进；
- 多标签；
-  minimap/主题/字体设置（可选）；
- 诊断波浪线。

### 2.3 工程

- 新建 app/library；
- 编辑 `xnull.project`；
- profile/目标平台选择；
- 依赖/链接库展示（只读/编辑文本）；
- 校验通过 `xnull check/build`；
- 不实现 XPD 语义。

### 2.4 标准库

- 8 包浏览；
- 文档/签名；
- snippets；
- LSP 补全/hover（方案 B 可用后）。

### 2.5 构建/运行/二进制

- Build：`xnull build --json`；
- Run：终端/输出面板 `xnull run`；
- Package Binary：`xnull build -o target/<name>`；
- 完整 packaging 由第 7 部分模块 06；
- 输出路径、退出码、日志可见；
- 不直接调用 `cc`。

### 2.6 诊断

- LSP 诊断优先；
- 无 LSP 时用 `check --json`；
- 问题面板跳转；
- 错误码说明；
- 构建错误单独日志面板。

### 2.7 终端/日志

- 内嵌终端（壳/前端能力）；
- Build/Run 输出；
- 可复制完整命令；
- 不隐藏 stderr。

### 2.8 调试（可选）

- 仅在第 7 部分调试协议/解释器具备后；
- 启动配置、断点、变量查看为后续；
- 不承诺首版。

## 3. 进程与协议

### 3.1 启动

- 壳启动前端；
- 前端启动 LSP（stdio）；
- 前端通过壳/Node 启动 `xnull` CLI；
- 工作区根传给 LSP/CLI。

### 3.2 权限

- 文件读写限于工作区（用户确认除外）；
- 进程执行只允许 `xnull` 及明确配置的工具；
- 不执行任意 shell 字符串；
- 网络默认关闭（更新/遥测非承诺）。

### 3.3 协议

- LSP：方案 B；
- CLI：`new/check/build/run` JSON；
- 内部 UI 消息可用自定义 JSON-RPC；
- 不把内部 UI 协议公开为稳定 API。

## 4. 打包与分发

| 平台 | 产物 |
| --- | --- |
| macOS | `.dmg`/`.app` |
| Windows | `.msi`/`.exe` |
| Linux | AppImage/deb |

要求：

- 不打包编译器/运行时源码？运行时源码可随工具链；
- 工具链路径可配置；
- 版本号与 IDE/工具链分别管理；
- 代码签名/公证非承诺；
- 自动更新非承诺；
- 安装包体积目标（建议 < 150MB，非承诺）。

## 7. 边界与建议

### 7.1 边界

- 依赖 Tauri/Electron 生态；
- 需要 Rust（Tauri）或 Node（Electron）；
- 不承诺全平台首版；
- 不承诺调试器；
- 不承诺第三方插件；
- 不承诺 XNull 原生 GUI。

### 7.2 建议

1. 先完成方案 A/B，再启动 C；否则会重复实现编辑/语言服务。
2. 优先 Tauri；Rust 只做壳，禁止把编译/构建逻辑写进 Rust。
3. 复用方案 A 的命令/诊断/标准库索引。
4. 复用方案 B 的 LSP；不要另写语言服务。
5. 首个安装包只做一个平台，稳定后再扩。
6. 把“完整命令可见”作为硬要求，方便用户排障。
