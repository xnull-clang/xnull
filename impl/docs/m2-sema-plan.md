# M2 语义分析切片立项（impl/docs，2026-11-06）

> 背景：M1 语法层 4a–4d 已完成、最小可运行闭环已上线。本文件把语义分析
> 拆成三个可独立验收的子切片，并声明首个子切片（名称解析）已交付首批用例。

## 依赖顺序

```
M2-A 名称解析（S1 §3.3/§3.4/§3.5）        ← 先行，已开工
    ↓ 依赖
M2-B 确定赋值（S1 §5.3）                   ← 需要名称解析的作用域模型
    ↓ 依赖
M2-C 类型检查（S1 §2.6/§2.10/第 8 节）     ← 需要名称解析 + 确定赋值
```

三个子切片共用 `internal/sema` 包；诊断统一在 xfront 语法诊断之后、解释器执行
之前返回（CLI `run` 接入点已就位）。

## M2-A 名称解析（首个子切片）

- **范围**：S1 §3.3 四级顺序（局部/参数/类型参数 → 当前包顶层 → 导入符号 →
  完全限定名）、遮蔽合法性（§5.2）、同一作用域重复声明、顶层前向引用（§3.4）、
  §3.5 导入诊断。
- **已交付**：`internal/sema/sema.go`——第 1/2 级解析、遮蔽、RES-101（未定义
  名称）、RES-102（重复声明）；13 条用例（sema_test.go）。第 3/4 级（导入符号、
  完全限定名）在包符号表接入前，对含 import 的文件跳过未定义诊断（避免误报，
  行为已在用例中固化为占位约定）。
- **涉及台账条目**：PKG-01（简单名歧义/别名冲突/导入环/符号存在性——剩余诊断）、
  GEN-01（类型参数进入第 1 级名字空间）、FIELD-01（成员解析依赖 S2 类型声明）。
- **诊断码段位**：RES-1xx（已启用 RES-101/102；后续 RES-103 别名冲突、
  RES-104 简单名歧义、RES-105 导入环、RES-106 符号不存在）。
- **接入点**：`cli.runFile`：ParseUnit → sema.Analyze → interp.Run（已接通）。
- **验收**：PKG-01 翻 PASS（多包/导入诊断完备后）；本切片自身以 sema_test.go
  用例矩阵验收。

## M2-B 确定赋值

- **范围**：S1 §5.3——读取前必须已赋值；控制流图（if/else、while、do-while、
  for、switch、break/continue/return 汇合、`&&`/`||`/`??`/try 的路径合并）；
  `final`/`const` 声明后不得再赋值。
- **涉及台账条目**：CTRL-01 剩余项（"非 `void` 返回路径完整"）、TYPE-01 的
  确定赋值前置部分。
- **诊断码段位**：DA-1xx（DA-101 可能未赋值即读取、DA-102 final/const 重复赋值、
  DA-103 返回路径缺失）。
- **接入点**：sema 第二遍（名称解析之后、类型检查之前），复用 nscope 结构
  扩展为"已赋值集合"数据流。

## M2-C 类型检查

- **范围**：S1 §2.6 可赋值性（同一类型、`null` 与可空提升、字面量适配、容器
  字面量、闭包、`Any` 装箱、`Object` 根；隐式数值转换拒绝）、§2.10 数字字面量
  适配、第 8 节泛型实参与推断、`Result<T,E>` 实例化检查、元组类型身份（§2.11）、
  运算符操作数类型（§7.3）。
- **涉及台账条目**：TYPE-01、TYPE-02（全量）、GEN-01（推断/冲突/未绑定/单态化）、
  TUPLE-01 剩余项（类型身份/推断/相等/插值/越界选择器）。
- **诊断码段位**：TY-1xx（TY-101 类型不符、TY-102 不可赋值、TY-103 非可空收
  null、TY-104 泛型实参不符、TY-105 重载歧义）。
- **接入点**：sema 第三遍；完成后可移除解释器内对应的运行时宽松行为
  （arith 的动态类型分支转为不可达后备）。
