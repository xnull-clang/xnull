# 工具链总体结构与模块约束（内部实现基线）

> 2026-11-15：从第 7 部分工具链标准移出；不属于语言规范。

## 2. 工具链总体结构

### 2.1 结构图

```
02 命令行工具
  ├─ 01 编译前端与 C 代码生成
  │    └─ 05 FFI 绑定合同与包装生成（.xfb → 注册表/包装）
  ├─ 06 工程配置与构建编排
  │    ├─ 01 编译前端与 C 代码生成
  │    ├─ 03 运行时内存与标准原语
  │    ├─ 04 运行时稳定 ABI 与句柄
  │    └─ 系统 cc / libc
  ├─ 08 解释执行与双路径对照
  └─ 09 规范守门与维护工具（xnull dev check/ledger/res）

10 解析对照工具（xnpt）→ 01 前端
07 诊断与错误呈现：横切全部模块
```

### 2.2 依赖方向

| 模块 | 可以依赖 | 不得依赖 |
| --- | --- | --- |
| 01 编译前端与 C 代码生成 | 07 诊断与错误呈现（诊断值） | 02 命令行工具、06 工程配置与构建编排、03 运行时内存与标准原语 |
| 02 命令行工具 | 01、06、08、07、04/05 的公开接口 | 编译器内部、运行时内部 |
| 03 运行时内存与标准原语 | 04 运行时稳定 ABI 的内部映射、libc | 01 编译前端与 C 代码生成、02 命令行工具、06 工程配置与构建编排 |
| 04 运行时稳定 ABI 与句柄 | 03 内部运行时 | 01/02/05/06 |
| 05 FFI 绑定合同与包装生成 | 07 诊断与错误呈现、04 的 ABI 头 | 01 编译前端与 C 代码生成内部、03 运行时内存与标准原语 |
| 06 工程配置与构建编排 | 01、05、03/04（通过构建清单）、07 | 02 命令行工具内部 |
| 07 诊断与错误呈现 | 无（纯值/渲染） | 其他模块内部 |
| 08 解释执行与双路径对照 | 01 的 AST、07 诊断与错误呈现 | 03/04/05/06 |
| 09 规范守门与维护工具 | 第 1—6 部分文档、索引、status.tsv、资源目录 | 编译器/运行时/FFI 实现 |
| 10 解析对照工具 | 01 的 `ParseUnit`/`PrintExpr`、07 诊断 | 语义/代码生成/运行时/构建 |

说明：

- 01 编译前端与 C 代码生成消费 05 的注册表，但不依赖 `.xfb` 解析细节；
- 06 工程配置与构建编排负责把 01、03、04、05 的产物组织成 C 编译命令；
- 02 命令行工具只做分派，不直接拼编译器/运行时内部逻辑；
- 07 诊断与错误呈现是横切模块，只接收结构化诊断值。

### 2.3 一次文件构建的数据流

```
.x 文件
  → 01 编译前端与 C 代码生成：装载 → 前端 → 语义 → C 文本
  → 05 FFI 绑定合同与包装生成：提供注册表/包装片段（如有 .xfb）
  → 06 工程配置与构建编排：组织 C 文件、运行时 C 源、LinkArgs
  → 系统 cc
  → 03 运行时内存与标准原语 + 04 运行时稳定 ABI 与句柄 链接
  → 可执行文件
  → 运行期错误经 07 诊断与错误呈现输出
```

### 2.4 一次调试运行的数据流

```
.x 文件
  → 01 编译前端与 C 代码生成：前端/语义（共享 AST、诊断）
  → 08 解释执行与双路径对照：直接执行 AST
  → stdout + 退出码
```

解释执行路径不经过 03/04/05/06。

### 2.5 维护与对照流

```
xnull dev check/ledger/res
  → 09 规范守门与维护工具
  → 守门报告 / 台账 Markdown / 资源表 C 源

xnpt "<expr>" ...
  → 10 解析对照工具
  → 01 前端 ParseUnit
  → PrintExpr S 表达式
```

维护与对照工具不进入语言用户稳定 CLI 面。

## 3. 跨模块合同

### 3.1 诊断合同

- 所有模块产生结构化诊断值，不直接写 stderr；
- 诊断码段位由第 1—6 部分与第 7 部分模块共同登记；
- 渲染、排序、退出码映射归 07/02；
- 同一输入同一诊断顺序。

### 3.2 确定性合同

- 同一源程序 + 同一工具链版本 + 同一编译选项 → 相同 C 文本/产物/运行结果；
- map 参与输出必须排序；
- 注册表、策略结果、资源表、锁文件、诊断均排序；
- 临时变量编号、诊断顺序、链接参数顺序稳定；
- 回收时机不要求确定，但可观察顺序必须符合第 3 部分。

### 3.3 错误与退出码合同

| 层 | 失败表现 | 退出码 |
| --- | --- | --- |
| 用法/清单 | CLI/工程诊断 | 2 |
| 编译/语义/构建 | 诊断 | 1 |
| 中断 | 工具链信号处理 | 130 |
| 程序 fatal | 运行时终止 | 134 |
| 程序正常返回 | `main` 返回值 | 透传 |

### 3.4 稳定 ABI 合同

- `xrt.h` 是唯一对外稳定 ABI；
- 生成代码、FFI 包装、原生侧只经 `xrt_*` 管理内存；
- `rt.h` 是内部头，不随 SDK 分发；
- 符号/签名变更走主版本；
- 句柄 close 幂等、不依赖 `deinit`；
- 弱表只对 FFI 合同层开放。

### 3.5 无静默降级合同

- 编译器未支持构造 → 显式错误；
- FFI 未覆盖形态 → `Problems`/构建失败；
- 工程配置未知字段/未解析变量 → 构建失败；
- 运行时合同违约 → fatal；
- 不得生成“看起来能跑”的替代实现。

### 3.6 可复现合同

- 构建不访问网络（工程插件禁网）；
- 依赖只认清单与约定目录；
- 锁文件字节稳定；
- 构建只写 `target/`；
- `.xmeta` 记录输入摘要；
- 同输入同产物。

## 6. 模块间禁止事项

| 禁止 | 原因 |
| --- | --- |
| CLI 直接解析 `.x` 或生成 C | 绕过编译器和诊断 |
| 编译器直接调用 `cc` | 构建编排归 06 |
| 编译器直接操作运行时内部头 | 只经 `xrt.h` |
| FFI 合同层依赖编译器内部 AST | 保持单向依赖 |
| 运行时反向依赖 CLI/工程 | 运行时必须可独立链接 |
| 诊断模块反向依赖语言前端 | 诊断只接收值 |
| 解释器模拟 ARC/GC 时序 | 调试路径不承担正式运行时 |
| 工程构建写入 `target/` 之外 | 可复现/隔离 |
| 用环境变量隐式改变构建选项 | 可复现 |
