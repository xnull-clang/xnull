## 0. 定位与边界

### 0.1 定位

`xnpt` 是**开发期解析对照工具**，不是语言用户稳定 CLI。

用途：

- 把命令行给出的表达式串交给 `xfront` 解析器；
- 用 `PrintExpr` 输出 S 表达式；
- 与 `examples/parser-seed.x`（XNull 版 Pratt 表达式解析器）做同输入对照；
- 为自举前端提供表达式 AST 形态的独立参照。

### 0.2 边界

| 属于 xnpt | 不属于 xnpt |
| --- | --- |
| 表达式串 → 合成源码 → `ParseUnit` | 语义分析、类型检查 |
| 遍历 `main` 体内 `dump(expr)` 语句 | 代码生成、C 编译、执行 |
| 输出 `PrintExpr` S 表达式 | 完整编译单元打印/格式化 |
| 解析诊断透传 | 工程配置、FFI、运行时 |

### 0.3 不做

- 不检查表达式是否符合完整类型规则；
- 不执行表达式；
- 不输出源码格式化结果；
- 不替代编译器前端测试；
- 不承诺命令行参数/输出格式长期稳定。

## 1. 输入与输出

### 1.1 输入

```
xnpt "<expr>" ["<expr>" ...]
```

每个参数是一个 XNull 表达式串。

### 1.2 合成源码

工具构造：

```x
static Int main() {
    dump(<expr1>);
    dump(<expr2>);
    return 0;
}
static void dump(Int _) {}
```

目的：

- 复用 `xfront.ParseUnit` 的完整编译单元解析路径；
- 让每个表达式位于独立表达式语句中；
- 避免为表达式单独扩展解析入口。

### 1.3 输出

- 每个表达式一行 `xfront.PrintExpr` 结果；
- 顺序与命令行参数一致；
- 只输出 `main` 体内 `dump(...)` 的实参表达式；
- 不输出其他声明/语句。

### 1.4 退出码

| 情形 | 退出码 |
| --- | --- |
| 全部解析成功 | 0 |
| 任一解析诊断 | 1 |
| 无参数 | 0，无输出 |
| 参数不是合法表达式 | 1，诊断写 stderr |

### 1.5 诊断

- 解析诊断复用 `diag.Diagnostic.String()`；
- 输出到 stderr；
- 出处文件名为 `xnpt.x`；
- 不进行诊断重排/重写；
- 有诊断时不输出部分 S 表达式（先报错退出）。

## 2. 处理流程

```
1. 读取 os.Args[1:]
2. 拼接合成源码
3. xfront.ParseUnit("xnpt.x", src)
4. 有诊断 → 逐条打印 stderr → exit 1
5. 遍历 u.Decls，找 main
6. 遍历 main.Body.Stmts
7. 取 ExprStmt → Call(dump, 1 arg)
8. PrintExpr(arg) → stdout
9. 退出 0
```

说明：

- 只处理 `*xfront.ExprStmt`；
- 只处理 `*xfront.Call` 且 `len(Args)==1`；
- 其他语句/调用跳过；
- 不做类型检查；
- 不执行 `dump`。

## 3. 对照合同

### 3.1 对照对象

| 侧 | 实现 | 输出 |
| --- | --- | --- |
| Go 侧 | `internal/xfront` 解析器 + `PrintExpr` | S 表达式 |
| XNull 侧 | `examples/parser-seed.x` Pratt 解析器 | 同形态 S 表达式 |

### 3.2 对照范围

- 表达式 AST 形态；
- 运算符优先级/结合性；
- 括号透明（不进树）；
- 一元/二元/字面量/标识符节点；
- 不做语义/类型/求值对照。

### 3.3 输出形态

`PrintExpr` 的 S 表达式形态是唯一对照面：

```
(int 1)
(ident x)
(binary + (int 1) (int 2))
(unary - (ident x))
```

具体括号/空格由 `PrintExpr` 决定；XNull 侧必须逐字节一致。

### 3.4 不在对照范围

- 语句/声明解析；
- 类型声明；
- 语义检查/代码生成；
- 运行时行为；
- 诊断文本（只对照成功解析的 S 表达式）。

## 4. 依赖与调用边界

### 4.1 依赖

| 依赖 | 用途 |
| --- | --- |
| `internal/xfront` | `ParseUnit`、`PrintExpr`、AST |
| `internal/diag` | 诊断渲染 |

不依赖 `sema`、`codegen`、`interp`、`runtime`、`ffi`、`xpd`。

### 4.2 与模块 01 的关系

- `xnpt` 只消费模块 01 的前端接口；
- 不修改 AST；
- 不触发语义分析；
- 作为模块 01 表达式解析的独立对照工具。

### 4.3 与模块 07 的关系

- 诊断只透传；
- 不新增诊断码；
- 输出格式由模块 07 统一。

## 5. 确定性与限制

### 5.1 确定性

- 参数顺序决定输出顺序；
- 不依赖 map/文件系统；
- 同一参数序列两次运行输出一致；
- 无随机源。

### 5.2 限制

| 限制 | 说明 |
| --- | --- |
| 仅表达式 | 不能测语句/声明/类型 |
| 合成源码 | 表达式被包在 `dump(...)` 中，不能覆盖所有上下文 |
| 仅 Go 解析器 | 不执行 XNull 侧 parser-seed，仅生成对照输入/输出 |
| 无独立测试 | 当前作为开发对照工具，未建立独立测试套件 |
| 非稳定 CLI | 参数/输出可作为开发工具调整 |

### 5.3 已知风险

- 表达式含换行/注释时，合成源码的行号与原始输入不一致；
- 表达式含依赖外部声明的标识符时仍可解析，但不做存在性检查；
- `PrintExpr` 形态变更会影响对照基线；
- `parser-seed.x` 只覆盖表达式子集，不能代表完整前端。

## 7. 边界与建议

### 7.1 当前边界

- 不是语言用户工具；
- 不进入发布物稳定命令面；
- 只覆盖表达式；
- 不做语义/运行时验证。

### 7.2 建议

1. 为 `xnpt` 增加最小 golden 用例集，至少覆盖优先级、结合性、括号、错误输入。
2. 支持从文件/stdin 批量读取表达式，便于与 `parser-seed.x` 自动化对照。
3. 增加 `--json` 或稳定分隔格式时，明确它是开发工具接口，不承诺用户稳定。
4. 若要扩展为完整 AST 对照工具，应复用 `PrintUnit`/`PrintStmt`，而不是继续拼接 `dump(...)` 合成源码。
5. 将对照用例纳入 CI 或证据流水线，避免只靠人工运行。

- `PrintExpr` S 表达式作为对照面；
- 无独立测试套件。

以上为实现选择，不新增语言语义；表达式语义以第 1 部分为准。
