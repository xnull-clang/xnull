## 0. 核心立场

- 工程配置是**显式合同**：清单里没有的，构建系统不得猜测；清单里写了但无法满足的，构建失败而不是降级。
- 可复现优先：同一清单 + 同一锁文件 + 同一工具链版本 ⇒ 同一产物（确定性构建是目标，不承诺跨工具链版本一致）。
- 配置无隐式状态：不读取用户目录下的全局配置、不读取环境变量里的构建参数（环境仅用于工具链定位，且必须可审计）。

## 1. 定位与范围

### 1.1 范围

本部分规定：工程目录结构与清单格式、入口解析（落实第 1 部分 §11.4 的委托）、依赖声明与锁文件、XDK/语言版本声明（落实第 6 部分定案 4-3）、链接与 FFI 原生库声明、构建选项与产物布局、可复现性合同。

### 1.2 不规定

- 编译器命令行接口（`xnc` 的具体参数名；构建系统可自定，但行为必须等价于本部分语义）；
- 包注册中心的协议与运营（首版非承诺）；
- IDE 工程文件、CI 平台配置（由生态适配）。

### 1.3 与其他部分的分界

| 维度 | 规定者 | 本部分的角色 |
| --- | --- | --- |
| 入口签名与语义 | 第 1 部分 §11.2 | 只规定"入口如何被找到"（§4） |
| 退出码映射 | 第 4 部分 §7.2 | 引用 |
| XDK 版本声明机制 | 第 6 部分定案 4-3（§5） | 给出清单字段与校验语义（§6） |
| FFI 原生库声明 | 第 7 部分 §2.2/§6.1 | 给出清单字段与链接合同（§7） |

## 2. 工程结构

```text
myapp/
├── xnull.json          # 工程清单（唯一必需文件）
├── xnull.lock          # 锁文件（构建后生成，纳入版本控制）
├── src/                # 源码目录（清单 sources 可改）
│   └── main.x          # 默认入口（第 1 部分 §11.4）
└── build/              # 产物目录（构建生成，不纳入版本控制）
```

- 清单文件名固定为 `xnull.json`（严格 JSON，UTF-8，无注释）；
- `build/` 是构建系统独占目录，不得作为源码来源；
- 一个目录只有一个工程；嵌套工程通过依赖声明引用（§5）。

## 3. 清单格式

```json
{
  "schemaVersion": 1,
  "name": "myapp",
  "version": "1.0.0",
  "kind": "app",
  "entryFile": "src/main.x",
  "entryPackage": "app",
  "sources": ["src/**/*.x"],
  "xdk": { "minVersion": "1.0.0", "language": ">=3.3.0 <4.0.0" },
  "dependencies": {
    "util": { "path": "../util" }
  },
  "targets": [
    { "name": "linux-x64", "platform": "linux", "arch": "x64", "linker": "cc" }
  ],
  "build": { "mode": "release", "warnings": "strict" },
  "link": {
    "libraries": [{ "name": "sqlite3", "kind": "dynamic", "system": true }],
    "unsafe": false
  }
}
```

字段规则：

| 字段 | 必需 | 语义 |
| --- | --- | --- |
| `schemaVersion` | 是 | 清单格式版本；当前为 1；未知版本构建失败 |
| `name` / `version` | 是 | 工程名（小写字母/数字/连字符）与语义化版本 |
| `kind` | 是 | `app`（可执行）或 `library`（库） |
| `entryFile` / `entryPackage` | app 必需 | 入口定位（§4）；library 禁止出现 |
| `sources` | 是 | 源码 glob（相对清单目录）；未匹配任何文件是构建失败 |
| `xdk` | 是 | 版本声明（§6） |
| `dependencies` | 否 | 依赖映射（§5） |
| `targets` | 是 | 目标平台列表（至少一项）；构建时选定其一 |
| `build` | 否 | 构建选项（§8），缺省 `{ "mode": "debug", "warnings": "default" }` |
| `link` | 否 | 原生库与 `@unsafe` 开关（§7） |

- **未知字段是构建失败**（不静默忽略）：清单拼写错误必须暴露，对齐"显式"气质；
- 清单不含任何可执行逻辑（脚本钩子、条件表达式一律不支持）。

## 4. 入口解析（落实第 1 部分 §11.4）

解析顺序（前者优先，冲突即错误）：

1. 清单 `entryFile` + `entryPackage` 都给出：入口 = 该文件的 `main`，且必须位于 `entryPackage` 包内；不一致是构建失败；
2. 只给 `entryFile`：入口 = 该文件的 `main`（包不限）；
3. 清单无入口字段：入口文件 = 默认 `main.x`（相对清单目录）；
4. 无清单：入口 = 当前目录 `main.x`（第 1 部分 §11.4）。

错误集合（全部是构建失败，不降级）：入口文件不存在、无匹配签名 `main`、多个匹配签名 `main`、`entryPackage` 不匹配、library 声明入口字段。

## 5. 依赖声明与锁文件

- **首版仅支持 path 依赖**（本地目录，含 `../` 相对路径）；注册中心依赖非承诺（登记待办）；
- 依赖图不允许环（检测到即失败）；
- 每个依赖项解析其 `xnull.json`，并入 `xnull.lock`：依赖名、版本、内容摘要（hash）、目标平台；
- `xnull.lock` 纳入版本控制；清单变化后重新生成；构建时以锁文件为准（锁文件与清单不一致 → 失败并提示重新生成）；
- 依赖的 `kind` 必须是 `library`；app 不能作为依赖。

## 6. XDK 与语言版本声明（落实第 6 部分定案 4-3）

- `xdk.minVersion`：所需 XDK 最低版本；工具链 XDK 低于此值 → 失败；
- `xdk.language`：语言版本范围表达式（比较运算符 + 语义化版本，如 `>=3.3.0 <4.0.0`）；范围外 → 失败；
- 未声明 `xdk` 字段视为清单不完整（构建失败）——不存在"默认跟随最新"的隐式行为；
- 版本校验在编译前、解析依赖后执行。

## 7. 链接与 FFI 原生库声明

- 原生库必须在 `link.libraries` 显式列出：`name`、`kind`（`static` / `dynamic`）、`system`（是否系统库，影响查找路径）；
- 未在清单声明的原生库不得被链接；FFI 绑定引用了未声明库 → 构建失败（对齐第 7 部分 §2.2 合同可审计）；
- `link.unsafe`：是否允许 `@unsafe` 受控入口（第 7 部分 §8）。**缺省 `false`**；启用后构建日志必须记录（可审计）；
- 运行时 ABI 符号（`xrt_*`，第 7 部分 §6.1）由工具链自动链接，不需声明，也不允许改写。

## 8. 构建选项

| 选项 | 取值 | 语义 |
| --- | --- | --- |
| `mode` | `debug` / `release` / `size` | 优化档位；`debug` 保留诊断信息，`release` 默认，`size` 以体积为先（不改变语义） |
| `warnings` | `default` / `strict` | `strict` 把未使用变量/函数等级别的警告提升为错误 |

- 构建选项不改变语言语义（优化档位只影响输出，不影响程序行为承诺）；
- 选项作用于整个工程；`targets` 逐目标可覆盖（覆盖规则：目标级 > 工程级）。

## 9. 可复现性与产物

- 同一清单 + 同一 `xnull.lock` + 同一工具链版本 ⇒ 同一产物（字节等价为目标，验收 PROJ-05 按内容摘要比对）；
- 产物布局：`build/<target>/` 下为可执行文件或库文件，附 `<name>.xmeta`（工程名、版本、目标、XDK 版本、锁文件摘要）；
- 构建过程不得写入清单目录以外的位置（缓存可写入 `build/.cache`）。

## 10. 验收矩阵

| 编号 | 领域 | 验收内容 |
| --- | --- | --- |
| PROJ-01 | 清单 | 未知字段/未知 schemaVersion/缺必需字段均构建失败；library 声明入口失败；app 无入口失败 |
| PROJ-02 | 入口 | 四种解析顺序逐项正确；`entryPackage` 不匹配失败；多入口失败；无清单时 `main.x` 生效（第 1 部分 §11.4 联动） |
| PROJ-03 | 依赖 | path 依赖解析正确；环检测失败；app 作依赖失败；锁文件与清单不一致失败 |
| PROJ-04 | 版本 | `xdk.minVersion` 与 `language` 范围校验正确；缺 `xdk` 字段失败；不存在隐式跟随 |
| PROJ-05 | 可复现 | 两次构建产物内容摘要一致；`build/` 外无写入 |
| PROJ-06 | 链接 | 未声明的原生库被拒绝；`link.unsafe` 缺省关闭；启用后有审计记录 |

## 11. 实现边界

- 增量编译、并行构建策略不承诺；只承诺语义与可复现（PROJ-05）；
- 注册中心依赖（版本解析、镜像、签名）非承诺，首版仅 path 依赖；
- 跨工具链版本的字节等价不承诺（只承诺同版本内）；
- 清单内不支持任何脚本/条件逻辑——需要生成配置时用外部工具，产出静态清单。

## 附录 A：决策留痕

1. **严格 JSON、未知字段失败**：与"显式、可预测"一致；拼写错误立即暴露比静默忽略更便宜。
2. **首版仅 path 依赖**：注册中心是生态问题而非语言问题，先冻结可复现的核心；避免在语言规范里预埋半成品的包管理语义。
3. **`xdk` 字段必需**：落实第 6 部分定案 4-3 的声明机制；拒绝"默认跟随最新"，版本升级必须显式。
4. **`link.unsafe` 缺省关闭 + 审计记录**：`@unsafe` 受控入口（第 7 部分 §8）的工程层闸门；默认安全。
5. **产物附 `.xmeta`**：可复现验收需要可机器比对的元数据（PROJ-05）。
