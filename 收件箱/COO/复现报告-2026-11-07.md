## 3. 失败点分析

首个失败点不是代码编译错误，而是**构建入口文件未入库**：

```bash
cd impl
git check-ignore -v cmd/xnull/main.go
# .gitignore:13:xnull/	cmd/xnull/main.go
```

- `.gitignore:13` 的 `xnull/` 本意是忽略根目录下嵌套的公开仓库 `xnull/`，但该模式不带前导 `/`，会匹配任意层级的 `xnull/` 目录。
- 因此 `impl/cmd/xnull/` 整目录被忽略；其中唯一文件 `main.go`（490 B）从未被跟踪：
  ```bash
  git log --all --oneline -- impl/cmd/xnull
  # 空
  ```
- 干净 clone 中 `impl/cmd/xnull/` 不存在；源仓库因本地文件存在而掩盖了该问题。
- `impl/cmd/xnpt`、`internal/*` 等均已入库，`go build ./...` 可过，故障范围仅限 CLI 入口。

本地被忽略文件指纹（仅备案，未复制进 clone）：

```
sha256 e9455dc78169e18271bded42e65b0fc33c7ef307  impl/cmd/xnull/main.go
```

## 4. 结论

**不可复现。**

在 `ad70f19` 上，按 `impl/README.md` 的文档命令无法从干净 clone 构建出编译器 CLI，原因是 `impl/cmd/xnull/` 被 `.gitignore:13` 的 `xnull/` 规则误伤、从未入库。最小示例步骤因此阻塞，未取得运行结果。
