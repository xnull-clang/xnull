### XDK-03 errors

```x
// tests/s6/xdk03_errors.x
import xdk.errors

class E implements Error {
    ErrorKind k = ErrorKind.Io
    String m = "disk"
    ErrorKind kind() { return self.k }
    String describe() { return self.m }
}

static Int main() {
    E e = new E()
    Result<Int, Error> r = Err(e)
    Result<Int, Error> w = wrap(r, e)
    Result<Int, Int> m = mapErr(r, (Error x) -> 7)
    report(w)
    return 0
}
```

> `report` 当前实现为 `void`（S4 门口径）；若 C-1 裁决为“返回原 `Result`”，本用例改为 `Result<Int, Error> rep = report(w)`，并由 S4/S6 共同回验。

## 7. 判定口径（不替代 QA 签字）

- **可判 PASS 的最低条件**：正例 + 负例 + 诊断位置/码 + 运行时或绑定行为证据 + 证据可复现；跨层锚点必须两层都覆盖。
- **部分**：只有 sema 或只有 runtime/绑定一侧；或端到端路径未跑通。
- **BLOCKED**：依赖卡未合入（S6-04 资源、S6-03 绑定/Process/Async、S6-09 net）。
- **冲突**：规范/已签门结论不一致（当前仅 C-1）。
- 本计划不更新 `status.tsv`；QA 独立执行并签署后，由 SSOT 脚本翻转台账。
