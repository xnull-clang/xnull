## 三、缺口清单（按优先级）

### S2-E5-01 用户 `deinit()` 方法体被静默丢弃（P0，E4）
- 现象：`class R { void deinit() { print("bye") } }` 编译通过，运行只输出 `main`，无 `bye`；生成的 `R_deinit` 只有字段释放。
- 证据：`impl/internal/codegen/codegen.go:421,433`（两处 `if md.IsDeinit { continue }`，方法体/前向声明均跳过）；`impl/internal/codegen/classes.go:151-165`（deinit 只按字段类别释放）。
- 影响：S2 §6.4 规定的终结动作（提前置 null、显式资源协调）全部丢失；属静默违约（BND-14）。
- 最小复现：`/tmp` 临时程序（审计后删除），生成 C 中无 `bye` 字符串。
- 建议验收：`go test ./internal/codegen/ -run TestS2_E5_01 -v`（待建：用户 deinit 体先执行、字段释放后执行、`super.deinit()` 接管）。

### S2-E5-02 内存策略只算不用，类一律 ARC（P0，E4+E5）
- 现象：`sema.ComputeStrategies` 对引用环类返回 `policy=gc`、对纯值类返回 stack-eligible，但 codegen 全部 `rt_arc_new`，无任何 `Strategy` 消费者。
- 证据：`impl/internal/sema/policy.go:147-195`（判定规则 5-9）；`impl/internal/codegen/classes.go:177`（`rt_arc_new`）；`grep ComputeStrategies impl/internal/codegen` 为空。
- 影响：BND-10/MEM-01 的运行半段不成立；全 ARC 引用环永久泄漏（策略判定为 gc 也不回收）。
- 建议验收：环类对象端到端 → 收集后 `rt_gc_live()` 归零；stack 候选不改变引用语义的行为用例。

### S2-E5-03 GC 收集与全局根未接入生成代码（P0，E5+E4）
- 现象：`xrt_safepoint` 仅 `rt_quarantine_flush()`，从不调用 `rt_gc_collect`；codegen 从不调用 `xrt_register_root`/`rt_gc_collect`；`rt_gc_collect` 仅测试调用。
- 证据：`impl/runtime/xrt_abi.c:69-73`；`impl/runtime/rt_gc.c:146`；`grep register_root internal/codegen` 为空。
- 影响：GC 对象（未来 enum/singleton/环类）永不回收；S2 §6.4「GC 对象在清扫时调用 deinit」在生成程序中不可达；BND-07/SINGLE-01 的「GC 全局根」无落地。
- 建议验收：`xnull build` 产物内出现根登记与安全点收集；`rt_gc_live` 在 safepoint 后下降；单例/枚举项在收集后仍存活。

### S2-E5-04 类字段赋值不 retain、不释放旧值（P0，E4）
- 现象：`b.a = a` 生成裸赋值 `b->a = a;`，无 `rt_retain(a)`、无 `rt_release(b->a)`；`h.f = g`（句柄字段）同样。`B_deinit` 却会 `rt_release(o->a)`。
- 证据：`impl/internal/codegen/classes_expr.go:139-166`（仅 `f.isStr` 分支做释放，其余走 `intExpr` 裸赋值）；生成 C 见最小复现。
- 影响：新值不持有（原引用释放后字段悬挂）；旧值泄漏（重复赋值）；句柄字段的句柄对象泄漏且 deinit 诊断为「未显式 close」。
- 最小复现：
  ```x
  class A { Int x = 1 }
  class B { A a }
  static Int main() { A a = new A(); B b = new B(); b.a = a; return 0 }
  ```
  生成：`b->a = a;`（无 retain）；`b->a = a2` 时 `a1` 泄漏。
- 建议验收：字段赋值生成「求值→retain 新值→release 旧值→写入」；重复赋值后旧值 refcount 归零；句柄字段 deinit 前必须显式 close。

### S2-E5-05 类 `deinit` 漏掉句柄/Bytes 字段（P1，E4）
- 现象：`classField` 只标记 `isStr/isArr/isCls`；`xrt_handle *` 与 `xrt_bytes_obj *` 字段既不释放也不扫描，生成的 deinit 为空。
- 证据：`impl/internal/codegen/classes.go:82-83`（分类）；`classes.go:151-163`（释放分支）；`File` 字段复现：`class Holder { File f }` 编译通过，deinit 为空，运行打印 `xrt: 句柄泄漏`。
- 影响：S2 §6.4「释放仍然非空的引用字段」不成立；句柄/Bytes 对象泄漏；若 Bytes 按 S3 §188 转 GC，还会缺扫描。
- 建议验收：`Holder{File,Bytes}` 释放后 refcount/句柄状态归零；`test_abi` 同款断言。

### S2-E5-06 弱槽位在目标内存释放后仍可被解引用（P1，E5）
- 现象：`rt_weak_clear_slots` 只置 `cleared=1`，不清 `target`；`rt_weak_get` 先看 `cleared` 所以安全，但 `rt_weak_destroy` 无条件遍历 `s->target->hdr.weak_head`。目标经 `rt_quarantine_flush` 或 GC `free` 后，销毁槽位即 UAF。
- 证据：`impl/runtime/rt_weak.c:43-58`（destroy 解引用 target）、`rt_weak.c:62-70`（clear 不清 target）、`rt.c:129-138`（free）、`rt_gc.c:140`（free）。
- 影响：FFI 合同层若在目标死亡后清理弱槽位，读/写已释放内存；S3 §16「清除后的槽位必须可复用」也不成立。
- 最小复现（只读）：绑定→release→safepoint→`xrt_weak_clear`；当前依赖隔离区未复用的偶然性，换分配器/GC 即触发。
- 建议验收：目标死亡后 `weak_clear` 幂等且不触达目标内存；槽位池复用计数。

### S2-E5-07 类类型描述符 `payload_size` 含分配头（P2，E4+E5）
- 现象：codegen 传 `sizeof(xn_Cls_X)`（含 `rt_header`），运行时按 `sizeof(rt_header) + payload_size` 分配 → 每对象多分配一个头（64B），且与运行时约定（`test_hard` 用 `sizeof(T)-sizeof(rt_header)`）不一致。
- 证据：`impl/internal/codegen/classes.go:165`；`impl/runtime/rt_gc.c:23`；`impl/runtime/test_hard.c:49`。
- 影响：内存放大；描述符语义分裂，未来 GC/scan 若按 payload 布局解释会错位。
- 建议验收：`sizeof` 断言或描述符构造器统一（`payload_size` 不含头）。

### S2-E5-08 协议字段含 GC 引用：类型面与扫描策略均未定义（P1/P2，E4+E2）
- 现象：`class C { P? p = null }` 通过 sema，codegen 报 `类型 P 未支持`；`P p = null` 在 sema 报 `TY-103`（协议未被当作引用类型接受 null）。协议实现/vtable 在 codegen 显式拒绝（`classes.go:63-68`）。
- 影响：协议字段（尤其将来持有 GC 对象）无扫描实现；vtable 指针是静态地址，必须被 scan 排除；`deinit` 需先释放协议字段的动态对象。
- 要求（实现时）：scan 遍历协议字段时按实际对象指针 visit；vtable/类型描述符指针不入扫描；`deinit` 在用户体之后释放字段。
- 建议验收：协议字段持有 GC 对象 → 收集不悬挂；持有 ARC 对象 → 不泄漏；vtable 指针不被标记。

### S2-E5-09 `deinit` 的发布/调用约束缺静态检查（P2，E2）
- 现象：sema 已校验 deinit 的签名/修饰符/数量（`typedecl.go:315-334`），但未检查「deinit 内不得发布 self」「不得显式调用 deinit（除 super）」；显式 `r.deinit()` 落到 codegen 才报「类 R 没有成员 deinit」。
- 影响：BND-14「禁止构造必须有带位置诊断」不满足；运行时仅能兜住「retain 已终结对象」这一种复活路径。
- 建议验收：负例 `deinit` 内把 self 存入全局/容器/闭包 → 编译错误；`r.deinit()` → TY 诊断而非 codegen 内部错误。

### S2-E5-10 生成代码未调用 `xrt_runtime_init`（P2，E4）
- 现象：S7 §6.3 规定初始化顺序，`xrt_abi.c` 提供幂等 `xrt_runtime_init`，但 `rt_alloc` 未校验、codegen 未发射调用。
- 影响：合同文字与实际不符；嵌入/多入口场景无保障。
- 建议验收：产物 `xn_main` 首行调用 `xrt_runtime_init`；未初始化创建对象的负例。

### S2-E5-11 弱槽位无复用池（P3，E5）
- 现象：清除只置标志，槽位需显式 `rt_weak_destroy` 才 `free`；无复用池/上限。
- 影响：S3 §16「清除后的槽位必须可复用」只做到「可 free 后 malloc 复用」，高频弱引用场景有额外分配。
- 建议验收：批量建立/清除/重建的分配计数稳定。

### S2-E5-12 继承链 deinit 与「字段在 deinit 后释放」的前置未就绪（P1 潜在，E4）
- 现象：codegen 对 `Base`/`Protocols` 显式拒绝（`classes.go:63-68`），S2 §6.4 的「派生→父类链、显式 super 接管、链后释放字段」无法验证；现有单类 deinit 没有「用户体先行」阶段（见 S2-E5-01）。
- 影响：一旦继承落地，若照当前实现直接扩链，顺序会错。
- 建议验收：实现顺序固定为「派生 deinit 体 → 父链 → 剩余字段释放」；`super.deinit()` 接管后不重复调用父类。

## 六、建议顺序（审计后派卡，不属本文件执行）

1. **第 1 波（E4，静默违约优先）**：S2-E5-01（deinit 体）→ S2-E5-04（字段所有权）→ S2-E5-05（handle/Bytes 字段释放）。
2. **第 2 波（E5，生命周期安全）**：S2-E5-06（弱槽死亡后操作）→ S2-E5-11（槽位复用）→ S2-E5-07（描述符布局）。
3. **第 3 波（E4+E5，GC 集成，BND-10/MEM-01/02 主体）**：S2-E5-02（策略消费）→ S2-E5-03（根/收集）→ S2-E5-08（协议字段扫描）→ S2-E5-12（继承链）。
4. **E2 前置**：S2-E5-09（deinit 发布/调用负例）、协议类型可空分类（`P p = null`）。
5. 每项落地后由 QA1 按锚点补独立用例；本审计不承诺 PASS，只登记现状与验收命令。
