## 一、结论摘要

| 维度 | codegen 现状 | 判定 |
|---|---|---|
| 类布局 | `{ rt_header hdr; 字段... }`，单类、无父类子对象、无 vtable 指针、类型描述符 `scan=NULL` | **单类基线可用**；S2 布局不全 |
| 继承 | `collectClass` 遇 `Base` 直接报错 | **FAIL（全缺）** |
| 协议 vtable / 动态派发 | 遇 `Protocols` 直接报错；全部方法调用按静态 C 名 | **FAIL（全缺）** |
| 类方法静态派发 | `self.m()` 可用；非限定 `m()` 未解析 | **部分** |
| 字段 | `self.x` 可用；非限定 `x` / 私有 `_x` 生成非法 C；静态字段当实例字段 | **部分（§5.8 缺口）** |
| 构造器 | 主构造器/普通构造器体被忽略；`new C(args)` 直接拒绝；无参构造器体也不执行 | **FAIL（静默丢语义）** |
| deinit | 用户 `deinit` 体被跳过；仅按声明序释放引用字段 | **FAIL（静默丢语义）** |
| struct | 顶层 `StructDecl` 未发射 | **FAIL（全缺）** |
| enum | 顶层 `EnumDecl` 未发射；`switch` 语句未发射 | **FAIL（全缺）** |
| factory / singleton / extension / annotation | xfront 语法层即 `SYN-110`，无 AST | **FAIL（前置缺失）** |
| 泛型类 | `cType("T")` 未支持，类未单态化 | **FAIL** |
| 内存策略 | 类一律 `rt_arc_new`；sema 策略结果未消费；无 GC/弱引用 | **部分（E4/E5）** |

共 **13 个 E4 缺口**（P0 × 9、P1 × 4）。其中「构造器体 / deinit 体被静默忽略」违反 BND-14（不得静默降级），优先级最高。

## 三、缺口详情（精确文件 / 行为 / 复现）

### S2-E4-01 类布局：无继承子对象、无 vtable 指针（P0，BND-02/03/11）
- 位置：`impl/internal/codegen/classes.go:145-150`（`typedef struct { rt_header hdr; 字段... }`）、`:152-163`（deinit 钩子）、`:165`（`rt_type`）。
- 行为：对象只含分配头 + 本类字段；无 `base` 子对象、无协议 vtable 指针、类型描述符无协议信息，`scan` 恒 `NULL`。
- 期望（S2 §5.7）：载荷起始放 vtable 指针（仅实现协议的类），字段在其后；类型描述符支撑 `is`/`as` 动态检查。
- 复现：`go build -o /tmp/xnull ./cmd/xnull; /tmp/xnull run /tmp/inh.x`（见 §四 用例 A）。

### S2-E4-02 协议实现与动态派发全缺（P0，PROTO-01/BND-03/DISP-01）
- 位置：`classes.go:66-68`（拒绝协议）；`classes_expr.go:92-105`（成员按静态类查找）；`codegen.go:915`（协议类型名落到「类型未支持」）。
- 行为：`class One implements V` 编译期即报「协议实现暂未支持」；即使绕过，协议类型变量也无 C 表示、无 vtable 槽位。
- 期望（§5.6/§5.7）：协议类型接收者按槽位动态派发；类接收者仍静态；槽位按签名确定、跨实现复用。
- 复现：用例 B。

### S2-E4-03 继承全缺（P0，INH-01/BND-02）
- 位置：`classes.go:63-65`；`emitNewClass`（`classes_expr.go:76-88`）无父类构造链；`genMethod` 无 `super` 绑定。
- 行为：`class Derived : Base` 直接编译失败；`super.f()`/`super.x` 无解析路径；无父类字段合并、无 deinit 链。
- 复现：用例 A、F。

### S2-E4-04 非限定字段/成员解析缺（P0，FIELD-01/§5.8）
- 位置：`codegen.go` `scope`（字段未进作用域）；`cRef`（仅参数/局部/顶层字段）；`classes.go` `genMethod` 只登记 `self`。
- 行为：
  - `class C { Int x = 3; Int get() { return x } }` → 生成 `int64_t ... = x;` → cc `use of undeclared identifier 'x'`。
  - `private Int x; ... _x = 7` → cc `use of undeclared identifier '_x'`。
  - `self.x` 正常。
- 期望：方法/构造器/deinit 内非限定名按「局部 → 字段 → 方法 → 静态 → 顶层」解析；私有字段规范名 `_name` 类内裸写可用。
- 复现：用例 D1/D2。

### S2-E4-05 构造器体与主构造器被忽略（P0，PCTOR-01/§6.3）
- 位置：`classes.go:62-101` `collectClass` 不读 `d.Primary`/`d.Ctors`；`emitClassCtor`（`:172-190`）只生成隐式无参构造；`classes_expr.go:85-87` 拒绝带参 `new`。
- 行为：
  - `class C { Int x; C() { x = 7 } }` + `new C()` → 输出 `0`（体未执行），**无诊断**。
  - `C(Int v)` / `class Worker(final Int id)` + `new C(7)` → 「带参构造暂未支持」。
- 期望：字段初值（声明序）→ 主构造器参数绑定 → 构造器体；`final` 恰一次；重载按实参选择。
- 复现：用例 C1/C2/C3。

### S2-E4-06 用户 deinit 体被静默丢弃（P0，§6.4/BND-14）
- 位置：`classes.go:86` `if m.IsDeinit { continue }`；`:152-163` 仅释放引用字段。
- 行为：`class D { void deinit() { print("bye") } }` 运行无 `bye`，**无诊断**；`self.s = null` 不生效。
- 期望：类型 deinit 钩子先执行派生类 `deinit` 体（可把字段置 null），再释放仍非空引用字段；显式 `super.deinit()` 接管父链。
- 复现：用例 E。

### S2-E4-07 静态字段/静态方法缺（P1，§7.1/§7.2）
- 位置：`collectClass` 忽略 `FieldDecl.Mod.Static`/`MethodDecl.Mod.Static`（全按实例成员发射）；`cType` 无类名表达式；`exprType`/`intExpr` 不解析 `S.n`。
- 行为：`class S { static Int n = 3; static Int f(){...} }` + `print(S.n)` → `未登记标识符 S`。
- 期望：静态字段独立存储与启动初始化；静态方法无 `self`；`C.m()` 与类内裸名可解析。
- 复现：用例 G。

### S2-E4-08 结构体未发射（P0，STRUCT-01/BND-04）
- 位置：`codegen.go:314` 顶层 `*xfront.StructDecl` 未支持；`cType` 无 struct 类型。
- 行为：`struct P { Int x; }` 编译即失败；无值布局、复制、方法、构造器。
- 复现：用例 H。

### S2-E4-09 枚举未发射 + switch 未发射（P0，ENUM-01/BND-06）
- 位置：`codegen.go:314` 顶层 `*xfront.EnumDecl` 未支持；`codegen.go:1158` `SwitchStmt` 未支持。
- 行为：任何含 `enum` 的程序编译失败；即便无枚举，`switch` 也失败。
- 期望：简单枚举按 `Int` 内联（值/比较/格式化/`switch`）；数据枚举项为启动期单例对象（GC）、`==`/`===` 按身份。
- 复现：用例 I/J。

### S2-E4-10 abstract 类可被实例化（P0，BND-02）
- 位置：`collectClass`/`emitNewClass` 无 `Mod.Abstract` 检查（E2 sema 亦未拦）。
- 行为：`abstract class A { Int f(){return 1} }` + `new A()` → 正常输出 `1`。
- 复现：用例 K。owner：E2（sema 主）＋ E4（codegen 兜底）。

### S2-E4-11 泛型类未单态化（P0，BND-12）
- 位置：`cType` `NamedType` 默认分支（`codegen.go:915`）；`collectClass` 不处理 `TypePars`。
- 行为：`class Box<T> { T v; }` + `Box<Int>` → `类型 T 未支持`。
- 复现：用例 L。

### S2-E4-12 factory / singleton / extension / annotation 前置缺失（P0，BND-07/08/13）
- 位置：`impl/internal/xfront/unit.go:259-276`；`singleton/factory/extension/@annotation` 声明直接 `SYN-110`。
- 行为：四类声明无法解析，无 AST，codegen 无从生成。
- 复现：`echo 'singleton S { }' > /tmp/s.x; /tmp/xnull run /tmp/s.x` → `SYN-110`。

### S2-E4-13 内存策略未消费（P1，MEM-01/02/BND-10/11）
- 位置：`classes.go:177` 恒 `rt_arc_new`；`classes.go:165` `rt_type.scan = NULL`。
- 行为：sema `ComputeStrategies` 结果不进 codegen；所有类按 ARC；无 GC 根/弱引用。
- owner：E5（运行时/策略）＋ E4（发射选择）。
