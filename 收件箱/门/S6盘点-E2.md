  - 工作树未合并 main，本盘点按 **main 资产**统计；E2 侧 sema 变更以工作树为准（`xdk.go` 与 main 一致）

## 一、结论（先看这段）

1. **C 原语层过半已就位**：runtime、text、sys（文件/目录/存在性/子进程/UTF-8）、Bytes 均有实现与 C 测试；S5-01/02 又补了任务/取消运行时。
2. **语言面是最大缺口**：sema 的 XDK 只有“包名 → 符号名”表，`runtime/sys/text/collections` **没有签名**；`xnull check` 不注入 `.xfb`，任何实参都能通过（`ty.go` 调用回退到空类型）。这是 XDK-06/08/09/10 共同的第一道阻塞。
3. **绑定面只覆盖 runtime + sys 子集**：`bindings/xdk` 仅 `runtime.xfb`（4 项）与 `sys.xfb`（12 项）；`env`、`dumpTasks`、`Process`、资源读取 5 API、`text`/`collections`/`net` 全无绑定。
4. **XDK-10 为零**：资源生成器（`xnull dev res`）与样例 `test_res.c` 已有，但未进构建清单、无 `xdkc_resource_*`、无 5 API、无 sema 签名。
5. **XDK 源码层只有种子**：`impl/lib/xdk/` 仅 `text.x`（3 个纯函数），8 包单元与依赖/稳定性核验（XDK-01/02）未落地。

## 六、边界与不做

- 本卡不写 runtime/codegen/interp；C 原语、`.xfb`、调度器归 E5/E4。
- 不把“符号名存在”当“API 可用”：XDK-04/05/06/09 的验收必须区分 sema 面 / 绑定面 / 运行时面。
- 不新增未定案 API 名；S6 §4.6/§4.7 未冻结的 `Format` 具体方法名、net 符号名，先按设计文档占位，实现卡立项时冻结。
- 资源表接线与构建清单属 E6；E2 只负责语言面签名与诊断。
