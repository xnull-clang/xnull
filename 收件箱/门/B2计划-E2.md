# B2 计划：XNull 重写 lexer + parser，AST 与 Go 版逐字节一致（E2）

> **版本**：v0.1　**日期**：2026-11-08
> **依据**：`ADR/ADR-009-B2定义与net前置.md`、`死命令.md` 第 1 号、S1 §1/§7/附录 A、S2 §2–§13
> **基线**：main `f26e0f9`（S8 门 11/11；S6 net 已补 sema 面，E5/E4 待接）
> **性质**：只盘点与设计；**不写实现**。B2 预算 24h（ADR-009；AGENTS 记 48h 为上限口径，按 ADR 24h 执行）
> **当前门**：S1–S8 全绿；B2 硬前置 = S1–S8 定版 + SHA-256 + XDK-09 net 补齐。

## 0. 结论（先看这段）

1. Go 前端规模约 **4.4k 行**：lexer 732、parser 1244、printer 731、AST/unit/types 1739；**72 个 AST 类型/接口**，覆盖 S1 表达式/语句/类型 + S2 八类类型声明。
2. 已有 **S 表达式打印器** `PrintUnit`/`PrintExpr`/`PrintType`，是现成的“结构字节”口径；但它**不含位置**，也不保证覆盖 AST 全部字段。B2 若直接拿它做逐字节比较，会漏掉位置/字段差异。
3. 已有 XNull 自举素材：`examples/parser-seed.x`（表达式 Pratt 子集，237 行）、`impl/xnfmt/xnfmt.x`（857 行，已能跑词法/格式化），证明当前 XNull 语言面可写词法器/解析器；但**尚无完整 lexer/parser**，也**无 AST 序列化器**。
4. **建议口径**：新增强制 oracle `xnast`（Go）+ XNull 版 `xlex/xparse/xnast`；比较分三层——token 流（含位置）→ AST（含位置、完整字段）→ 诊断（码/位置/顺序）。以 `cmp` 字节相等为 PASS，不以“输出看起来一样”代替。
5. B2 拆 5 张卡（oracle 冻结 → lexer → parser 表达式/语句 → 声明/类型 → 差分与工具链接入），24h 内按串行推进；风险集中在 XNull 语言面、Unicode 列号、自动分号、错误恢复与打印器完备性。

## 1. Go 侧资产盘点（`impl/internal/xfront`）

### 1.1 文件与职责

| 文件 | 行数 | 职责 | B2 关注点 |
|---|---:|---|---|
| `lexer.go` | 732 | 词法、注释/BOM/CRLF、自动分号、数字/字符/五种字符串、插值、LEX-101..106 | token 类别/值/位置必须逐项一致 |
| `parser.go` | 1244 | 表达式优先级/结合性、语句全集、类型引用、泛型、lambda、new、块/声明；SYN-101..112 | AST 结构与错误恢复顺序 |
| `ast.go` | 458 | Expr/Stmt/TypeRef 节点（约 40 类） | 每个字段都要进序列化 |
| `unit.go` | 450 | CompilationUnit/Package/Import/TopFunc/TopField | 顶层顺序/修饰符/注解 |
| `types.go` | 831 | Class/Struct/Protocol/Enum/Singleton/Factory/Extension/Annotation、成员/参数/构造器 | S2 八类声明 |
| `printer.go` | 731 | `PrintExpr`/`PrintUnit`/`PrintType` S 表达式；`--emit ast` 口径 | 当前不含位置；需核对字段覆盖 |
| `token.go` | — | Kind（EOF/Semi/Ident/Keyword/Annotation/字面量/Op/括号/逗号）、Pos(1 基行列)、StrKind 五种 | 位置列按 Unicode 标量 |

### 1.2 现有测试资产

- `lexer_test.go`：整数进制/后缀、浮点、字符、字符串五形态、注释、关键字、最长匹配运算符、自动分号（含 `else`/`while` 例外）、源码规则、多错误位置、保留名。
- `parser_test.go`：优先级表、结合性、不可链式比较/范围、类型运算、后缀、字面量/容器、lambda、插值串、类型引用、错误码、规范示例。
- `unit_test.go`：package/import/top func/top field/完整单元/多诊断。
- `s2_syntax_test.go`、`stmt_test.go`、`import_generics_test.go`、`reserved_test.go`：S2 声明、语句、导入/泛型、保留名。
- 现有 AST 断言全部通过 `PrintUnit` 字符串比较（无位置）；因此“打印器覆盖不到的字段”目前**没有测试保护**。

### 1.3 现有序列化能力与缺口

| 能力 | 现状 | B2 需要 |
|---|---|---|
| 表达式 S 表达式 | `PrintExpr` 完整覆盖 Expr | 保留；补位置模式 |
| 编译单元 S 表达式 | `PrintUnit` 覆盖 package/import/顶层声明 | 补位置、补遗漏字段 |
| 类型/声明打印 | `writeType`/`writeTopDecl`/`writeMembers` | 逐字段核对 |
| token 流打印 | 无 | 新增 `PrintTokens`（kind/text/value/pos） |
| 位置 | AST `Pos` 存在于所有节点，但打印器不输出 | 新增带位置口径；否则无法证明“AST 一致” |
| 诊断 | `diag.Diagnostic{File,Line,Col,Code,Message,Path,Snippet,Width,Hint}` | 单独比较码/位置/顺序；消息模板先冻结 |

**关键判断**：`PrintUnit` 是“结构摘要”，不是“AST 全量”。B2 的逐字节口径必须新增强制 serializer；否则 parser 少写一个字段也能“通过”。

## 3. AST 对齐口径（逐字节比较）

### 3.1 三层比较

| 层 | oracle（Go） | XNull 侧 | 比较内容 |
|---|---|---|---|
| L1 token | `PrintTokens(file)` | `xlex.x` 的 token dump | 每个 token：`kind`、原文/解码值、字符串五形态、插值段、数字 base/suffix、`line:col` |
| L2 AST | `PrintUnitPos(file)` | `xparse.x` 的 AST dump | 每个节点：标签、全部字段、子节点顺序、`line:col` |
| L3 诊断 | `PrintDiags(file)` | 同左 | 码、`line:col`、消息、顺序；错误恢复不得少报/多报 |

AST 通过是 B2 的硬指标；token/诊断是定位差异的辅助层。三层都过才记 PASS。

### 3.2 文本格式（建议冻结为 v1）

```
(xnast v1
  (unit
    (package com.example)
    (import xdk.sys)
    (func @3:1 public static (ret (named Int)) main
      (params)
      (block
        (expr (call (ident print) (args (int 1))))))))
```

规则：

1. UTF-8 + LF，末尾单换行；无时间戳/路径/环境变量。
2. 每个节点带 `@line:col`（1 基、列按 Unicode 标量；与 `Pos` 同口径）。
3. 字段按固定顺序输出；空字段输出显式空标记（如 `(params)`），不得省略。
4. 字面量保留源文本（`IntLitExpr.Text`、`FloatLitExpr.Text`）与规范化值（Base/Suffix/StrKind），避免“数值相等但字节不同”。
5. 字符串按 Go `%q` 规则转义；插值串输出 `(segs ...)(interps ...)`，保持交错关系。
6. 不输出 Go 指针/地址/结构体内存；不依赖 map 迭代。
7. `PrintTokens` 采用一行一 token，便于 `diff`；`PrintUnitPos` 采用缩进 S 表达式。
8. 诊断消息先冻结模板；比较时按 `(文件,行,列,码,消息)` 排序后逐行比较。

### 3.3 比较器

- 新增强制 oracle：`impl/cmd/xnast`（仅测试/CI，非用户命令）：
  - `xnast --tokens file.x` → L1；
  - `xnast --ast file.x` → L2；
  - `xnast --diags file.x` → L3。
- XNull 侧：`impl/selfhost/xlex.x`、`xparse.x`、`xast.x` 以同格式输出；B2-04 接工具链。
- 差分脚本（Go 测试内，不新增独立脚本体系）：
  1. 读取冻结语料清单；
  2. 对每文件分别跑 Go/XNull，`bytes.Equal`；
  3. 失败写 `evidence/B2/<case>/{go,xnull,diff}`；
  4. 两道运行结果一致（DET-01）。
- 语料：`examples/**/*.x`、`tests/**/*.x`、`impl/lib/xdk/*.x`、`impl/xnfmt/xnfmt.x`、`evidence/**/fixtures/*.x`；冻结为 `tests/b2/corpus.tsv`（路径 + SHA-256），新增文件先入清单再比较。

### 3.4 与现有 `PrintUnit` 的关系

- 保留 `PrintUnit` 作为人读摘要/既有测试；新增 `PrintUnitPos` 作为 B2 口径，避免一次性改写大量既有断言。
- 先补“字段覆盖测试”：对每个 AST 节点构造样例，确认 serializer 输出包含其全部字段（可用反射对 Go 结构体字段名做清单，测试保证 serializer 覆盖）。
- 位置口径先与 `Pos` 对齐，不先引入字节偏移；字节偏移如需可后续加 `@off` 字段，属规范修订。

## 5. 风险与缓解

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 现有 `PrintUnit` 不含位置/可能漏字段 | 假 PASS | B2-00 先补全量 serializer + 字段覆盖测试 |
| R2 | XNull 语言面不足（char/rune、String 下标、Map、类递归） | lexer/parser 写不出 | 以 `xnfmt.x` 为能力基线；缺失面先拆小卡补语言/库，不静默绕过 |
| R3 | Unicode 列号/CRLF/BOM/自动分号细节 | token 位置全错 | L1 先对齐；用 lexer_test 全量语料；列按标量 |
| R4 | 错误恢复策略不同 | 诊断层不一致 | L2 通过先于 L3；按“首错位置+码”对齐，再收敛多错顺序 |
| R5 | 281 文件含 evidence 负例，语料噪声大 | 差分不稳定 | 冻结清单 + 分类（valid/invalid）；失败证据逐文件 |
| R6 | XNull 版性能/内存（递归下降+AST） | 超时/爆栈 | 先用解释器跑通；深嵌套语料单独基线；AST 复用容器 |
| R7 | 工具链切换导致现有双路径回归 | 构建/解释失败 | B2-04 前保留 Go 前端开关；全量测试与示例双路径门禁 |
| R8 | AST 位置字段在 XNull 类中表示差异 | 序列化不一致 | 位置在节点构造时写入；`line:col` 统一整数；序列化只看逻辑字段 |

## 6. 验收与证据

- **PASS**：冻结语料 L1/L2/L3 全部逐字节一致；两次运行一致；`xnull check/run/build` 使用 XNull 前端后全量测试绿。
- **证据目录**：`evidence/B2/{oracle,lexer,parser,decls,diff}/`，每项含 command/stdout/stderr/exit/SHA-256；失败项保留 `go.out`/`xnull.out`/`diff`。
- **不签 PASS 的边界**：只完成 parser 子集、只比较 `PrintUnit`、或只比较“示例输出”均不算 B2 完成；AST 字段/位置缺失按 FAIL。
