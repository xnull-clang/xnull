# S2 审计（解释器 E3）

- 依据：`ADR/ADR-004-M2对象编程门.md`、`收件箱/门/S2审计-E2.md`、S2 §2/§4/§5/§6/§8。
- 基线：`main=91c89c0`（只读审计，未改生产代码）。
- 方法：`interp.Run` 直跑（隔离 sema）+ `xnull run --interp`（端到端）双口径；用例文件不入库。
- 目标：M2 的 S2 锚点在解释路径可执行、与静态语义一致；本审计只报解释器缺口与精确用例。

## 一、结论摘要

| 维度 | 解释器现状 | 判定 |
|---|---|---|
| 协议分派（基本） | 协议变量调用按对象实际类方法名动态解析 | **部分 PASS** |
| 继承（字段/方法复用） | 单继承链字段合并、基类方法查找可用 | **PASS** |
| 字段初始化 | 零值、声明序、`self.x`、主构造器绑定正确 | **PASS** |
| 枚举 | 无任何运行时支持 | **FAIL（全缺）** |
| 方法调用 | `self.m()` 可用；重载/静态/`super` 不可用 | **部分 PASS** |
| `is` / `as`（类/协议） | 恒 `false` / `null` | **FAIL** |

共 **8 个缺口**（P0 × 6、P1 × 2），全部有最小复现；解释器域可独立修，不依赖 codegen。

| 锚点 | 场景 | interp 直跑 | CLI `--interp` | 备注 |
|---|---|---|---|---|

## 三、缺口与精确用例（按优先级）

### S2-E3-01 显式构造器未执行（P0，PCTOR-01）
- 根因：`evalNew` 只读 `cls.Primary`，从不执行 `cls.Ctors`；`super(...)` 亦无。
- 用例 A（无参构造器被忽略）：
  ```x
  class E {
      Int v = 1;
      E() { self.v = 5 }
  }
  static Int main() { E e = new E(); print(e.v); return 0 }
  ```
  期望 `5`；实际 `1`（CLI `--interp` 同样）。
- 用例 B（带参构造器）：
  ```x
  class D {
      Int v;
      D(Int x) { self.v = x }
  }
  static Int main() { D d = new D(5); print(d.v); return 0 }
  ```
  期望 `5`；实际 `fatal: 类 D 没有带参构造器（§6.1）`。
- 需覆盖：重载构造器选择、`super(...)` 首位、字段初始化式在 super 后、final 一次赋值。

### S2-E3-02 裸字段名未解析（P0，FIELD-01/§5.8）
- 根因：`eval` 的 `IdentExpr` 只查词法作用域与顶层函数，不回退到 `self` 字段；方法/字段初值作用域只定义了 `self`。
- 用例：
  ```x
  class A {
      Int x = 1;
      Int get() { return x }
  }
  static Int main() { A a = new A(); print(a.get()); return 0 }
  ```
  期望 `1`；实际 `xnull: 未定义的名称：x`。
- 同类：`class C { Int a = 1; Int b = a + 1 }` 期望 `2`，实际未定义 `a`。
- `self.x` 正常，修复只需在标识符解析阶段按 `self` 对象补字段回退（私有 `_name` 规则照 §7.4）。

### S2-E3-03 类/协议的 `is` / `as` 恒失败（P0，PROTO-01/BND-03）
- 根因：`typeMatches` 的 `NamedType` 分支只覆盖内建类型，类/协议名落到 `return false`。
- 用例：
  ```x
  protocol Shape { Int area(); }
  class Sq implements Shape { Int area() { return 1 } }
  class Base { }
  class Sub : Base { }
  static Int main() {
      Sq s = new Sq(); print(s is Shape)
      Sub b = new Sub(); Base a = b
      print(a is Sub)
      Sub? c = a as? Sub
      print(c != null)
      return 0
  }
  ```
  期望 `true / true / true`；实际 `false / false / false`（CLI 当前在 `Base a = b` 前被 sema 以 TY-101 拦下，见 §四）。
- 需覆盖：类继承链向上/向下判定、协议实现链、`as` 失败 fatal / `as?` null、`Object`/`Any` 互转。

### S2-E3-04 `super` 未支持（P0，§5.4/BND-03）
- 根因：`callMethod` 只绑定 `self`，`IdentExpr`/`Member` 无 `super` 绑定。
- 用例：
  ```x
  class A { Int x = 3; Int f() { return 1 } }
  class B : A {
      Int g() { return super.f() + super.x }
  }
  static Int main() { B b = new B(); print(b.g()); return 0 }
  ```
  期望 `4`；实际 `未定义的名称：super`。
- 需覆盖：`super.m()` 从父类起点静态查找（跳过当前类）、`super.field`、多级继承。

### S2-E3-05 枚举运行时全缺（P0，ENUM-01）
- 根因：`Run` 不登记 `EnumDecl`，`Value` 无枚举 kind，`Member` 无 `Enum.Item` 解析。
- 用例 A（简单枚举 + 格式化）：
  ```x
  enum Color { Red, Green, Blue }
  static Int main() { Color c = Color.Green; print(c); return 0 }
  ```
  期望 `Green`；实际 `未定义的名称：Color`。
- 用例 B（switch 穷尽性运行）：
  ```x
  enum Color { Red, Green, Blue }
  static Int main() {
      Color c = Color.Green
      switch c {
          case Color.Red: print("r")
          case Color.Green: print("g")
          case Color.Blue: print("b")
      }
      return 0
  }
  ```
  期望 `g`；实际同上。
- 用例 C（数据枚举）：
  ```x
  enum Status {
      Ready(0, "ready"), Failed(1, "failed");
      final Int code;
      final String label;
      Status(Int code, String label) { self.code = code; self.label = label }
      Int getCode() { return self.code }
  }
  static Int main() { print(Status.Ready.getCode()); return 0 }
  ```
  期望 `0`；实际 `未定义的名称：Status`。
- 需覆盖：简单枚举底层值/比较/顺序/格式化、数据枚举项单例身份/字段/方法、`switch` 按项匹配、项前向引用拒绝（sema）。

### S2-E3-06 方法重载按名取首个（P0，§6.8/DISP-01）
- 根因：`findMethod` 只按 `name` 返回首个；`callMethod` 不校验实参数/类型。
- 用例 A（同参数个数）：
  ```x
  class M {
      Int f(Int x) { return x * 2 }
      Int f(String s) { return 1 }
  }
  static Int main() { M m = new M(); print(m.f(7)); print(m.f("z")); return 0 }
  ```
  期望 `14 / 1`；实际 `14` 后 `运算 * 的操作数类型不符：String * Int`。
- 用例 B（不同参数个数）：
  ```x
  class M {
      Int f(Int a) { return a }
      Int f(Int a, Int b) { return a + b }
  }
  static Int main() { M m = new M(); print(m.f(1, 2)); return 0 }
  ```
  期望 `3`；实际 `1`（多余实参被忽略）。
- 需覆盖：按实参数+类型选候选、唯一/无候选诊断、类静态派发不受协议影响。

### S2-E3-07 协议分派缺少“仅协议方法”约束（P1，PROTO-01/BND-03）
- 现状：协议变量与类变量走同一按名动态解析；类静态派发/协议 vtable 未区分。
- 用例（协议变量调协议未声明方法）：
  ```x
  protocol P { Int f(); }
  class C implements P { Int f() { return 1 } Int g() { return 2 } }
  static Int main() { P p = new C(); print(p.g()); return 0 }
  ```
  sema 应报错；interp 直跑返回 `2`。
- 影响：静态语义未落地时，解释器会静默接受协议外成员；需在 callMethod 按静态接收者类型过滤（协议接收者只允许协议签名）。

### S2-E3-08 静态字段/静态方法未支持（P1，§7.1/§7.2）
- 用例：
  ```x
  class C {
      static Int n = 4;
      static Int f() { return C.n + 1 }
  }
  static Int main() { print(C.n); print(C.f()); return 0 }
  ```
  期望 `4 / 5`；实际 `未定义的名称：C`。
- 需覆盖：静态字段存储、`C.m()` 与类内裸名/`C.` 访问、静态方法无 `self`。

## 四、跨域观察（非 interp，登记给对应线）

1. **sema 阻断类向上转换**：`class B : A` 下 `A a = new B()` 报 `TY-101 类型 B 不能赋给 A`（E2 域）；S2 §5.2 要求隐式向上转换。此条使 S2-E3-03 的用例无法经 CLI 端到端复现，但 interp 直跑仍可验证。
2. **codegen 对象面**：类/协议/枚举的编译路径未在本次审计范围；`S2审计-E2.md` 已把 BND-03/DISP-01/ENUM-01 的编译半段归 E4。
3. **sema 允许枚举声明后进入 interp**：`enum` 会被解析/语义接受，但 interp 运行即失败（S2-E3-05），属“编译过、解释不过”的双路径缺口。
