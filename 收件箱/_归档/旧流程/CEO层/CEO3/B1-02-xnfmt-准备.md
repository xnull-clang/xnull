## 1. B1 要求（原文要点）

- 用 XNull 写一个**非核心但长期留在产品里**的工具；默认 `xnfmt`（格式化器）。
- 对全仓库 `.x` 文件输出与 **Go 版逐字节一致**。
- 该工具进入**正式发布物**，不是演示品。

B1 的完成定义不是“能格式化几个文件”，而是“全仓库逐字节一致 + 进发布物 + 四件套证据”。

## 3. 必须先定的四件事（阻塞 B1-02 开工）

1. **Go 版 oracle 是谁**：B1 要求“与 Go 版逐字节一致”，但当前没有 Go 版格式化器。需要先指定/实现一个 Go 参考实现（或书面定义一份等价于 oracle 的格式规范），否则验收无法机械执行。
2. **注释与空行策略**：现有 AST 丢注释；若走 AST 打印，必须扩展词法/语法保留 trivia（属 `xfront` 域，需 E1 配合），否则全仓库 12 个含注释文件必然不一致。可选策略：
   - A. token/trivia 流格式化：保留注释与空行，改动小（建议先评估）；
   - B. AST 规范化打印：统一删除/重排注释，需先由 PM/CEO1 书面接受“注释会变”的语义；
   - C. Go 侧先保留注释做 oracle，XNull 侧后补。
3. **格式化规则**：缩进宽度、行宽、运算符空格、逗号/分号、空块、字符串/字符字面量原样、CRLF/LF、文件末尾换行。规则必须先写成可执行清单，不能做一步看一步。
4. **落点与产品面**：`cmd/xnfmt` 独立二进制，还是 `xnull fmt` 子命令？B1 要求“进入正式发布物”，需 CEO3-PM/CEO1 定发布口径；`fmt` 当前是非承诺，不能直接沿用旧帮助文本。

## 5. 主要风险

- **注释丢失**是最大风险：12/13 个语料含注释，AST 当前不保留；不先解决，B1 必然逐字节不一致。
- **oracle 缺失**：没有 Go 版就无法定义“逐字节一致”；不能把“看起来整齐”当验收。
- **语法覆盖**：格式化器必须覆盖仓库现有全部 `.x` 构造（类/容器/闭包/多文件/顶层字段），任何未覆盖构造必须显式失败，不得静默原样输出。
- **确定性**：DET-01 从 B1 起生效；格式化输出不得依赖 map 遍历或文件系统顺序。
- **发布口径**：`xnull fmt` 在 S8 是非承诺；B1 要进正式发布物，需先改产品口径或明确独立 `xnfmt` 定位。

## 6. 结论

- B0 已过，B1 具备开工前置；但 `xnfmt` 尚无可执行 oracle、无格式规范、无注释保留能力。
- 建议先发 B1-02a（规范 + golden），再决定 Go oracle 与 XNull 实现路径；不要在规则未冻结时先写代码。
