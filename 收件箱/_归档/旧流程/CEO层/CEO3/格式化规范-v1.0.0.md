## 1. 范围与文件集合

| 项 | 定案 |
|---|---|
| 处理对象 | `git ls-files '*.x'`（main 基线 122 个：`examples/` 12、`impl/` 1、`evidence/` 109） |
| 不处理 | `wt/**`（各 worktree 是独立检出）、`xnull/**`（`/xnull/` 为独立嵌套公开仓，见 `.gitignore`） |
| B1 落盘 | **B1-01/B1-02 只做差分，不改写仓库文件**；`xnfmt` 的日常就地改写从 B1 通过后启用 |
| 输入 | 任意可读文件；不校验扩展名；目录参数拒绝（FMT-104） |
| 输出 | 文本写回或 stdout；不留中间文件 |

**为什么“不改写仓库”**：122 个 `.x` 中 109 个在 `evidence/`，改写会把格式化噪声混进历史证据；B1 门只要求**输出逐字节一致**，不要求仓库被格式化。

## 2. 处理模型（规范性）

```
输入字节
  → P1 解码（UTF-8 严格 / BOM 删除 / 换行归一）
  → P2 词法（第 1 部分 §1；注释、字面量整体成 token）
  → P3 行记录（按 token 起始行分组；跨行 token 独占其覆盖行）
  → P4 头部区（文件头注释 / package / import 块）
  → P5 正文（空行 → 缩进 → 行内空白）
  → 输出（每行 LF 结尾）
```

三条不变量：

1. **token 文本不变**：标识符、关键字、数字/字符/字符串/原始串/插值串、注释正文，逐字节原样输出。
2. **换行位置不变**，除两处：§5 空行增删、§9 头部区重排。空行不触发自动分号插入（第 1 部分 §1.6），import 行重排不改变每行的行终止形态，因此**语义不变**。
3. **无外部依赖**：不读环境变量、时钟、locale；任何集合遍历必须排序（`死命令.md` §1.5.1 DET-01）。

## 3. 编码与文件级规则

| 编号 | 规则 |
|---|---|
| R3.1 | 输入必须是合法 UTF-8；非法字节 → `FMT-102`，不写文件。 |
| R3.2 | 开头 BOM 删除；输出永不写 BOM。 |
| R3.3 | `\r\n` 与孤立 `\r` 归一为 `\n`；输出只用 LF。 |
| R3.4 | 每行行尾空白（空格/制表符）全部删除。 |
| R3.5 | 文件末尾恰好一个 `\n`；无空行结尾。 |
| R3.6 | 空文件或只含空白 → 输出 0 字节。 |

## 4. 缩进（R4）

- 每层 **4 个空格**；输出不得出现制表符（字面量与注释正文内部除外）。
- 记号：`b` = 行首时未闭合 `{` 数；`p` = 行首时未闭合 `(` 与 `[` 数。

| 编号 | 情形 | 缩进层数 |
|---|---|---|
| R4.1 | 普通行 | `b` |
| R4.2 | 行首 token 为 `}` | `b − 1` |
| R4.3 | 处于 `switch` 体、该 `case` 子句已开启、且修正后的 `b > switchBase`、且行首不是 `case`/`default`/`}` | `b + 1` |
| R4.4 | `p > 0`（括号续行） | `b′ + p − (行首为 `)`/`]` ? 1 : 0)`；`b′` 按 R4.1/R4.2 计算；**R4.3 不叠加** |
| R4.5 | 标签行 `name:` | 同 R4.1（不增不减） |

- `switchBase` = 该 `switch` 的 `{` 打开前的 `b`。`case`/`default` 行令 `caseOpen = true`；该 `switch` 的 `}` 出栈并复位。
- `{` 必须与其头部同行（第 1 部分 §1.6）；若输入违反，按词法/语法错误处理（本规范不改写为合法）。
- 示例见 §13 样例 D、E。

## 5. 空行（R5）

| 编号 | 规则 |
|---|---|
| R5.1 | 文件开头空行全部删除。 |
| R5.2 | 连续空行折叠为 1 行。 |
| R5.3 | 上一行以 `{` 结尾时，其后的空行删除。 |
| R5.4 | 下一行以 `}` 开头时，其前的空行删除。 |
| R5.5 | 文件末尾空行删除（只留 R3.5 的结尾 LF）。 |
| R5.6 | 空行输出为空字符串（不含空格/制表符）。 |
| R5.7 | 跨行字面量/跨行注释内部的空行是内容，不适用 R5.1–R5.6。 |

## 6. 行内空白（R6）

**默认**：任意两个相邻 token 之间 1 个空格。以下为例外，穷举。

| 编号 | 例外 | 结果 |
|---|---|---|
| R6.1 | `(` `[` 之后 | 0 空格 |
| R6.2 | `)` `]` 之前 | 0 空格 |
| R6.3 | `,` `;` 之前 | 0 空格 |
| R6.4 | `.` `?.` 两侧 | 0 空格 |
| R6.5 | `(` 紧跟标识符 / `)` / `]` / 泛型闭合 `>`（调用、分组） | 0 空格 |
| R6.6 | `[` 紧跟标识符 / `)` / `]` / `>`（下标、数组、类型后缀、`new T[n]`） | 0 空格 |
| R6.7 | `@` 与其后注解名 | 0 空格 |
| R6.8 | 一元前缀运算符与其操作数、后缀 `++`/`--` 与其操作数 | 0 空格 |
| R6.9 | `{` 与 `}` 相邻（空体 `{}`） | 0 空格 |
| R6.10 | `{` 之前 | 1 空格 |
| R6.11 | `{` 之后同一行有内容 | 1 空格 |
| R6.12 | `}` 之前同一行有内容且非 `{}` | 1 空格 |
| R6.13 | `,` `;` 之后（同行有内容） | 1 空格 |
| R6.14 | `:` 之后（行尾除外，见 R8.5） | 1 空格 |
| R6.15 | 控制关键字后的 `(`（`if (`、`while (`、`for (`、`switch (`） | 1 空格 |
| R6.16 | 行尾注释与前一 token 之间 | 1 空格 |
| R6.17 | 其余全部 | 1 空格 |
| R6.18 | 区间运算符 `..<`、`...` 两侧 | 0 空格（`0..<n`，与第 1 部分 §6.7 写法一致） |
| R6.19 | 空 Map 字面量 `[:]` | `[`、`:`、`]` 三者之间均 0 空格 |

- `;` 在行尾时只应用 R6.3（前面 0 空格），后面无 token。
- `}` 在行首时应用缩进，不应用 R6.12。

## 7. 一元/二元判定（R7）

用于 `+ - ++ -- ! ~`：

| 编号 | 规则 |
|---|---|
| R7.1 | `!` `~` 恒为一元前缀。 |
| R7.2 | 前一 token 属于「表达式结束」→ `++`/`--` 为后缀，`+`/`-` 为二元。 |
| R7.3 | 否则 → `++`/`--`/`+`/`-` 为一元前缀。 |
| R7.4 | 「表达式结束」= 标识符、数字/字符/字符串字面量、`)`、`]`、`}`、后缀 `++`/`--`。 |

- 一元前缀：操作数前 0 空格（R6.8）；前缀符之前按默认/R6 与前文处理（例：`return -1`）。
- 二元：两侧 1 空格（R6.17）。

## 8. 歧义 token：`?` / `<` / `>`（R8）

这三类 token 在 XNull 中同时承担两种语法角色，词法形状相同；本规范用**同一套可判定的前向扫描**定角色，不做“按输入空格保留”。

### 8.1 `?`：可空后缀 vs 三元

| 编号 | 规则 |
|---|---|
| R8.1 | 从 `?` 起在同一语句内前向扫描（记录 `()`/`[]`/`{}` 嵌套；只认与 `?` 同层的 `:`；遇到 `;`、`{`、`}` 或 EOF 停止）：若找到同层 `:` → **三元**。 |
| R8.2 | 未找到 `:` 且前一 token 是类型原子（标识符、`]`、`>`、`>>`）→ **可空后缀**；其余情况按语法错误输入处理（R6 默认间距原样输出，不报错——诊断归编译器）。 |
| R8.3 | 三元 `?` 与其配对 `:` 均两侧 1 空格。 |
| R8.4 | 可空 `?` 两侧 0 空格（`String?`、`List<Int>?`、`Map<String, Int>?`）。 |
| R8.5 | 非配对 `:`：行尾 → 前 0 空格、后无 token；否则前 0、后 1 空格（`case 1:`、`name:`、`["k": 1]`）。多个 `?` 时，`:` 与其**最近的前一个同层未配对 `?`** 配对（嵌套三元右结合）。 |
| R8.6 | `?.`、`as?` 是单 token（第 1 部分 §1.5），不适用本条。 |

### 8.2 `<` / `>`：泛型 vs 比较

| 编号 | 规则 |
|---|---|
| R8.7 | `<` 是**泛型开括号**，当且仅当：① 前一 token 是标识符/`]`/`>`；② 从它起按 §8.3 扫描到同层闭合 `>`/`>>`；③ 中间 token 全部属于允许集。 |
| R8.8 | 泛型开/闭括号两侧 0 空格（`Result<Int, String>`、`identity<Int>(1)`）；泛型内部按 R6（`,` 后 1 空格）。 |
| R8.9 | 非泛型的 `<` `>` 为比较运算符，两侧 1 空格。 |
| R8.10 | `>>` 在角度嵌套 ≥ 2 时按两个闭合符处理，两侧 0 空格（`Map<String, List<Int>>`）；否则按移位运算符，两侧 1 空格。 |
| R8.11 | 允许集 = 标识符、`,`、`.`、`[`、`]`、`?`、`<`、`>`、`>>`、`(`、`)`、`->`。出现其他 token（`&&`、`||`、`+`、`=`、字面量等）即判定为比较，不是泛型。 |

**判定可靠性来源**：第 1 部分 §7.2 规定比较运算不可链式，因此合法的 `a<b` 不会在语句内出现配对 `>`；反之配对的 `<…>` 只可能是泛型实参表。

### 8.3 扫描伪代码（两实现必须逐字对齐）

```text
isGenericOpen(i):
  if tokens[i] != "<": return false
  if prev(i) not in {ident, "]", ">"}: return false
  depth = 0
  for j = i .. end-of-statement:
    t = tokens[j]
    if t == "<": depth += 1
    else if t == ">": depth -= 1
    else if t == ">>": depth -= 2
    else if t not in ALLOWED: return false
    if depth <= 0: return true
  return false
```

- `end-of-statement` = `;`、`{`、`}`、EOF（这三者不在允许集内，会先行返回 false）。
- 判定结果按 token 下标缓存，避免二义。

## 9. 头部区与 import 排序（R9）

**头部区** = 文件开头的连续注释行（文件头注释块）→ 可选 `package` 行 → import 块。

| 编号 | 规则 |
|---|---|
| R9.1 | 输出顺序固定：文件头注释块 → `package` → import 块 → 正文；相邻两个**非空**区段之间恰好 1 空行；空区段不产生空行（无文件头注释时文件不以空行开头，无 `package`/无 import 时不多插空行）。 |
| R9.2 | import 块 = `package` 之后、首个非 `import`/非独立注释/非空行之前的所有行；块内空行全部删除。 |
| R9.3 | 块内以独立注释行为界分段；每段内按 key **稳定升序**排序；独立注释行的相对位置不变。 |
| R9.4 | key = 导入路径的 UTF-8 字节序（`memcmp` 语义；不做 locale、大小写折叠）；路径相同者「无别名」在前，再按别名字节序。 |
| R9.5 | 行首 `import` 与路径之间 1 空格；`as` 两侧 1 空格（R6.17）。 |
| R9.6 | 行尾注释随所在 import 行一起移动。 |
| R9.7 | 文件头注释块之前不得有空行；块内注释行逐字节保留。 |
| R9.8 | 无 `package` 时，头部注释块之后直接是 import 块（仍 1 空行分隔）。 |
| R9.9 | 正文中出现的 `import` 行不做排序（只做行内空白归一）。 |

**排序合法性**：第 1 部分 §3.2/§3.3 的导入解析与声明顺序无关；排序不改变导入集合、别名集合与冲突关系。

## 10. 注释（R10）

| 编号 | 规则 |
|---|---|
| R10.1 | `//` 注释正文逐字节保留（含 `//` 后的空格数）；仅删行尾空白（R3.4）。 |
| R10.2 | 独立注释行按 R4 缩进；位于括号续行内时按 R4.4。 |
| R10.3 | 行尾注释与前一 token 之间恰好 1 空格（R6.16）。 |
| R10.4 | `/* */` 与 `/** */`：起始行缩进按 R4；**整体逐字节原样**（含内部换行与内部行首空白），不做重排。 |
| R10.5 | 注释不参与 `{`/`(`/`[` 深度计数。 |
| R10.6 | 字符串/字符/原始串/插值串内部的 `//`、`/*` 不是注释（由词法保证，不二次判断）。 |

## 11. 长行（R11）

| 编号 | 规则 |
|---|---|
| R11.1 | **不折行、不合并行**；行长无上限。 |
| R11.2 | 输出行数变化只来自 §5 空行增删与 §9 头部区重排。 |
| R11.3 | 禁止按显示宽度做任何决定（避免 Unicode 宽度/制表符歧义）。 |

**理由**：第 1 部分 §1.6 的自动分号插入使换行具有语义；折行需要“在哪断不改变 ASI”的语法级保证，属 B2 解析器之后的能力（见 §15 v2 候补）。

## 13. CLI 与诊断（R13）

| 编号 | 项 | 定案 |
|---|---|---|
| R13.1 | 必需形态 | `xnfmt <file>...` → 就地写回；先全部读入并格式化，任一失败则不写任何文件（批处理原子性） |
| R13.2 | 写入方式 | 同目录临时文件 + `rename`；保留权限位；内容未变则不重写 |
| R13.3 | 建议形态（不属 B1 门禁） | `xnfmt --check <file>...`：不写；全规范 → 0，有差异 → 1，错误 → 2 |
| R13.4 | 退出码 | `0` 成功；`1` 仅 `--check` 有差异；`2` 用法/编码/词法/IO 错误 |
| R13.5 | 诊断格式 | `file:line:col: error[FMT-10x]: message`（沿用第 8 部分 附录 C.4 渲染形态） |
| R13.6 | 诊断码 | `FMT-101` 词法错误；`FMT-102` 编码错误；`FMT-103` 读写/rename 失败；`FMT-104` 参数错误（目录、空参数） |
| R13.7 | 禁止 | 静默跳过失败文件；部分写入；输出诊断到 stdout |

## 14. 明确不做（v1 非承诺，R14）

1. 不增删 `;`、不合并/拆分语句、不改任何 token 文本（数字进制与后缀、转义写法、字符串内容均原样）。
2. 不重排 import 之外的声明，不做“声明间固定 1 空行”的结构化排版。
3. 不折行、不对齐行尾注释、不做 import 分组（标准库/第三方/本地）。
4. 不处理 `xnull.project` / `.xmeta` / `.xplugin` / `xnull.lock`（那是 `xnull fmt` 的对象，另立规范）。
5. 不支持目录递归、stdin、并行；v1 只接受显式文件列表。
6. 多行字面量内部的缩进不重排（内容原样）。

**v2 候补（B2 前端之后）**：基于 AST 的结构化排版（声明间空行、参数列表折行、注释对齐）、`xnull fmt` 与 `xnfmt` 合并。

## 16. 样例（before → after）

> 约定：`→` 前为输入原文，`→` 后为规范输出；行尾不可见空白在样例说明中单独标注。

### 样例 A：真实文件已是固定点（`examples/hello.x`）

before == after：

```x
// hello.x —— 最小程序
// 预期输出：
//   hello, XNull
//   1 + 2 = 3

static Int main() {
    print("hello, XNull")
    print("1 + 2 = " + str(1 + 2))
    return 0
}
```

命中规则：R3.5、R9.1、R4.1、R6.5、R6.17、R10.1。**固定点样例**：`F(x)=x` 必须成立。
