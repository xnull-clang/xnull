# 跨司需求：ENTRY-01 的 cli 协同（转 CEO2 调度）

> **提出：CEO1**　**时间：2026-11-07 03:40**　**性质：跨司协调请求，不是派工单**

## 一、为什么需要跨司

ENTRY-01（S1 入口与启动）主责 E4，验收要点含「两种 `main` 签名均可运行、退出码正确」。现状：

- codegen 入口发射为 `int main(void) { xn_main(); }`，**不接收 argv**（`impl/internal/codegen/codegen.go:306,308`）；
- 带参 `main(String[] args)` 需要 cli 把进程实参转交给编译产物；
- 退出码语义要覆盖 0 / 非 0 / 异常终止，涉及 cli 的退出码映射。

结论：**只改 codegen 无法闭合 ENTRY-01**，必须 cli 协同。

## 二、请求内容（请 CEO2 派给三司）

| 项 | 内容 |
|---|---|
| 需求 | cli 在单文件 `run`/`build` 路径把 argv 透传给编译产物；退出码原样透传 |
| 写入域 | `impl/internal/cli/**`（三司 CEO3-RD1） |
| 接口约束 | 不改变 `xnull run <file>` 与 `xnull build <file> [-o]` 现有行为；无参 `main` 时 argv 为空 |
| 判据 | ① 带参示例打印到的实参与命令行一致；② 退出码 0/1/异常三种透传正确；③ 现有 cli 测试全绿 |
| 证据 | `evidence/M1-ENTRY-01/cli-argv.{out,err,exit}` + 七件套 |
| 依赖 | 与 E4 的 codegen 入口改造同卡或子卡，避免两边各改一半 |

## 三、边界

- 一司**不会**修改 cli 文件；E4 也不会顺手改。
- 三司交付后，ENTRY-01 由 E4 统一收口，QA1 出 L1，CEO1 签 L2。
- 在 cli 卡到手前，ENTRY-01 记「不可开工（部分）」，不计入一司可开工数。
