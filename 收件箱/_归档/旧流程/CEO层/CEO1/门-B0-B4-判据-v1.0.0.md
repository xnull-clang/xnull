## 〇、总则（先于任何单项）

1. **证据唯一**：无证据 = 未完成；口头结论、聊天截图、自述进度一律不算。
2. **门序锁**：上一门未通过，下一门不得开工；抢跑即打回，并从上一门重验。
3. **四件套**（死命令 §1.6，缺一不算）：① 代码 + 从干净 clone 可复现的构建命令；② 对照证据（逐字节比对或差分报告）；③ 产物 SHA-256；④ 日志块 + 回执（`收件箱/回执箱/<司>/回执-<卡>.md`）。
4. **测试不可动**：修改测试期望以过门 = 直接判负；删测试同罪。
5. **不降级解释**：不得把“下一版”解释成“下一个 commit”，不得把“借力”解释成“永久用 Go”。

## 七、打回清单（命中即不通过）

1. 四件套缺项，或 `acceptance.md` 无逐条打勾；
2. 对照证据只给“通过/一致”的结论，无原始输出与 sha；
3. 跳门、抢跑，或用 Go 补功能后宣称已达门；
4. 修改测试期望、删测试、跳过用例；
5. B2 前置（语义冻结/条款 ID）未闭环就开工；
6. 用“部分完成/基本一致/接近逐字节”申请放行；
7. B4 保留任何进入构建的 Go 代码或 Go 二进制；
8. 预置 Go 二进制当构建依赖；
9. 以“暂时保留双实现”为由拖延 B4；
10. 对外使用“已自举/自举中”口径而无已过门证据。
