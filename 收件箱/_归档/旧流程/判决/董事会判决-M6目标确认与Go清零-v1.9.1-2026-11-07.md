# 董事会判决：M6 目标确认——用 XNull 实现下一版工具链，B4 后 Go 清零 v1.9.1

> **判决版本：v1.9.1**　**判决日期：2026-11-07 04:45**　**性质：对 v1.9.0 的目标澄清，不改变 B0–B4 门序**
> **最高依据：`死命令.md` 第 1 号；本件与死命令冲突时以死命令为准。**
> **触发：用户确认「新里程碑不是用 Go 把第一版做出来，而是用 XNull 实现下一版编译器，目的是完全摆脱 Go」。**
> **本件冻结，不得修改；修订另发 v1.9.2。**

---

## 第 0 条　先确认，避免再理解错

**用户确认的目标：**

> 不是“Go 版能跑就算完成”；
> 是“**用 XNull 写出下一版编译器/工具链，最后把 Go 全部删掉**”。

**Go 的地位：只做脚手架（bootstrap），不做终点。**

| 阶段 | Go 的角色 | 是否里程碑 |
|---|---|---|
| 现在 | 编译器/CLI/工具链都是 Go | **不是**，是借力 |
| B0–B1 | Go 版编译 XNull 写的程序/工具 | **不是**，是准备 |
| B2 | XNull 前端替换 Go 前端 | 门，但不是终点 |
| B3 | XNull 写完整 `xnullc` | 门，但不是终点 |
| **B4** | **删除 Go，XNull 自编译不动点** | **是终点** |

---

## 第 1 条　“完全摆脱 Go”的精确范围

| 组件 | 现在 | B4 后 | 说明 |
|---|---|---|---|
| 编译器前端（lexer/parser/AST） | Go | **XNull** | B2 |
| 代码生成器（AST → C） | Go | **XNull** | B3 |
| CLI `xnull` | Go | **XNull** | 新增 B4 范围 |
| `xnull dev check/ledger/res` | Go | **XNull** | 新增 B4 范围 |
| `xnfmt` | Go | **XNull** | B1 |
| C 运行时 | C | **C** | 长期保留 |
| 系统 `cc` / 平台 ABI | 外部 | **外部** | 长期保留 |
| Shell 构建脚本 | sh | sh | 不是 Go，可保留 |

**判定口径**：B4 通过时，产品工具链的 Go 源码与 Go 二进制为 **0**；构建只需“上一版 XNull 编译器 + 系统 cc + C 运行时”。

**明确不在范围**：C 运行时、系统 cc、平台 ABI 不重写；自举不是性能优化。

---

## 第 2 条　B4 的硬判据（在死命令基础上加严）

1. `git ls-files '*.go'` 在产品工具链范围内 = **0**（`impl/**`、`cmd/**`；文档/历史证据除外，需列白名单）。
2. 构建链：`上一版 xnull 二进制 → 源码 → 新 xnull 二进制`，全程不调用 `go`。
3. `xn-s2` 与 `xn-s3` 逐字节一致。
4. 删除 Go 后，全量测试、9 示例双路径、`dev check/ledger/res` 全部通过。
5. 干净 clone + 预置上一版 XNull 二进制，能在无 Go 环境完成构建。

**缺任一项 = B4 不通过，不得宣布“摆脱 Go”。**

## 第 4 条　禁止曲解（新增）

1. 把“Go 版能编译 XNull 程序”当自举完成；
