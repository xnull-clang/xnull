## 第 2 条　阶段规划：按能力闭包排序，不按日历切

- **不砍范围**。S1–S8 + 自举全部保留。
- **按依赖排序**，前一阶段的退出条件不满足，后一阶段不得开工。
- **每阶段以「条款闭包」退出**，不以「示例能跑」退出。
- **阶段内允许部分完成；门级不允许**。

### 2.4 阶段内的三条铁律

1. **不得跨阶段抢跑**。阶段 1 没闭包，不开工阶段 3。抢跑产生的是假绿，不是进度。

## 第 3 条　门禁重定义：只有「通过 / 不通过」，取消「条件通过」

### 3.1 判决

v1.0.0 允许门级「条件通过」，这是错的，直接导致「演示通过」被当成「能力完成」。**即刻废除门级「条件通过」。**

- 「条件通过」只允许用于**阶段内的中间检查点**，不得用于阶段门。
- 阶段门只有两种结论：**通过 / 不通过**。
- 不通过就是回到阶段内继续做，不存在「带条件放行」。

### 3.2 「能力完成」八条硬条件（全部满足才算通过）

| 编号 | 条件 | 判定方式 |
|---|---|---|
| E1 | 范围内锚点 **100% PASS**，零「部分」结转 | 台账机械统计 |
| E2 | 范围内规范条款 **100% 可追溯**：每条至少一个测试引用其条款 ID | `spec-clauses.tsv` × 测试名 × CI 校验 |
| E3 | 范围内诊断码 **100% 有触发测试**，且优先级/恢复策略有断言 | `diagnostics.tsv` × 测试 |
| E4 | 范围内双路径 **100% 逐字节一致**，且重复构建确定性一致 | 差分测试 + 两次构建 hash |
| E5 | 范围内否决项 **100% 有拒绝测试**，报指定诊断码 | 负向用例 |
| E6 | 已知 P0/P1 **清零**；非承诺项显式登记，不冒充完成 | 缺陷清单 + 台账 |
| E7 | 实现者**不自验**；验收人签字 + commit sha + CI artifact | 收件箱回执 |
| E8 | 规范 changelog、台账 evidence、公开 README 能力表三方同步 | diff 为空 |

### 3.3 门禁输入与输出

- **输入只认三样**：commit sha、CI run ID、可下载产物。回执文字不是证据。
- **输出必须含**：实测项清单、未测项声明、E1–E8 逐条判定、验收人签名。
- **没有 sha 的「全绿」一律不作为门证据。**

### 3.4 判决

门不是「做了没有」的确认书，是「做对没有」的判决书。**「做了」只是入场券，「做对」才是门。**

## 第 4 条　为什么「做对没有」没被验证：根因与整改

### 4.1 十层根因（按因果链排序）

| 层 | 根因 | 证据 |
|---|---|---|
| R1 | **验证目标错位**：门验「交付行为」，不验「规范符合性」 | 七次验收放行 `.xn` |

| 编号 | 机制 | 落地物 | 拦截层 |

## 第 5 条　语言完成度：先建分母，再谈百分比

### 5.1 判决

用户说「要语言完成度，不要 demo」——**成立**。但必须先承认一个事实：

> **当前无法计算「语言完成度」。不是完成度低，是度量不存在。**

原因：语言完成度的分母是**规范条款**，不是示例、不是代码行、不是里程碑。条款没有 ID，就没有分母；没有分母，所有百分比都是叙事。

### 5.2 三个口径，只用最严格的那个对外

| 口径 | 数值 | 含义 | 能否对外 |
|---|---:|---|---|
| 加权台账 | 19.31% | PASS + 0.5×部分，工作进度视图 | 内部参考 |
| PASS-only | 9.90% | 只认端到端证据 | 可对外，但要注明「按 101 锚点」 |
| **条款闭包率** | **≈ 0（度量未建立）** | 条款 ID + 差分 + 负向 + 独立验证全齐才算闭包 | **建好分母后作为唯一对外口径** |

**条款覆盖的粗略估算**：101 锚点 ÷ 正文约 789 次规范性关键词出现 ≈ **12.8%**。这只是量级参考，不是精确覆盖率，因为关键词出现次数不等于条款数。

### 5.3 「Demo 完成」与「语言完成」的分界

| 维度 | Demo | 语言完成 |
|---|---|---|
| 输入 | 挑过的示例能跑 | 规范允许的所有输入都产生规定结果 |
| 拒绝 | 不管 | 规范禁止的输入都产生规定诊断 |
| 证据 | 截图/输出 | 条款 ID + 测试 + CI artifact |
| 双路径 | 一条能跑 | 编译/解释逐字节一致 |
| 缺陷 | 已知也不阻断 | P0/P1 清零才过门 |
| 度量 | 示例数、代码行、里程碑 | 条款闭包率 |

### 5.4 完成度的唯一定义（本判决生效）

```
语言完成度 = 已闭包条款数 / 规范条款总数

闭包 = PASS 锚点
     ∧ 条款 ID 可追溯
     ∧ 双路径差分通过
     ∧ 负向诊断通过
     ∧ 独立验收签字
```

任何不满足五项的条款，不得计入完成度。**「部分」不计分，只作为阶段内工作状态。**
