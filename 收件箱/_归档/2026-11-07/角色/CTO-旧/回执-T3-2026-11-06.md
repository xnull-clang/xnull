**C2 | 修改**
"The compiler decides memory management. Source never expresses reference strength — no ownership annotations, no smart-pointer types, no `weak` fields. Compiler adjudicates ARC vs GC vs stack per decision table (S2 §15.1, criterion DET-01); deterministic: same source + same compiler version **and options** = same adjudication."
修改理由：DET-01 原文是"同一源程序、同一**实现版本**、同一**编译选项**必须产生相同判定"（S2 §15.1 末段）。漏掉 options 会被 HN 抓住"编译选项变了判定变不算非确定"的反例。实现层面站得住：T1 解释器无 map 随机源、连跑 5 轮逐字节一致（回执-T1）；判定表输入全部来自单态化后源码结构，无环境依赖。

**C4 | 修改**
"Errors: `Result` values + `try` propagation + `defer`/`errdefer`; no exceptions."
修改理由：补 `propagation` 和 `errdefer`——errdefer 是差异点（Rust/Swift 都没有对位物），发布帖漏掉可惜；且 `try` 在本语言是传播运算符而非 Swift 的可选解包，加上 propagation 避免误读。

**C6 | 修改（判定表四例对照 S2 §15.1 原文）**
"判定表四例：单例→GC 全局根；数据枚举→GC；类方法捕获 self 或存在 deinit→ARC；类只有值字段且不逃逸→栈候选（逃逸后按 14.2 提升）。混合引用图靠不变量：每个强引用要么增加 ARC 计数要么被 GC 追踪（S3 §78 引 S2 §15.6 不变量 1），绝不两者皆无；环在静态分析阶段检测并归入 GC（§15.1.1：出现 GC 节点的环由 GC 回收，全 ARC 环由内存分析改判 GC）。"
修改理由（两处与原文的偏差）：
1. 原表述"被闭包捕获 self→ARC"——原文条件是"类**方法**捕获 self"（判定表第 7 行），闭包捕获只是子情形，按原表述会被"方法捕获 self 但无闭包却 ARC"的反例打；
2. 原表述"纯值不逃逸→栈"——原文是"栈**候选**，逃逸后按 14.2 提升"（第 8 行），漏掉候选/提升会被"栈上对象逃逸了怎么办"打。
