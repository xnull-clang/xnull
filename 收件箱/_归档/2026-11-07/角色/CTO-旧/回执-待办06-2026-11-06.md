## 四、任务 3b：M4.4b 类/协议 —— ✅ 已完成（A 案裁决后补记）

**实测事实**（不是推测）：解释器**不能执行类**。以下程序在 `--interp` 下直接报错：

```
class Counter { Int count = 0; Int bump(Int by) { self.count = self.count + by; return self.count; } }
static Int main() { Counter c = Counter(); ... }
→ xnull: 未定义的函数：Counter
```

`grep ClassDecl internal/interp/` 零命中——M2.4 只做到"类可解析 + 语义检查"（TY-201—207），类运行时（实例对象/new/字段/方法绑定）从未实现；`new W()` 只在 sema 测试里出现过。

**因此**："含类 + 容器示例双路径逐字节一致"必须先补 **interp 类运行时**，再让 codegen 对齐。工作量是新增，不是阻塞。

> **结案（2026-11-06 深夜）**：按 A 案执行完毕。解释器补 `internal/interp/objects.go`（对象模型/new/字段/方法/协议按名分派，不做 ARC 时序模拟）；codegen 补 `classes.go`+`classes_expr.go`（ARC 对象 + rt_type 描述符 + 构造器 + 方法静态绑定）；`examples/classes.xn` 双路径 stdout 与退出码一致（10 行输出）。详见 `回执-阶段M4.4-2026-11-06.md`。以下请示文本保留为决策留痕。

**请示两个口径**（已裁决 A 案）：
1. **A 案（严格）**：补 interp 类运行时（实例对象 + new + 字段读写 + 方法绑定 + ARC/析构语义），双路径仍逐字节一致 —— 预计多出 1 个工作块，M4.4 顺延但验收标准不打折；
2. **B 案（放宽）**：类的验收改为"编译路径可运行 + sema 判定通过 + 与规范语义一致"，双路径要求只对容器与既有四示例生效 —— 快，但类在解释器调试模式下不可用，违背 `--interp` 作为调试模式的定位。

我的建议：**A 案**。`--interp` 是调试模式，缺类会让后续所有类相关缺陷只能靠读 C 代码定位；且 M5.1 自举的 AST 节点本就含类（若自举代码里出现类，调试链会断）。
