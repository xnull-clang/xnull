## 二、XDK 阶段 A：`impl/docs/xdk-design.md` —— 完成 ✅

1. **S6 合规映射表**：XDK-01—10 逐条 → 实现层决策 → 切片；含 §1.4.3 依赖矩阵的机械核验（`tools/check_xdk.py` 规划）与 §3 七条合同原则的可核验项；
2. **三层结构（核心决策）**：公开 API 全部是 XNull 源码（`impl/lib/xdk/*.xn`，8 单元）→ 经 `bindings/xdk/*.xfb` 绑定 → C 原语 `rt_std_*.c`（符号 `xdkc_*`，静态编入 `libxrt.a`，不对外导出）。理由：合同一次校验（复用 M4.5a 校验器）、API 约束只有 XNull 类型系统能表达（`withLock` 作用域化、闭包参数）、自举铺垫、`--interp` 与编译路径共享同一份 API 源码；
3. **C 层清单**：`rt_std_runtime/text/sync/sys/net/resource_table` 六个文件与既有 `xrt_*`、P-02/P-03 提案的关系（直接消费，不重复造）；
4. **与 M4 集成点**：`libxrt.a` 扩容（P-07 缓存不变）；生成代码只 include `xrt.h`（提示：M4.1 当前 include `rt.h`，M4.5b 切换）；XDK 内部库自动链接、不入用户 `link.libraries`；资源表构建期生成（S8 §5.6）；
5. **切片**：M4.6a（包骨架+errors/runtime/text）→ M4.6b（sys+资源读取）→ M4.6c（collections+Regex）→ M4.6d（net+tasks/sync 结构面）；**八包优先级**按自举最小需求集：P0 sys 文件读写/errors/runtime/text → P1 collections/sys 进程与资源 → P2 net/tasks/sync；
6. **风险 6 项**：调度器依赖（XDK-04/05 只能部分验收，禁虚报）、AtomicRef 保活、资源表规模上限（建议单 8 MiB / 总 64 MiB）、Windows 后置、Regex 用 POSIX ERE 不引三方库、XDK 与语言版本解耦校验。
