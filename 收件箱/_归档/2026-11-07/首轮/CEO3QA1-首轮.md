## 3. 证据七件套核验

### 3.1 定义（与验收标准 v1.0.0 §4.3 一致）

| # | 文件 | 必须内容 | 机械判据 |
|---|---|---|---|
| 1 | `command.txt` | 可复制执行的命令；不依赖 shell 历史、不依赖私有环境变量 | 干净 clone 可直接执行 |
| 2 | `stdout.txt` | 标准输出原文 | 可 grep 到关键 PASS 行 |
| 3 | `stderr.txt` | 标准错误原文；允许为空文件 | 文件存在 |
| 4 | `exit_code.txt` | 纯整数退出码 | `^[0-9]+$` |
| 5 | `sha.txt` | 被测 commit sha，单个值 | `^[0-9a-f]{40}$` 且 = 交付 sha |
| 6 | `artifact.sha256` | 产物哈希，`sha256sum` 格式 | 64 hex + 两空格 + 路径；`-c` 校验 exit 0 |
| 7 | `acceptance.md` | 验收人签名 + 时间 + 结论 + 证据目录 + 未测项 | 签名人 ≠ 主责；结论为「通过/不通过」 |

**三条硬口径：**

1. **以交付 sha 为准**，不以工作树为准；`wt/` 里的未跟踪副本不算入库。
2. **以 `git ls-tree <head>` 为准**，不以本机 `ls` 为准；换机器/干净 clone 必须还在。
3. **以可复现为准**，不以文字声明为准；`command.txt` 跑不出同样退出码即失败。

### 3.2 一键核验脚本（只读，人工审阅 `command.txt` 后再执行）

```bash
#!/usr/bin/env bash
# 用法: bash l1-evidence-check.sh <task-id> <head-sha>
set -u
T="$1"; H="$2"; E="evidence/$T"; fail=0
for f in command.txt stdout.txt stderr.txt exit_code.txt sha.txt artifact.sha256 acceptance.md; do
  git cat-file -e "$H:$E/$f" 2>/dev/null || { echo "MISSING $H:$E/$f"; fail=1; }
done
git cat-file -p "$H:$E/exit_code.txt" | tr -d '[:space:]' | grep -Eq '^[0-9]+$' || { echo "BAD exit_code"; fail=1; }
git cat-file -p "$H:$E/sha.txt"       | tr -d '[:space:]' | grep -Eq '^[0-9a-f]{40}$' || { echo "BAD sha"; fail=1; }
git cat-file -p "$H:$E/artifact.sha256" | grep -Eq '^[0-9a-f]{64}  .+' || { echo "BAD artifact"; fail=1; }
[ "$(git cat-file -p "$H:$E/sha.txt" | tr -d '[:space:]')" = "$(git rev-parse "$H")" ] \
  || { echo "SHA MISMATCH: sha.txt != head"; fail=1; }
tmp="$(mktemp -d)"
git clone -q . "$tmp/r" && git -C "$tmp/r" checkout -q "$H" \
  || { echo "CLONE/CHECKOUT FAILED"; fail=1; }
( cd "$tmp/r" && bash "$E/command.txt" >/tmp/l1.out 2>/tmp/l1.err ); rc=$?
want="$(git cat-file -p "$H:$E/exit_code.txt" | tr -d '[:space:]')"
[ "$rc" = "$want" ] || { echo "REPRO MISMATCH: got $rc want $want"; fail=1; }
( cd "$tmp/r" && shasum -a 256 -c "$E/artifact.sha256" >/dev/null 2>&1 ) \
  || { echo "ARTIFACT CHECK FAILED"; fail=1; }
rm -rf "$tmp"
[ "$fail" = 0 ] && echo "PASS $T @ $H" || echo "FAIL $T @ $H"
exit "$fail"
```

**安全前置**：执行他人 `command.txt` 前必须人工确认不含网络下载、`rm -rf`、写生产路径、提权；不确认则只做静态审查并记「未复现」。

## 4. 打回规则

### 4.1 直接打回（命中任一，不看比例、不看解释）

| # | 打回项 | 判据 |
|---|---|---|
| 1 | 七件套缺任一项 | B1 |
| 2 | 证据未入库 / 换机器不复现 | B3 |
| 3 | 无 commit sha 或无法复算的 artifact | B4/B5 |
| 4 | 实现者自验 | A3/B6 |
| 5 | 测试或期望值被改绿 | E1 |
| 6 | 存在跳过/xfail 未批准 | E2 |
| 7 | 范围内有「部分」未清零 | C1 |
| 8 | 条款映射缺失 | C2 |
| 9 | 诊断码无触发测试 | C4 |
| 10 | 双路径未跑 / 超时未处理 | C3 |
| 11 | 范围内有 P0/P1 | C6 |
| 12 | 声称「条件通过」 | F1 |
| 13 | 越写入域 / 未走 worktree | A2 |
| 14 | 证据只指向 `wt/` 副本 | B3 |
| 15 | 用解释器输出当编译路径期望值 | C3 |
| 16 | 用「挂账」冲抵本卡缺项 | §4.4 |

### 4.2 打回动作（五步，缺一步视为未打回）

1. **不签** `acceptance.md`，不写「通过」；
2. 在验收单写「不通过」+ 缺项表（路径 / 事实 / 复现命令 / 必须补交物）；
3. 回执落 `收件箱/CEO3/验收-<卡号>-打回.md`（我的写入域）；
4. 交 CEO3 登记缺陷/整改，归口司修，原 QA 复验（v1.6.0 §4.6）；
5. **不代补证据、不改实现者文件、不 commit**。补证据是主责的事。

### 4.3 复验规则

- 必须用**新 sha**；不得复用被打回时的 sha 与证据；
- 只复验「缺项 + 受影响的相邻项」，但不免除全量回归；
- 同一卡连续 2 次打回 → 升级 CEO3/CEO2，不得由原验收人私下放行；
- 复验通过后，新验收单必须引用旧打回单号，形成闭环。

### 4.4 挂账 ≠ 通过

- **可挂账**：卡外既存缺口（如 `ci/` 04–09 SKIP 桩、tag=0、公开副本未同步），且已登记归属与期限；
- **不可挂账**：本卡验收列内的任何缺项、七件套缺项、自验、改绿；
- 挂账只写进「未测项/风险」，不得写进结论，**不得用「整改中」代替「不通过」**。

### 4.5 没有「条件通过」

- L1 只有「通过 / 不通过」；不设「基本通过」「原则通过」「补证据后通过」；
- 判据必须在**验收前**写死在卡面；验收后新增解释 = 打回或升董事会，不接受事后放宽。
- 先例：S1-22 第 7 项「注释文件名同步」当时以说明放行并向董事会请示。本清单生效后，同类情形必须在卡面预写豁免条款，否则按打回处理。
