## 2. 口径定义（后文全部引用此节）

### 2.1 状态四值

| 状态 | 定义 | 能否过门 |
|---|---|---|
| `PASS` | 锚点全部判据有可复现证据，验收人≠实现者 | 能 |
| `部分` | 有实现/有测试，但判据未全覆盖（缺负例、缺边界、缺路径） | **不能**；不得写成“基本通过” |
| `未实现` | 无实现或无有效用例 | 不能 |
| `N/A` | 规范明示“否决/非承诺”，并有留痕条款指向 | 不计入分母，但必须能指到规范行 |

**禁用词**：条件通过、基本可用、先过后补、抽样放行、口头通过。门结论只有「通过 / 不通过」。

### 2.2 锚点与条款不是一回事

- **条款**=规范正文的一句可判定要求（如 S1 §2.6 可赋值性规则）；**锚点**=规范验收表里的一行（如 `TYPE-01`）。
- 一个锚点覆盖多条条款时，**条款→测试必须逐条映射**（`clause-test-map.tsv`），不能只挂一个测试文件就算覆盖。
- Stage 0 第⑤项、G-03 要的是**条款级 100%**，不是锚点级 100%；当前台账只有锚点列，这是 §5.4 的缺口。

### 2.3 单条锚点判 PASS 的 6 个必要项

| 编号 | 判据 | 反例（直接判不通过） |
|---|---|---|
| A1 正例 | 规范允许的输入产生规定结果；期望值溯源到条款 ID | 期望值抄实现输出 |
| A2 负例 | 规范禁止的输入必须被拒绝，断言**具体诊断码 + 文件:行:列** | 只断言“编译失败”；只报“未实现” |
| A3 双路径 | 编译路径与解释路径输出逐字节一致、退出码一致（语言语义类锚点） | 只跑一条路径；用解释器输出当编译期望 |
| A4 确定性 | 同源/同版/同选项，两次构建 hash 一致，10 次连续跑输出一致 | 顺序随机、时间/浮点未固定 |
| A5 追溯 | 测试名含锚点 ID；锚点→条款→测试三列可对账 | 测试名无 ID、映射表缺行 |
| A6 独立 | 证据七件套齐全（`command/stdout/stderr/exit_code/sha/artifact.sha256/acceptance.md`）；验收人≠实现者 | 无 sha/artifact；自验 |

### 2.4 证据与抽样

- 证据目录：`evidence/<task-id>/`，缺任一项=任务未完成（验收标准 §4.3，L203–216）。
- 抽样：QA ≥20% 条款、CEO ≥5 卡 + ≥3 条款；抽到 1 条不通过→整阶段不通过（§4.2，L193–201）。
- 反作弊 10 条与直接打回 10 条照抄验收标准 §4.4/§6（L218–229、L294–305），本文件不另立宽严。
