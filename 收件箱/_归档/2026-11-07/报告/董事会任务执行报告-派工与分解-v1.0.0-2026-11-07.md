## 第 1 条　派工六原则（所有任务卡必须满足）

| 原则 | 含义 | 违反判定 |
|---|---|---|
| P1 单一主责 | 每张任务卡只有一个 A（主责），必签人只签不干 | 两个 A = 无效派工 |
| P2 能力闭包 | 完成 = E1–E8 中适用项全满足，不是“代码写完” | 只写代码不交证据 = 未完成 |
| P3 依赖优先 | 前置任务未过门，后置任务不得开工 | 抢跑 = 回退 |
| P4 WIP 限制 | 每人同时在做任务数有上限（见第 2 条） | 超 WIP = CEO 拒绝新任务 |
| P5 证据先行 | 交付物 = 代码 + 测试 + sha + CI artifact + 回执 | 口头完成 = 不算 |
| P6 实现/验收分离 | 实现者不自验；验收人独立跑命令 | 自验 = 门无效 |

## 第 3 条　任务卡标准（DoR / DoD）

### 3.1 任务卡必填字段

| 字段 | 要求 |
|---|---|
| ID | `S<阶段>-<序号>`，例如 `S1-02` |
| 标题 | 动词开头，一句话 |
| 主责 / 必签 | 各一人，不得同一人 |
| 输入 | 文件、条款 ID、前置产物 |
| 输出 | 代码路径、测试路径、报告路径 |
| 验收 | 可机械执行的命令或断言 |
| 依赖 | 前置任务 ID |
| 预估 | 人日，上限 2 人日；超过必须再拆 |
| 证据 | sha、CI artifact、日志路径 |
| 状态 | 待派 / 进行中 / 待验 / 通过 / 打回 |

### 3.2 DoR（开工前必须满足）

1. 对应条款 ID 已存在；
2. 验收命令可复制执行；
3. 依赖任务已“通过”；
4. 证据落盘路径已确定；
5. 主责已书面确认（回执或看板认领）。

**任一条不满足，不得开工。**

### 3.3 DoD（完成时必须满足）

1. 代码 + 测试 + 文档三者齐全；
2. 适用 E1–E8 全满足；
3. 独立验收人跑过命令并签字；
4. 回执五行齐全：改了什么、怎么验、sha、产物、未测项。

## 第 7 条　派工与验收流程（五步闭环）

```
① 派工：CEO 写任务卡 → 收件箱/CTO|COO
        ↓ 30 分钟内认领
② 开工：主责在任务看板置“进行中”，声明 WIP
        ↓ 每日 18:00 更新
③ 交付：代码 + 测试 + 回执五行 + artifact 路径
        ↓ 主责不自验
④ 验收：必签人独立跑命令，逐条判 E1–E8
        ↓ 打回则回 ②；通过则 ⑤
⑤ 过门：CEO 签“通过/不通过”，记日志，更新台账
```

**证据要求**：回执必须包含

1. 改了什么（文件 + 条款 ID）；
2. 怎么验（可复制命令）；
3. commit sha；
4. CI artifact 链接/路径；
5. 未测项声明。

**打回规则**：缺任一项，必签人直接打回，不进入门。
