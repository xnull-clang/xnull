## 第 2 条　发现与修正

### 2.1 缺陷 1：`/message` 是倒序，不是正序

实测消息数组（`data`）顺序，按 `time.created`：

| 数组下标 | 类型 | 时间 | 内容 |
|---:|---|---:|---|
| 0 | idle | 1793981663668 | `outcome:succeeded`（最新） |
| 1 | assistant | 1793981662144 | `ASYNC-OK` |
| 2 | user | 1793981662123 | 异步自检 |
| … | … | … | … |
| 8 | location-switched | 1793981649395 | 迁目录事件（最旧） |

**问题**：约定写“看最后一条 `type:"idle"` 的 `outcome`”。若按数组末元素取，会拿到最旧的 `location-switched`，永远等不到 idle。

**修正**：

1. 取**数组第一条** `type=="idle"`；或按 `time.created` 取最大的一条。
2. 更稳的做法：轮询 `GET /api/session/<id>`，等 `outcome` 出现且 `time.idle > time.busy`；不解析消息数组。
3. 约定 v1.0.1 应改为：“`/message` 返回倒序（最新在前）；取最新 idle 用 `data[0]` 或按时间排序。”

### 2.2 缺陷 2：`subagent` 只能续聊自己的子会话

- 对 `ses_e4e59d2b…`（`subagent` 新建的子会话）续聊：**成功**。
- 对 `ses_e4e5c7bf…`（API 新建的顶层会话）续聊：**报错** `not a child of the current session`。

**结论**：`subagent` 是父子链路工具，不是任意会话投递工具。

**修正**：约定表格拆成两行：

| 方向 | 手段 |
|---|---|
| 主 → 自己的子会话 | `subagent` + `sessionID` |
| 主 → 任意顶层会话 | `opencode run -s <id> -m …` 或 `prompt` API |

### 2.3 缺口 3：收件箱写入仍是 404

- `GET /inbox` 可用，返回空数组。
- `POST /inbox` 返回 404。
- 异步子→主仍应走 `收件箱/<角色>/回执-*.md`，不要依赖 inbox 写接口。

## 第 3 条　推荐调用范式

### 3.1 新建并接管一个执行会话

```bash
# 1. 建会话（title 必须符合 <角色>-<任务卡ID>-<任务名>）
opencode api POST /api/session -d '{"title":"E6-S0-18-建-worktree与分支"}'
# 2. 迁目录（不调 move 会在错误目录开工）
opencode api POST /api/session/<SID>/move -d '{"directory":"/Users/vjs/Desktop/XNull-Lang"}'
# 3. 设模型（prompt 的 body 不认 model）
opencode api POST /api/session/<SID>/model -d '{"model":{"providerID":"opencode","id":"deepseek-v4.1-flash-free"}}'
# 4. 同步投递（推荐：一次拿结果）
opencode run -s <SID> -m opencode/deepseek-v4.1-flash-free "<任务>"
# 5. 异步投递（长任务）
opencode api POST /api/session/<SID>/prompt -d '{"text":"<任务>"}'
# 6. 轮询状态（推荐，不解析消息数组）
opencode api GET /api/session/<SID>
```

### 3.2 父子会话

```text
新建子会话：subagent（不带 sessionID）
续聊子会话：subagent + sessionID
子→父异步：写 收件箱/<角色>/回执-*.md
```

### 3.3 判定完成

- 优先看 `GET /api/session/<id>` 的 `outcome` + `time.idle > time.busy`。
- 需要助手原文时再看 `/message`，取 `data[0]` 或按 `time.created` 取最新 idle。
