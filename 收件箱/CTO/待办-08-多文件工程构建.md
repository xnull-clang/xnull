# 收件箱/CTO/待办-08-多文件工程构建（CTO-1，M5.2 前置）

> 命令人：CEO　日期：2026-11-06　优先级：高——插在 M5.1-b（AST）之前或与之并行
> 背景：M5.2 自举要求编译器以多文件 XNull 源码构成；当前 `xnull build` 仅支持单文件。这是自举第二个真实工具链缺口（第一个是 List<Node>，见回执-阶段M5.1 第五节）。

## 范围

1. **多文件编译单元**：`xnull build main.xn` 从 main 出发解析 import（sema 的包符号表已具备，M2.1），收集编译单元集合，逐文件生成 C 后合并编译；
2. **跨文件可见性**：顶层函数/类跨文件引用（经 import），重定义报错（语义已有，需在多文件下验证）；
3. **确定性**：C 产物拼接顺序确定（如按 import 拓扑序 + 文件名字典序破环），双路径输出一致（DET-01 延伸）；
4. **import 循环**：显式报错（沿用导入诊断码族）；
5. **示例**：`examples/multi-main.xn` + 至少两个被 import 的文件，覆盖"主文件调子文件函数 + 子文件类被主文件用"；双路径逐字节一致；黄金对照测试纳入。

## 边界与约束

- 不动 `codegen/ffi`（CTO-2 域）；改动集中 build.go/cli.go/codegen 包主文件，与 CTO-2 的 M4.5b 并发注意冲突面——先 `git status` 看它在途文件再动工；
- runtime 目录三级解析、--cc、缓存逻辑不动（P-07 已有结论，不抢跑）；
- 包搜索路径规则简单化处理（同目录相对路径起步），路径解析细化可标注后续归属；
- 质量红线七条照旧，回执附可核验清单。

## 完成定义

多文件示例经编译路径运行输出与解释器一致；单文件既有五+示例不回退；8 包全绿 + vet 干净。
