- **状态**：`DONE`

## 1. 默认回退 go

- `XNULL_FRONTEND` 未设置即为 `go`（Go oracle）；`xnull` 仅显式开启；`auto` 也需显式，且只允许外部原生 `xparser`。
- **auto 生产路径禁用进程内解释器**：只认 `XNULL_NATIVE_XPARSER` 或缓存中的原生二进制；没有就回退 Go。解释器只在 `xnull`/测试中使用。
- 自动构建：找到工具链（`XNULL_TOOLCHAIN_BIN` 或 PATH 中 `xnull`）时 `xnull build` 一次并缓存；失败写 1 小时 `.fail` 标记，避免重复尝试。
- **默认未切回 auto**：本工作树无法用 `xnull build` 生成原生 xparser（codegen 尚不支持该源码），真实 auto/native 路径的 ≤170s 门禁无法验证，按规则保持 `go`。

## 2. 元组类型防丢

- `Deserialize` 增加校验：dump 中 `(TupleTypeRef` 数量必须与解码后 AST 等量，否则视为传输失败（auto 回退 Go，避免生成缺 `xn_tup_*` 定义的 C）。
- 新增 `TestDeserializeTupleTypes`（含 `List<(Int, Int)>`、`(Int, Int)[]`、嵌套元组）。
- `TestTupleCodegenRuns` 在默认 go 与 auto+原生路径（fake native 转发 xparser）下均 PASS（`evidence/B2-04b/tuple.out`）。

## 3. 性能修复与前后数据

- AST 缓存：`sha256(格式版本 + parser SHA-256 + 源码 SHA-256)` → 进程内 LRU（256）+ 磁盘缓存（`XNULL_FRONTBRIDGE_CACHE` 可覆盖）。
- 批处理：`frontbridge.ParseBatch`（≤4 并发）；`codegen.LoadUnits` 对同一文件的直接 import 预取批解析。
