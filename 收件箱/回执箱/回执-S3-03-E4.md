## 一、红 → 绿

| 用例 | 修前（红） | 修后（绿） |
|---|---|---|
| `class V { Int x=1 }` 局部 `V v = new V()` | 调用 `xn_Cls_V_new()`（`rt_arc_new`） | 栈槽 + `_new_init(&slot)`，无分配器调用 |
| 带参构造 `P p = new P(5)` | 堆 ARC | 栈槽 + `xn_Cls_P_new_init(&slot, 5)` |
| 循环内 `new V()` | 堆 ARC，每轮分配 | 每轮独立栈槽（身份/生命周期随块） |
| 局部被发布：`take(v)`、`return v`、`V w = v` | 堆 ARC（但无依据） | 预扫描判定逃逸 → 保持堆 ARC |
| `Escape=return`（有 deinit） | ARC | ARC（不变） |
| `Escape=other`（引用环） | GC | GC（不变） |

`go test ./internal/codegen/ -run 'TestS3_03' -count=1 -v`：4/4 PASS。

## 二、实现要点

- `codegen.go`：`emitC` 从 `Strategy` 建 `stack[类名] = Escape=="none"`；`gen` 增
  `stack`/`curEscaped`；`--mem=arc/gc` 强制路径把 Escape 置 `n/a`（禁用栈优化）。
- `stack.go`：
  - `emitStackNew`：`T name = new T(args)` → 零初始化栈槽 + 构造器 init 函数
    （与堆路径共用字段初值/参数绑定/构造器体）+ 指向槽的指针局部。
  - `escapeIdents`：函数体预扫描「逃逸位置」——调用实参、return/throw 值、赋值
    右值/目标、声明初始化式、容器/元组/构造实参、闭包体引用；字段读写与方法
    调用的接收者、`is`/`===` 比较不计。被标记的局部退回堆分配。
- `classes_expr.go`：`classIsStack` 防御校验——仅当策略 `none`、非 GC、类链无
  deinit、无协议 vtable、无引用字段（含引用元组）时才栈分配。
- `emitLocalDecl`：局部 `new` 且 `classIsStack && !localEscaped` 时走栈路径；
  其余构造点（实参/返回/字段初值/Any 装箱）沿用 E5 的 ARC/GC 堆路径。
- 函数/方法/构造器体入口设置 `curEscaped`（构造器体、方法体、顶层函数）。

## 三、边界（如实说明）

- **分配头**：栈对象不调用分配器、不写分配头（kind/type/refcount 保持零值）、
  不登记 GC 链/ARC 扫描链，随块消亡；由于栈/堆共用同一 C 类结构体（堆回退需要
  相同字段偏移），结构体保留一个零值 `rt_header` 槽作为布局占位。若验收要求物理
  删除该槽位，需要为栈类引入独立载荷类型并改造全部字段/所有权路径（更大改动）。
- 逃逸分类是**类级**（sema S3-03pre 口径）。本卡在局部构造点消费；对函数内被
  发布的局部做保守预扫描（实参/返回/别名等）保证不产生悬垂指针。跨函数/字段
  发布的“对象级逃逸”仍由 sema 后续对象级分析提供，codegen 不越权推断。
- 含协议的类不栈分配（协议上转需要 vtable/分配头 ABI 一致性；本卡保守）。
- `--mem=arc/gc` 强制堆分配，栈优化关闭（S3-08 选项语义不变）。
- 栈对象无 deinit（Escape=none 保证类链无 deinit）；无引用字段，无清理动作。
