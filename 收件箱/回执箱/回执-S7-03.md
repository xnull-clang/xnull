## 一、红 → 绿

| 项 | 修前（红） | 修后（绿） |
|---|---|---|
| `.xfb` 回调声明 | 无语法，`callback ... -> Ret;` 非法字符（FFI-100） | `callback Name(P0,P1) -> Ret;` 解析/校验/登记 |
| trampoline 消费方 | `EmitTrampoline` 无调用方 | `EmitSupport` 为每个回调自动发射 typed trampoline |
| env 根生命周期 | 只有运行时入口，无生成侧生命周期 | `_new` 登记根 / `_destroy` 注销（幂等）/ `_alive` 可观测 |
| 注销后调用 | 无端到端用例 | 子进程断言 abort（`xrt_fatal`，S7 §5.2） |
| 回调内 panic | 无端到端用例 | 闭包非 0 状态 → trampoline 转 `xrt_fatal`（S7 §5.3） |

## 二、声明形态与生成面

```x
ffi native {
  callback LogCb(Int32, Int64) -> Int64;
  callback Notify(Int64) -> Void;
}
```

校验（S7 §5.1/§5.3）：参数限标量 / `layout(c)` / 句柄；返回限标量或 `Void`；
跨声明块重名 → `FFI-111`；非法签名 → `FFI-112`。

每个回调生成：

```c
typedef struct { int32_t p0; int64_t p1; } xn_tramp_LogCb_args;
typedef int32_t (*xn_tramp_LogCb_fn)(void *captures, const xn_tramp_LogCb_args *, int64_t *result);
typedef struct { xn_tramp_LogCb_fn fn; void *captures; } xn_tramp_LogCb_closure;

xrt_callback_env *xn_tramp_LogCb_new(xn_tramp_LogCb_closure *);
void xn_tramp_LogCb_destroy(xrt_callback_env *);        /* 幂等注销根 */
int32_t xn_tramp_LogCb_invoke(xrt_callback_env *, const xn_tramp_LogCb_args *, int64_t *);
```

- `_new` → `xrt_callback_env_new`：env 创建即登记为运行时根（S7 §5.2）。
- `_destroy` → `xrt_callback_env_destroy`：注销根，重复销毁幂等。
- `_invoke` 校验 `nargs == sizeof(args)`；闭包状态非 0 按 panic 终止进程（§5.3），
  已注销 env 由运行时 `xrt_fatal` 终止（§5.2），均不静默。
- 闭包对象 `{fn, captures}` 由调用方持有；原生持有期间必须保持有效（与句柄销毁合同一致）。

## 三、端到端证据

`TestS703CallbackTrampolineEndToEnd` 编译生成支撑代码 + 运行时，输出：

```
log st=0 r=7 n=1 alive=1
notify st=0 n=9
destroyed alive=0
```

子进程模式：

- `destroyed`：注销后调用 → abort，无 `destroyed-missed`；
- `panic`：闭包返回 7 → trampoline 转 fatal → abort，无 `panic-missed`。

`TestS703CallbackValidation` 覆盖 Bytes 参数、layout 返回、重复回调三类拒绝。

## 四、边界

- 回调参数不含 `String`/`Text`/`Bytes`/数组/闭包（多字编组与别名规则未纳入 S7-03；
  需要时按 §3.4/§3.6 单独开卡）。
- 生成侧只给 C 闭包 ABI；XNull 语言层闭包取用语法仍待前端卡，本卡不发明调用点语法。
- 进入 FFI 的入口参数暂不自动转成回调类型；`FFI` 入口如需接收回调，按原生
  `xrt_callback_env *` 由绑定层包装（后续卡）。
