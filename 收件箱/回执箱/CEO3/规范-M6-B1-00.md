## 二、关键设计决策（需 CTO1 确认）

1. **歧义 token 用前向扫描判定，不采用「按输入空格保留」**（§8）。理由：保留法会把 `Result<Int, String> double(...)` 的闭合 `>` 误判为比较符输出成 `String > double`，对仓库现有 93 处泛型写法（73 个文件）即产生明显错排；扫描法有两个可靠依据——比较运算不可链式（第 1 部分 §7.2）、泛型内部 token 集受限。
2. **长行不折**（§11）。理由：自动分号插入使换行有语义，折行需语法级保证，属 B2 之后；且宽度判定会引入 Unicode/制表符歧义，破坏双实现一致性。
3. **头部区插入两处空行**（§9 R9.1：注释块↔package、package↔import 块、import 块↔正文 之间各 1 空行；空区段不插）。理由：让 122 个文件的头部形态唯一，避免"有无空行"成为实现分歧点。
4. **`xnfmt` 与 `xnull fmt` 是两件事**（§17 D4）：前者格式化 `.x` 源码，后者格式化 `xnull.project`/`.xmeta`/`.xplugin`/`xnull.lock`（`impl/internal/cli/cli.go:116`）。B4-5 要求 CLI 含 `fmt`，届时并入 `xnull fmt` 子命令、共用本规范，不得混用对象。
