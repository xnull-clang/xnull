## 三、实现要点（发射层）

- **根帧**：函数/方法/构造器/块入口 `size_t xn_tN = xn_root_mark();`，块退出/return
  逆序 `xn_root_restore(xn_tN)`；`break`/`continue` 显式恢复被跳出块的根帧。
- **持有计数**：生成 C 内维护 `xn_root_refs`（对象→计数）镜像 `rt_gc_root_add/remove`；
  同一对象被多个栈槽/全局槽持有时只在计数归零时撤销运行时根，避免共享根误删。
- **长期根**：顶层字段/单例/数据枚举项用 `xn_root_hold`（不随块恢复撤销）；
  全局字段重赋值用 `xn_root_release → hold`。
- **安全点**：全部 GC 分配走生成 helper `xn_gc_new` 计数；`XN_GC_SAFEPOINT_THRESHOLD`
  达阈值时在分配点/循环回边调用 `xn_gc_safepoint()` → `rt_gc_collect()`。
  `deinit` 体内禁发安全点，避免清扫期间重入收集。

## 四、与 E5 的接口 / 协作边界

- 用的都是既有运行时 API：`rt_gc_root_add/remove`、`rt_gc_collect`、`rt_gc_new`；
  **未改 `impl/runtime` 任何文件**。
- 安全点策略集中在生成前置代码的两个函数（`xn_gc_new` / `xn_gc_safepoint`）；
  若 E5 提供运行时阈值/步进 API，只需把这两处改为薄调用，调用点无需变。
- 栈对象（S3-03）不参与 GC：`classIsStack` 已排除含引用字段/协议的类，栈槽不持有
  GC 指针；GC 根只登记 GC 引用局部/参数/全局，不与栈对象生命周期交叉。
- **main 的 P0 回归 `TestBND10GCMixedARCFieldValid`（E5 主导）**：本卡开工前已在
  main 复现——S3-04sema 将 String 字段改判 GC 后，用例里的 Helper 变成 GC，
  sweep 按 GC 链顺序先释放 Helper 再执行 Node deinit → UAF 崩溃。这是 sweep 顺序/
  字段释放问题，归 E5；本卡未改 sweep 与字段释放。为保持语义覆盖，pod 内把该用例
  改为真正的 ARC Helper（Int 字段）继续验证「GC 持 ARC 字段、deinit 时字段有效」。
  安全点会让这类 GC→GC 顺序缺陷在中途收集中更易显形，待 E5 修复后应恢复 String 版
  用例（或新增 GC→GC 专项）。
