# 回执：S4-04 FFI errorMap → ErrorKind（E4 codegen）

- 卡片：S4-04（S4 §7.3 / S4盘点 P0-05：FFI 错误码→ErrorKind，未知码不得当 Ok）
- 提交：`c8f98f8`（仅 pod/e4-codegen）
- 顺序：先红后绿（`evidence/S4-04/red.log`：规范分类名被 FFI-106 拒绝；`green.log` 绿）

## 一、红 → 绿

| 用例 | 修前（红） | 修后（绿） |
|---|---|---|
| 规范分类名 `Io/InvalidArgument/PermissionDenied/...` | `FFI-106 未知错误分类` | 14 个 S4 §3.1 名全部接受 |
| 生成稳定枚举映射 | 仅短名（Invalid/Conflict/...） | 规范名 → `XRT_ERR_*`（InvalidArgument→INVALID_ARGUMENT、Io→IO、Network→NETWORK、DataCorrupted、Unsupported、OutOfMemory…） |
| 未知码 | 可能被当 Ok | `default: XRT_ERR_INTERNAL`（绝不 Ok） |
| Cancelled / Timeout | 仅字符串骨架 | 精确映射 `XRT_ERR_CANCELLED` / `XRT_ERR_TIMEOUT`，不降级 Internal |
| 调用点诊断 | 原始错误码字符串 | `xrt_error_kind_name(xn_ffi_<region>_error_kind_id(rc))` → 规范 ErrorKind 名 |

`go test ./internal/codegen/ -run TestS4_04 -count=1 -v`：3/3 PASS（含运行期 Io/Cancelled/
Timeout/未知码四分支，出参非零 → 134 且入口不执行）。

## 二、实现要点

- `ffi/check.go`：`errorKinds` 扩为 S4 §3.1 的 14 项规范名 + 历史短名别名；
  未知名仍 FFI-106。
- `ffi/emit.go`：`errorKindEnum` 完整映射（含短名别名）；保留
  `xn_ffi_<region>_error_kind`（字符串，兼容既有测试/诊断）与
  `xn_ffi_<region>_error_kind_id`（稳定枚举，未知 Internal）。
- `ffi_gen.go`：出参形态错误路径改用 `xrt_error_kind_name(..._error_kind_id(rc))`；
  非零即 fatal 134（不隐藏、不吞错），分类名与 S4 附录 A 一致。
- 返回码形态（`@errorCode(codeParam = .result)`）按 S7 §7.1 仍把 rc 交调用方
  （不改变 `Int32` 返回合同）；调用方可用生成的 `error_kind_id` 做分类，
  未知码不会变成 0/Ok。

## 三、边界

- 取消/超时的**机制**（B3 调度器）不在本卡；本卡只保证错误码分类映射不降级。
- 返回码形态的“调用方忽略 rc”属源码责任（S7 合同），codegen 不强制 fatal；
  出参形态已强制 fatal。
- 规范名与短名并存：既有 `bindings/xdk/sys.xfb`（Invalid/Internal）继续可用。
