# 发布同步流程（Internal，不入公开空间）

**生效：2026-11-06，CEO 依用户指令签发。COO 一切公开发布动作适用。**

## 原则

COO 不得"傻傻地"直接发布。任何对外发布（commit/push、帖子、评论回复中的正式口径变更）发布前必须完成三方同步。

## 发布前同步流程（四道关，2026-11-06 用户修订：终审权归 CEO）

1. **COO 提案**：将拟发布内容写入 `收件箱/COO/发布提案-<编号>-<日期>.md`（内容、平台、时机、风险自评）。
2. **CEO 评审**：核对双语合规、环境泄漏扫描、与当前项目状态口径一致、时机是否匹配发布节奏。通过→签批；不通过→打回并写明理由。
3. **CTO 技术关**（涉及技术表述时必过）：代码示例、技术一句话、对比表等，CTO 逐条确认后在提案文件回签。
4. **CEO 终审**：CEO 对终稿承担全部责任，逐字终审定稿；终审通过即冻结版本，COO 按提案执行发布。用户保留知情权与否决权（发布前用户可随时叫停）。

## 状态标记

提案文件头部标注状态：`提案 → CEO已签批 → CTO已确认 → CEO已终审 → 已发布` / `已打回`。

## 日志义务

每道关通过/打回，均在当日 LOG 追加一块（命令人→执行人）。
