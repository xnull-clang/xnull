## 第 1 条　四级验收体系

| 级别 | 验收对象 | 验收人 | 通过判据 | 输出 |
|---|---|---|---|---|
| **L1 任务验收** | 单张任务卡 | 必签人（非实现者） | 该卡“验收”列全满足 + 证据目录齐全 | 任务验收单 |
| **L2 阶段验收** | 一个阶段（Stage 0–9） | QA-1 + CEO + 域 CTO | E1–E8 + 第 3 条质量阈值 + 抽样 | 阶段门报告 |
| **L3 发布验收** | 公开副本 | COO + CEO + 董事会抽查 | 公开副本 = 已判 tag；能力表一致；泄漏零命中 | 发布验收单 |
| **L4 董事会验收** | 判决执行情况 | 董事会 | 判决条款逐条有证据；无未申报偏离 | 新版本判决 |

**铁律**：上一级验收不得跳过下一级；L2 不通过，不得进入 L3；L1 有一张卡未过，L2 不得判通过。

## 第 3 条　验收内容（十类，逐条可查）

> 每条都写清：验什么、怎么验、证据、不通过示例。

### A. 规范符合性

| 项 | 内容 |
|---|---|
| 验什么 | 每条规范性语句有 ID；每条有测试映射；无禁用措辞；无规范-实现偏离 |
| 怎么验 | `spec-clauses.tsv` × 测试名 × CI 校验；禁用措辞扫描；第六检 |
| 证据 | 覆盖率报告 + 缺失清单（必须为空） |
| 不通过 | 条款无 ID、测试名不含 ID、正式版出现“待定/可能/实现定义” |

### B. 行为正确性

| 项 | 内容 |
|---|---|
| 验什么 | 规范允许的输入产生规定结果；边界/异常路径正确 |
| 怎么验 | 单元测试 + 端到端 + 差分 + 边界值 + 负向 |
| 证据 | 测试报告 + 实际输出 + 期望输出来源（条款 ID） |
| 不通过 | 只测 happy path、期望值抄实现输出、边界未测 |

### C. 诊断质量

| 项 | 内容 |
|---|---|
| 验什么 | 每个错误有 `文件:行:列` + 诊断码 + 消息 + 修复提示；用户错误不 panic |
| 怎么验 | 每个诊断码至少一个触发用例；断言码/位置/消息关键字 |
| 证据 | 诊断快照测试 |
| 不通过 | 只报“error”、无位置、用户输入触发 panic/栈回溯 |

### D. 双路径一致

| 项 | 内容 |
|---|---|
| 验什么 | 编译路径与解释路径输出逐字节一致、退出码一致 |
| 怎么验 | 差分框架；同一输入两路径各跑一次；超时即失败 |
| 证据 | diff 为空 + 两路径输出文件 |
| 不通过 | 只跑一条路径、用解释器输出当期望值、超时不处理 |

### E. 确定性

| 项 | 内容 |
|---|---|
| 验什么 | 同源、同版本、同选项 → 同诊断、同结果；构建可复现 |
| 怎么验 | 两次构建 hash 对比；10 次连续运行对比；map 顺序按规范 |
| 证据 | hash 清单 + 10 次输出 |
| 不通过 | 构建产物 hash 不同、输出顺序随机、浮点/时间未固定 |

### F. 回归

| 项 | 内容 |
|---|---|
| 验什么 | 既有示例/测试不退化；覆盖率不下降；无新 P0/P1 |
| 怎么验 | 全量测试 + 9 示例 + multi + 覆盖率对比基线 |
| 证据 | 回归报告 + 覆盖率 diff |
| 不通过 | 删测试、跳过测试、覆盖率下降无说明 |

### G. 测试质量

| 项 | 内容 |
|---|---|
| 验什么 | 断言能区分正确/错误实现；无 flaky；变异可杀死 |
| 怎么验 | 变异测试；10 次连续跑；随机抽样断言审查 |
| 证据 | 变异分数 + flaky 统计 |
| 不通过 | 断言恒真、测试依赖执行顺序、跳过/xfail 无批准 |

### H. 交付完整性

| 项 | 内容 |
|---|---|
| 验什么 | 代码 + 测试 + 文档 + 示例 + artifact + sha 齐全 |
| 怎么验 | 任务卡 DoD 清单；证据目录检查 |
| 证据 | `evidence/<task-id>/` |
| 不通过 | 只有代码、无测试；有测试、无 artifact；无 sha |

### I. 文档同步

| 项 | 内容 |
|---|---|
| 验什么 | 规范 changelog、台账 evidence、README 能力表三方同步 |
| 怎么验 | 三文件 diff；再生成脚本幂等 |
| 证据 | diff 为空 |
| 不通过 | 实现已改、台账未改；README 写“next”但已上线 |

### J. 独立性与反作弊

| 项 | 内容 |
|---|---|
| 验什么 | 实现者不自验；测试未被篡改；期望值来自规范 |
| 怎么验 | 验收人 ≠ 实现者；git diff 检查测试/示例；期望值溯源到条款 ID |
| 证据 | 验收签名 + diff + 溯源表 |
| 不通过 | 自验、改期望值、删测试、硬编码示例输出 |

**阈值调整**：只能由董事会发新版本调整；CEO 不得在门现场降低阈值。

### 4.2 抽样规则

| 角色 | 抽样量 | 必抽项 | 随机种子 |
|---|---|---|---|
| QA-1 | 每阶段 ≥20% 条款 | 所有 P0 相关条款、所有本阶段变更条款 | 记录并公开 |
| CEO | 每阶段 ≥5 张任务卡 + ≥3 条条款 | 所有 P0 任务 | 记录 |
| 董事会 | 每次判决 ≥3 条条款 | 上次判决的整改项 | 记录 |

**抽样失败处理**：抽到 1 条不通过，该阶段整体不通过，不因“抽样比例低”而放行。

### 4.3 证据格式（每张任务卡必须有）

```
evidence/<task-id>/
├── command.txt        可复制执行的命令
├── stdout.txt         标准输出
├── stderr.txt         标准错误
├── exit_code.txt      退出码
├── sha.txt            commit sha
├── artifact.sha256    产物哈希
└── acceptance.md      验收单（验收人签名 + 时间）
```

**缺任一项 = 任务未完成。** 不接受截图、口头说明、聊天记录作为唯一证据。

### 4.4 反作弊条款（触发即判不通过）

1. 修改期望值让测试变绿；
2. 删除/跳过/xfail 测试且无董事会批准；
3. 硬编码示例输出；
4. 用解释器输出当编译路径期望值；
5. 测试依赖执行顺序或全局状态；
6. 断言恒真（如 `assert(true)`、只断言不 panic）；
7. 验收人 = 实现者；
8. 无 sha / 无 artifact；
9. 覆盖率下降无书面说明；
10. 声称“条件通过”。

### 4.5 Flaky 与性能

- **Flaky**：同一提交连续 10 次 CI，任一失败即判不稳定；不稳定不得过门。
- **性能**：Stage 0 记录基线；后续阶段回归超过 20% 需书面豁免，否则不通过。
- **超时**：任何测试挂起视为失败，不得用“它只是慢”解释。
