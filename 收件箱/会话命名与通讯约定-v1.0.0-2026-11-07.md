# 会话命名与通讯约定 v1.0.0

> 生效：2026-11-07　签发：CEO　适用范围：所有由 agent 创建/接管的 OpenCode 会话

## 1. 命名规范

### 1.1 新建会话

格式：`<角色>-<任务卡ID>-<任务名>`

示例：

- `E6-S0-18-建-worktree与分支`
- `E3-S1-02-break传播修复`
- `QA1-S1-04-差分框架`

规则：

- 角色用编制代号（E1–E6、QA1、CTO1、CTO2、CEO、COO），不用人名。
- 任务卡 ID 必须是判决/任务规划里的正式 ID。
- 不用「新会话」「临时」「测试」之类无信息量标题。
- 创建时直接带 title，不做事后补救。

### 1.2 重启会话

同一任务中断后恢复（换模型、上下文压缩、隔日续做），在原名称后追加：

格式：`<原名称>｜重启<N>-<本次任务说明>-<YYYY-MM-DD>`

示例：

- `E3-S1-02-break传播修复｜重启1-接续在途改动-2026-11-07`
- `E3-S1-02-break传播修复｜重启2-修回归后补差分-2026-11-08`

规则：

- `N` 从 1 递增，不重置。
- 任务说明写「这一次要干什么」，不写「继续上次」。
- 任务卡变更（换卡）不叫重启，应另建会话并按新卡命名。

## 2. 跨会话通讯

| 方向 | 手段 | 同步性 | 状态 |
|---|---|---|---|
| 主 → 子 | `subagent` 工具 + `sessionID` 续聊 | 同步，返回最终答复 | 已验证 |
| 主 → 任意会话 | `opencode run -s <id> -m <model> "<消息>"` | 同步，返回该会话输出 | 已验证 |
| 主 → 任意会话 | `opencode api POST /api/session/<id>/prompt -d '{"text":"…"}'` | 异步，立即返回 `delivery:"steer"` | 已验证 |
| 结果查询 | `opencode api GET /api/session/<id>/message`（看最后一条 `type:"idle"` 的 `outcome`） | 轮询 | 已验证 |
| 状态查询 | `opencode api GET /api/session/<id>`（`outcome` / `time.busy` / `time.idle` / `cost` / `tokens`） | 即时 | 已验证 |
| 切换模型 | `opencode api POST /api/session/<id>/model -d '{"model":{"providerID":"opencode","id":"…"}}'` | 即时 | 已验证 |
| 子 → 主 | subagent 的最终答复直接回传父会话 | 同步 | 已验证 |
| 子 → 主（异步） | 写 `收件箱/<角色>/回执-*.md`，主会话读取 | 异步 | 既有制度 |
| 任意 ↔ 任意 | `opencode api GET /api/session/<id>/inbox` 收件箱 | 异步 | 端点存在 |

### 2.1 关键约束

1. **必须显式指定模型**：`-m opencode/deepseek-v4.1-flash-free`。不带 `-m` 会用项目默认模型，当前默认模型返回 `403 RegionError`，会话直接失败。
2. 会话的 `directory` 决定工具的工作根目录。跨项目/工作组会话创建后立即 `session_move` 到目标目录（或 API body 指定 directory）。
3. 子会话的 `sessionID` 可长期复用；删除父会话会连带删除子会话。

## 4. 已知缺口（未闭环项）

| # | 缺口 | 后果 | 补法 |
|---|---|---|---|
| 1 | 创建时 `directory` 参数被忽略，一律落在服务端 cwd | 建会话必须两步（建 + `move`） | 封装 `oc-new` 一步完成 |
| 2 | 投递不指定 `-m` 会命中区域封锁模型 | 会话直接失败，且**模型被永久切到坏模型**，后续 prompt 继续失败 | 投递强制带模型；失败后调 `/model` 复位 |
| 3 | `prompt` 请求体里的 `model` 被忽略 | 无法按次指定模型，只能先切会话模型 | 先 `/model` 再 `/prompt` |
| 4 | 无完成通知，只能轮询 `/message` | 长任务需要外部轮询器 | 写巡检脚本轮询 `outcome` |
| 5 | 无任务卡 ↔ 会话台账 | 43 张卡无法对应到 session/worktree，重启会认错会话 | 建 `收件箱/会话台账.md` |
| 6 | 重启命名靠自觉 | 上下文压缩后可能忘记追加说明 | 启动提示词内置检查 + 台账记录重启次数 |
| 7 | `/inbox` 只读通，写入 404 | 异步收件箱方向未打通 | 改用 `prompt` + 文件回执 |
| 8 | 子会话不出现在 `session list` | 无法巡检子会话 | 台账单独登记子会话 ID |
| 9 | `session delete` 级联删子会话 | 误删在途任务 | 删除前查台账确认无在途子会话 |

## 5. 一句话

**会话名就是任务单，重启要写清这一次做什么；通讯优先走 `sessionID`，跨进程走 CLI/API，异步留痕走收件箱。**
