## EXP-008 `>>` 词法阻断

**原文主张**：`grow<List<T>>(v)` 被 `>>` 单 token 阻断，建议类型实参上下文拆分为两个 `>`；S1 附录 A 补条款。

**规范判定**：部分接受。附录 A 只有 `TypeArgList`（`:1666`）与“`<` 仅在能解析为类型实参且紧跟 `(` 时生效”（`:1775`），**没有** `>>` 拆分规则；用 `grep "类型实参上下文"` 只在专家/证据文件中命中，S1 原文无此条款。

**实现判定**：已落地，无需再改代码。

- `impl/internal/xfront/parser.go:121 splitAngleClose` 在类型实参上下文把 `>>` 拆成两个 `>`，不触碰移位路径（`:294-297`）。
- `go test ./internal/xfront -run TestNestedTypeArgs -count=1` → PASS；`go run ./cmd/xnpt 'grow<List<Int>>(v)'` → `(call (ident grow) <List<Int>> (ident v))`；`a >> b` 仍解析为 `(binary >> ...)`。
- 因此 G7 的“不可测”前提已解除；G7 的无限展开诊断另有 sema 用例。

**会签动作**：
1. 规范侧：S1 发新版本（v3.3.1 或 v3.4.0），在附录 A 文法说明补“类型实参上下文内，`>>` 按两个 `>` 处理；仅由尖括号配平触发”。
2. **缩小专家建议范围**：不需要拆 `>=`。类型实参后出现 `=` 的合法上下文不存在；把 `>=` 也拆会破坏比较语义。只写 `>>`。
3. E2 落地条款后，把 G7 用例从“不可测”改为常规回归。

**关门条件**：S1 新版本含上述条款；代码与测试保持现状即可。

## EXP-009 无目标类型闭包内的 `try`

**原文主张**：`var h = (Int x) -> { ... try ... }` 这类无目标类型闭包，规范未定案、实现不检查。

**规范判定**：**驳回“规范留洞”这一前提**。条款已经存在且明确：

- S1 §7.7 `:1155`：“闭包内 `try` 要求闭包的目标返回类型是 `Result<_, E>`；**没有目标类型且推断不出 `Result` 时是编译错误**。”
- S1 §2.7 `:474`：“没有目标类型的闭包字面量**不能用于 `var`**。”
- S1 §10.2 `:1478`：闭包内 `try` 错误从闭包返回，目标返回类型必须是 `Result`。

按原文给出的 `var` 例子，正确的规范结论是“本就非法”，不需要新增定案。真正的窄口径歧义只在“立即调用/其他无目标位置”的闭包上（§7.7 允许按首个 `return` 推断，§10.2 又要求目标类型），这需要澄清，但不是专家描述的那个洞。

**实现判定**：接受问题存在，且比原文更广：**无目标类型闭包体没有被类型检查**。

- `impl/internal/sema/ty.go:925-926` 对 `Lambda` 只返回 `key:"fn"`，不遍历体；`impl/internal/sema/error.go:184-188` 只在有目标函数类型时调用 `checkLambda`。
- 实测 1：`var h = (Int x) -> { return x }` 被 sema 放行（`run --interp` exit 0），违反 §2.7:474。
- 实测 2：`var h = (Int x) -> { Int v = try g(x); return Ok(v) }` 同样 exit 0，违反 §7.7:1155。
- 实测 3：`Int v = ((Int x) -> { return "str" })(1)` sema 无诊断，直到解释器报“非常量可调用表达式”，证明闭包体返回类型完全未检查。
- 现有 `TestERR01LambdaTry`（`impl/internal/sema/err01_test.go:412`）只覆盖“有目标类型 Int 必拒 / Result 必过”，未覆盖无目标形态。

**会签动作**：
1. **规范侧不改**：不新增“`var` + 无目标闭包”的定案，§2.7 已有；最多在 S1 新版本给立即调用闭包补一句澄清（推断期检查体，推断不出 `Result` 则报错）。
2. E2 实现侧：无目标闭包也必须遍历体做类型检查；`var` 初始化式无目标闭包按 §2.7 直接报错；补 3 个负向用例（`var` 无 try、`var` 含 try、立即调用体返回类型不符）。
3. 这条与 EXP-001 的推断管线同卡，不另开范围。

**关门条件**：上述 3 个最小程序在 sema 阶段报错且诊断位置非零；`TestERR01LambdaTry` 扩展为含无目标形态。
