## 决策摘要

- 类型按名义身份检查；对象种类与内存/派发规则见 0.4。
- 普通类采用静态继承：子类只复用父类字段和方法，不能覆写；多态只通过协议实现。
- 结构体只有值语义：只能承载值字段，禁止引用字段、`deinit` 和捕获 `self`；需要引用语义、身份或共享时使用 `class`。
- 协议只有方法签名；禁止协议字段、方法体、默认实现、泛型协议、关联类型、泛型方法和约束。
- 数据枚举项为 GC 单例；简单枚举内联整数；单例是 GC 全局根；所有枚举和单例都不实现协议。
- 枚举 `switch` 做穷尽性检查：无 `default` 时必须覆盖全部项；有 `default` 时免除。
- 内存管理能力由编译器与运行时全权负责：内存策略由编译器按第 15 节判定表决定，管理动作由运行时执行；源码不得表达引用强度、地址、指针或回收策略。
- 语言与 XDK 公共 API 不提供弱引用；弱表是运行时内部机制，只对 FFI 合同层开放（见内存管理方案 §16、§19、§22）。原 `weak` 字段修饰符移除，场景改用替代模式（15.8）。
- `@arc` / `@gc` 降为实现内部注解：源码不得出现，仅限实现预览使用，属实现边界内的非承诺入口（15.1.2）。
- 泛型在内存分析前单态化；`out` / `in` 只用于类；裸泛型按 `Box<Any>`。
- `factory` 是无实例的创建命名空间，可绑定同包或跨包的 `class` / `struct`；同包保留目标私有构造器访问，跨包只能使用目标公开成员。
- 私有字段的规范内部名统一为 `_name`。只有 `Int _name` 和 `private Int name` 两种声明，映射到同一字段；`private Int _name` 是编译错误。类内只能写裸 `_name`，`self._name` 和裸 `name` 都非法，局部变量/参数不能与 `_name` 同名。外部访问 `name` 和 `_name` 都报私有错误。
- 元组是第 1 部分 2.11 的内建值类型；全值元素元组可作 `struct` 字段，含引用元素的元组字段使拥有者按 GC 分析。
- 无访问器模式：字段直接读写，禁止 getter/setter 访问器模式与 property 语法（7.3）；计算与校验用动词方法。
- 主构造器（6.3）：`class Worker(final Int id)` 在类头部声明字段与构造器，参数绑定同名字段；仅 `class`，不与其他构造器混用。
- 函数统一规则：方法与顶层函数、构造器、Lambda 遵循同一套显式函数规则（第 1 部分 7.10）。
- 实现边界是发布门槛，不是“未强制”清单；未通过项阻止发布，不得静默降级。

## 0. 规范基础

### 0.1 范围

本方案规定 XNull 的对象模型：类型声明、继承、协议、结构体、枚举、单例、工厂类型、扩展、注解、泛型类型与方法、成员解析、派发、对象布局、生命周期和内存策略。

本方案不规定：

- 词法、基础类型、表达式、语句、闭包语法、包与导入、入口；见第 1 部分。
- `Result`、`try`、`defer` / `errdefer` 的基本语义；见第 1 部分第 10 节。
- 错误的观测、取消、超时和 `ErrorKind` 策略；见错误处理规范。
- C ABI、IPC 和跨语言所有权；见第 7 部分。
- XDK 包的完整 API；见第 6 部分。

### 0.2 与第 1 部分的关系

第 1 部分定义基础语法和类型系统；本方案在其上增加：

- 类型声明与对象身份；
- 值语义与引用语义的分界；
- 普通类的静态继承、协议多态与 vtable 动态派发；
- 协议方法签名合同与实现检查；
- factory 创建命名空间、同包私有构造器访问与跨包公开构造；
- 泛型类型实例化与型变；
- ARC / GC / stack 三种内存策略。

本方案使用第 1 部分的类型可赋值性、表达式、语句、闭包和入口规则。两篇冲突时，以本方案对对象语义的专门规定为准；基础语法仍以第 1 部分为准。

### 0.3 规范用语与一致性

**必须**、**禁止**、**应当**、**可以** 按 RFC 2119 语义使用。

实现必须接受所有满足本方案“必须”条款的源程序，并产生本方案规定的可观察行为；违反“禁止”条款的源程序必须被拒绝。文法可以接受某些语义非法的构造，但类型检查阶段必须拒绝，不得因为文法接受就视为合法。

实现可以提供扩展，但扩展必须显式启用；默认构建不得依赖扩展。同一源程序、同一实现版本、同一选项必须产生相同的诊断和运行结果。

### 0.4 对象模型摘要

| 种类 | 实例 | 继承 | 协议实现 | 派发 | 内存 | 身份 |
| --- | --- | --- | --- | --- | --- | --- |
| `class` | 引用对象 | 单父类；仅字段/方法复用 | 可以 | 类类型接收者静态；协议类型接收者动态 | ARC / GC；非逃逸纯值对象可栈分配 | 有 |
| `struct` | 值 | 禁止 | 禁止 | 静态 | 内联值；复制；不进入 ARC/GC | 无 |
| `protocol` | 无 | 继承协议 | 不适用 | 实现者 vtable | 不分配 | 无 |
| 简单 `enum` | 整数值 | 禁止 | 禁止 | 静态 | 内联整数 | 无 |
| 数据 `enum` | 枚举项对象 | 禁止 | 禁止 | 静态 | GC | 有 |
| `singleton` | 唯一全局实例 | 禁止 | 禁止 | 静态 | GC 全局根 | 有 |
| `factory` | 无 | 禁止 | 禁止 | 静态方法 | 不分配 | 无 |
| `extension` | 无 | 禁止 | 禁止 | 合并到目标类型；静态调用 | 不分配 | 无 |
| `@annotation` | 无 | 禁止 | 禁止 | 不适用 | 不分配 | 无 |

只有 `class`、`struct`、数据 `enum`、`singleton` 产生实际对象或值。`protocol`、`factory`、`extension`、`@annotation` 不产生独立对象。`class` 的类继承不产生类层级多态；通过协议类型调用才使用 vtable。

## 1. 类型声明总览

### 1.1 声明形式

```x
class Device : Base implements Ready, Secure { }
struct Point { }
protocol Ready { }
enum Color { }
singleton AppInfo { }
factory DeviceFactory for Device {
    static Device create(String name) { ... }
}
extension Device { }
@annotation Marker { }
```

- 类型声明只能位于包顶层；不支持嵌套类型、局部类型或匿名类型。
- 声明前缀是注解和修饰符；顺序为 `{ Annotation } { Modifier }`。
- 类型名和 `factory` 名在包内唯一；不得与预定义类型名、其他类型名、`factory` 名或类型参数冲突。
- 一个文件可以声明多个类型；声明顺序不影响可见性。
- 类型声明可以相互前向引用；递归限制见 1.5。
- 类型名使用 `PascalCase` 是规范写法，但命名不参与语义。
- 类型头、`factory` 头、方法头、构造器头和 `deinit` 头的 `{` 必须与头部同一行；换行会触发自动分号插入。

### 1.2 类型种类

| 关键字 | 语义 | 可实例化 | 可作为父类型 |
| --- | --- | --- | --- |
| `class` | 引用类型；单继承复用字段/方法，可实现协议 | `new` | 是 |
| `struct` | 纯值类型；只含值字段，可复制 | `new` | 否 |
| `protocol` | 名义方法签名合同 | 否 | 是（协议继承） |
| `enum` | 封闭枚举；简单枚举或数据枚举 | 否 | 否 |
| `singleton` | 预加载唯一实例 | 否 | 否 |
| `factory` | 绑定目标类型的创建命名空间 | 否 | 否 |
| `extension` | 给已有类型添加方法 | 否 | 否 |
| `@annotation` | 编译期注解类型 | 否 | 否 |

### 1.3 名义类型与类型身份

- 类型按声明身份检查，不做结构匹配。两个类即使字段和方法完全相同也不兼容。
- 类型身份由“声明 + 类型实参列表”确定；导入别名不改变身份。
- 同一包内不能声明两个同名类型；不同包的同名类型是不同类型。
- 泛型类型的不同实参列表是不同类型：`Box<Int>` 与 `Box<String>` 不同。
- 型变转换只在声明允许时成立；否则泛型类型不变。
- 类型参数只在声明内部是类型；声明外不能引用。
- 裸泛型名 `Box` 等价于 `Box<Any>`；这是擦除，不是“未知类型”。
- 类继承只复用字段和方法，不建立可覆写的动态类型槽；子类方法不能覆写父类同签名方法。
- 协议是唯一的多态入口；只有协议类型接收者通过 vtable 选择实现。
- 成员访问统一点语法：`.`、`?.`；没有 `->`、地址符、指针、智能指针或解引用语法。本方案中的“引用”仅指对象模型的隐式句柄/持有语义，见第 1 部分 0.7。
- 源码没有弱引用、地址符、指针或引用强度概念；ARC/GC 是运行时策略，不是源码类型。
- `factory` 是创建命名空间，不是值类型或引用类型；不能出现在变量、参数、字段、泛型实参、`is` / `as` 或 `Object` 中。

### 1.4 声明位置与顺序

- 类型声明和 `factory` 必须在包顶层；不能写在函数体、控制体、类或其他类型内部。
- 同包声明顺序无关；类型、函数和字段可以相互引用。
- 跨包引用必须通过 `import` 或完全限定名。
- 类型的可见性由第 1 部分 4.5 和本方案 7.3 规定。

### 1.5 递归类型

- 引用递归允许：`class Node { Node? next; }`。
- 容器递归允许：`class Tree { List<Tree> children; }`。
- 值包含递归禁止：`struct S { S value; }` 和 `struct S { S? value; }` 都是无限大小，必须报错。
- 结构体不能通过容器、引用字段或可空字段断开递归；需要递归结构时使用 `class`，例如 `class Node { Node? next; }`。
- 继承环禁止：`class A : B` 且 `class B : A` 是编译错误。
- 协议继承环禁止。
- 泛型递归实例化必须终止；编译器必须检测无限展开并报错。

### 1.6 修饰符

| 修饰符 | 适用位置 | 语义 |
| --- | --- | --- |
| `public` | 类型、成员 | 公开；默认可见性 |
| `protected` | 类型、成员 | 类型及其子类可访问；顶层等价于 `private` |
| `private` | 类型、成员 | 仅声明类型内部可访问 |
| `abstract` | 类 | 类不能实例化；抽象类不能声明抽象方法 |
| `final` | 类、方法、字段、局部变量、参数 | 类不可继承；方法不可覆写；字段/绑定只赋值一次 |
| `static` | 成员、顶层函数 | 类型级成员，不依赖实例 |
| `const` | 顶层字段、静态字段 | 编译期常量；隐式 `static`；不占实例布局 |
| `var` | 局部变量 | 类型推断；不是字段修饰符 |
| `out` / `in` | 类的泛型参数 | 协变 / 逆变；见 13.2 |

组合规则：

- `abstract final` 类非法。
- `abstract` 只能修饰类；方法不能写 `abstract`，所有类方法必须有方法体。
- 类方法默认不可覆写；方法级 `final` 合法但冗余，不改变派发。
- `final` 类不能是 `abstract`。
- `static` 方法不能使用 `self` / `super`。
- 语言不提供弱引用修饰符；原 `weak` 字段场景见 15.8 的替代模式。
- 私有字段的规范内部名统一为 `_name`。只有两种声明写法，且映射到同一字段：
  - `Int _name;`：声明名 `_name`，规范名 `_name`；
  - `private Int name;`：声明名 `name`，规范名 `_name`。
- `private Int _name;` 是编译错误：`private` 与 `_` 前缀不能同时使用。
- `_name` 声明中的 name 必须是 lowerCamelCase；`_`、`__x`、`_1` 非法。类内引用该字段只能写裸 `_name`；`self._name` 和裸 `name` 都是编译错误。局部变量、参数和类型参数不能声明为同类私有字段的规范名 `_name`。外部 `name` 和 `_name` 都报私有访问错误。`public` / `protected` 与 `_name` 同时出现是编译错误。
- `const` 字段不能与 `final` 重复修饰；`const` 已隐含 `static` 和只读；显式写 `static const` 合法且等价。
- 同一修饰符重复出现是编译错误；可见性修饰符互斥。
- 未知修饰符或修饰符用于错误位置是编译错误。
- `factory` 只接受顶层可见性修饰符；不能是 `abstract`、`final` 或 `static`。工厂方法必须写 `static`。

### 1.7 类型可见性

- 类型默认公开。
- 顶层 `private` / `protected` 类型不能被其他包导入；同包可见。
- 顶层 `protected` 不提供额外的继承语义，等价于 `private`。
- `factory` 的可见性按顶层声明处理；工厂方法可写 `public` / `private`，不能写 `protected`。
- `factory` 的 Target 必须从声明包可见；跨包 Target 受其顶层可见性约束。
- 类型和 `factory` 的可见性只影响编译期访问，不改变布局或内存策略。

## 2. 类 class

### 2.1 声明与语义

```x
class Device : Base implements Ready, Secure {
    String name = "device";

    Device(String name) {
        self.name = name;
    }

    void rename(final String next) {
        self.name = next;
    }
}
```

- `class` 声明引用类型；变量持有对象引用，多个变量可以指向同一对象。
- 类支持单继承；父类写在 `:` 后，最多一个。继承只复用父类字段和具体方法，不产生类层级多态。
- 协议写在 `implements` 后，可以多个。
- 没有父类时只写 `implements`；没有协议时只写 `:`。
- 所有类的引用都兼容引用根 `Object`；`Object` 是隐式引用根，不进入源码继承链。没有显式父类时不能使用 `super`。`Object` 没有用户可见成员，不能 `new`。
- 类可以实现协议；实现协议的类及其子类带协议 vtable。类类型接收者仍静态派发，只有协议类型接收者使用 vtable。
- 类不接受内存策略注解；`@arc` / `@gc` 是实现内部注解，不是源码入口（见 15.1.2）。
- 类可以是泛型；型变只允许 `out` / `in` 类型参数。
- 类可以是 `abstract` 或 `final`；`abstract` 类不能实例化且不能声明抽象方法；规则见 2.6。
- 类的实例字段、方法、构造器、`deinit` 见第 6 节。

### 2.2 字段

- 实例字段属于对象，每个实例一份；字段声明、默认值、`final` / `const` 和初始化顺序见 6.1。
- 字段名在继承链上必须唯一；禁止字段隐藏。
- 私有字段使用 `private` 修饰，或用 `_name` 前导下划线声明；规范名统一为 `_name`，类内只能写裸 `_name`，`self._name` 和裸 `name` 都是编译错误。访问规则见 5.8、7.4。
- 字段布局见 15.3。

### 2.3 方法

- 方法声明、签名、重载、`final` / `static` 和可见性见 6.2、6.8、7.3；方法不能写 `abstract`。
- 实例方法可以访问 `self` 和实例字段；静态方法不能。
- 类方法全部静态派发；协议类型接收者动态派发；`super` 静态派发；见 5.6。
- 方法体中的非限定名解析见 5.8。

### 2.4 构造器

- 构造器与类同名，不写返回类型；重载、可见性、`final` 字段赋值和 `self` 发布限制见 6.3；类头部的主构造器形式见 6.3。
- 没有声明构造器时生成无参构造器；有显式父类时调用 `super()`。
- 有显式父类时，显式 `super(...)` 必须是首个动作；字段初始化式在 `super` 后、构造器体前。
- 构造器内 `self.method()` 静态派发到当前类。
- `new C(args)` 规则见 2.7。

### 2.5 继承

- 单继承；父类可以继续有父类；继承链最终到达 `Object`。
- 父类不能是 `final`。
- 子类继承父类的字段和方法（受可见性限制），用于复用，不产生新的派发槽。
- 子类不能声明与父类同名的字段；字段名在整个继承链上唯一。
- 子类不能声明与任意祖先实例方法同签名的方法；同签名是编译错误，包括祖先的 `private` 方法。返回类型、可见性、`final` 均不改变该规则。
- 子类可以用不同参数列表声明同名方法，构成重载；重载不改变父类方法的静态绑定。
- 类方法全部静态绑定；不存在“子类覆写父类”的语义。通过父类或子类静态类型调用，都选择该静态类型对应的继承方法。
- `@Override` 不能标记类继承方法；它只用于协议实现检查。
- 子类可以继续实现协议；继承的公开实例方法可以满足协议要求，协议实现沿继承链传递。
- 子类可以调用 `super(...)`、`super.method()` 和可访问的 `super.field`。
- 子类构造器必须完成父类构造；`deinit` 链见 6.4。

### 2.6 抽象类与 final 类

- 抽象类不能 `new`；可以声明构造器供子类调用，用于共享字段、方法和构造逻辑。
- 抽象类不能声明抽象方法；抽象类中的每个实例方法都必须有方法体。
- 抽象类可以实现协议，但必须同时提供协议全部方法的具体实现；否则不得声明 `implements`，由具体子类声明协议并实现。
- `final` 类不能有子类；`final` 方法合法但冗余，因为类方法本来不可覆写。
- `final` 方法可以满足协议要求。
- `abstract final` 类非法。
- 抽象类可以有静态成员和具体方法。

### 2.7 类实例化

```x
Device device = new Device("camera-01");
```

- `new` 返回类引用；对象身份在分配时确定。
- `new` 按内存策略分配：stack、ARC 或 GC；语言层面始终是引用语义。
- 非逃逸、只有值字段、无 `deinit`、未捕获 `self` 的局部对象可以栈分配；这是优化，不改变引用语义。
- `new` 的参数按构造器重载解析；无匹配构造器是编译错误。
- 分配失败是 panic；构造器 panic 时对象不会发布，进程终止。
- `new` 不能用于 `abstract` 类、`protocol`、`enum`、`singleton`、`@annotation`。

### 2.8 类与 Object

- 所有引用类型都可以赋给 `Object`；`Object` 变量可以持有类、协议、单例、数据枚举项、闭包、数组、容器、`String`、`Text`、`Bytes`、`StringBuilder` 等引用。
- `Object` 不能直接实例化。
- `Object` 的值可以为 `null`；`null` 赋给 `Object` 合法。
- 从 `Object` 取回具体类型必须使用 `as` / `as?`；失败是 panic 或 `null`。
- 值类型进入 `Object` 前必须装箱为 `Any`。
- `Object` 的 `==` / `===` 都是引用身份比较。

## 3. 结构体 struct

### 3.1 声明与语义

```x
struct Point {
    Int x = 0;
    Int y = 0;

    Int sum() {
        return self.x + self.y;
    }
}
```

- `struct` 声明纯值类型；每个值内联存储，赋值、传参和返回复制整个值。
- 结构体不参与继承，不实现协议；不能写父类或 `implements`。
- 结构体可以有实例字段、实例方法、静态成员和构造器；不能声明 `deinit`。
- 结构体不能在方法或闭包中捕获 `self`；结构体只有值字段，不存在内存策略或弱引用字段问题。
- 结构体可以是泛型；泛型参数不变，不支持 `out` / `in`。
- 结构体的每个类型实参必须是 3.2 的值字段类型；引用类型、`Result` 或其他非值字段类型实参在类型检查阶段拒绝。
- 结构体不能是 `abstract` 或 `final`；不能作为父类，也不能作为协议类型。
- 需要引用语义、对象身份、共享状态、协议多态或 `deinit` 时，必须使用 `class`。

### 3.2 值字段限制

结构体实例字段必须是值字段。允许的字段类型仅限：

- `Bool`、`Byte`、`Short`、`Int`、`Long`、`UByte`、`UShort`、`UInt`、`ULong`、`Int128`、`UInt128`；
- `Float`、`Double`、`Char`；
- 简单枚举；
- 另一个满足本节限制的 `struct`；
- `T?`，其中 `T` 是上述值字段类型；可选值必须内联，不得引入引用。
- 元组 `(T1, T2, ...)`，当且仅当每个元素类型均为本节允许的值字段类型（第 1 部分 2.11）。

以下类型不能作为结构体实例字段：

- `String`、`T[]`、`List`、`Set`、`Map`、`Text`、`Bytes`、`StringBuilder`；
- `Any`、`Object`、协议、函数类型、`class`、数据枚举、单例；
- `Result`；
- 含引用元素的元组；
- 可空类型 `T?` 且 `T` 不是允许的值字段类型；
- 任何含引用字段或递归值包含的 `struct`。

结构体实例字段按声明类型递归检查；值包含环在 1.5 已禁止。泛型结构体在实例化后按替换结果检查字段；任一实例字段含引用类型即编译错误。静态字段不受 3.2 限制，按 7.1 作为类型级存储处理。结构体没有“可复制判定”分支，所有合法结构体都是可复制的值。

### 3.3 复制语义

- 赋值、传参、返回、存入数组/容器、结构体字段初始化都复制整个值；副本与原值独立。
- 修改副本不影响原值；不存在共享同一份字段存储的 `struct` 变量。
- 结构体没有对象身份；`==` 按字段逐值比较；`===` 与 `==` 相同。
- 不可作为 `Map` / `Set` 键（第 1 部分 9.5 的键限制）。
- 字段按值内联存储；布局见 3.6。
- 闭包捕获结构体变量时，cell 保存该结构体值；外部变量与闭包共享 cell，但不会产生对象身份。
- 结构体复制不触发 ARC/GC，不调用 `deinit`。

### 3.4 方法与 self

- 结构体的 `self` 指接收者值的存储槽；不是对象引用。
- 方法写入 `self.field` 或调用 `self` 的写入方法时，该方法视为“写入方法”。
- 写入方法要求接收者可赋值：局部变量、可写字段、数组/List 元素。对临时值或只读位置调用写入方法是编译错误。
- 只读方法可以用于任意接收者。
- `final` 字段在初始化后不能写入；写入方法也不能绕过。
- 结构体方法不支持 `super`；结构体没有父类。
- 结构体方法全部静态派发；结构体没有 vtable。
- 结构体方法不得在闭包中捕获 `self`；需要捕获接收者时改用 `class`。

### 3.5 构造器

- 结构体构造器与结构体同名，不写返回类型；可以重载。
- `new Point(1, 2)` 创建结构体值；赋值或返回时复制该值。
- 没有声明构造器时，生成无参构造器：执行字段初始化式并结束。
- `final` 字段必须在初始化式或构造器体中恰好赋值一次。
- 结构体没有 `deinit`；资源清理由持有该值的代码显式完成。
- 结构体构造失败按第 1 部分错误规则处理；不产生可观察的对象身份。

### 3.6 布局与 ABI

- 字段按声明顺序排列，每个字段按 8 字节对齐。
- 标量值字段占一个 8 字节槽位；嵌套结构体字段内联，大小向上取整到 8 字节。
- 结构体没有对象头、没有 vtable 指针、没有 ARC/GC 头。
- 结构体方法不进入 vtable；没有动态派发。
- 语言语义按值复制；ABI 可以使用“地址 + sret”传递。这里的“地址”是编译器内部调用约定术语，不是源码地址符/指针语法；ABI 传递地址时，被调用方仍必须按语言语义复制，不能把地址暴露为共享身份。

### 3.7 struct vs class

| 维度 | `struct` | `class` |
| --- | --- | --- |
| 语义 | 纯值类型；始终复制 | 引用类型 |
| 字段 | 只能是标量、简单枚举、`struct` 或其可空值 | 任意合法字段，受内存策略约束 |
| 赋值/传参 | 复制整个值 | 传对象句柄，不复制对象 |
| 身份 | 无 | 有对象身份 |
| 继承 | 禁止 | 单父类；只复用字段/方法 |
| 协议 | 禁止 | 可以；协议类型接收者动态派发 |
| 派发 | 静态 | 类类型静态；协议类型动态 |
| 内存 | 内联/复制；不进入 ARC/GC | ARC/GC；非逃逸纯值对象可栈优化 |
| 生命周期 | 跟随持有它的值或容器 | 跟随引用计数 / GC 可达性 |
| 典型用途 | 坐标、尺寸、颜色、范围、纯值配置快照 | 实体、服务、共享状态、多态、需要 `deinit` 的对象 |

选择规则：需要独立副本且字段都是值类型时用 `struct`；需要身份、共享、协议多态、生命周期回调或引用字段时用 `class`。

## 4. 协议 protocol

### 4.1 声明

```x
protocol Ready {
    Bool ready();
}

protocol Secure : Ready {
    Bool secure();
}
```

- 协议是名义方法签名合同；只有声明 `implements` 的类才实现协议。
- 协议可以继承一个或多个协议，写在 `:` 后，逗号分隔。
- 协议不能继承类；协议继承环是编译错误。
- 协议不能实例化，不能 `new`。
- 协议本身不分配对象；协议类型的变量持有具体实现对象的引用。
- 协议只能声明实例方法签名；协议体中的字段、方法体、默认实现都不合法。
- 协议不支持泛型参数、关联类型、静态方法、构造器、`deinit`、泛型方法或类型约束。
- 协议可以是空协议；任何类都可以 `implements` 空协议。

### 4.2 方法签名

- 协议方法默认公开；不能写 `private` / `protected`。
- 协议方法只写签名，以 `;` 结束，不写方法体。
- 实现类必须提供同签名方法；协议本身不生成任何实现。
- 协议方法不能是 `static`、`final`、`abstract` 或泛型。
- 协议不能声明字段、属性、构造器或 `deinit`。
- 协议方法不能访问字段，因为协议没有字段。

### 4.3 实现检查

类实现协议时：

- 类及其父协议的全部方法都必须有实现。
- 实现方法必须是实例方法、公开可见、签名完全相同：名称、参数类型、返回类型一致。
- 继承自父类的公开实例方法可以满足协议要求；子类继承该协议实现。
- 扩展方法不能作为协议实现；协议实现必须来自类声明或继承方法。
- 类不能通过抽象方法延迟协议实现；抽象类只有在提供全部实现时才能声明 `implements`。
- 一个类可以实现多个协议；相同签名且返回类型相同的重复要求由同一个方法满足。
- 两个协议要求同名同参数但返回类型不同，类无法同时实现，必须报错。
- 类可以有多余方法；不影响实现检查。
- 仅成员相同但不写 `implements` 不构成实现。

`@Override` 可选；写了必须能对应协议中的同签名方法，否则报错。`@Override` 不能标记父类方法，因为类继承不存在覆写。

### 4.4 协议类型与可赋值性

- 协议类型是引用类型；变量可以为 `null`。
- 类到已实现协议是隐式向上转换；子类继承父类的协议实现。
- 协议到父协议是隐式向上转换。
- 协议到类、类到未实现协议必须显式 `as` / `as?`。
- 协议变量强持有具体对象：ARC 对象被 retain，GC 对象成为根；协议本身不产生包装对象。
- 协议变量可以赋给 `Object`；可以装箱为 `Any`。
- 类字段可以声明为协议类型 `P?`，赋值为实现对象或 `null`。协议本身不能声明字段。
- 通过协议变量调用方法走 vtable；只能调用协议声明的方法。
- 通过类类型变量调用同一对象的方法仍静态派发，不因对象实现了协议而改变。

### 4.5 协议内存规则

- 协议没有实例，不单独分配对象。
- 实现协议的类及其子类带协议 vtable 头，用于协议类型接收者的动态派发；vtable 头是布局，不决定 ARC/GC。
- 具体对象的内存策略仍由字段图与第 15 节判定表决定。
- 协议类型作为字段时，引用图不精确，拥有该字段的类型按 GC 处理。
- 协议类型出现在容器、`Any`、闭包环境、任务环境中时，相关对象按 GC 处理。
- 协议变量是强持有；不要把它当成“借用视图”而省略生命周期管理。

### 4.6 协议限制

- 不支持泛型协议。
- 不支持关联类型、协议泛型方法、`where` 子句或类型约束。
- 不支持协议静态要求。
- 不支持协议字段、属性或存储语义。
- 不支持协议默认实现、方法体或扩展协议。
- 不支持 `new` 协议。
- 不支持协议作为父类。
- 不支持结构体、枚举、单例实现协议。

## 5. 继承、协议实现与派发

### 5.1 合法继承形式

| 声明 | `:` | `implements` |
| --- | --- | --- |
| `class` | 0 或 1 个类 | 0 个或多个协议 |
| `protocol` | 0 个或多个协议 | 禁止 |
| `struct` | 禁止 | 禁止 |
| `enum` | 禁止 | 禁止 |
| `singleton` | 禁止 | 禁止 |
| `extension` | 禁止 | 禁止 |
| `@annotation` | 禁止 | 禁止 |

必须拒绝：

- `class C : P` 且 `P` 是协议：父类不能是协议。
- `class C implements Base` 且 `Base` 是类：只能实现协议。
- 父类是 `final` 类。
- 父类是 `struct`、`enum`、`singleton`、`@annotation`、`extension`。
- 继承环或协议继承环。
- 直接 `implements` 重复协议；通过父类继承的重复实现允许，只保留一份实现。
- 协议继承类。
- 结构体声明 `implements`。
- 枚举、单例、扩展、注解声明继承或实现。
- 子类声明与任意祖先实例方法同签名的方法；类继承只复用，不允许覆写。
- 子类声明与祖先同名字段。

### 5.2 可赋值性与转换

- `Sub` 可赋给 `Base`，当 `Sub` 继承 `Base`。
- `C` 可赋给 `P`，当 `C` 声明 `implements P` 或继承自已实现 `P` 的类。
- `P` 可赋给 `Q`，当 `P` 继承 `Q`。
- 类、协议、单例、数据枚举项、闭包、数组、容器可赋给 `Object`。
- 值类型必须装箱为 `Any` 后才能赋给 `Any` / `Object`。
- 父类到子类、协议到类、`Object` 到具体类型必须显式 `as` / `as?`。
- `as` 失败 panic；`as?` 失败返回 `null`。
- `is` 检查动态类型或协议实现；`null` 返回 `false`。
- 类到父类的转换不改变派发方式；通过父类静态类型调用仍选择父类方法。
- 类到协议的转换启用协议 vtable 派发；转换回类类型后恢复静态派发。
- 不支持结构化转换；成员相同不代表类型兼容。

### 5.3 方法复用与重载

复用：

- 子类直接继承父类实例方法；继承方法保持原有签名、可见性和实现。
- 子类不能声明与任意祖先实例方法同签名的方法；不存在覆写、协变返回或 `@Override` 类继承检查。
- 父类方法与子类方法同签名时，编译器必须拒绝子类声明，而不是按静态类型选择不同实现。
- 方法级 `final` 合法但冗余；所有类方法都不可覆写。
- `private` 方法不被子类继承，但方法签名仍占用继承链名称；子类不能声明同签名方法。
- `@Override` 只能标记协议实现；标记父类方法或找不到协议方法时报错。

重载：

- 方法签名由名称和参数类型列表组成；返回类型、参数名、`final`、可见性不参与签名。
- 同一类型内不能有两个实例方法签名相同；也不能有一个实例方法和一个静态方法签名相同。
- 子类可以用不同参数列表声明同名方法，构成重载；同签名声明被拒绝。
- 调用时按接收者静态类型收集候选：当前类型声明的方法和继承方法共同参与重载解析。
- 多个候选适用时是歧义错误；没有候选是编译错误。

### 5.4 super

- `super(...)` 用于父类构造；必须是构造器的首个动作。
- `super.method()` 调用直接父类实现；静态派发；类继承不存在子类覆写。
- `super.field` 访问父类字段；受可见性限制；父类私有字段不可访问。
- 没有显式父类时不能使用 `super`。
- `super` 不能用于静态方法。
- `super` 不能出现在闭包内；需要父类行为时在方法内调用 `super.method()`，不要把 `super` 捕获到闭包。

### 5.5 构造与析构链

构造与析构的完整顺序见 6.5。继承相关规则：

- 构造时先完成父类构造，再执行当前类字段初始化式，最后执行构造器体。
- 构造完成前对象不可发布。
- `deinit` 先执行派生类，再沿父类链；显式 `super.deinit()` 接管剩余链。

### 5.6 派发模型

派发分两类：

| 类别 | 适用 | 规则 |
| --- | --- | --- |
| 静态派发 | 类、结构体、简单枚举、数据枚举、单例、构造器、静态方法、`super` | 按静态类型或显式类型名选择实现 |
| 动态派发 | 协议类型接收者 | 通过 vtable 槽位选择运行时实现 |

关键规则：

- 类继承不产生 vtable。
- 类类型接收者上的实例方法调用全部静态派发，包括 `self.method()`。
- 实现协议的类（直接或通过继承）带协议 vtable；vtable 只保存协议要求的方法槽位。
- 类类型接收者调用协议方法时仍静态派发；只有接收者静态类型是协议时使用 vtable。
- 子类不能覆写父类方法；协议实现由类声明或继承方法提供，子类继承同一个实现。
- `super.method()` 始终静态调用直接父类实现。
- 构造器内 `self.method()` 静态派发到当前类，避免调用未完成构造的运行时类型。
- `deinit` 内 `self.method()` 静态派发到当前类，避免访问已释放的派生类字段。
- 协议类型接收者只能调用协议声明的方法；通过 vtable 动态派发。
- `Any` 接收者必须先 `as` 到具体类型或协议，再调用。
- 扩展方法合并进目标类型的静态方法集合；扩展方法不进入 vtable，不参与协议实现。

类继承静态派发示例：

```x
class Base {
    Int f() { return 1; }
}

class Derived : Base {
    Int g() { return 2; }
}

Base value = new Derived();
Int x = value.f();
```

`Derived` 继承 `Base.f`，没有覆写；`value.f()` 按静态类型 `Base` 选择 `Base.f`，`x` 为 `1`。

协议动态派发示例：

```x
protocol Value {
    Int get();
}

class One implements Value {
    Int get() { return 1; }
}

class Two implements Value {
    Int get() { return 2; }
}

Value value = new Two();
Int x = value.get();
```

`value` 的静态类型是协议 `Value`，`value.get()` 通过 vtable 选择 `Two.get`，`x` 为 `2`。若把 `value` 转回 `One` / `Two` 类类型，调用恢复静态派发。

### 5.7 vtable 布局

- 实现协议的类对象在载荷起始位置放协议 vtable 指针；字段在 vtable 指针之后。
- vtable 只包含协议方法槽位，不包含普通类方法、静态方法、构造器、`deinit` 或扩展方法。
- vtable 以协议方法签名为索引；同一签名在整个程序中对应同一槽位。
- 同一实现签名被多个协议要求时复用同一槽位；不同实现类在同一槽位放各自实现。
- 子类不能覆写协议实现，继承父类实现的槽位保持不变；子类新增协议时追加对应槽位。
- 槽位分配必须确定：同一程序、同一实现版本、同一编译选项产生相同槽位。
- 分配头保存类型描述符；`is` / `as` 使用类型描述符检查动态类型和协议实现。
- 没有实现协议的类没有 vtable 指针；其动态类型检查依赖分配头中的类型描述符；栈对象使用静态类型检查。
- vtable 槽位编号是实现细节，不暴露给源码；跨模块 ABI 需要稳定槽位规则。
- 内存策略不影响 vtable 存在与否；vtable 只由协议实现关系决定。

### 5.8 成员解析

在实例方法、构造器或 `deinit` 内，非限定名按以下顺序解析：

1. 局部变量、参数、类型参数；
2. 当前类及祖先中可访问的实例字段；
3. 当前类及祖先的实例方法（用于非限定调用）；
4. 当前类及祖先的静态成员；
5. 当前包的顶层声明、导入符号、完全限定名。

规则：

- 实例字段可以非限定访问：`count = 1;` 与 `self.count = 1;` 等价。
- 局部变量或参数与字段同名时，局部名优先并遮蔽字段；要访问被遮蔽的字段，写 `self.field`。
- 赋值、读取、写入方法和构造器遵循同一遮蔽规则；不得根据左值/右值切换解析顺序。
- 字段和方法不能同名；同一类型及继承链内名称冲突是编译错误。
- 字段名在整个继承链上唯一，包括 `private` 字段；子类不能声明同名字段。
- 私有字段的规范名统一为 `_name`；`private name` 和 `_name` 都映射到该字段。类内只能写裸 `_name`，`self._name` 和裸 `name` 都是编译错误。私有字段只在声明类内部可访问；外部 `name` 和 `_name` 都报私有错误。子类不能访问父类私有字段，但该字段的基名仍占用继承链名称。
- 当前类的私有字段规范名 `_name` 不能被同类局部变量、参数或类型参数复用；否则编译错误。
- 若当前类或祖先声明了同名字段但当前上下文不可访问，非限定引用报可见性错误，不回退到外层同名符号。
- 父类 `protected` 字段按 7.3 的规则访问；`super.field` 访问父类字段。
- `super.method()` 访问直接父类；`super.field` 访问父类字段。
- 静态上下文没有 `self` / `super`；非限定名只解析静态成员、顶层声明和导入。

## 6. 成员、构造与销毁

### 6.1 字段

```x
class Worker(final Int id) {     // 主构造器：声明并绑定同名字段
    Int _retries = 0;
    Node? parent = null;
}
```

- 字段声明：`[可见性] [static] [final | const] Type name [= expression]`。
- 实例字段默认值：

| 类型 | 默认值 |
| --- | --- |
| `Bool` | `false` |
| 整数 | 0 |
| `Float` / `Double` | 0.0 |
| `Char` | `'\0'` |
| 引用类型 | `null` |
| 值类型 `T?` | `null` |
| `struct` | 按字段递归零值；含无默认值字段时必须显式初始化 |
| 简单枚举 | 无默认值；必须显式初始化或赋值 |
| `Result` | 无默认值；必须显式初始化或赋值 |
| `final` 字段 | 必须恰好赋值一次 |

- 字段初始化式在父类构造完成后、构造器体之前按声明顺序执行。
- 字段初始化式不能引用 `self`、其他实例字段或构造器参数；可以引用常量、静态成员和顶层函数。
- `final` 字段：有初始化式时不能在构造器体再赋值；没有初始化式时必须在每条构造路径上恰好赋值一次。
- `const` 字段隐式 `static` 且只读；必须有编译期常量初始化式；不占实例布局。
- 语言不提供弱引用字段；原 `weak` 字段场景改用双向强引用（环由策略分类回收）或 ID/注册表模式，见 15.8。
- 实例字段类型必须满足 3.2 的值字段限制。
- 静态字段属于类型，不属于实例；规则见 7.1。
- 字段名在整个继承链上必须唯一；禁止字段隐藏。
- 私有字段使用 `private` 修饰，或用 `_name` 前导下划线声明；规范名统一为 `_name`，类内只能写裸 `_name`，`self._name` 和裸 `name` 都是编译错误；见 5.8、7.4。

### 6.2 方法

```x
class Counter {
    Int value = 0;

    Int next(final Int step) {
        self.value = self.value + step;
        return self.value;
    }
}
```

- 方法声明：`[可见性] [static] [final] ReturnType name(parameters) Block`。
- 返回类型必须在方法名前；无返回值写 `void`。
- 方法与顶层函数、构造器、Lambda 遵循同一套函数规则（第 1 部分 7.10）：参数只有类型和名字（可写 `final`），不支持默认参数、命名实参、可变参数；花括号体；显式返回类型。方法独有的差异是接收者与派发方式（5.6）。
- 实例方法可以访问 `self`、实例字段和实例方法；静态方法不能。
- 非 `void` 方法的所有正常路径必须返回值；`throw` 终止的路径不需要。
- 方法不能写 `abstract`；所有类方法必须有方法体。
- `final` 方法合法但冗余，因为类方法本来不可覆写。
- 方法可以重载；签名规则见 6.8。
- 方法体中的非限定名解析见 5.8。
- 类方法在闭包中捕获 `self` 时，接收者必须堆分配；栈分配被禁止。
- 结构体方法不得在闭包中捕获 `self`；需要捕获接收者时改用 `class`。
- 类类型接收者的实例方法静态派发；协议类型接收者走 vtable，见 5.6。

### 6.3 构造器

- 构造器名与类型名相同；不写返回类型；可以重载；可以写 `public` / `protected` / `private`。
- **主构造器**：写在类头部的构造器形式 `class Worker(final Int id, final String name) { }`，是"声明同名字段 + 声明同名构造器"的缩写：
  - 主构造器参数必须写 `final`；每个参数同时声明一个同名字段，字段类型即参数类型；
  - 绑定动作等价于在 `super(...)` 之后、主构造器体之前，按声明顺序把每个参数赋给同名字段；`final` 字段因此恰好赋值一次；
  - 主构造器体可以省略或写普通语句；体中可以读取已绑定的字段；
  - 有主构造器时不再生成无参构造器，且不能再声明其他构造器（普通构造器与主构造器不混用）；
  - 主构造器声明的字段遵守字段通用规则（6.1）：默认可见性、`final` 恰好赋值一次、字段名继承链唯一；
  - 主构造器的可见性按构造器规则：默认公开，可在参数列表前不写——需要私有构造器时改用普通构造器形式；
  - 仅 `class` 支持主构造器；`struct` / `singleton` / `enum` / `factory` 不支持。
- 类构造器规则见 2.4；结构体构造器规则见 3.5。
- 没有构造器时生成无参构造器；有构造器时不再生成。
- 有显式父类时，显式 `super(...)` 必须是首个动作；没有显式调用时插入 `super()`；父类没有可访问无参构造器时是编译错误。没有显式父类时不插入 `super`，隐式 `Object` 根由运行时处理。
- 字段初始化式在 `super(...)` 之后、构造器体之前执行。
- `final` 字段必须恰好赋值一次；字段初始化式和构造器体不能同时赋值。
- 构造器可以执行 `return;` 提前结束，但每条路径上所有 `final` 字段必须已赋值；不能 `return value`。
- 构造完成前，`self` 不能作为值传递、捕获、存入容器或字段；成员访问允许。通过 `self` 调用的实例方法也受同一发布限制，被调用方法不得把 `self` 传出。
- 构造器内 `self.method()` 静态派发到当前类。
- 构造器 panic 时对象不会发布，进程终止；不执行 `deinit`。
- `new` 按 2.7 / 3.5 实例化。

### 6.4 deinit

```x
class Worker {
    void deinit() {
        self.parent = null;
    }
}
```

- `deinit` 只能出现在 `class` 或 `singleton` 中；`struct`、`enum`、`factory`、`protocol` 不能声明 `deinit`。
- `deinit` 不能是 `static`，不能有参数，必须返回 `void`，不能有可见性修饰符。
- 每个类或单例最多一个 `deinit`；不能重载。
- `deinit` 不能显式调用，除在 `deinit` 内调用 `super.deinit()`。
- 派生类 `deinit` 默认自动调用父类 `deinit`；显式 `super.deinit()` 接管剩余父类链，编译器不得再自动调用父类 `deinit`。
- `deinit` 执行时字段仍然有效；运行时在 `deinit` 链完成后释放仍然非空的引用字段。
- 在 `deinit` 中把引用字段置 `null` 可以提前释放该字段；运行时不会重复释放。
- 指向对象的弱引用在 `deinit` 前清除；`deinit` 内的弱字段可能已经是 `null`。
- `deinit` 内 `self.method()` 静态派发到当前类。
- `deinit` 不能发布 `self`、不能把 `self` 存入全局/容器/闭包、不能返回 `self`；禁止对象复活。
- ARC 对象在计数归零时确定调用 `deinit`；GC 对象在清扫时调用，时机不确定。
- 进程退出、`panic`、`throw` 不保证调用 `deinit`；文件、句柄、任务组等资源必须在使用点显式关闭。
- 单例的 `deinit` 不作为清理保证；单例生命周期跟随进程。

### 6.5 初始化顺序总表

对象构造：

1. 分配内存并清零。
2. 安装类型描述符；实现协议的类安装协议 vtable 指针。
3. 有显式父类时调用父类构造器。
4. 按声明顺序执行当前类实例字段初始化式。
5. 执行构造器体（`super(...)` 之后）。
6. 构造完成，`self` 可以发布。

结构体构造：

1. 按字段声明顺序求值初始化式。
2. 在接收者存储中写入字段值。
3. 构造完成；值可以在赋值/传参/返回时复制。

对象析构：

1. 清除弱引用。
2. 执行派生类 `deinit`。
3. 执行父类 `deinit` 链（显式或自动）。
4. 释放剩余引用字段。
5. 回收内存。

程序启动：

1. 运行时和 GC 初始化。
2. 顶层字段、静态字段置零。
3. 按包依赖顺序执行顶层/静态字段初始化式。
4. 按包依赖顺序初始化单例。
5. 调用 `main`。

### 6.6 失败处理

- 分配失败是 panic；进程终止。
- 构造器 `panic` / `throw` 时对象不发布，不执行 `deinit`，进程终止。
- `deinit` 中 `panic` / `throw` 直接终止进程；不保证其余清理。
- `deinit` 不得依赖其他对象的 `deinit` 顺序；跨对象清理必须显式协调。
- 资源清理使用显式关闭或错误处理规范的结构化清理机制；`deinit` 只作为最后兜底。

### 6.7 名称解析与私有字段

名称解析见 5.8；私有字段的声明和访问见 7.4。字段和方法不能同名。实例字段可以非限定访问；局部变量或参数同名时遮蔽公开字段，使用 `self.field` 访问公开字段；私有字段只能裸写规范名 `_name`，不能用 `self._name`；`super.field` 访问父类公开字段。

### 6.8 重载与签名

签名由以下组成：

- 方法名；
- 参数类型列表；
- 实例或静态类别。

不参与签名：

- 返回类型；
- 参数名；
- `final` 参数修饰；
- 可见性；
- 泛型参数名；
- 方法体。

规则：

- 同一类型内不能有两个实例方法签名相同；不能有一个实例方法和一个静态方法签名相同。
- 返回类型不同不构成重载；只改返回类型是编译错误。
- 参数数量或类型不同可以重载。
- 子类不能声明与祖先同签名的实例方法；不同参数列表构成重载。
- 泛型方法的类型参数数量不用于区分重载；只按参数类型解析。
- 重载解析失败、歧义或没有候选时是编译错误。
- `@Override` 只能对应协议的同签名方法；标记父类方法或找不到协议方法是编译错误。

## 7. 静态成员与可见性

### 7.1 静态字段

```x
class Counter {
    static Int count = 0;
    static final Int limit = 10;
    static const Int start = 0;
}
```

- 静态字段属于类型，不依赖实例；每个类型一份。
- 静态字段在程序启动时置零，再按包/文件/声明顺序初始化；规则与第 1 部分 4.3 相同。
- 静态字段是全局根：ARC 引用被 retain，GC 引用被追踪。
- 静态字段不能使用类的泛型参数；`static T value` 是编译错误。
- `static final` 字段必须在声明处初始化一次；语言不提供静态初始化块，因此不支持后置赋值。`static const` 要求编译期常量。
- 静态字段通过类型名访问：`Counter.count`；通过实例访问 `counter.count` 是编译错误。
- 静态字段初始化式可以读取已经初始化的静态字段；读取尚未初始化的字段得到零值。
- 结构体、数据枚举、单例可以有静态字段；简单枚举、协议、扩展、注解不能有静态字段。

### 7.2 静态方法

- 静态方法不依赖实例；不能使用 `self` / `super`。
- 静态方法可以访问静态字段、静态方法、顶层声明和导入符号；不能访问实例字段或实例方法。
- 静态方法不参与动态派发；子类同名静态方法隐藏父类静态方法，调用按显式类型名解析。
- 静态方法可以重载；签名规则同 6.8。
- 静态方法可以是泛型方法；类型参数规则见 13。
- 静态方法不能是 `abstract`；`final` 对静态方法没有额外语义。

### 7.3 可见性

- 成员默认公开；可以写 `public` / `protected` / `private`。
- `public`：任何可见类型的地方都可访问。
- `protected`：声明类型及其子类可访问；必须通过 `self`、`super` 或静态类型为当前类/子类的表达式访问；不能通过父类类型引用访问另一个实例的受保护成员。
- `private`：仅声明类型内部可访问；子类不可访问。私有字段规范名为 `_name`；`_name` 和 `private name` 两种声明映射到该字段，`private _name` 是编译错误。类内只能裸写 `_name`，`self._name` 非法。外部 `name` 和 `_name` 都报私有错误。同包绑定 Target 的 `factory` 按 10.3 获得 Target 私有构造器和私有静态成员的创建访问，这是唯一例外。
- 类方法不能覆写，因此不存在“覆写降低可见性”的规则；协议实现方法必须公开。
- 构造器可以写可见性；`new` 受构造器可见性约束。
- 静态成员遵守相同可见性规则。
- 可见性只做编译期检查，不改变字段布局、ARC/GC 策略或 retain/release。
- 没有包级私有可见性；同包非子类不能访问 `protected` 成员。
- **无访问器模式**：类不提供 getter/setter 访问器方法模式，也不提供自定义 property get/set 语法；公有字段就是默认属性访问，字段访问本身就是属性访问。
- 只有计算值、校验、日志、惰性初始化或私有状态对外暴露时，才写显式动词方法（6.2）；方法名表达行为，不是访问；这不是字段访问的默认要求。
- 标准库容器的 `get` / `set` / `at` 是集合 API 的动词方法（第 1 部分 9.1），不属于访问器模式。

### 7.4 私有字段与规范名

私有字段的基名是去掉一个前导 `_` 后的名称；规范内部名统一为 `_name`。只有两种声明写法，且映射到同一字段：

- `Int _name;`：声明名 `_name`，基名 `name`，规范名 `_name`；
- `private Int name;`：声明名 `name`，基名 `name`，规范名 `_name`。

`private Int _name;` 是编译错误：`private` 与 `_` 前缀不能同时使用。

例如 `private Int limit = 10;` 的基名是 `limit`，规范名是 `_limit`；类内只能写 `_limit`。写 `self._limit` 或裸 `limit` 都是编译错误。外部访问 `account.limit` 和 `account._limit` 都报私有错误。

规则：

- `_name` 声明中的 `name` 必须是 lowerCamelCase；`private name` 中的 `name` 遵循普通字段命名。基名不能以下划线开头；`_`、`__x`、`_1` 不能作为基名。
- `_name` 适用于实例字段和静态字段；不适用于方法、构造器、局部变量、参数或类型名。
- `private Int _name;` 是编译错误；显式 `private` 只能声明 `name`，`_` 前缀只能用于不带 `private` 的 `_name` 声明。
- `public` / `protected` 与 `_name` 同时出现是编译错误。
- 声明类内部只能裸写规范名 `_name` 读写；`self._name` 和裸 `name` 都是编译错误。
- 同类局部变量、参数或类型参数不能使用规范名 `_name`；出现同名声明是编译错误，避免私有字段失去可访问名称。
- 父类私有字段在子类不可访问；`super._name` 也不能绕过私有可见性。
- 字段基名在整个继承链上唯一；公开 `x`、`_x`、`private x` 都占用基名 `x`，不能同时声明。
- 子类不能访问父类私有字段；父类私有字段的基名仍占用继承链名称。
- `private final Int id;` 在构造器中写 `_id = id`；基名是 `id`，规范名是 `_id`，不能用 `self._id`。
- 私有字段不产生额外字段、存储或布局槽位；内存中只有一个字段。
- 私有字段仍然是引用字段时，参与 ARC/GC 扫描和 retain/release。

```x
class Account {
    private Int balance;
    Int _retries = 0;
    private Int limit = 10;

    Account(Int balance) {
        _balance = balance;
    }

    void deposit(Int amount) {
        Int next = _balance + amount;
        _balance = next;
        _retries = _retries + 1;
    }

    Int retryCount() {
        return _retries;
    }

    Int maxAllowed() {
        return _limit;
    }
}
```

`balance`、`retries`、`limit` 的规范名分别是 `_balance`、`_retries`、`_limit`；类内只写规范名，`balance`、`retries`、`limit` 不访问私有字段。外部访问 `account.balance`、`account._balance`、`account.retries`、`account._retries`、`account.limit`、`account._limit` 全部报私有错误。

### 7.5 @ReadOnly

- `@ReadOnly` 只能用于字段。
- 公有/受保护字段外部可读、不可写；声明类型内部仍可写。
- 私有字段外部本来不可访问；`@ReadOnly` 不改变私有访问规则，声明类型内部仍可写。
- `@ReadOnly` 不影响布局、ARC/GC 或引用计数。
- `@ReadOnly` 不能用于局部变量、参数或方法。

### 7.6 可见性与内存

- `public` / `protected` / `private` 只影响编译期访问。
- 字段无论可见性都参与布局、ARC/GC 扫描和 retain/release。
- `final` / `@ReadOnly` 是编译期限制，不改变运行时内存。

## 8. enum

### 8.1 形式

```x
enum Color { Red, Green, Blue }
enum Code { A = 1, B = 2, C = 4 }

enum Status {
    Ready(0, "ready"),
    Failed(1, "failed");

    final Int code;
    final String label;

    Status(Int code, String label) {
        self.code = code;
        self.label = label;
    }
}
```

- 枚举分两种：简单枚举和数据枚举。
- 简单枚举：项没有构造参数，没有字段、方法、构造器、`deinit` 或静态成员。
- 数据枚举：项带构造参数；枚举声明字段、构造器和方法。
- 同一枚举的所有项必须使用同一种形式；不能混合 `Item`、`Item(args)`、`Item = value`。
- 枚举不能是泛型；不能声明父类或 `implements`；不能是 `abstract`；隐式 `final`。
- 枚举不实现任何协议；不能把枚举值赋给协议类型，也不能用协议类型接收者调用枚举方法。
- 枚举项是封闭的；外部不能 `new`，只能通过 `Enum.Item` 访问。
- 数据枚举可以声明字段、构造器、实例方法、静态字段和静态方法；简单枚举只有项。
- 枚举声明只能位于包顶层。

### 8.2 简单枚举

- 项直接写名字；可选 `= integer-literal`，整数字面量可以带前导 `-`。
- 不写值时从 0 开始递增；显式值设置当前项，后续裸项继续递增。
- 显式值必须是 `Int` 范围内的整数；重复值、溢出和超出范围都是编译错误。
- 简单枚举是独立名义类型，底层按 `Int` 表示；不能隐式赋给 `Int`，也不能与 `Int` 算术。
- 简单枚举支持 `==` / `!=` / `===` / `!==`，按底层值比较。
- 简单枚举支持 `<` / `<=` / `>` / `>=`，按底层值比较。
- 简单枚举支持 `switch`；`case Color.Red` 使用底层值比较。
- 简单枚举不分配对象，不进入 ARC/GC，不产生 retain/release；变量、参数、字段、数组元素按值内联。
- 简单枚举字段没有默认值；字段必须显式初始化或在构造器中赋值。
- 简单枚举项可以用于 `const` 初始化式。
- 插值字符串把简单枚举格式化为项名。

### 8.3 数据枚举

- 数据枚举项必须带构造参数：`Ready(0, "ready")`。
- 数据枚举必须声明字段和构造器；字段必须 `final`；构造器与枚举同名。
- 数据枚举构造器隐式私有，只能由枚举项声明调用；外部不能 `new`。
- 数据枚举字段在构造时初始化；所有路径必须赋值 `final` 字段。
- 数据枚举实例不可变：字段 `final`，方法不能写字段；静态字段可以可变。
- 数据枚举项是编译器提供的单例对象；每个项在程序启动时构造一次。
- 数据枚举项参数在启动时按项声明顺序求值；项参数可以引用前面的项、常量和静态成员，不能引用后面的项。
- 数据枚举项参数求值 panic 时程序终止。
- 数据枚举支持实例方法、静态字段和静态方法；不支持 `deinit`。
- 数据枚举不参与继承和协议实现；方法静态派发。
- 数据枚举项有对象身份；`==` / `===` 按身份比较；同一个项的所有引用相等，不同项不相等。
- 数据枚举字段是引用时按 GC 追踪；数据枚举对象由 GC 管理，不走 ARC 计数。
- 插值字符串：如果数据枚举声明了 `String toString()`，调用该方法；否则格式化为项名。

### 8.4 枚举项与初始化

- 项名在枚举内唯一；简单枚举的底层值唯一。
- 数据枚举的构造参数数量和类型必须匹配构造器签名；不匹配是编译错误。
- 数据枚举项按声明顺序在启动时构造；所有项构造完成后才对外可用。
- 项初始化不能引用尚未构造的后续项；编译器必须检查直接和间接前向引用。
- 枚举项是全局根；数据枚举项在进程生命周期内常驻。
- 枚举类型本身不能创建实例；简单枚举没有对象身份；数据枚举项身份由编译器提供。

### 8.5 比较、switch 与格式化

- `switch` 的 `case` 使用 `==` 语义；简单枚举按底层值，数据枚举按身份。
- 枚举 `switch` 的 `case` 表达式必须是该枚举的项常量，例如 `Color.Red` 或 `Status.Ready`；任意表达式不能作为枚举 `case`。
- 枚举 `switch` 无 `default` 时必须覆盖该枚举的全部项，每个项恰好一次；遗漏、重复或未知项是编译错误。
- 枚举 `switch` 有 `default` 时，`default` 视为覆盖剩余项，不做穷尽性要求；`default` 最多一个且必须位于最后。
- 非枚举 `switch` 不检查穷尽性；没有匹配且没有 `default` 时直接退出 `switch`。
- 枚举不支持模式匹配；需要检查数据枚举字段时，先 `switch` 到项，再读取字段或使用方法。
- 简单枚举支持顺序比较；数据枚举不支持顺序比较。
- 简单枚举 `Color.Red` 的类型是 `Color`；不能直接与 `Int` 比较或赋值。
- 数据枚举不能用 `is` 检查子类型；`is Status` 只检查是否为该枚举类型。
- 数据枚举项不能 `new`；不能反射创建。
- 枚举不参与 `Object` 继承；简单枚举需要装箱为 `Any` 才能进入 `Object`；数据枚举项是引用，可赋给 `Object`。
- 枚举不实现协议；协议类型变量不能持有枚举值。

### 8.6 内存规则

- 简单枚举按 `Int` 内联：变量、参数、字段、数组元素、容器元素都是整数值。
- 简单枚举不分配对象，不进入 ARC/GC，不产生 retain/release，不登记 GC 根。
- 数据枚举项是 GC 对象；枚举类型本身不产生额外对象。
- 数据枚举项是全局根，进程生命周期常驻；字段按 GC 引用追踪。
- 数据枚举不走 ARC 引用计数；没有 `deinit`。
- 数据枚举字段为 ARC 引用时，GC 负责保持和释放；具体规则见 15.6。

## 9. singleton

### 9.1 声明与访问

```x
singleton AppInfo {
    final String name = "XNull";
}
```

- `singleton` 声明一个预加载的全局唯一实例。
- `instance` 是编译器自动提供的隐式只读字段，类型是单例类型；只有 `singleton` 拥有该字段。
- 不能手动声明 `instance`；手动声明是编译错误。
- 外部通过 `AppInfo.instance` 访问唯一实例；单例内通过 `self` 访问字段和方法。
- `instance` 不能重新赋值，不能为 `null`。
- 单例不能 `new`；不能继承，不能实现协议；隐式 `final`、不可子类化。
- 单例不能是泛型；不能是 `abstract`。
- 单例可以有实例字段、实例方法、静态字段和静态方法。
- 单例不能声明构造器；字段由初始化式或默认值初始化，编译器负责构造实例。
- 单例可以声明 `deinit`，但不保证在进程退出时调用；不得依赖它清理资源。

### 9.2 初始化

- 单例实例在程序启动时预加载，位于顶层/静态字段初始化之后、`main` 之前。
- 单例按包依赖顺序、文件顺序、声明顺序初始化。
- 单例字段先置零，再执行字段初始化式。
- 单例初始化式可以引用已经初始化的顶层字段、静态字段和前面的单例；不能引用后面的单例。
- 单例初始化 panic 时程序终止，`main` 不会被调用。
- 单例实例在 `main` 之前完成构造；`main` 看到的是完整初始化的实例。
- 单例的静态字段与其他静态字段一起初始化。

### 9.3 内存规则

- `instance` 是全局 GC 根，进程生命周期常驻，不按普通局部对象回收。
- 单例实例固定使用 GC 语义。
- 调用者只持有 `instance` 的持有视图，不需要也不应该对 `instance` 做 retain/release。
- 单例字段按普通字段规则管理；引用字段会把目标对象保持到进程结束。
- 需要释放单例字段持有的对象时，显式 `clear()` 或置 `null`。
- 单例被闭包或任务捕获时仍是同一个全局实例，不会复制。
- 单例的 `deinit` 不作为清理保证；文件、句柄、任务组应在使用点显式关闭。

### 9.4 限制

- 不支持泛型单例。
- 不支持继承、协议实现、构造器、子类化。
- 不支持手动声明 `instance`。
- 不支持 `new`。
- 单例字段的并发访问不做同步；需要同步时使用 `xdk.sync`。
- 单例初始化顺序是确定的；跨单例前向引用是编译错误。

## 10. factory

### 10.1 声明与目标

```x
factory DeviceFactory for Device {
    static Device create(final String name) {
        return new Device(name);
    }

    static Result<Device, DeviceError> open(final String path) {
        ...
    }
}
```

- `factory` 声明创建命名空间，绑定一个目标类型；没有实例，不分配对象。
- `factory` 只能位于包顶层；不能嵌套。
- `for Target` 的 Target 必须是当前包或另一个包中可见的 `class` 或 `struct` 声明；泛型目标写裸类型名 `Box`，不写类型实参。
- Target 可以是抽象类；工厂方法返回具体子类实例并上转为目标类型。
- Target 不能是 `protocol`、`enum`、`singleton`、`@annotation`、另一个 `factory`、数组、容器、函数类型、`Object`、`Any`、可空类型或泛型实例化。
- 需要按协议创建时，绑定一个实现类，并让工厂方法返回该协议或父类；协议本身不作为 Target。
- `factory` 名称在声明包内占用顶层类型命名空间；不得与该包其他类型同名；不能作为类型使用。
- `factory` 默认公开；可写 `public` / `private` / `protected`；顶层 `protected` 等价于 `private`。
- `factory` 不能写 `abstract`、`final`、`static` 或 `const`；隐式不可实例化、不可继承。
- `factory` 不能声明字段、构造器、`deinit`、实例方法、父类或协议实现。
- `factory` 是无状态创建命名空间；需要缓存或共享状态时使用 `singleton` 或顶层静态字段。
- 同一个 Target 可以有多个 `factory`，可以分布在同一包或不同包；每个工厂的访问权按包边界确定。
- 同包 `factory` 获得 Target 的私有构造器和私有静态成员访问；跨包 `factory` 只能访问 Target 的公开成员。
- 跨包 Target 必须从 `factory` 所在包可见；不可见类型、非公开顶层类型不能作为 Target。
- 工厂方法的有效可见性是 `factory` 类型可见性与方法可见性中更严格的一方。
- Target 的可见性低于工厂方法有效可见性时，方法的返回/参数签名不得暴露 Target；可以返回公开父类、协议或 `Object`。
- `factory` 可以带声明注解；`@Override` 非法；其他注解只做编译期标记。

### 10.2 工厂方法

```x
factory BoxFactory for Box {
    static Box<T> create<T>(final T value) {
        return new Box<T>(value);
    }
}

Box<Int> box = BoxFactory.create(1);
```

- 工厂方法必须写 `static`；不能使用 `self` / `super`；不能访问实例字段。
- 工厂方法默认公开；可以写 `public` / `private`；不能写 `protected`、`abstract`、`final`。
- 方法可以重载；可以声明方法级泛型参数。
- 允许的返回基类型 R：
  - Target 实例：`Device`；泛型目标 `Box<T>` / `Box<Int>` 等；
  - 类 Target 可返回 Target 可赋值到的父类、协议或 `Object`；
  - struct Target 只能返回 Target。
- 返回类型可以是 `R`、`R?`、`Result<R, E>` 或 `Result<R?, E>`；E 不能是 `void`。
- 禁止返回 `void`、数组、容器、`Any` 或无关类型。
- 工厂方法可以返回新对象、缓存对象、单例、`null`（Target 可选时）或 `Err`。
- 工厂方法可以使用 `try`、`defer`、`errdefer`；`Result` 遵守 `@mustUse`。
- 工厂方法不自动观测错误；调用方使用 `try` 或 `Result` 成员处理。
- 工厂方法可以调用同一 `factory` 的私有方法、顶层函数和其他 `factory` 的公开方法。
- 工厂方法不能作为入口 `main`；入口必须是顶层 `main`。

### 10.3 访问与创建

- `factory` 与 Target 同包时，自动获得 Target 的私有创建访问：
  - 可以调用 Target 的私有构造器；
  - 可以调用 Target 的私有静态字段/方法；
  - 不能访问 Target 的私有实例字段/方法；构造完成后只能通过公开成员操作；
  - 不能访问 Target 的 `protected` 实例成员（`factory` 不是子类）。
- `new Target(...)` 在同包 `factory` 内可以命中私有构造器；这是同包工厂的核心用途。
- `factory` 不是 Target 的子类，不能调用 Target 的 `protected` 构造器或 `protected` 实例成员。
- 跨包 `factory` 只能调用 Target 的公开构造器、公开静态字段和公开静态方法；不能调用私有或受保护成员。
- 工厂方法可以创建子类实例，但只能调用子类的公开构造器；返回时按 Target 上转。
- 工厂不能访问其他类型的私有构造器，包括 Target 子类的私有构造器。
- Target 有私有构造器时，只有 Target 自身和同包绑定 Target 的 `factory` 可以构造；跨包工厂不能构造。
- 多个同包 `factory` 绑定同一 Target 时，每个都有私有创建访问；需要更细粒度时只保留一个 `factory`，其他创建走私有方法。
- 跨包 `factory` 依赖 Target 的公开创建入口；Target 没有公开构造器或公开静态工厂时，跨包工厂不能创建实例，只能在方法内返回已有对象或 `Err`。
- Target 为 `struct` 时，`factory` 返回结构体值；值复制按 3.3 执行，私有构造器访问仍只授予同包工厂。
- `factory` 方法可以返回父类、协议或 `Object`；返回对象仍由具体 Target 或子类构造。

### 10.4 类型、内存与限制

- `factory` 不是值类型、引用类型或对象类型；不能作为变量、参数、字段、泛型实参或容器元素；不能用于 `is` / `as` / `as?`；不能赋给 `Object` / `Any`。
- `new Factory` 是编译错误；`factory` 只能通过 `Factory.method(...)` 静态调用。
- `factory` 没有对象布局、类型描述符、vtable、ARC/GC 生命周期；不分配内存，不调用 `deinit`。
- 工厂方法本身是静态方法，不使用 `self`，不参与 vtable 派发；调用不创建 `factory` 对象。
- 工厂方法创建的对象按 Target 的正常内存策略分配（stack/ARC/GC）。
- `factory` 的静态方法不引入额外全局根；方法内创建的对象按正常规则管理。
- `factory` 不能被 `extension` 扩展；不能作为 `extension` 目标、父类型、协议实现者或被 `singleton` 替代。
- `factory` 可以被 `import`；通过 `Factory.method` 调用；可见性按顶层声明。
- `factory` 不能声明泛型参数；泛型目标用裸名，由工厂方法的类型参数生成实例。

### 10.5 限制与诊断

编译器必须拒绝：

- `factory` 与当前包的类型或其他 `factory` 同名；
- Target 不是可见的 `class` / `struct`；
- Target 是 `protocol`、`enum`、`singleton`、`@annotation`、`factory`、数组、容器、函数类型、`Object`、`Any`、可空类型或泛型实例化；
- 跨包 Target 从 `factory` 所在包不可见；
- `factory` 声明字段、构造器、`deinit`、实例方法、父类或协议；
- 工厂方法缺少 `static`，或使用 `self` / `super`、访问实例字段；
- 工厂方法写 `protected` / `abstract` / `final`；
- 工厂方法返回类型不在 10.2 允许集合；
- 工厂方法的有效可见性高于 Target 可见性且签名暴露 Target；
- 跨包工厂访问 Target 的私有或受保护构造器、静态成员、实例成员；
- 同包工厂访问 Target 的 `protected` 实例成员；
- 把 `factory` 当类型/值使用、`new` factory、`is` / `as` factory；
- `Result` 错误类型为 `void`；
- 工厂方法重复签名；
- 在 Target 自身和同包绑定 Target 的 `factory` 之外调用 Target 私有构造器。

### 10.6 示例

```x
class Device {
    final String name;

    private Device(final String name) {
        self.name = name;
    }
}

factory DeviceFactory for Device {
    static Device create(final String name) {
        return new Device(name);
    }

    static Result<Device, DeviceError> open(final String path) {
        ...
    }
}

Device device = DeviceFactory.create("camera-01");
```

- `Device` 的构造器私有；外部不能 `new`；同一包的 `DeviceFactory` 是唯一创建入口。
- 工厂方法返回 `Device`；调用方不持有 `factory` 对象。
- `open` 返回 `Result<Device, DeviceError>`；调用方使用 `try`。
- 跨包工厂绑定同一 `Device` 时，只能使用 `public` 构造器或 `public` 静态创建方法；上例的私有构造器访问不会扩展到其他包。
- 跨包 `factory` 的声明仍需位于包顶层，通过 `import` 或完全限定名引用 Target，并受 Target 顶层可见性约束。

跨包示例：

```x
package devices

class Device {
    final String name;

    Device(final String name) {
        self.name = name;
    }
}
```

```x
package app

import devices.Device

factory DeviceFactory for Device {
    static Device create(final String name) {
        return new Device(name);
    }
}
```

`Device` 的构造器是公开的，`app` 包的 `DeviceFactory` 可以跨包调用。若把 `Device` 的构造器改为 `private`，同一包的工厂仍可调用，但跨包工厂不能；跨包工厂必须改用 Target 的公开静态创建方法。

## 11. extension

### 11.1 声明

```x
extension Device {
    String label() {
        return self.name;
    }
}
```

- `extension` 只能添加方法，不能添加字段、构造器、`deinit` 或静态方法。
- 目标类型必须是同包声明的非泛型 `class`、`struct`、`singleton` 或数据 `enum`。
- 不能扩展协议、注解、简单枚举、扩展本身、预定义类型或 XDK 类型。
- 不能扩展泛型类型或泛型实例化。
- 扩展方法默认公开；不能写 `private` / `protected`。
- 扩展方法可以重载；同名同参数重复声明是编译错误。
- 扩展方法不能与目标类型或父类已有的同签名方法冲突；同签名是编译错误。
- 扩展方法不能被目标类型的子类覆写；子类同签名声明是编译错误，类继承只复用方法。
- 扩展声明顺序无关；同一包内所有扩展一起参与解析。

### 11.2 方法解析与派发

- 扩展方法参与正常方法解析和重载；类类型接收者上的扩展方法静态派发。
- 扩展方法不进入 vtable；即使目标类实现协议，扩展方法也不参与协议派发。
- 扩展方法被子类继承；子类不能声明同签名方法覆写扩展方法，同签名是编译错误。
- 扩展方法不能作为协议实现；协议要求必须由类声明或继承方法满足。
- 协议类型接收者不能调用未在协议中声明的扩展方法；需要先转换到具体类型。
- 扩展方法之间、扩展方法与目标方法之间同名同参数是重复定义，必须报错。
- 扩展方法不能改变目标类型的布局或内存策略。

### 11.3 访问与内存

- 扩展方法只能访问目标的公开成员；`protected` / `private` 成员不可访问，即使扩展与目标同包。
- `self` 是借用视图，不额外 retain 目标对象；目标生命周期由原持有者决定。
- 类扩展方法在闭包中捕获 `self` 时，按闭包捕获规则建立强持有；目标生命周期由闭包环境保持。
- 结构体扩展方法遵守结构体写入规则：写入方法要求接收者可赋值；不得在闭包中捕获 `self`。
- 扩展方法不创建额外对象，不增加字段，不改变布局。
- 扩展方法合入目标类型的静态方法集合，不进入 vtable，不单独分配。
- 单例/数据枚举扩展方法遵守其不可变性：数据枚举字段 `final`，不能写字段。

### 11.4 限制

- 不支持扩展字段、构造器、`deinit`、静态方法。
- 不支持扩展协议、注解、预定义类型、XDK 类型。
- 不支持扩展泛型类型；不支持泛型扩展方法。
- 不支持跨包扩展。
- 不支持用扩展实现协议。
- 扩展方法不能与已有继承方法同签名，也不能被覆写。

## 12. annotation

### 12.1 声明

```x
@annotation Marker {
    final String name = "";
}
```

- `@annotation` 声明编译期注解类型；不生成运行期对象。
- 注解只能声明 `final` 字段；字段类型必须是编译期常量类型：`Bool`、整数、`Float`、`Double`、`Char`、`String`、简单枚举。
- 注解字段必须有编译期常量初始化式。
- 注解不能有方法、构造器、`deinit`、静态成员、泛型参数、继承或协议实现。
- 注解字段不占运行期布局；注解声明不产生实例。
- 注解类型只在编译期存在；不能 `new`，不能作为值传递。

### 12.2 使用

```x
@Marker
class Device { }
```

注解参数只支持位置参数：

```x
@Marker("x")
class Device { }
```

- 使用形式：`@Name` 或 `@Name(arg1, arg2, ...)`；参数按字段声明顺序绑定。
- 参数必须是编译期常量；类型必须可赋给字段类型；省略的尾部字段使用声明处的初始化式。
- 多余参数是编译错误；不能跳过中间字段；不支持命名参数。
- 注解可以用于类型声明、字段、方法、构造器、`deinit`、参数和枚举项。
- 注解不能用于表达式、类型参数、类型实参或控制体；`@tasks` / `@arena` 的块注解语义由第 5 部分定义（§2.3）。
- 未知注解是编译错误；注解必须解析到同包或导入的 `@annotation` 类型，或内建注解。
- 同一目标重复使用同一注解是编译错误；`@Repeatable` 在 v3.0.0 不生效。
- 注解不影响控制流、布局、分配或引用计数；内存策略注解是实现内部注解，不属于语言注解体系（15.1.2）。

### 12.3 内建注解

| 注解 | 目标 | 强制 | 语义 |
| --- | --- | --- | --- |
| `@ReadOnly` | 字段 | 是 | 外部只读；声明类型内部可写 |
| `@Override` | 方法 | 是 | 必须对应协议同签名方法；不能标记父类方法 |
| `@WriteOnly` | 字段 | 否 | 识别但不强制 |
| `@Target` | 注解 | 否 | 识别但不强制 |
| `@Retention` | 注解 | 否 | 识别但不强制 |
| `@Repeatable` | 注解 | 否 | 识别但不强制 |
| `@Deprecated` | 声明 | 否 | 识别但不强制 |
| `@SuppressWarnings` | 声明 | 否 | 识别但不强制 |
| `@tasks` / `@arena` | 块 | 解析 | 语义由 XDK 任务/内存规范规定 |
| `@Immediate` / `@NoAlloc` / `@Pure` / `@Sendable` | 保留 | 否 | 保留，不改变语义 |

内存策略注解 `@arc` / `@gc` 不是语言注解体系的成员；源码使用它们是编译错误。它们作为实现内部注解的语义见 15.1.2；内存策略的源码判定只依据第 15 节判定表。

### 12.4 内存与限制

- 注解使用不分配内存，不进入 ARC/GC，不产生运行期对象。
- `@annotation` 声明只是编译期类型，不生成注解实例。
- 语言注解只做编译期检查或识别；`@arc` / `@gc` 是实现内部注解（15.1.2），不属于语言注解体系。
- 注解字段不产生运行期存储；注解参数不求值运行期表达式。
- 不支持反射、运行时注解查询、注解处理器或代码生成。
- 不支持注解继承、重复注解、默认参数或命名参数。
- 注解不能改变对象布局。

## 13. 泛型类型与泛型方法

### 13.1 声明

```x
class Box<T> {
    T value;
}

struct Pair<A, B> {
    A first;
    B second;
}

class Util {
    U convert<U>(U value) {
        return value;
    }
}
```

- 泛型类/结构体在类型名后声明 `<...>` 类型参数。
- 泛型方法在方法名后声明 `<...>` 类型参数。
- 泛型参数只写名字；不支持约束、`where` 子句、默认类型、可变参数或关联类型。
- 类型参数名在同一泛型声明内唯一；方法类型参数不能与所在类的类型参数重名。
- 泛型类可以继承泛型父类或实现非泛型协议。
- 泛型结构体不参与继承和协议；每个类型实参必须是 3.2 的值字段类型。
- 协议不支持泛型参数、泛型方法、关联类型或协议内部类型约束。
- 单例、枚举、注解、扩展目标不支持泛型。
- 扩展方法不支持泛型（v3.0.0）。
- 裸泛型名按 `Any` 擦除：`Box` 等价于 `Box<Any>`。

### 13.2 型变

型变只允许在类的泛型参数上声明：

```x
class Producer<out T> { }
class Consumer<in T> { }
```

- `out T`：协变。`Producer<Derived>` 可赋给 `Producer<Base>`。
- `in T`：逆变。`Consumer<Base>` 可赋给 `Consumer<Derived>`。
- 未标注的类型参数不变；只能相同实参兼容。
- 结构体泛型参数不变；泛型方法没有型变。
- 型变只对引用类型实参有意义；值类型实参没有子类型关系，只能相同类型。

位置规则：

| 位置 | `out T` | `in T` | 不变 `T` |
| --- | --- | --- | --- |
| 方法返回类型 | 允许 | 禁止 | 允许 |
| 方法参数类型 | 禁止 | 允许 | 允许 |
| 构造器参数 | 允许 | 允许 | 允许 |
| `final` 字段 | 允许 | 禁止 | 允许 |
| 可变字段 | 禁止 | 禁止 | 允许 |
| `T?` | 保持 | 保持 | 保持 |
| `T[]` | 禁止 | 禁止 | 允许 |
| `List<T>` / `Set<T>` / `Map<...,T>` | 禁止 | 禁止 | 允许 |
| 泛型实参 `G<T>` | 仅当 G 对应参数为 `out` | 仅当 G 对应参数为 `in` | 允许 |
| 函数类型参数位置 | 禁止 | 允许 | 允许 |
| 函数类型返回位置 | 允许 | 禁止 | 允许 |

规则：

- 构造器参数不作为型变位置；构造时按具体实参检查。
- `out T` 可以出现在返回类型和 `final` 字段；不能出现在方法参数、可变字段、数组或不变容器中。
- `in T` 可以出现在方法参数；不能出现在返回类型或任何字段中。
- 可变字段使类型参数不变。
- 型变转换不分配对象、不改变表示；编译器必须验证布局和 vtable 槽位兼容。
- 型变违规是编译错误；不得在运行期静默转换。

### 13.3 实例化与推断

```x
Box<Int> box = new Box<Int>(1);
Box<Int> inferred = new Box(1);
```

- 泛型类型实参数量必须与声明一致。
- `new` 可以显式写类型实参；省略时从构造器实参推断。
- 如果构造器实参无法唯一确定类型实参，必须显式写类型实参。
- 类型实参不能是 `void`；不能是未绑定的类型参数。
- 嵌套泛型使用 `>>` 时按两个 `>` 解析；词法/语法必须支持。
- `Box<Int>?` 是可空引用；对引用类型 `T?` 与 `T` 同类型。
- 泛型类继承：`class Child<T> : Base<T>`、`class IntChild : Base<Int>`；父类实参必须具体化。
- 裸父类 `Base` 按 `Base<Any>` 处理。
- 泛型类实现协议：协议非泛型；方法签名在替换类型实参后必须完全匹配。
- 泛型结构体的每个具体实例都必须满足 3.2：`Pair<Int, Int>` 合法，`Pair<String, Int>` 因字段含引用类型被拒绝。
- 泛型结构体的类型参数不能以非值字段类型实参实例化，即使该参数不出现在字段中；结构体不提供引用回退分支。

### 13.4 单态化

- 泛型类型和泛型方法在类型检查后、内存分析前单态化。
- 每个不同的类型实参列表生成独立的类型/函数实例；实例有独立布局和内存策略；只有实现协议的类实例生成协议 vtable。
- 单态化后残留类型参数是编译错误；未实例化模板不进入内存分析。
- 裸泛型 `Box` / `Box<Any>` 按 `Any` 擦除；字段含 `Any` 时拥有者进入 GC。
- 泛型实例字段含 `Any` / 协议 / 未定类型时，拥有者按 GC 分析（15.1 第 7 条）。
- 泛型方法按每个实例生成函数；局部对象按具体类型选择 stack/ARC/GC。
- 递归单态化必须终止；无限展开是编译错误；实现可以使用深度上限，但超限必须诊断。
- 跨包泛型实例化需要模板或中间表示；工具链必须保证实例化点能访问泛型体。
- 不支持运行期类型实参；`is T` / `as T` 在单态化后按具体类型检查。
- `new T()` 是编译错误；`T` 不是运行期可构造类型。
- 静态成员不能使用类的类型参数；`static T value` 是编译错误。
- 泛型闭包不支持；需要泛型行为时使用泛型函数。

### 13.5 泛型内存

- 单态化先于内存分析；每个实例独立判定。
- 泛型结构体的每个实例都必须只含值字段；不存在“某些实参可复制、另一些不可复制”的分支。
- 泛型类的字段含具体引用时按引用分析；含 `Any` / 协议时按 GC。
- 泛型方法局部变量按具体类型选择策略。
- 协议 vtable 按实现协议的类实例生成；未实现协议的实例没有 vtable。
- 型变只影响类型兼容检查，不改变布局或回收策略。

### 13.6 限制

- 不支持类型约束、`where` 子句、默认类型实参、可变类型参数。
- 不支持泛型协议、协议泛型方法、关联类型或协议内部类型别名。
- 不支持泛型单例、泛型枚举、泛型注解。
- 不支持泛型扩展目标或泛型扩展方法。
- 不支持泛型结构体使用非值字段类型实参。
- 不支持泛型闭包。
- 不支持 `new T()`。
- 不支持静态成员使用类类型参数。

## 14. 闭包的内存形态

### 14.1 表示

闭包不是 `struct`，也不是普通函数指针，而是可调用的 GC 对象：

```c
typedef struct {
    void* fn;
    void* env;
} xnull_closure;
```

- 函数类型（`Int()`、`Int(Int)`）是静态类型；闭包值是该类型的运行期对象。
- `fn` 是编译期生成的 lambda 函数指针；所有 lambda 函数都带隐式 `env` 参数。
- `env` 是独立 GC 块，保存捕获变量。
- 调用闭包时先取 `fn` 和 `env`，再传 `env + 实参`。
- 闭包对象、`env` 和 cell 都由 GC 管理。

### 14.2 捕获

| 闭包形式 | env 内容 | 捕获方式 | 内存 |
| --- | --- | --- | --- |
| 无捕获 | 空 env | 无 | 闭包对象是 GC；不额外保存变量 |
| 捕获局部变量 | cell 指针 | 按引用 | 局部变量提升为 GC cell |
| 捕获参数 | cell 指针 | 按引用 | 参数提升为 GC cell |
| 捕获类 `self` | self 句柄 | 强持有 | env 保存实例句柄；不提升为 cell；结构体禁止 |
| 嵌套闭包 | cell 指针 | 共享外层 cell | 内外闭包共享同一个 cell |
| 任务闭包 | env / 捕获图 | 跨线程共享 | 运行时做共享标记，env 登记为 external root |

规则：

- 捕获局部变量、参数和 `self`。
- 被捕获的局部变量/参数提升为 GC cell；之后读写都走 cell。
- 闭包返回后，外部变量仍然有效，因为 cell 由闭包环境持有。
- 多个闭包捕获同一个变量时共享同一个 cell，修改互相可见。
- 不支持按值捕获语法。
- 捕获变量不需要是 `final`。
- 捕获 `self` 存储强持有；ARC 对象 retain，GC 对象追踪；调用期间借用。结构体方法不能捕获 `self`。
- 捕获结构体变量时，cell 保存结构体值；外部变量和闭包共享 cell；修改互相可见，但不产生对象身份。
- 结构体不得含引用字段，因此闭包环境不会因结构体捕获而间接持有引用对象。

### 14.3 生命周期

- 闭包对象、`env`、cell 都是 GC 对象。
- 闭包不可达 → env 不可达 → 释放捕获的 ARC 引用。
- 闭包与 env/cell 成环时由 GC 回收。
- 闭包作为返回值、字段、容器元素时，GC 保持其环境存活。
- 闭包进入 `xdk.tasks` 时，环境可达图做共享标记，env 作为跨线程根；任务 dispose 时移除。
- 闭包身份按引用比较；`null` 闭包调用是 panic。
- 类方法在闭包中捕获 `self` 时，接收者不能栈分配，必须堆分配（ARC/GC）；结构体方法禁止捕获 `self`。
- 闭包环境持有引用字段时，环境本身是 GC；环境释放时释放其 ARC 引用，GC 引用由追踪回收。

### 14.4 任务

- 闭包进入 `xdk.tasks` 后，env 是跨线程根；运行时必须保证 env 在任务存活期间可达。
- 任务 dispose 时移除根；之后 env 按普通 GC 规则回收。
- `@Sendable` 在 v3.0.0 保留但不强制；运行时不做数据竞争检查。
- 跨任务共享的对象必须由调用方同步；语言不提供隐式线程安全。
- 单例捕获不复制实例；所有任务看到同一个全局实例。

### 14.5 调用约定

- 闭包调用：加载 `fn` 和 `env`；按函数类型检查实参；调用 `fn(env, args...)`。
- 无捕获闭包仍带 `env` 参数；`env` 可以为空块。
- 闭包返回引用类型时按返回值类型传递；返回结构体时按值/指针 + sret 规则。
- 闭包不能作为 C 函数指针直接传递；跨 FFI 需要显式 trampoline 和生命周期合同（见第 7 部分 §5）。

## 15. 对象生命周期与内存

### 15.1 策略判定

内存策略只适用于 `class` 与 `singleton`；`struct`、简单枚举是值，不进入 ARC/GC。

| 顺序 | 条件 | 策略 |
| ---: | --- | --- |
| 1 | `singleton` | GC 全局根 |
| 2 | `protocol` | 无实例；分析按 GC |
| 3 | 简单 `enum` | stack / 内联整数 |
| 4 | 数据 `enum` | GC |
| 5 | 类强引用字段含 `Any`、`Object`、协议、未单态化泛型、含引用元素的元组或当前实现中的 `Result` | GC |
| 6 | 类强引用成环 | GC |
| 7 | 类方法捕获 `self` 或类存在 `deinit` | ARC |
| 8 | 类只有值字段 | 类对象 stack 候选，逃逸后按 14.2 提升 |
| 9 | 其余无环类引用 | ARC |

判定输入全部来自单态化后的源码结构：种类、字段类型图、引用环分析、逃逸分类、`deinit` 存在性、`self` 捕获。判定是确定性的；同一源程序、同一实现版本、同一编译选项必须产生相同判定（DET-01）。

#### 15.1.1 判定的保守性

- 引用环中出现至少一个 GC 节点时，环由 GC 回收；全 ARC 强引用环由内存分析改判 GC。
- 分析不完整或存在不可见边界（FFI、XDK 调用、任务提交）时，必须按逃逸处理。
- 判定不得静默接受无法分析的对象；无法分析时归入 GC。

#### 15.1.2 内部策略注解（实现边界内，非承诺入口）

`@arc` / `@gc` 保留为实现内部注解：

- 源码不得出现；语言注解体系（第 12 节）不包含它们，源码使用是编译错误。
- 仅限实现预览与调优实验使用：`@arc` 语义为强制 ARC（须满足原条件：`class`、强引用字段具体、无环），`@gc` 语义为强制 GC。
- 非承诺入口：不构成语言特性，不进入验收矩阵，实现可以在任何版本移除或更改。
- 长期调优需求应通过实现侧编译选项表达（内存管理方案 §23），不得固化为源码语法。

说明：

- 普通类默认 ARC/GC；纯值字段、不逃逸的局部类对象可以栈分配。
- 结构体始终是值，按 3.3 复制；没有引用回退、ARC/GC 或 `deinit` 分支。
- 结构体字段只能是 3.2 允许的值字段；引用字段、`Any`、协议、函数类型、数据枚举、单例、类都不能出现在结构体中。
- 类有 `deinit` 时不做栈分配。
- 泛型在内存分析前单态化；每个实例独立判定。

### 15.2 逃逸分析

逃逸分析只适用于类对象；结构体按值传递、返回和存储，不因逃逸改为引用，也不做堆提升。

对象逃逸指满足任一条件：

- 作为返回值离开当前函数；
- 存入字段、静态字段、全局字段或容器；
- 被闭包捕获；
- 传给未知函数、XDK 边界或 FFI；
- 跨任务共享；
- 被赋给可能逃逸的变量。

逃逸分类：

| 类别 | 含义 | 分配影响 |
| --- | --- | --- |
| `none` | 只在局部读取、字段读写、条件中使用 | 可栈分配 |
| `return` | 只作为返回值离开 | 提升为 ARC；若字段已要求 GC，则保持 GC |
| `other` | 存入容器/字段、被闭包捕获、传参、重新赋值 | 提升为 GC |

栈分配是优化，不改变语言语义：对象仍然有身份，引用仍然指向同一对象，只是生命周期受词法作用域限制。对象一旦逃逸，编译器必须改为堆分配，不能复制对象。

### 15.3 布局

分配头：

- 所有堆对象有统一分配头：对象种类（ARC / GC）、类型描述符、ARC 计数或 GC 标记、扫描信息。
- 类型描述符用于 `is` / `as`、协议检查和 `Any` 拆箱。
- 栈对象没有堆分配头；编译器必须在需要 `is` / `as` 时保留动态类型信息，或在静态类型可证明时省略。

对象载荷：

- 实现协议的类：载荷起始位置是指向协议 vtable 的指针；字段在之后。
- 未实现协议的类：字段从载荷起始位置开始，没有 vtable 指针。
- 结构体：字段从值存储起始位置开始，没有对象头、vtable 指针或 ARC/GC 头。
- 字段按 8 字节对齐；父类字段在前，子类字段在后。
- 标量值字段占一个 8 字节槽位；结构体字段内联，大小向上取整到 8 字节；引用字段占一个指针槽位。
- 元组值内联：值元素按其类型占标量或内联槽位；引用元素占指针槽位并登记扫描；元组不产生对象头或 vtable 指针。
- 简单枚举按 `Int` 占一个槽位；数据枚举项是 GC 对象。
- 闭包对象是 `{ fn, env }` 两个指针；`env` 是 GC 块。
- `Any` 装箱对象包含分配头、类型描述符和值载荷。

vtable：

- vtable 只保存协议方法槽位；同一签名全程序同一槽位；继承实现复用槽位；新增协议追加槽位。
- 普通类方法、静态方法、构造器、`deinit` 和扩展方法不进入 vtable。
- 槽位分配必须确定；跨模块 ABI 需要稳定槽位规则。
- vtable 头不决定 ARC/GC；回收策略由分配头和类型策略决定。

### 15.4 ARC

- ARC 对象有引用计数；retain 增加，release 减少。
- 计数归零时：清除弱引用 → 调用 `deinit` → 释放引用字段 → 回收内存。
- ARC 对象可以持有 ARC 引用和 GC 引用；ARC 引用由 retain/release 管理；GC 引用通过混合图规则保持。
- 弱引用不增加计数；目标释放时置 `null`；弱引用操作在并发下必须原子。
- ARC 循环由内存分析避免：检测到环时使用 GC。
- ARC 计数在任务并发下必须原子；无并发时可以优化为非原子。
- ARC 对象是全局根或栈根时，其 GC 引用字段必须被 GC 扫描。

### 15.5 GC

- GC 采用标记—清扫；对象由可达性决定生命周期。
- 根包括：栈槽位、顶层/静态字段、单例、闭包 env、任务 external root、ARC 扫描列表。
- GC 对象可以持有 GC 引用和 ARC 引用；GC 引用被追踪；ARC 引用在对象死亡时 release。
- 循环引用由 GC 回收；GC 对象的 `deinit` 在清扫时调用，时机不确定。
- GC 可以在分配点或安全点触发；实现可以使用分代/增量策略，但必须保持根和写屏障正确。
- GC 不保证进程退出时执行 `deinit`；关键资源必须显式关闭。

### 15.6 混合引用图

不变量：

1. 每个强引用要么增加 ARC 计数，要么被 GC 追踪；不存在既不计入也不追踪的强引用。
2. ARC 对象持有 GC 引用时，该 ARC 对象在存活期间登记为 GC 扫描对象；GC 把它的 GC 引用字段当作根。
3. GC 对象持有 ARC 引用时，GC 标记 ARC 目标为可达；GC 对象死亡时 release 该 ARC 引用。
4. 弱引用不增加计数、不阻止回收；目标死亡时清除。
5. 含环的强引用图只要有至少一个 GC 对象，就由 GC 回收；全 ARC 强引用环由分析避免或拒绝。
6. ARC 对象释放时清除其 GC 引用，避免悬挂；GC 对象清扫时释放其 ARC 引用，避免泄漏。

正确性条件：

- 没有提前释放：ARC 目标在计数归零前不会被释放；GC 目标在不可达前不会被清扫。
- 没有悬挂：弱引用在目标死亡时清除；强引用始终阻止释放。
- 没有泄漏：GC 回收环；ARC 引用在 GC 清扫时释放。
- 没有重复释放：ARC 字段置 `null` 后不再 release；GC 清扫只处理仍存活的引用。

### 15.7 生命周期与 deinit

- 分配：清零；安装分配头、类型描述符；实现协议的类安装协议 vtable。
- 构造：父类构造 → 字段初始化 → 构造器体。
- 发布：构造完成后 `self` 可以逃逸。
- 使用：引用计数或 GC 可达性保持对象。
- 释放：ARC 计数归零或 GC 清扫。
- `deinit`：弱引用先清除；派生类到父类；字段在链完成后释放。
- 对象复活禁止：`deinit` 不能把 `self` 存入全局/容器/闭包，不能返回 `self`。
- 进程退出：单例和全局对象不保证 `deinit`；显式关闭资源。
- `panic` / `throw`：不展开栈，不保证 `deinit`；进程终止。

### 15.8 弱引用（运行时内部机制）

语言与 XDK 公共 API 不提供弱引用；源码没有 `weak` 修饰符或弱引用类型。弱表作为运行时内部机制保留：

- 弱表由运行时维护；入口只对 FFI 合同层和运行时内部开放（见内存管理方案 §16、§19、§22）。
- 弱引用不增加引用计数；目标终结前从弱表清除。
- 弱操作必须原子，避免读到已终结目标。

原 `weak` 字段场景的替代模式：

- 树 / 父子双向引用：直接双向强引用；出现强引用环时拥有者按第 15.1 节归入 GC，环不会泄漏。
- 观察者 / 监听：事件列表 + 显式注销；或 ID + 注册表解析，目标可能已不存在，返回 `null` / `Err` 由调用方显式处理。
- 缓存：强引用 + 显式失效策略（容量、过期）；缓存语义保持显式。

### 15.9 线程与共享

- ARC 计数在任务并发下必须原子；单线程实现可以优化为非原子。
- GC 使用安全点和根扫描；实现可以暂停所有 mutator。
- 运行时内部弱表操作必须原子，避免读到已终结目标。
- 对象字段的并发读写不做同步；数据竞争是程序错误，本方案不定义结果。
- 跨任务闭包 env 登记为 external root；任务 dispose 时移除。
- 单例和静态字段在 `main` 前完成初始化，发布安全。
- `@Sendable` 在 v3.0.0 保留但不强制；需要线程安全时使用 `xdk.sync`。

### 15.10 内存诊断

编译期必须报告：

- 泛型单态化残留类型参数；
- 结构体值递归包含或含引用字段；
- 结构体使用非值字段类型泛型实参；
- 源码使用内存策略注解 `@arc` / `@gc`；
- 私有字段的外部访问（`name` 和 `_name` 都拒绝）、`private` 与 `_` 前缀同时使用、类内 `self._name`、类内用基名访问私有字段、同类局部/参数复用 `_name`、字段隐藏、继承链基名重复；
- 子类声明与祖先同签名的实例方法；
- 协议字段、协议方法体、泛型协议、关联类型或协议泛型方法；
- 协议实现缺失或签名不匹配；
- 枚举 `switch` 缺少项、重复项或未知项；
- 工厂跨包访问非公开成员，或绑定不可见 Target；
- `final` 字段重复赋值或未赋值；
- 构造完成前 `self` 逃逸；
- 非 `void` 方法缺少返回；
- 扩展目标非法、重复方法或同签名冲突；
- 注解目标、参数或类型非法。

运行期必须报告：

- 分配失败、栈溢出；
- 空引用解引用；
- 数组/List/Set 下标越界；
- 类型转换失败（`as`）；
- 整数除零、移位越界；
- 显式 `throw`。

`xdk.runtime` 可以提供分配统计、GC 指标和泄漏诊断；这些不是语言语义的一部分。

## 16. 实现边界

本节定义 v3.0.0 的发布门槛，不是能力缺口清单。下列每项必须在编译器、运行时和 LSP 中实现；任一项未通过，构建不得声明符合本规范。实现不得以“先接受后诊断”、静默降级、运行时兜底或文档声明替代编译期检查。

| 编号 | 发布门槛 | 未通过处理 |
| --- | --- | --- |
| BND-01 | 成员级 `public` / `protected` / `private` 可见性全部强制；跨包按顶层与成员规则执行 | 编译错误，禁止只报未实现 |
| BND-02 | 类继承只复用字段/方法；子类同签名方法、字段隐藏、`abstract` 实例化、继承 `final` 类全部拒绝 | 编译错误 |
| BND-03 | 类类型接收者静态派发；只有协议类型接收者走 vtable；内存策略不影响 vtable；构造器、`deinit`、`super` 静态派发 | 行为不符合第 5 节即失败 |
| BND-04 | 结构体只含 3.2 值字段；实例引用字段、`deinit`、捕获 `self`、非值字段类型泛型实参全部拒绝 | 编译错误 |
| BND-05 | 协议只有方法签名；字段、方法体、默认实现、泛型协议、关联类型、协议泛型方法、约束全部拒绝；实现检查覆盖父协议 | 编译错误 |
| BND-06 | 枚举不实现协议；枚举 `switch` 按 8.5 检查穷尽性、重复项、未知项和 `default` 位置 | 编译错误 |
| BND-07 | 单例不继承、不实现协议、不 `new`；`instance` 只读且为 GC 根 | 编译错误 |
| BND-08 | 工厂可同包或跨包绑定；同包有私有构造器访问；跨包只能访问公开成员；Target 必须可见；工厂不是类型 | 编译错误 |
| BND-09 | 私有字段只能写 `private name` 或 `_name`；`private _name` 拒绝。规范名为 `_name`，类内只能裸写 `_name`，`self._name` 和裸 `name` 都拒绝；外部 `name` 和 `_name` 都拒绝；字段按基名继承链唯一 | 编译错误 |
| BND-10 | 内存策略由 15.1 判定表决定；源码使用 `@arc` / `@gc` 被拒绝；混合引用图满足 15.6 不变量 | 编译错误或运行时不变量失败 |
| BND-11 | 结构体按值复制；类对象身份不因优化改变；vtable 只含协议槽位；地址 + sret ABI 不得暴露共享身份 | 行为不符合第 3、5、15 节即失败 |
| BND-12 | 泛型在内存分析前单态化；残留类型参数、泛型协议、泛型结构体非值字段类型实参全部拒绝 | 编译错误 |
| BND-13 | 扩展只支持同包非泛型目标；只加方法；不进入 vtable；不得作为协议实现或覆写已有方法 | 编译错误 |
| BND-14 | 所有禁止构造必须给出带源位置的诊断；编译器不得崩溃、静默接受或只在运行期失败 | 该负例失败 |
| BND-15 | 第 1 部分 v3.0.0 的 `Result` / `try`、`defer` / `errdefer`、`new T[count]`、标签控制、枚举穷尽性集成通过验收 | 集成验收失败 |

实现内部可以采用不同的布局、槽位编号和优化策略，但必须满足上表规定的可观察语义。验收必须同时包含正例、负例和跨包用例；负例必须断言具体诊断，不得只断言“编译失败”。

## 17. 面向对象关键字内存总表

### 17.1 类型关键字

| 关键字 | 内存语义 | 派发 |
| --- | --- | --- |
| `class` | 引用类型；ARC/GC；纯值非逃逸局部对象可栈优化；不改变引用语义 | 类类型静态；协议类型动态 |
| `struct` | 纯值类型；按值复制并内联；不进入 ARC/GC | 静态 |
| `protocol` | 只有方法签名；没有实例；协议变量是具体对象的强持有视图；实现者带协议 vtable 头 | 动态（实现者 vtable） |
| 简单 `enum` | 按整数内联；不分配、不进入 ARC/GC | 静态 |
| 数据 `enum` | 项是 GC 对象；项为全局根；不走 ARC 计数 | 静态 |
| `singleton` | `instance` 是全局 GC 根，进程生命周期常驻；不实现协议 | 静态 |
| `factory` | 无实例、无布局、无 ARC/GC；可跨包绑定 Target；只声明静态工厂方法 | 静态 |
| `extension` | 不增加字段、不改变布局、不创建对象；方法合入静态方法集合 | 静态 |
| `@annotation` | 只是编译期类型，不生成运行期对象，不分配内存 | 不适用 |

### 17.2 成员与修饰符

| 关键字 | 内存语义 |
| --- | --- |
| `static` | 类型级成员，不依赖 `self`；引用字段是全局根；不是实例所有权单位 |
| `public` / `protected` / `private` | 只影响编译期可见性，不改变布局、ARC/GC 或 retain/release；`private` 字段和 `_name` 私有字段都不产生额外存储；规范名 `_name`，类内使用 `_name` |
| `final` | 编译期限制，字段/变量只绑定一次；类方法本就不可覆写，方法级 `final` 冗余 |
| `abstract` | 只修饰类；类型没有实例；不支持抽象方法，不额外分配 |
| `deinit` | 只用于 class/singleton；不额外分配对象；ARC 计数归零或 GC 清扫时调用；用于释放字段/资源 |

### 17.3 使用与访问

| 关键字 | 内存语义 |
| --- | --- |
| `new` | 按类型策略分配：stack / ARC / GC；`struct` 产生值，`class` 产生引用对象，枚举/协议/单例不能 `new` |
| `self` | 当前实例或值存储的借用视图；结构体方法捕获受限；不额外 retain |
| `super` | 父类构造/成员的借用视图；不创建父类副本；静态派发 |
| `implements` | 仅 class 可用的协议实现关系；引入协议 vtable 头；不改变字段所有权策略 |
| `instance` | 仅 `singleton` 拥有的隐式只读字段；全局根，进程生命周期常驻 |

### 17.4 注解与泛型

| 关键字 | 内存语义 |
| --- | --- |
| `@arc` / `@gc` | 实现内部注解（15.1.2）；源码不得出现；不是语言注解体系成员 |
| `@ReadOnly` | 编译期写入限制；不改变布局或回收策略 |
| `@Override` | 只检查协议方法实现；不能标记父类方法；不影响内存 |
| 其他注解 | 只识别，不改变布局、分配或引用计数 |
| 泛型类型 / 泛型方法 | 内存分析前单态化；每个具体实例独立布局和策略；残留 `T` 报错，裸泛型按 `Any` 擦除并可能进 GC；泛型协议和关联类型不支持 |

### 17.5 汇总

- 只有 `class` / `struct` / 数据 `enum` / `singleton` 会产生实际类型对象或其值。
- `protocol`、`factory`、`extension`、`@annotation`、`@Override`、可见性修饰符不产生独立对象。
- `factory` 没有布局和生命周期，只提供静态创建方法；创建出的 class 对象按类策略回收，struct 返回值按值复制。
- 真正决定 class 回收方式的是：字段图、引用环、是否含 `Any` / 协议、是否逃逸、是否有 `deinit`、是否捕获 `self`。
- 结构体不进入 ARC/GC；实例引用字段、`deinit` 和捕获 `self` 全部禁止。
- 简单枚举是整数；数据枚举和单例是 GC；协议只提供方法签名和持有视图；类类型静态派发，协议类型动态派发。
- 枚举 `switch` 无 `default` 时必须穷尽全部枚举项；非枚举 `switch` 不要求穷尽。

## 附录 A：类型声明文法

本附录使用 EBNF；`{ X }` 表示零次或多次，`[ X ]` 表示可选。基础表达式和语句文法见第 1 部分附录 A。

```ebnf
TypeDecl          = { Annotation } { TypeModifier } TypeDeclBody ;
TypeModifier      = "public" | "protected" | "private" | "abstract" | "final" ;
TypeDeclBody      = ClassDecl | StructDecl | ProtocolDecl | EnumDecl
                  | SingletonDecl | FactoryDecl | ExtensionDecl | AnnotationDecl ;

ClassDecl         = "class" Identifier [ GenericParams ]
                    [ "(" ParamList ")" ]
                    [ ":" TypeRef ]
                    [ "implements" TypeRef { "," TypeRef } ]
                    "{" { Member } "}" ;
StructDecl        = "struct" Identifier [ GenericParams ]
                    "{" { Member } "}" ;
ProtocolDecl      = "protocol" Identifier
                    [ ":" TypeRef { "," TypeRef } ]
                    "{" { ProtocolMember } "}" ;
EnumDecl          = "enum" Identifier "{" EnumBody "}" ;
EnumBody          = [ EnumItem { "," EnumItem } [ ";" ] ] { Member } ;
EnumItem          = { Annotation } Identifier
                    [ "(" [ ArgList ] ")" | "=" [ "-" ] IntegerLiteral ] ;
SingletonDecl     = "singleton" Identifier "{" { Member } "}" ;
FactoryDecl       = "factory" Identifier "for" TypeRef "{" { FactoryMember } "}" ;
FactoryMember     = { Annotation } [ "public" | "protected" | "private" ] "static"
                    Type Identifier [ GenericParams ]
                    "(" [ ParamList ] ")" Block ;
ExtensionDecl     = "extension" TypeRef "{" { ExtensionMember } "}" ;
AnnotationDecl    = "@annotation" Identifier "{" { AnnotationField } "}" ;

Member            = { Annotation } { MemberModifier }
                    ( FieldDecl | MethodDecl | ConstructorDecl | DeinitDecl ) ;
MemberModifier    = "public" | "protected" | "private" | "static"
                  | "final" | "const" ;
FieldDecl         = Type Identifier [ "=" Expression ] [ ";" ] ;
MethodDecl        = Type Identifier [ GenericParams ]
                    "(" [ ParamList ] ")" Block ;
ConstructorDecl   = Identifier "(" [ ParamList ] ")" Block ;
DeinitDecl        = "deinit" "(" ")" Block ;

ProtocolMember    = ProtocolMethod ;
ProtocolMethod    = { Annotation } Type Identifier
                    "(" [ ParamList ] ")" ";" ;
ExtensionMember   = MethodDecl ;
AnnotationField   = "final" Type Identifier "=" Expression [ ";" ] ;

GenericParams     = "<" GenericParam { "," GenericParam } ">" ;
GenericParam      = [ "out" | "in" ] Identifier ;
TypeArgList       = TypeRef { "," TypeRef } ;
ParamList         = Param { "," Param } ;
Param             = { Annotation } [ "final" ] Type Identifier ;
Annotation        = "@" Identifier [ "(" [ ArgList ] ")" ] ;
ArgList           = Expression { "," Expression } ;

Type              = TypeRef ;
TypeRef           = PrimaryType { "[]" | "?" } ;
PrimaryType       = FunctionType | NamedType | TupleType ;
FunctionType      = ReturnType "(" [ TypeRef { "," TypeRef } ] ")" ;
ReturnType        = "void" | NamedType | TupleType ;
TupleType         = "(" TypeRef "," TypeRef { "," TypeRef } ")" ;
NamedType         = QualifiedName [ "<" TypeArgList ">" ] ;
```

表达式文法继承第 1 部分附录 A；`new` 表达式已在第 1 部分 `PrimaryExpr` 中定义，本附录不重复。元组类型、元组字面量与元素访问的文法见第 1 部分附录 A。

文法说明：

- `ProtocolDecl` 的 `:` 只接受协议；`ClassDecl` 的 `:` 只接受类；语义检查必须拒绝错误种类。
- `StructDecl`、`EnumDecl`、`SingletonDecl`、`ExtensionDecl`、`AnnotationDecl` 不接受 `:` 或 `implements`；文法未列出这些分支。
- `EnumItem` 的三种形式互斥；同一枚举必须统一形式；简单枚举项不能带构造参数，数据枚举项不能带 `= value`。
- `MethodDecl` 必须有 `Block`；类方法不能省略方法体。`abstract` 不是 `MemberModifier`，类声明中写 `abstract` 方法由文法拒绝。
- `ProtocolMember` 只接受 `ProtocolMethod`；协议字段、方法体、默认实现由文法拒绝。协议方法以 `;` 结束。
- `ExtensionDecl` 只接受方法；字段、构造器、`deinit`、静态方法由文法拒绝；语义检查再拒绝泛型目标和泛型方法。
- `FactoryDecl` 的 Target 必须是当前包或跨包可见的 `class` / `struct`；泛型目标写裸类型名，写类型实参由语义检查拒绝。跨包 Target 的私有成员访问不因工厂关系获得。
- `FactoryMember` 必须是 `static` 方法；字段、构造器、`deinit`、实例方法、父类和协议实现由文法或语义检查拒绝。
- `factory` 不是类型；不能用于变量、参数、字段、泛型实参、`new`、`is` / `as`。`FactoryDecl` 只接受可见性修饰符，`abstract` / `final` 等由语义检查拒绝。
- `AnnotationDecl` 只接受 `final` 字段；字段类型和初始化式的常量限制由语义检查执行。
- `GenericParam` 的 `out` / `in` 只允许出现在 `ClassDecl` 的类型参数上；其他位置由语义检查拒绝。
- `ProtocolDecl` 不支持 `GenericParams`、关联类型或协议泛型方法；文法未列出。
- `ClassDecl` 头部的 `( ParamList )` 是主构造器：参数必须写 `final`（语义检查执行），参数同时声明同名字段；有主构造器的类不能再声明构造器；仅 `class` 支持，`struct` / `singleton` / `enum` / `factory` 的头部参数列表由文法拒绝。
- `SingletonDecl`、`EnumDecl`、`AnnotationDecl` 不支持 `GenericParams`；文法未列出。
- `StructDecl` 的字段限制由语义检查执行；引用字段、可空引用字段、`deinit` 和捕获 `self` 必须拒绝；可空值字段允许，但不得形成递归值包含。源码出现 `weak` 或 `@arc` / `@gc` 由文法或语义检查拒绝。
- `FieldDecl` 的字段名采用 `_name` 形式或声明为 `private name` 时按私有处理；`private _name` 由语义检查拒绝。规范名为 `_name`，类内只能裸写 `_name`，`self._name` 和裸 `name` 由语义检查拒绝。同类局部变量、参数或类型参数使用 `_name` 也拒绝。`public` / `protected` 与 `_name` 同时出现由语义检查拒绝；字段名按基名做继承链唯一性检查。
- `TypeRef` 的 `[]` / `?` 语义与第 1 部分附录 A 相同；`T?[]` 是“可空 T 的数组”，`T[]?` 是“可空数组”。
- 文法接受的构造如果违反语义规则，类型检查阶段必须拒绝。
