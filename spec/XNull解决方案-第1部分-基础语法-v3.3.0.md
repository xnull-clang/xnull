## 决策摘要

- 本方案是基础语法的规范性文本，按 RFC 2119 用语；实现边界内的能力不保证。
- 语句终止采用自动分号插入；跨行表达式必须用括号。
- 引用类型的 `T?` 与 `T` 同型；不提供流敏感收窄，解包用 `as` / `??`。
- `&&` / `||` 短路，`??` 仅在左侧为 `null` 时求值右侧。
- 数值类型无隐式转换；整数溢出回绕，除零/移位越界 panic。
- 元组 `(T1, T2, ...)` 是内建值类型，至少两个元素，按位置访问 `t.0`；不提供解构、标签、元组方法。
- 函数统一规则：顶层函数、方法、构造器与 Lambda 遵循同一套显式函数规则（7.10）——显式类型、无默认参数、无命名实参、无可变参数；花括号体（Lambda 例外，允许单表达式体）；重载按 4.4 与第 2 部分 6.8。
- 顶层函数默认静态，`static` 可写可省（4.1）。
- `Map` / `Set` 键限 `String`、整数、简单枚举；`Map.get` 缺失键返回 `null`，`getOr` 提供默认值。
- 泛型函数单态化；不支持约束、默认类型实参或泛型闭包。
- 本版保留 `switch`、`Result` / `try` 错误处理、`defer` / `errdefer`、`new` 对象构造和标签控制；不支持项在 0.6 明确列出。
- 通用 `switch` 不检查穷尽性；枚举 `switch` 的穷尽性由第 2 部分 8.5 规定。

## 0. 规范基础

### 0.1 范围

本方案规定 XNull 的基础语法与语义：词法、类型系统、包与导入、顶层声明、局部变量、语句与控制流、表达式与运算符、闭包、泛型函数、内置类型、错误处理核心、对象构造表达式、XDK 导入和程序入口。

本方案不规定：

- 类型声明、继承、协议、枚举、单例、扩展和对象内存布局；见第 2 部分。
- 错误的观测、取消、超时和 `ErrorKind` 策略；核心语法见第 10 节，完整模型见错误处理规范。
- FFI、C ABI、`unsafe` 边界和跨语言所有权；见第 7 部分与第 6 部分。
- 并发、异步和任务的运行时语义；语言不提供 `async` / `await` 语法，使用 `xdk.tasks`。
- XDK 包的完整 API；见第 6 部分。
- 工程清单、构建系统和包管理；本方案只规定入口解析。

### 0.2 规范用语

**必须**、**禁止**、**应当**、**可以** 按 RFC 2119 语义使用。**禁止**等价于“必须不”。**应当**表示存在理由充分的例外，但例外必须在实现文档中说明。

“实现边界”列出的能力是当前实现不保证或未强制的部分；边界内的行为不受本方案保护。未在正文或实现边界中列出的语法不得视为已支持。

### 0.3 一致性

实现必须接受所有满足本方案“必须”条款的源程序，并产生本方案规定的可观察行为。违反“禁止”条款的源程序必须被拒绝，并给出带源位置的诊断。

实现可以提供本方案未列出的扩展，但扩展必须显式启用；默认构建不得依赖扩展，也不得用扩展改变本方案已规定的行为。同一源程序、同一实现版本、同一编译选项必须产生相同的诊断和运行结果。

### 0.4 程序模型

一个程序由一个或多个包组成。包由一个或多个源文件组成，一个文件只属于一个包。包内的顶层声明在包作用域可见；跨包访问必须通过 `import` 或完全限定名。

程序入口是一个顶层 `static` 函数 `main`。启动时先完成包、顶层字段、静态字段和单例的初始化，再调用入口。

编译单元的文法见附录 A。编译器必须按“词法 → 语法 → 类型检查 → 单态化 → 内存分析 → 代码生成”的语义阶段处理源程序；阶段划分不约束内部实现，但每阶段的诊断必须对应本方案的条款。

### 0.5 版本与兼容

本方案采用语义化版本：

| 版本位 | 允许的变更 | 不允许的变更 |
| --- | --- | --- |
| 主版本 | 删除语法、改变语义、改变默认行为 | 无 |
| 次版本 | 新增语法、新增内置成员、新增诊断 | 改变既有程序的含义 |
| 修订号 | 澄清措辞、补充示例、修正笔误 | 改变规范约束 |

同一主版本内，符合旧版本的源程序必须继续被接受，且可观察行为不变。实现不得静默降级或忽略不兼容的规范版本。

### 0.6 明确不支持的语法

以下特性不属于 XNull 基础语法。实现必须拒绝，不得以隐式行为模拟；需要这些能力时使用右侧替代方案。

| 不支持 | 原因 | 替代方案 |
| --- | --- | --- |
| 命名实参、默认参数、可变参数、展开实参 | 调用解析保持显式、可预测 | 构造 DTO / 配置 `class`，或显式重载 |
| C 风格 `for (init; cond; step)` | 已有 `while`、`do-while`、`for-in`、区间循环 | 用 `while` + 显式状态，或区间循环 |
| `catch` / `finally`、跨帧异常 | 错误必须显式传播，禁止隐式 unwind；`try` 只用于 `Result` 传播 | `Result` + `try` + `defer` / `errdefer`；致命错误用 `throw` |
| 运算符重载、用户定义隐式转换 | 类型行为保持可预测 | 命名方法；显式 `as` / `as?` |
| 地址符、指针、智能指针、弱引用修饰符、内存策略注解（`@arc` / `@gc`） | 内存管理能力由编译器与运行时全权负责，源码不得表达引用强度或回收策略 | 策略由编译器按第 2 部分 15.1 判定；运行时执行管理；FFI 走合同（内存管理方案 §19） |
| 自定义访问器属性（property get/set 语法） | XNull 默认公有字段直接读写，不需要 getter/setter | 公有字段直接访问；计算、校验、私有状态用方法 |
| 用户定义索引器 | 容器接口已提供 | `get` / `set` / `at` |
| 事件 | 不引入事件语法 | 闭包回调或显式观察者列表 |
| `if` / `switch` 表达式、块表达式 | 语句与表达式边界保持清晰 | 三元表达式，或在分支内赋值/返回 |
| 独立 `{}` 语句块 | 作用域只由函数体、控制体、类型体、`defer` 体引入 | 用 `if` / `while` / 函数体封装 |
| `match` / 模式匹配 | 保留原 `switch`，不引入独立模式系统 | `switch` + `if` + `Result` 成员 |
| 元组解构、元组标签、元组方法、单元素 / 零元元组 | 元组保持匿名、按位置访问的最小形态 | 逐元素访问；需要命名字段或行为时用 `class` / `struct` |
| `??=` | 不引入空值赋值语法 | `if x == null { x = ... }` |
| `?.()` / `?.[]` | 点语法只保留可空成员访问 | `if` 判断后调用/下标 |
| 函数类型箭头 `(P) -> R` | 保留 `R(P...)` 形式 | `R(P...)` |
| `async` / `await`、生成器、`yield` | 并发由运行时库负责，不引入函数着色 | `xdk.tasks` + 显式 `TaskGroup` / `Context` |
| `unsafe` 块、裸指针、内联汇编、宏 | XNull 源码没有地址符、指针或智能指针语法；安全边界在 XDK / FFI | `xdk.sys` 的 `@unsafe` API（第 7 部分 §8）；FFI 合同（第 7 部分） |
| 条件编译、宏展开、运行时反射 | 构建与元编程不属于语言核心 | 工程清单、代码生成、XDK 反射包 |
| 包重导出、显式 export 列表 | 避免包表面膨胀和隐式依赖 | 公开 wrapper 类型 / 函数，或直接导入 |
| 嵌套类型、局部类型 | 类型声明保持包顶层，便于跨包解析 | 顶层类型 + 限定名 |
| 静态初始化块、实例初始化块 | 初始化顺序保持可预测 | 字段初始化式 + 构造器 |
| 多继承、类型类 / trait、隐式实现 | 保持名义类型和单继承模型 | 单继承 + 协议 + 组合 |
| 类方法覆写、类层级动态派发 | 普通类只做字段/方法复用，多态只走协议 | 协议 + 实现类 |
| 抽象方法、类继承动态合同 | 抽象类只表示不可实例化的复用基类，不建立类层级合同 | 协议 + 具体类 |
| 结构体、枚举、单例实现协议 | 协议实现只限 `class` | 用 `class` 包装或组合 |
| 结构体实例引用字段、引用回退 | `struct` 只承载值字段，始终复制 | 需要引用语义时声明 `class` |
| 协议字段、协议方法体、协议默认实现 | 协议只保留方法签名，避免隐式实现 | 具体类字段/方法 + 组合 |
| 泛型协议、关联类型、协议泛型方法 | 协议是非泛型方法签名合同 | 非泛型协议 + 具体类型 + 方法重载 |
| 泛型约束、`where` 子句、默认类型实参 | 类型参数保持简单，避免约束求解 | 协议 + 重载 + 运行时检查 |
| 类型别名 / newtype | XNull 类型身份由声明直接决定，不引入别名层 | 直接写目标类型；需要独立身份时声明 `class` / `struct` |
| 包级私有 / `internal` 可见性 | 可见性模型保持三种修饰符 | `private` / `protected` + 包拆分 |
| 隐式数值提升、`Bool` 与整数互转 | 避免跨类型静默行为 | 显式字面量类型、XDK 数值转换 |

### 0.7 点语法与无指针模型

- 成员访问、调用和可空访问统一使用点语法：`value.member`、`value.method()`、`value?.member`、`value?.method()`。`->` 只用于 lambda，不用于成员访问或指针解引用。
- 没有地址符 `&`（`&` 只作按位与）、指针类型 `T*`、解引用 `*p`、显式引用类型语法 `&T` / `ref T`、`ref` / `out` 参数修饰符、指针算术或手动 `free`。
- `out` / `in` 只用于泛型型变，不是引用传递修饰符。
- 没有智能指针类型：`Box<T>`、`Rc<T>`、`Arc<T>`、`Ref<T>`、`Weak<T>` 等都不存在。ARC、GC、stack 是编译器和运行时的内存策略，不是源码类型；源码不写 `retain` / `release`。
- 源码没有弱引用概念；引用强度与回收策略由编译器与运行时全权管理，源码不得表达，见第 2 部分第 15 节。
- 类、协议、数组、容器、`String`、闭包在语义上是对象句柄/引用语义；不能取地址、转成整数、做指针算术或手动释放。
- FFI、裸指针和 `unsafe` 块不属于 XNull 语言语法；它们由第 7 部分（FFI）与第 6 部分（XDK）定义。XNull 源码不出现指针声明或解引用。

## 1. 词法

### 1.1 源文件

- 源文件扩展名 `.x`，编码 UTF-8。
- 文件开头可以有一个 UTF-8 BOM；BOM 不参与列号计数。
- 换行可以是 LF 或 CRLF；CRLF 在词法阶段归一化为 LF。
- 行号、列号从 1 开始。列按 Unicode 标量值计数；实现可以内部使用 UTF-16 偏移，但诊断必须换算为标量列。

### 1.2 注释

```text
// 行注释，直到行尾
/* 块注释，不嵌套 */
/** 文档注释，按普通块注释处理 */
```

- 注释等价于空白，可以出现在任意两个 token 之间。
- 块注释不嵌套；遇到第一个 `*/` 结束。
- 未闭合的块注释是词法错误。
- 文档注释不参与语义；编译器不得因文档注释改变类型、可见性或代码生成。

### 1.3 标识符、关键字与保留名

标识符：

```text
[A-Za-z_][A-Za-z0-9_]*
```

只使用 ASCII 字母、数字和下划线。命名规范只用于可读性和编辑器着色，不参与语义：

- `PascalCase`：类型；
- `UPPER_SNAKE_CASE`：常量；
- `lowerCamelCase`：变量、函数、字段。

关键字按用途分组：

| 用途 | 关键字 |
| --- | --- |
| 包与导入 | `package` `import` `as` |
| 可见性与修饰 | `public` `protected` `private` `final` `static` `const` `var` `abstract` |
| 类型与对象 | `class` `struct` `protocol` `enum` `singleton` `factory` `extension` `implements` `new` `self` `super` `out` `in` |
| 控制流 | `if` `else` `while` `do` `for` `switch` `case` `default` `break` `continue` `return` `throw` `try` `goto` `defer` `errdefer` |
| 类型运算 | `is` |

`true`、`false`、`null` 是字面量常量，不是关键字，但禁止用作声明名。

以下名称保留给 0.6 列出的未支持能力和未来版本，禁止用作标识符：

```text
async await yield unsafe extern macro
```

`@` 开头的注解由词法单独识别，不属于关键字。

以下名称是预定义类型名，禁止被用户类型或类型参数遮蔽：

```text
Bool Byte Short Int Long UByte UShort UInt ULong Int128 UInt128
Float Double Char void
String Object Any List Set Map Result Text StringBuilder Bytes
```

`Array` 是 `T[]` 的内部表示名，禁止在源码中作为类型名使用。

### 1.4 字面量

#### 1.4.1 整数

```text
0  42  1_000_000
0xFF  0b1010  0o755
42L  42U  42UL
```

- 支持十进制、`0x` 十六进制、`0b` 二进制、`0o` 八进制。
- 下划线只能出现在两个数字之间；不得出现在进制前缀后、字面量开头、字面量末尾或连续出现。
- 后缀不区分大小写，但规范写法为 `L`、`U`、`UL`。后缀不得重复或组合成其他形式。
- 后缀固定字面量类型：`L` 为 `Long`，`U` 为 `UInt`，`UL` 为 `ULong`。
- 无后缀整数是目标类型字面量：有期望数值类型且值可表示时，取期望类型；无期望类型时取 `Int`；值超出目标类型范围时是编译错误。
- 带后缀字面量的期望类型必须与后缀类型相同，否则是编译错误。
- 整数类型包括 `Byte`、`Short`、`Int`、`Long`、`UByte`、`UShort`、`UInt`、`ULong`、`Int128`、`UInt128`；`Int128` / `UInt128` 的宽度见实现边界。
- 整数字面量不带符号；负号是前缀运算符，不是字面量的一部分。

#### 1.4.2 浮点

```text
1.0  3.14159  1.0e9  2.5e-3  1.0f
```

- 浮点字面量必须包含小数点或指数部分；小数点前后都必须有数字。`1.` 和 `.5` 不是合法浮点字面量。
- 支持十进制指数 `e` / `E`，可带 `+` / `-` 符号。
- 下划线只能出现在两个数字之间。
- 无后缀浮点字面量是目标类型字面量：有期望类型时取期望类型，否则取 `Double`。
- `f` 后缀固定为 `Float`；`Float` 期望类型与 `f` 后缀必须一致。
- 浮点采用 IEEE 754 二进制32（`Float`）或二进制64（`Double`）；编译期按就近偶数舍入。
- 不提供十六进制浮点、NaN 字面量或无穷大字面量；这些值由 XDK 数值 API 产生。

#### 1.4.3 字符

```text
'a'  '\n'  '\''  '\\'  '\u{1F600}'
```

字符字面量使用单引号，内容必须恰好是一个 Unicode 标量值或一个转义序列。空字符字面量、多字符字面量和跨行字符字面量都是词法错误。

`Char` 是 32 位值类型，表示 `0..0x10FFFF` 范围内、排除代理区 `0xD800..0xDFFF` 的 Unicode 标量值。`Char` 不参与算术运算，只支持相等和按码点顺序比较；与整数的转换由 XDK 提供。

转义序列：

| 转义 | 值 |
| --- | --- |
| `\\` | 反斜杠 |
| `\'` | 单引号 |
| `\"` | 双引号 |
| `\n` | U+000A |
| `\r` | U+000D |
| `\t` | U+0009 |
| `\0` | U+0000 |
| `\xHH` | 恰好两位十六进制，值 0..255 |
| `\uHHHH` | 恰好四位十六进制 |
| `\u{H...}` | 1 到 6 位十六进制，值必须是合法标量 |

未知转义、位数不足或值超出合法标量范围都是词法错误。

#### 1.4.4 字符串与插值

| 形式 | 定界符 | 转义 | 跨行 | 插值 |
| --- | --- | --- | --- | --- |
| 普通字符串 | `"..."` | 是 | 否 | 否 |
| 原始字符串 | `r"..."` | 否 | 否 | 否 |
| 多行字符串 | `"""..."""` | 是 | 是 | 否 |
| 原始多行字符串 | `r"""..."""` | 否 | 是 | 否 |
| 插值字符串 | `$"..."` | 是 | 否 | 是 |

- 普通字符串不能跨行；未闭合的字符串是词法错误。
- 原始字符串不处理反斜杠转义；反斜杠按普通字符保存。原始字符串不能包含其结束定界符。
- 多行字符串的内容原样保存，不去除缩进、不去除首尾换行。非原始多行字符串仍处理转义。
- 字符串字面量类型为 `String`。`String` 是不可变 UTF-8 字节序列；`length()` 按字节计。
- 插值字符串中，`{expression}` 是表达式；`{{` 产生字面量 `{`；不在插值中的 `}` 按字面量处理。插值表达式必须完整，括号可以嵌套；未闭合的插值是词法错误。
- 插值表达式不得为 `void`。允许的格式化值：`String`、`Bool`、整数、`Float`、`Double`、`Char`、`null`、简单枚举、元素均可格式化的元组（格式为 `(a, b)`，元素递归应用本规则），以及声明了 `String toString()` 的类型。`Bool` 格式化为 `true` / `false`，整数为十进制，浮点为可往返的最短表示，简单枚举按项名格式化，`null` 为 `null`。
- 插值按源码顺序从左到右求值；所有插值部分求值后拼接为一个新的 `String`。插值字符串不是常量表达式。
- 相邻字符串字面量不会自动拼接；必须使用 `+` 或插值。

#### 1.4.5 布尔与空

`true`、`false` 是 `Bool` 字面量。`null` 是空值字面量，其静态类型为内部类型 `Null`，只能赋给引用类型或 `T?`。

### 1.5 运算符与标点

运算符按最长匹配识别：

```text
<<=  >>=  ...  ..<  ===  !==  ==  !=  <=  >=  <<  >>
&&  ||  ??  ?.  as?  ->  +=  -=  *=  /=  %=  &=  |=  ^=  ++  --
+  -  *  /  %  =  <  >  !  ?  :  &  |  ^  ~  .  ,  ;  @
```

标点：`(` `)` `{` `}` `[` `]`。

`..<` 是半开区间，`...` 是闭区间。`as?` 是一个 token，不是 `as` 加 `?`。`?.` 是一个 token。

### 1.6 语句终止与换行

采用 Go 式自动分号插入：

- 词法不产生换行 token；每个 token 记录起始行。
- 在换行处，如果最后一个 token 是标识符、字面量、`)`、`]`、`}`、`++`、`--`、`return`、`break`、`continue` 或 `throw`，自动插入语句结束。
- `else` 和 `do` 的 `while` 之前不插入语句结束。
- 行首的运算符不是续行；跨行表达式必须用括号包裹。禁止依赖 `+`、`.`、`?.` 等行首 token 继续上一行。
- 打开体的 `{` 必须与前面的头部同一行；换行会在头部末尾插入分号。
- `return` / `throw` 的值必须与关键字同一行；需要跨行时用括号包裹。
- 显式 `;` 仍然允许；同一行写多条语句必须用 `;` 分隔。
- 空行和注释行不触发语句结束。
- `package`、`import` 的分号可选。

```x
Int a = 1
Int b = 2
a = a + b

Int c = 1; Int d = 2

Int e = (a + b)

Int f = a
Int g = -b
```

- `e` 必须用括号写成跨行表达式；`Int f = a` 与 `Int g = -b` 是两条语句。
- `if` / `else` / `while` / `do` / `for` / `switch` 的条件和头部不写括号；体必须是花括号体。
- 花括号体只在函数、类型、控制体、lambda 和 `defer` / `errdefer` 的位置出现，不能作为独立语句。

`package`、`import` 的分号可选。控制体后的分号是可选的空语句。

### 1.7 词法诊断

以下情况必须产生词法错误：

- 未闭合的块注释、字符串、字符字面量；
- 非法转义、非法标量值；
- 非法数字格式、下划线位置错误、后缀冲突；
- 无法识别的字符；
- 非法插值表达式边界。

词法错误必须带文件、行、列范围。词法阶段可以继续扫描以报告多个错误，但不得把错误 token 静默当作合法 token。

## 2. 类型系统

### 2.1 类型分类

| 类别 | 类型 | 传递语义 |
| --- | --- | --- |
| 值类型 | `Bool` `Byte` `Short` `Int` `Long` `UByte` `UShort` `UInt` `ULong` `Int128` `UInt128` `Float` `Double` `Char` | 按值复制 |
| 引用类型 | `String` `Object` `Any` `T[]` `List<T>` `Set<T>` `Map<K,V>` `Text` `StringBuilder` `Bytes` | 按对象句柄传递 |
| 语言级错误类型 | `Result<T,E>` | 值类型；见第 10 节 |
| 元组 | `(T1, T2, ...)` | 按值复制；见 2.11 |
| 用户类型 | 第 2 部分的 `class`、`protocol`、`enum`、`singleton`、`struct` | 第 2 部分规定 |
| 函数类型 | `R(P1, P2, ...)` | 引用类型；值是闭包 |
| 空类型 | `void` | 只能作为返回类型或函数类型的返回类型 |

`void` 不能作为变量、参数、字段、泛型实参或容器元素类型。`void()` 是合法的函数类型。

`Object` 是引用类型根；所有引用类型和 `Any` 都可以赋给 `Object`。值类型必须显式装箱为 `Any` 后才能作为 `Object` 使用。

`Any` 是显式装箱类型；值类型和引用类型都可以通过 `as Any` 装箱。`Any` 的装箱值是 GC 对象，拆箱必须使用 `is` / `as` / `as?`。

### 2.2 值类型与数值语义

| 类型 | 宽度 | 符号 |
| --- | ---: | --- |
| `Byte` / `UByte` | 8 | 有符号 / 无符号 |
| `Short` / `UShort` | 16 | 有符号 / 无符号 |
| `Int` / `UInt` | 32 | 有符号 / 无符号 |
| `Long` / `ULong` | 64 | 有符号 / 无符号 |
| `Int128` / `UInt128` | 名义 128 | 有符号 / 无符号；见实现边界 |
| `Float` | 32 | IEEE 754 |
| `Double` | 64 | IEEE 754 |
| `Char` | 32 | Unicode 标量值 |
| `Bool` | 逻辑 1 位 | `true` / `false` |

整数规则：

- 有符号整数使用二进制补码；无符号整数的位模式相同，但比较、除法和右移按无符号解释。
- `+`、`-`、`*` 溢出按 2 的位宽取模回绕，不触发 panic。
- 整数除法向零截断；`%` 的符号跟随被除数。除数为 0 触发 panic；`MIN / -1` 按位宽回绕为 `MIN`。
- `<<`、`>>` 的右操作数必须是 `Int` 或可适配为 `Int` 的整数字面量。运行时移位数小于 0 或大于等于位宽时触发 panic；编译期常量越界是编译错误。
- 有符号 `>>` 是算术右移；无符号 `>>` 是逻辑右移。
- 不同数值类型之间没有隐式转换。二元算术、位运算要求两侧类型相同；字面量可以按目标类型适配。`Int + Long` 是编译错误。
- 一元 `-` 对无符号整数按位宽回绕；`~` 对所有整数类型按位取反；一元 `+` 只接受数值类型。

浮点规则：

- `Float` / `Double` 遵循 IEEE 754；溢出产生无穷大，下溢产生 0 或次正规数，除零产生无穷大或 NaN，不触发 panic。
- NaN 与任何值（包括自身）的 `==` 为 `false`，`!=` 为 `true`。
- 不提供语言级浮点到整数的转换；转换必须使用 XDK 数值 API。
- 浮点字面量和运算按就近偶数舍入。

`Char` 规则：

- `Char` 是独立值类型，不参与算术运算。
- `Char` 支持 `==`、`!=`、`<`、`<=`、`>`、`>=`，按 Unicode 码点比较。
- `Char` 与整数之间的转换由 XDK 提供。

### 2.3 引用类型与容器

`String` 是不可变 UTF-8 字节序列，按对象句柄传递；`String` 字面量、`+` 拼接和插值都产生新的 `String`。`String.length()` 返回字节数。

`T[]` 是固定长度一维数组，按对象句柄传递，GC 管理。多维数组写作连续追加 `[]`，语义是嵌套数组：`T[][]` 等价于 `Array<Array<T>>`。语言不提供矩形矩阵或 `Tensor` 类型。

`List<T>`、`Set<T>`、`Map<K,V>` 来自 `xdk.collections`，是可增长容器，使用前必须 `import xdk.collections`。三者都是引用类型，GC 管理，类型参数不变。

`Text`、`Bytes`、`StringBuilder` 来自 `xdk.text`，使用前必须 `import xdk.text`。`Text` 是不可变 UTF-8 文本；`Bytes` 是可变字节缓冲区；`StringBuilder` 是可变字符串构建器。

`Result<T,E>` 是语言级错误类型；`Ok` / `Err` 是构造器。`Result` 是值类型，可以出现在变量、参数、返回值、字段、容器和闭包中。核心传播与处理见第 10 节；错误观测、取消和超时由错误处理规范规定。

### 2.4 可空类型

- `T?` 表示可空类型。
- 对引用类型，`T?` 与 `T` 是同一类型；引用类型本来就允许 `null`。
- 对值类型，`T?` 是独立的可选值类型；`null` 是合法值。
- `T??` 等价于 `T?`。
- 非可空值类型不能接收 `null`。
- `null` 可以赋给任何引用类型或 `T?`。
- `?.` 在左侧为 `null` 时返回 `null`，否则访问成员；成员是值类型时结果类型为 `T?`，成员是引用类型时结果类型仍为引用类型。
- `??` 在左侧为 `null` 时返回右侧，否则返回左侧。左侧必须是引用类型或 `T?`；右侧必须可赋给左侧去掉可空后的类型。仅当左侧为 `null` 时求值右侧。
- 可选值解包：当 `T` 是值类型且 `x` 为 `T?` 时，`x as T` 检查非空并得到 `T`，为 `null` 时 panic；对引用类型，`T?` 与 `T` 相同，`as T` 不做非空检查。`x as? T` 失败返回 `null`；`x ?? fallback` 提供默认值。
- 本方案不提供隐式流敏感收窄。`if x != null` 不改变 `x` 的静态类型；需要非空值时使用 `as` 或 `??`。

```x
Int? maybe = 1;
Int value = maybe as Int;

Int? missing = null;
Int fallback = missing ?? 0;

String? name = null;
String display = name ?? "unknown";
```

### 2.5 函数类型

函数类型写作“返回类型(参数类型...)”，参数只有类型，没有名字：

```x
Int()
Int(String)
Int(Int, Int)
void()
```

- 函数类型是引用类型，默认可以为 `null`。
- 函数类型按签名相等检查，参数类型和返回类型都必须完全相同；函数类型不变。
- 闭包字面量可以按目标函数类型检查：参数类型必须匹配，每个 `return` 表达式必须可赋给目标返回类型。
- 调用 `null` 函数值是 panic。

### 2.6 可赋值性

`from` 可赋给 `to`，当且仅当满足以下之一：

| 规则 | 条件 |
| --- | --- |
| 同一类型 | `from` 与 `to` 完全相同 |
| 错误值 | 两者都是 `Result<T,E>`，且 `T` / `E` 相同 |
| 空值 | `from` 是 `null`，`to` 是引用类型或 `T?` |
| 可选提升 | `from` 是 `T`，`to` 是 `T?` |
| 子类型 | `from` 是 `to` 的子类，或 `from` 是实现 `to` 协议的类；见第 2 部分 |
| 泛型方差 | `from` 与 `to` 是同一泛型声明的实例，型变检查通过；见第 2 部分 |
| 字面量 | 整数字面量可表示在目标整数类型中；浮点字面量可表示在 `Float` / `Double` 中；字符串字面量到 `String` |
| 容器字面量 | 目标类型给出元素类型，且每个元素可赋值 |
| 闭包字面量 | 目标类型是函数类型，参数匹配，返回值可赋值 |
| 元组 | 长度相同且元素类型逐一相同；元组字面量元素按目标元素类型适配 |
| 装箱 | `from` 是任意类型，`to` 是 `Any`；必须显式写 `as Any` |
| 引用根 | `from` 是引用类型或 `Any`，`to` 是 `Object` |
| 拆箱 | `from` 是 `Any`，`to` 是具体类型；必须显式写 `as` / `as?` |

禁止：

- 数值类型之间的隐式 widen / narrow；
- `Bool` 与整数互转；
- 字符串与数值隐式互转；
- 把 `null` 赋给非可空值类型；
- 把值类型直接赋给 `Object`；
- 结构化类型匹配：类型按名义检查，成员相同不代表类型兼容。

### 2.7 类型推断

- `var` 从初始化式推断类型；初始化式必须有唯一确定的静态类型。
- `null`、空数组 `[]`、空 Map `[:]`、没有目标类型的闭包字面量不能用于 `var`。
- 整数/浮点字面量的默认类型分别是 `Int` / `Double`；有目标类型时按目标类型适配。
- 泛型函数的类型实参可以省略，按第 8 节推断。
- 返回类型上下文不参与泛型函数推断；需要时显式写类型实参。
- `var` 只用于局部变量；顶层字段和成员字段必须写显式类型。
- 元组字面量按元素表达式推断元素类型；每个元素必须有唯一确定的静态类型。

### 2.8 相等与顺序

| 运算 | 值类型 | `String` | 引用类型 | `Any` |
| --- | --- | --- | --- | --- |
| `==` / `!=` | 按值比较 | 按内容比较 | 默认按对象身份 | 按装箱对象身份 |
| `===` / `!==` | 按值比较 | 按对象身份 | 按对象身份 | 按装箱对象身份 |

- `==` / `!=` 的两侧必须有相同类型，或一侧是 `null` 且另一侧是引用类型/`T?`。
- 引用类型的内容比较必须显式调用类型提供的 `equals` 方法；`==` 不调用用户代码。
- `===` / `!==` 是严格同一性比较：值类型比较值，引用类型比较引用。`null === null` 为 `true`。
- `Result` 不提供 `==` / `===`；使用 `isOk` / `isErr` / `value` / `error` 检查。
- 元组的 `==` / `!=` 逐元素使用元素类型的相等语义；`===` / `!==` 逐元素比较同一性；两侧必须是相同元组类型。
- 顺序比较 `< <= > >=` 只适用于相同数值类型、`Char` 和简单枚举（按底层值）。`String`、容器、普通引用类型不参与顺序比较。
- 浮点 NaN 规则见 2.2。

### 2.9 类型检查与转换

- `x is T` 返回 `Bool`。`x` 为 `null` 时返回 `false`。值类型检查精确运行时类型；引用类型检查动态类型或协议实现。
- `x as T` 执行向上转换、向下转换、`Any` 拆箱或可选解包。失败是 panic。
- `x as? T` 与 `as` 相同，但失败返回 `null`；结果类型是 `T?`。
- `as` / `as?` 不支持数值类型转换，不支持 `void` 目标。
- 向上转换是身份转换；向下转换在运行时检查类型描述符；协议转换检查实现关系。
- `Any` 拆箱到具体类型时检查装箱类型；`Any` 拆箱到协议时检查实现关系。
- `x as Any` 对值类型创建装箱对象；对引用类型包装引用；装箱对象由 GC 管理。
- `is` / `as` / `as?` 的目标必须是类型，不能是表达式。

```x
Any boxed = 1 as Any;
if boxed is Int {
    Int value = boxed as Int;
}
Int? maybe = boxed as? Int;
```

### 2.10 Any 装箱

- 值类型进入 `Any` 必须装箱；装箱产生 GC 对象，包含类型描述符和值。
- 引用类型进入 `Any` 也产生装箱对象；拆箱得到原引用。
- `Any` 的 `==` / `===` 比较装箱对象身份，不自动拆箱。需要值比较时先 `as` 到具体类型。
- 装箱值由 GC 回收；装箱不改变原值的生命周期。
- 装箱后的值不能直接参与算术、比较或成员访问；必须先拆箱。

### 2.11 元组类型

```x
(Int, String) pair = (1, "a");
(Int, Int, Bool) triple = (1, 2, true);
var inferred = (1, "a");            // (Int, String)

Int first = pair.0;
String second = pair.1;
```

形式与身份：

- 元组类型写作 `(T1, T2, ...)`；至少两个元素，元素类型逐一列出，顺序有意义。
- 元组是内建匿名值类型，采用结构化身份：长度相同且元素类型逐一相同的元组是同一类型；不需要声明。
- `(T)` 不是元组，是 `T` 的括号形式；不存在单元素元组和零元元组。
- 元组元素按位置从 0 开始编号；元素没有名字、没有标签。
- 元组可以嵌套：`((Int, String), Bool)` 是合法类型。
- 元组可以作为变量、参数、返回值、字段、容器元素、闭包捕获值和泛型类型实参。
- 元组不能作为 `switch` 值、`Map` / `Set` 键、`const` 类型或常量表达式。
- 元组不参与 `is` / `as` 的有意义转换；同型 `as` 是恒等操作，异型是编译错误。
- 结构体字段对元组的限制、元组字段的内存布局见第 2 部分。

值语义：

- 赋值、传参、返回、存入容器都复制整个元组；副本与原值独立。
- 值元素按值复制；引用元素复制对象句柄。
- 元组不分配对象；全值元素元组不进入 ARC/GC。含引用元素的元组按第 2 部分的规则参与内存分析。

成员访问：

- 元素访问写作 `pair.0`、`pair.1`；`.` 后必须是落在范围内的整数字面量，越界是编译错误。
- 元组没有方法、属性或其他成员；`pair.length` 是编译错误。
- 对可空元组 `T?` 使用 `?.`：`pair?.0` 在 `pair` 为 `null` 时返回 `null`，元素是值类型时结果为 `T?`。
- 元组元素是可赋值位置：`pair.0 = 2;` 要求元组本身位于可赋值位置。

可赋值性与相等：

- 元组之间没有子类型关系；`from` 可赋给 `to` 当且仅当长度相同且元素类型逐一相同。
- 元组字面量按目标元组的元素类型适配各元素：`(Int, String)` 目标接受 `(1, "a")`。
- `==` / `!=` 逐元素使用元素类型的相等语义；`===` / `!==` 逐元素比较同一性；两侧必须是相同元组类型。

插值：

- 元组可以插值，格式为 `(a, b)`；各元素递归按 1.4.4 的规则格式化，任一元素不可格式化时是编译错误。

## 3. 包与导入

### 3.1 package

```x
package com.acme.order
```

- 一个文件最多一个 `package`，必须位于文件顶部（注释除外）。
- 分号可选。
- 包名是点分隔的标识符序列，不得为空段。
- 省略 `package` 时，文件属于默认包。默认包不能被其他包 `import`，只用于单文件程序或入口。
- 用户包名不得以 `xdk` 开头；`xdk.` 是保留命名空间。
- 包名区分大小写；命名规范不参与语义。

### 3.2 import

```x
import xdk.text
import xdk.net.http
import com.acme.common.Thing as AcmeThing
import com.other.Thing as OtherThing
```

- `import` 必须位于 `package` 之后、其他声明之前；分号可选。
- 导入包 `P`：把 `P` 的全部公开顶层符号引入文件作用域；不绑定包命名空间别名。
- 导入符号 `P.S`：只把 `S` 引入文件作用域。
- `import P.S as A`：仅在 `S` 的简单名与另一个已导入符号冲突时允许；`A` 是消歧别名，不用于任意重命名。非冲突场景使用 `as` 是编译错误。
- 导入时若简单名已被另一个导入占用，必须对新导入使用 `as` 别名；否则编译错误。
- 包导入无法为其中单个符号建别名；两个包有同名符号时，改用 `import P.S as A` 选择性导入。
- 重复导入同一包或同一符号是允许的，不产生新绑定；不同来源的同一简单名是冲突。
- 禁止通配符导入；禁止 `import P as Q` 包别名。
- XDK 包必须显式导入；未导入即使用 XDK 类型或静态入口是编译错误。
- 导入不得执行用户代码、注册全局状态或修改进程状态。XDK 导入的初始化必须无副作用，或由调用方显式触发。
- 非 XDK 导入必须解析到本次编译中的包；不得依赖未声明的二进制包。
- 完全限定名始终可用：`com.acme.common.helper(value)`。

### 3.3 名称解析

文件内名称按以下顺序解析：

1. 局部变量、参数、类型参数；
2. 当前包的顶层声明；
3. 导入的符号；
4. 完全限定名。

类型成员的解析见第 2 部分 5.8；实例字段可以非限定访问，局部变量或参数优先遮蔽字段，`self` / `super` 用于消歧。

- 当前包顶层声明遮蔽同名导入。
- 两个导入提供同一简单名且当前包没有同名声明时，必须对新导入使用 `as` 消歧，或使用完全限定名；不得让两个未消歧的简单名同时存在。
- 导入别名必须唯一，不得与关键字、预定义类型名或当前文件顶层声明冲突。
- 包名末段不绑定命名空间；不同包可以同名末段，符号冲突通过 `as` 或完全限定名解决。
- 顶层 `private` / `protected` 符号不能被其他包导入；同包内可见。
- 默认包的符号不能被其他包导入。

### 3.4 多包编译

- 多包编译时，类型和顶层函数在内部带包前缀；不同包的同名类型可以共存。
- 跨包引用必须通过 `import` 或完全限定名；编译器不得依赖文件顺序解析跨包符号。
- 包导入图必须无环；检测到环时是编译错误。
- 包内的声明顺序不影响可见性；函数、类型和顶层字段可以相互前向引用（初始化顺序见 4.3）。

### 3.5 导入诊断

以下情况必须报错：

- 包或符号不存在；
- 使用通配符；
- XDK 包未显式导入；
- 导入其他包的 `private` / `protected` 顶层符号；
- 默认包符号被跨包导入；
- 非冲突场景使用 `as` 别名；
- 导入别名冲突或未消歧的简单名；
- 包导入环；
- 用户包使用 `xdk` 前缀。

## 4. 顶层声明与静态

### 4.1 顶层函数

```x
static Int add(final Int left, Int right) {
    return left + right;
}

static void notify(final String message) {
    handle(message);
}
```

- 顶层函数默认静态：`static` 可以写、可以省略，两者等价；写 `static` 是显式风格，不写不改变语义。
- 返回类型写在函数名前；没有返回值写 `void`。
- 参数顺序固定为“类型在前、名字在后”。
- 参数可以写 `final`；`final` 参数在函数内不能重新赋值。
- 顶层函数可以重载，按参数数量和类型解析；返回类型不参与重载。
- 参数只支持普通参数和 `final`；不支持默认参数、可变参数、命名实参或展开实参。
- 顶层函数必须有函数体；本方案不提供无体声明。
- 顶层函数可以递归，也可以相互递归。
- 顶层函数默认公开；`private` / `protected` 只限制跨包导入。

### 4.2 顶层字段

```x
static Int nextId = 0;

Int version = 1;
final Int build = 42;
const Int limit = 10;
```

- 顶层字段可以写 `static`，也可以直接声明；两种写法语义相同。
- 字段默认可变；`final` 只能初始化一次；`const` 要求编译期常量。
- 顶层字段必须写显式类型；`var` 只用于局部变量。
- 可变顶层字段可以省略初始化式，此时取零值：数值 0、`Bool` 为 `false`、`Char` 为 `'\0'`、引用为 `null`。
- `final` 顶层字段必须在声明处初始化一次；语言不提供顶层赋值语句，因此不支持后置赋值。
- `const` 字段必须有编译期常量初始化式，且隐式 `static`。
- 顶层字段属于当前包；跨包访问通过导入或完全限定名。
- 顶层引用字段是全局根；ARC 对象被 retain，GC 对象被追踪。

### 4.3 初始化顺序

程序启动时按以下顺序初始化：

1. 所有顶层字段和静态字段先置零值。
2. 按包依赖拓扑顺序初始化包；同包内按工程清单给出的文件顺序，缺省按路径字典序；文件内按声明顺序。
3. 执行顶层字段、静态字段和单例的初始化式。
4. 所有初始化完成后调用 `main`。

规则：

- 初始化式读取尚未初始化的字段时，读到零值，不报错。
- `const` 不参与运行期初始化。
- 包导入图必须无环；环是编译错误。
- 初始化式可以调用函数；被调用函数看到的是当前已完成的初始化状态。
- 单例初始化顺序见第 2 部分。
- 初始化式 panic 时进程终止，`main` 不会被调用。

### 4.4 重载解析

- 候选函数按参数数量过滤，再按参数类型检查适用性。
- 返回类型不参与重载；仅返回类型不同不是合法重载。
- `null` 实参没有具体类型；如果有多个引用类型候选适用，解析为歧义，必须显式转换。
- 整数/浮点字面量按参数类型适配；如果有多个候选都能表示该字面量，解析为歧义，必须显式写类型。
- 没有候选或存在多个最佳候选时是编译错误。

### 4.5 可见性

- 顶层声明默认公开。
- `public` 显式公开；`private` 只允许同包访问；`protected` 在顶层与 `private` 相同，不提供额外语义。
- 可见性只做编译期检查，不改变布局、内存或运行期行为。
- 其他包的 `private` / `protected` 顶层符号不能被导入，也不能通过完全限定名访问。

## 5. 局部变量

### 5.1 声明形式

```x
Int total = 0;
final Int answer = 42;
const Int limit = 10;
var count = 1;
```

- 带类型局部变量：`Type name [= expression];`；可以在声明处初始化，也可以在之后确定赋值一次。
- `final`：绑定一次；可以在声明处初始化，也可以在之后确定赋值一次。
- `const`：编译期常量；必须有初始化式；类型必须是常量类型。
- `var`：从初始化式推断类型；必须有初始化式；只能用于局部变量。
- 一条语句只声明一个变量。
- 局部变量必须有显式类型或 `var`；不允许省略两者。
- 未初始化的局部变量在读取前必须确定赋值，否则是编译错误。

### 5.2 作用域

- 局部变量作用域从声明处开始，到所在函数体、控制体、`case` 或 `defer` 体结束。
- 花括号体可以嵌套：函数体、控制体、`defer` 体和闭包体；不能用独立 `{}` 创建作用域。
- 同一作用域内重复声明同名变量是编译错误。
- 参数位于函数体顶层作用域；函数体顶层不能声明与参数同名的局部变量。
- `for` 循环变量作用域是循环体；每轮迭代创建新的绑定。
- `switch` 的每个 `case` / `default` 子句是独立作用域。

### 5.3 确定赋值

- 局部变量在读取前必须确定已赋值；否则是编译错误。
- `final` 局部变量必须在每条正常路径上恰好赋值一次。
- `const` 局部变量在声明处初始化。
- `var` 在声明处初始化。
- 分支、循环和 `goto` 的确定赋值按控制流图分析；`while true` 且没有可达 `break` 的循环不要求后续赋值。
- `try` 的错误返回路径不要求后续赋值；成功路径继续按正常控制流分析。
- `goto` 的跳转边纳入上述控制流图分析：跳转目标处变量是否视为已赋值，按 6.10 的规则判定；`goto` 不得用于使未赋值变量“通过”确定赋值检查。
- 未初始化变量不读取时，允许声明后暂不赋值。

### 5.4 常量表达式

常量表达式由以下组成：

- 字面量；
- 其他 `const` 常量；
- 一元、二元、三元运算符，且操作数都是常量表达式；
- `String + String`；
- 简单枚举项（第 2 部分）。

常量表达式不得包含函数调用、对象创建、容器字面量、元组字面量、插值字符串、赋值、自增/自减或 `as` / `as?` 运行时检查。

`const` 允许的类型：`Bool`、整数类型、`Float`、`Double`、`Char`、`String`、简单枚举，以及带引用类型的 `null`。`const` 不允许类实例、容器、数组、闭包或 `Any` 装箱。

## 6. 语句与控制流

### 6.1 语句分类

| 语句 | 形式 | 规则 |
| --- | --- | --- |
| 局部声明 | `Int x = 1;` | 见第 5 节 |
| 表达式语句 | `f();` | 结果丢弃 |
| 赋值 | `x = 1;`、`x += 1;` | 左侧必须可赋值 |
| 自增/自减 | `i++;`、`--i;` | 只用于整数类型；只能作为语句 |
| `if` / `else` | `if cond { } else { }` | 条件必须是 `Bool` |
| `while` | `while cond { }` | 条件必须是 `Bool` |
| `do` / `while` | `do { } while cond` | 条件必须是 `Bool` |
| `for-in` | `for x in src { }` | 遍历数组、List、Set |
| 区间循环 | `for i in 0..<n` / `0...n` | 循环变量是 `Int` |
| `switch` | `switch value { case v: ... default: ... }` | 无隐式贯穿 |
| `defer` / `errdefer` | `defer body` / `errdefer body` | 作用域清理；见第 10 节 |
| `break` / `continue` | `break [label]` / `continue [label]` | 作用于最近的循环/`switch`，或指定标签 |
| `label` / `goto` | `name: stmt` / `goto name` | 同函数内跳转 |
| `return` | `return value` / `return` | 非 `void` 函数所有正常路径必须返回 |
| `throw` | `throw value` | fatal/panic；不是可恢复错误 |
| 空语句 | `;` | 无操作 |

赋值、自增、自减是语句，不是表达式。

### 6.2 花括号体

```x
if ready {
    Int x = 1;
    while x < 3 {
        x++;
    }
}
```

- `{ ... }` 是函数体、控制体、类型体、lambda 体和 `defer` / `errdefer` 体的语法形式，不是独立语句。
- 直接写 `{ ... }` 作为语句是编译错误；需要独立作用域时，使用 `if` / `while` / 函数或其他结构化控制体。
- 花括号体创建新作用域；体内声明在体结束后不可见。
- 花括号体可以嵌套在控制体、函数体或闭包体中；嵌套体可以遮蔽外层同名变量。
- 花括号体不能作为表达式；没有块表达式。

### 6.3 表达式语句

```x
compute();
value.method();
```

- 表达式语句求值并丢弃结果。
- 赋值、自增、自减不能出现在表达式位置；`a = (b = 1)` 是编译错误。
- 表达式语句的结果类型可以是任意类型；`void` 调用也是合法表达式语句。

### 6.4 赋值与自增/自减

```x
total = total + 1;
total += 1;
values[0] = 1;
list[0] = 2;
i++;
--i;
```

- 可赋值位置：非 `final` 局部变量、非 `final` 参数、可写字段、数组元素、`List` 元素、可赋值元组的元素。
- `Map` 不使用下标赋值；使用 `put`。
- `String` 不使用下标赋值。
- 复合赋值先读取左侧一次，再求值右侧，再应用运算符并写回。
- 复合赋值的中间结果必须可赋给左侧类型；`Int += Long` 是编译错误。
- `++` / `--` 只适用于整数类型；操作数必须可赋值；作为语句时结果丢弃。
- `final` 变量、`final` 字段、`@ReadOnly` 字段在外部、私有字段在类外均不可赋值。
- 赋值语句本身没有值；不得串联赋值。

### 6.5 if / else

```x
if condition {
    handle("yes");
} else if other {
    handle("maybe");
} else {
    handle("no");
}
```

- 条件必须是 `Bool`，条件外层不写括号。
- `if` / `else` 的体必须是花括号体；不支持单条语句体。
- `else` 与最近的未闭合 `if` 配对；因为体强制花括号，不存在 dangling else。
- `else if` 是嵌套 `if` 的语法糖。

### 6.6 while / do-while

```x
while condition {
    ...
}

do {
    ...
} while condition;
```

- 条件必须是 `Bool`，条件外层不写括号。
- `while` / `do-while` 的体必须是花括号体；不支持单条语句体。
- `do` 先执行循环体，再判断条件。
- `continue` 在 `do-while` 中跳到条件判断。

### 6.7 for-in 与区间

```x
for item in items {
    handle(item);
}

for i in 0..<n {
    total += i;
}

for i in 0...n {
    total += i;
}
```

- `for item in source` 遍历 `T[]`、`List<T>`、`Set<T>`；`Map` 不能直接遍历，必须先取 `keys()` 或 `values()`。
- 循环变量是新的局部绑定；每轮迭代创建新绑定，闭包捕获每轮的值互不影响。
- 遍历元素为 `struct` 时按值复制；引用类型复制对象句柄。结构体不存在“不可复制”分支。
- 循环变量可重新赋值，但不会写回容器。
- 区间 `a..<b` 是半开区间，`a...b` 是闭区间；左右操作数必须是 `Int`，在循环开始时求值一次。
- 如果下界大于上界，区间循环执行零次。
- 区间表达式只允许出现在 `for-in` 的源位置；其他位置使用是编译错误。
- `for` 头部不写括号；`for` 体必须是花括号体。
- `break` 退出循环；`continue` 进入下一轮。

### 6.8 switch

```x
switch value {
    case 1:
        handle("one");
    case 2:
        handle("two");
    default:
        handle("other");
}
```

- `switch` 值不写外层括号。
- `switch` 值只求值一次。
- `case` 表达式按源码顺序求值，直到第一个相等匹配；不会继续求值后续 `case`。
- 命中一个 `case` 后执行该子句，执行完自动退出 `switch`，没有隐式贯穿。
- `case` 不要求编译期常量；`switch` 默认不检查穷尽性。`switch` 值为枚举时，按第 2 部分 8.5 检查穷尽性：无 `default` 时必须覆盖全部枚举项。
- `default` 最多一个，必须位于最后。
- 每个 `case` / `default` 子句是独立作用域；子句内声明的变量不会泄漏到其他子句。
- `break` 退出 `switch`；`continue` 作用于最近的外层循环，若没有外层循环则报错。
- `switch` 值类型必须是 `Bool`、整数、`Char`、`String`、简单枚举或引用类型；`Float` / `Double`、`Result` 和元组不允许作为 `switch` 值。
- `case` 表达式必须可赋给 `switch` 值类型；比较使用 `==` 的语义。

### 6.9 break / continue / return / throw

- `break` 退出最近的循环或 `switch`；不在循环或 `switch` 内是编译错误。
- `continue` 进入最近循环的下一轮；不在循环内是编译错误；在 `switch` 内时作用于外层循环。
- `break label` 退出带该标签的循环或 `switch`；`continue label` 进入带该标签的循环下一轮。
- 标签必须位于同一函数内，且 `continue label` 的目标必须是循环；`break label` 可以指向循环或 `switch`。
- 带标签的 `break` / `continue` 是结构化控制流，退出作用域时执行 `defer` / `errdefer`；`goto` 不执行。
- `return value` 只能出现在非 `void` 函数中；`value` 必须可赋给返回类型。
- `return;` 只能出现在 `void` 函数、构造器或 `deinit` 中。
- 非 `void` 函数的所有正常路径必须返回值；`throw` 终止的路径不需要返回。
- `throw value` 是 fatal/panic：打印诊断和调用栈，然后终止进程。`throw` 不是可恢复错误；可恢复错误使用 `Result<T,E>`。
- `throw` 不展开栈，不保证执行 `deinit` 或清理逻辑。
- `throw` 的操作数必须是 `String` 或实现 `Error` 的类型；字符串按原样输出。

### 6.10 label / goto

```x
Int i = 0
start:
i++
if i < 3 {
    goto start;
}
```

- 标签写作 `name:`，后跟一条语句；空语句写作 `name: ;`。
- 标签可以标在循环或 `switch` 上，供 `break label` / `continue label` 使用；也可以标在其他语句上，供 `goto` 使用。
- 标签名在函数内唯一；标签与变量使用不同命名空间。
- `goto name` 跳到同函数内的标签；不能跨函数或 lambda。
- 目标标签必须位于当前函数体/控制体或外层函数体/控制体；禁止从外层体跳入内层体。
- `goto` 跳出函数体/控制体时不执行任何清理、`deinit` 或 `defer`；外部资源必须使用结构化控制流管理。
- `goto` 跳转后，未初始化的局部变量仍然未初始化；读取它们是编译错误。
- 重复标签和未定义标签是编译错误；`break label` / `continue label` 的目标类型不匹配也是编译错误。

### 6.11 空语句

```x
;
label: ;
```

空语句不执行任何操作。空语句可以用于标签或空循环体。空语句不得作为需要值的表达式。

### 6.12 控制流诊断

编译器必须拒绝：

- 非 `Bool` 条件；
- 在循环/`switch` 外使用 `break`；
- 在循环外使用 `continue`；
- 把独立 `{ ... }` 当作语句；
- `break label` / `continue label` 指向不存在的标签或错误的目标类型；
- 非 `void` 函数存在未返回的正常路径；
- `void` 函数返回值；
- 重复、未定义或跨作用域的 `goto`；
- `case` 表达式类型不兼容；
- `switch` 值使用 `Float` / `Double` / `Result`；
- `defer` / `errdefer` 体包含控制转移、`try` 或 `throw`；
- 在非 `Result` 返回函数中使用 `errdefer` 或 `try`；
- `if` / `else` / `while` / `do` / `for` / `switch` 的体不是花括号体。

## 7. 表达式与运算符

### 7.1 基本表达式

- 字面量、标识符。
- 成员访问：`value.member`、`value.method()`。
- 可空成员/调用：`value?.member`、`value?.method()`。
- 下标：`array[index]`、`list[index]`。
- 调用：`f(args)`、`value.method(args)`。
- 对象构造：`new Type(args)`；规则见第 2 部分，语法在本方案中合法。
- 显式泛型实参：`identity<Int>(1)`。
- 数组/集合字面量：`[1, 2, 3]`；`Set` 也使用 `[...]`，由目标类型决定。
- 固定数组创建：`new T[count]`，例如 `new Byte[4096]`；`count` 必须是 `Int`，元素零值初始化，结果是 `T[]`。
- Map 字面量：`["a": 1, "b": 2]`；空 Map 写 `[:]`。
- 元组字面量：`(1, "a")`；至少两个元素；类型与访问规则见 2.11。
- 闭包：`() -> { ... }`、`(Int x) -> { ... }`。
- 字符串插值：`$"value={total}"`。
- `Result` 传播：`try expression`；只用于 `Result`，见 10.2。

### 7.2 运算符与优先级

优先级从高到低：

```text
后缀 / 调用 / 下标 / 成员
前缀运算符（含 try）
* / %
+ -
<< >>
..< ...
< <= > >= is as as?
== != === !==
&
^
|
&&
||
??
cond ? a : b
```

- 后缀、调用、下标、成员左结合。
- 算术、移位、位运算、逻辑运算左结合。
- `??` 右结合。
- 三元运算右结合；条件必须是 `Bool`，两个分支必须有共同类型，或一侧是 `null` 且另一侧是引用类型。
- 比较运算不可链式使用；`a < b < c` 是编译错误，必须显式加括号并写出意图。
- 范围运算不可链式使用，且只允许出现在 `for-in` 源位置。
- 赋值语句单独处理，不参与表达式优先级。

规则：

- `String + String` 是拼接；字符串与数值不能直接 `+`，使用 `$"..."` 插值。
- 算术运算两侧必须是相同数值类型；字面量可以适配。
- `&&` / `||` 要求两侧是 `Bool`；短路求值：`&&` 左侧为 `false`、`||` 左侧为 `true` 时不求值右侧。
- `??` 的左侧必须是引用类型或 `T?`；仅当左侧为 `null` 时求值右侧。
- `a != null && a.f()` 依赖短路语义；若 `a` 为 `null`，右侧不执行。
- `==` / `!=` 默认是值比较；`String` 按内容比较；引用类型的默认比较是对象身份；内容比较使用类型提供的 `equals`。
- `===` / `!==` 是严格同一性比较。
- `is` / `as` / `as?` 的目标是类型。
- 泛型调用可以省略可推断的类型实参。
- 一元 `!` 只接受 `Bool`；一元 `-` / `+` 只接受数值；`~` 只接受整数。
- `try expr` 只用于 `Result`；失败时按 10.2 返回错误。
- `new` 是主表达式；`new Type(args)` 构造对象，`new T[count]` 创建数组。
- `?` 只用于类型可空后缀和三元运算，不再作为 `Result` 传播后缀。

### 7.3 求值顺序

除三元和 `?.` 外，表达式按从左到右求值，不得重排有副作用的子表达式：

- 二元运算：先左后右。
- 调用：先求值被调用表达式，再按从左到右求值实参。
- 赋值：先求值左侧地址（包括下标表达式），再求值右侧，再写回。
- 复合赋值：读取左侧一次，求值右侧，应用运算符，写回。
- `try` 传播：先求值操作数；`Ok` 时解包继续，`Err` 时执行当前作用域的 `defer` / `errdefer` 并返回错误。
- `&&` / `||`：先左后右；短路时不求值右侧。
- `??`：先左后右；左侧非 `null` 时不求值右侧。
- 三元 `cond ? a : b`：先求值 `cond`，只求值被选中的分支。
- `?.`：先求值左侧；为 `null` 时跳过成员访问和调用实参求值，结果为 `null`；否则继续。
- `new Type(args)`：先从左到右求值构造实参，再分配对象并调用构造器。
- `new T[count]`：先求值 `count`，再分配数组并零值初始化。
- 数组字面量：元素从左到右求值。
- Map 字面量：每个键值对先键后值，按键值对从左到右求值。
- 元组字面量：元素从左到右求值。
- 插值字符串：按源码顺序求值各部分。

### 7.4 数值与比较

- 二元算术、位运算要求两侧类型相同；整数字面量可以适配到另一侧类型。
- `+ - * /` 对整数和浮点适用；`%` 只适用于整数类型；浮点余数使用 XDK。
- `& | ^ ~ << >>` 只适用于整数类型。
- `<<` / `>>` 的右操作数必须是 `Int`；结果是左操作数类型。
- 比较运算要求两侧类型相同；`null` 只能与引用类型/`T?` 比较。
- `String` 只支持 `==` / `!=` / `===` / `!==`；顺序比较使用 `Text.compareTo` 或 XDK。
- 引用类型只支持 `==` / `!=` / `===` / `!==`；不提供 `<` 等顺序比较。
- `Bool` 只支持 `==` / `!=` / `===` / `!==`；不参与大小比较。

### 7.5 可空链与空值合并

```x
String? name = user?.name;
Int length = name?.length() ?? 0;
```

- `a?.b` 在 `a` 为 `null` 时返回 `null`，不访问 `b`。
- `a?.m(args)` 在 `a` 为 `null` 时不求值 `args`；返回类型是原返回类型的可选化版本。
- 链式 `a?.b.c`：`?.` 只保护紧邻的成员访问；如果 `a` 非空但 `b` 为 `null`，`.c` 仍然 panic。需要保护整条链时逐级使用 `?.`。
- `??` 只去除一层可空；`T??` 等价于 `T?`。
- `??` 仅在左侧为 `null` 时求值右侧。

### 7.6 类型运算

- `x is T`：返回 `Bool`；`x` 为 `null` 返回 `false`。
- `x as T`：向上转换、向下转换、拆箱或可选解包；失败 panic。
- `x as? T`：失败返回 `null`，结果类型 `T?`。
- `as` / `as?` 的右操作数必须是类型，不能是表达式。
- 对值类型，`is` 检查精确类型；对引用类型，`is` 检查动态类型或协议实现。
- `as` 到父类或已实现协议是向上转换，不产生运行时检查。
- `as` 到子类、未实现协议或具体 `Any` 类型需要运行时检查。
- `Result` 的 `is` / `as` 按具体类型检查；不做隐式转换。

### 7.7 闭包表达式

```x
Int() counter = () -> {
    Int value = 0;
    return () -> {
        value = value + 1;
        return value;
    };
};

Int(Int) add = (Int x) -> {
    return x + 1;
};

Int(Int) inc = (Int x) -> x + 1;   // 单表达式体，与上面的 add 等价

Int(Int, Int) sum = (Int a, Int b) -> {
    return a + b;
};

static Int apply(Int(Int) f, Int value) {
    return f(value);
}

Int result = apply(add, 1);
```

- 闭包语法：`(参数列表) -> { 语句块 }`；零参数写 `()`；参数类型必须写。
- 闭包参数只有类型和名字，可以写 `final`；不支持注解、默认值或可变参数。
- 有目标函数类型时，按目标返回类型检查每个 `return`；没有目标时，以第一个 `return` 的类型为候选，其余 `return` 必须可赋给该类型；没有值返回时推断为 `void`。
- 闭包体有两种形式：花括号体 `(参数) -> { 语句块 }`，或单表达式体 `(参数) -> 表达式`。
- 单表达式体是 `{ return 表达式; }` 的缩写：表达式的类型按目标返回类型检查，无目标时按 7.7 的 `return` 推断规则处理；表达式的求值、异常和确定赋值语义与 `return` 完全一致。
- 单表达式体中的表达式不能是赋值、自增/自减或裸块；需要副作用时写花括号体。
- 闭包按引用捕获外部局部变量、参数和 `self`。
- 捕获变量提升为堆 cell；后续读写都通过 cell。
- 多个闭包捕获同一变量时共享同一个 cell，修改互相可见。
- 嵌套闭包共享外层 cell。
- 不支持按值捕获语法；语言不提供弱引用，不存在弱捕获。
- 捕获变量不需要是 `final`。
- 闭包值是 GC 对象；闭包、环境和 cell 都由 GC 管理。内存细节见第 2 部分。
- 闭包可以嵌套、作为参数传递、作为返回值、存入容器和字段。
- 闭包可以返回 `Result`；返回 `Result` 时可以使用 `try`、`defer`、`errdefer`，错误只从闭包返回，不穿透外层函数。
- 闭包内 `try` 要求闭包的目标返回类型是 `Result<_, E>`；没有目标类型且推断不出 `Result` 时是编译错误。
- 闭包字面量可以立即调用：`((Int x) -> { return x + 1; })(1)`。
- 调用 `null` 闭包是 panic。

### 7.8 字符串插值

- 插值字符串是 `$"..."`；`{expression}` 求值并按 1.4.4 的规则格式化。
- `{{` 产生字面量 `{`；不在插值中的 `}` 是字面量。
- 插值表达式不能是 `void`；不能包含未配对的 `}`。
- 插值表达式可以包含嵌套括号、闭包和泛型调用。
- `Result` 不直接插值；先检查、解包或调用显式格式化 API。
- 不支持格式说明符，例如 `{value:X}`；需要格式化时显式调用 XDK 格式化 API。
- 插值结果是新的 `String`，不是常量表达式。

### 7.9 常量表达式

见 5.4。表达式中的常量折叠不得改变溢出、panic 或求值顺序语义；不能折叠包含运行时检查的表达式。

### 7.10 函数与 Lambda 的统一规则

顶层函数（4.1）、类与结构体的方法、构造器（第 2 部分 6.2、6.3）和 Lambda（7.7）遵循同一套函数规则：

- 形参形式统一：参数只有类型和名字，可写 `final`；不支持注解参数、默认值、可变参数、命名实参或展开实参。
- 体形式统一：函数、方法与构造器必须是花括号体，不提供表达式体；Lambda 例外，允许单表达式体（7.7）。必须有函数体，不提供无体声明。
- 类型标注统一：函数、方法与构造器的参数和返回类型必须显式；Lambda 参数类型必须显式，返回类型按 7.7 推断或按目标类型检查，不提供 `var` 式的形参省略。
- 调用统一：总是按位置传参；重载按 4.4 与第 2 部分 6.8 解析；`Result` 与 `@mustUse` 规则对所有函数形式一致适用。
- 派发方式是唯一差异：方法有接收者，按第 2 部分 5.6 静态派发或 vtable 派发；Lambda 是一等的函数值。

## 8. 泛型函数

### 8.1 声明

```x
static T identity<T>(T value) {
    return value;
}

static T first<T>(T[] values) {
    return values[0];
}
```

- 类型参数写在函数名后的 `<...>` 中；只写类型参数名，不支持约束、默认类型、可变类型参数或型变标注。
- 类型参数只在当前函数的签名和函数体内可见。
- 类型参数不得与同一函数的其他类型参数重名。
- 类型参数可以用于参数、返回值、局部变量、字段访问的泛型实参和嵌套类型；可以绑定 `Result`、函数类型和容器类型。
- 泛型函数可以与普通函数重载；解析规则见 8.2。
- 泛型函数不能作为值直接使用；必须先实例化。

### 8.2 调用与推断

- 显式类型实参：`identity<Int>(1)`；数量必须与类型参数数量一致。
- 省略类型实参时，编译器按实参类型对参数类型做合一：
  - 类型参数直接匹配实参类型；
  - 嵌套类型逐层匹配，例如 `List<T>` 匹配 `List<Int>` 得到 `T = Int`；
  - 同一个类型参数得到冲突绑定时报错；
  - 结束时仍有未绑定类型参数时报错。
- 无后缀整数/浮点实参在没有其他约束时分别绑定 `Int` / `Double`；如果同一类型参数已由其他实参绑定，则字面量适配该类型。
- 返回类型上下文不参与推断；需要时写显式类型实参。
- 重载解析先按参数数量过滤，再对每个候选做适用性检查；泛型候选在检查时推断类型实参。
- 只有一个候选适用时选择该候选；多个候选适用时是歧义错误；零个候选是编译错误。
- `null` 实参不能让类型参数唯一确定；必须显式写类型实参或转换。

### 8.3 单态化

- 每个不同的类型实参列表生成一个独立的函数实例；实例名由编译器内部编码，不暴露给源码。
- 泛型函数在单态化后不再含类型参数；每个实例按具体类型做类型检查和内存分析。
- 类型参数不能是 `void`；显式或推断出 `void` 是编译错误。
- 泛型函数内可以使用 `is T` / `as T`；单态化后按具体类型检查。
- 泛型函数内不能写 `new T()`；类型参数不是可构造的运行时类型。
- 递归单态化必须终止；编译器必须检测无限展开并报错。实现可以使用深度上限，但超限必须产生诊断，不得静默截断。
- 泛型函数体必须在实例化点可见；跨包泛型函数必须携带可供实例化的模板或中间表示。

### 8.4 限制

- 不支持类型约束、where 子句、默认类型实参、可变类型参数。
- 不支持泛型闭包；需要泛型行为时使用泛型函数。
- 不支持在泛型函数内声明静态局部变量。
- 不支持对泛型函数取引用后再延迟实例化。

## 9. 内置类型与常用成员

### 9.1 总表

| 类型 | 来源 | 类别 | 关键成员 |
| --- | --- | --- | --- |
| `String` | 语言 | 引用、不可变 UTF-8 | `length` `substring` `indexOf` `trim` `split` `replace` `toUpper` `toLower` |
| `T[]` | 语言 | 引用、固定长度、GC | 下标、`length`、`join` |
| `List<T>` | `xdk.collections` | 引用、可增长、GC | `push` `insert` `set` `get` `remove` `clear` `length` |
| `Map<K,V>` | `xdk.collections` | 引用、哈希表、GC | `put` `get` `getOr` `has` `remove` `clear` `length` `keys` `values` |
| `Set<T>` | `xdk.collections` | 引用、哈希集合、GC | `add` `has` `at` `remove` `clear` `length` |
| `StringBuilder` | `xdk.text` | 引用、可变、GC | `append` `toString` `length` |
| `Text` | `xdk.text` | 引用、不可变 UTF-8 | `fromString` `length` `codePointCount` `toString` |
| `Bytes` | `xdk.text` | 引用、可变字节缓冲 | `fromString` `get` `set` `push` `append` `slice` `length` |
| `(T1, T2, ...)` | 语言 | 值类型 | `.0` `.1`…；见 2.11 |
| `Result<T,E>` | 语言 | 值类型、`@mustUse` | `isOk` `isErr` `value` `error` `unwrapOr`；见 10.1 |

### 9.2 String

```x
String text = "a,b";
Int length = text.length();
String part = text.substring(0, 1);
Int index = text.indexOf(",");
String trimmed = text.trim();
Bool starts = text.startsWith("a");
Bool ends = text.endsWith("b");
String[] parts = text.split(",");
String replaced = text.replace("a", "x");
String upper = text.toUpper();
String lower = text.toLower();
String joined = parts.join("-");
```

- `length()` 返回 UTF-8 字节数。
- `substring(start, length)` 按字节截取；`start` 小于 0 按 0，超过长度按长度；`length` 小于 0 按 0；超出尾部时截断到末尾。结果总是新的 `String`。
- `indexOf(needle)` 返回首次匹配的字节偏移；未找到返回 `-1`。
- `trim()` 去除首尾 ASCII 空白：`0x09`、`0x0A`、`0x0B`、`0x0C`、`0x0D`、`0x20`。
- `startsWith` / `endsWith` 按字节前缀/后缀比较。
- `split(separator)` 按非空分隔符拆分；保留空段；分隔符为空时返回只含原字符串的一元素数组。
- `replace(from, to)` 替换全部非重叠匹配；`from` 为空时返回原字符串。
- `toUpper()` / `toLower()` 只转换 ASCII 字母；Unicode 大小写转换使用 `xdk.text`。
- `String` 不支持下标、`length` 属性或原地修改；需要按码点操作时使用 `Text` / `Rune`。
- `String + String` 产生新字符串；`String` 与数值不能直接 `+`。

### 9.3 T[]

```x
Int[] values = [1, 2, 3];
Int first = values[0];
values[1] = 9;
Int length = values.length();
String text = values.join(",");
```

- `T[]` 是固定长度一维数组；字面量 `[...]` 创建，长度由元素数量决定。
- `new T[count]` 创建指定长度的数组并零值初始化；`count` 必须是 `Int`，负数或分配失败是 panic；`T` 不能是数组类型。
- 下标从 0 开始；越界是 panic。
- 下标读取和赋值都支持。
- `length()` 返回元素数量。
- `join(separator)` 把元素格式化为字符串并用分隔符连接；元素必须可格式化。
- 多维数组是嵌套数组；不提供矩形矩阵或 `Tensor`。
- 不能 `push` 或改变长度；需要可增长容器时使用 `List<T>`。
- `T[]` 是引用类型；变量赋值复制对象句柄，不复制数组。元素为 `struct` 时，写入和读取按值复制；元素为引用类型时复制对象句柄。
- 数组元素类型不变；`String[]` 不能赋给 `Object[]`。

### 9.4 List

```x
List<Int> list = [1, 2];
list.push(3);
list.insert(1, 9);
list.set(0, 7);
Int first = list.get(0);
Int removed = list.remove(0);
list.clear();
Int length = list.length();
```

- `List<T>` 是可增长数组；保持插入顺序。
- `push(value)` 追加到尾部，均摊 O(1)。
- `insert(index, value)` 在 `0..length` 位置插入；越界 panic。
- `set(index, value)` 替换；越界 panic。
- `get(index)` 读取；越界 panic。
- `remove(index)` 删除并返回元素；越界 panic；后续元素前移。
- `clear()` 清空；`length()` 返回元素数量。
- `list[index]` 读取等价于 `get(index)`；`list[index] = value` 等价于 `set(index, value)`。
- `List<T>` 是引用类型，GC 管理；类型参数不变。

### 9.5 Map

```x
Map<String, Int> table = ["a": 1];
table.put("b", 2);
Bool has = table.has("a");
Int? value = table.get("a");
Int fallback = table.getOr("missing", 0);
table.remove("a");
table.clear();
Int length = table.length();
String[] keys = table.keys();
Int[] values = table.values();
```

- `Map<K,V>` 是哈希表；键唯一。
- v3.0.0 的键类型只支持 `String`、整数类型和简单枚举；其他键类型是编译错误。整数和简单枚举按 `Int` 编码。
- 空 Map 写 `[:]`；非空字面量写 `[key: value, ...]`；重复键后者覆盖前者。
- `put(key, value)` 插入或覆盖；不返回旧值。
- `get(key)` 返回 `V?`；键不存在时返回 `null`，不 panic。
- `getOr(key, fallback)` 返回 `V`；键不存在时返回 `fallback`。
- `has(key)` 返回键是否存在。
- `remove(key)` 删除键；键不存在时无操作。
- `clear()` 清空；`length()` 返回键值对数量。
- `keys()` / `values()` 返回当前键/值数组；顺序在容器未发生结构性修改时稳定，但语言不规定具体顺序。需要确定顺序时由调用方排序。
- `Map` 不能直接 `for-in`；先取 `keys()` 或 `values()`。
- `Map` 是引用类型，GC 管理；类型参数不变。

### 9.6 Set

```x
Set<String> tags = ["x", "y"];
tags.add("z");
Bool has = tags.has("y");
String first = tags.at(0);
tags.remove("x");
tags.clear();
Int length = tags.length();
```

- `Set<T>` 是哈希集合；元素唯一；保持插入顺序不作为语言保证。
- 元素类型限制与 `Map` 键相同：`String`、整数类型、简单枚举。
- 字面量 `[...]` 创建 Set；重复元素去重。
- `add(value)` 插入；已存在时无操作。
- `has(value)` 判断存在。
- `at(index)` 返回当前迭代顺序中的第 `index` 个元素；越界 panic；顺序不保证稳定。
- `remove(value)` 删除；不存在时无操作。
- `clear()` 清空；`length()` 返回元素数量。
- `Set` 可以 `for-in`；顺序不保证稳定。
- `Set` 是引用类型，GC 管理；类型参数不变。

### 9.7 StringBuilder / Text / Bytes

```x
import xdk.text;

StringBuilder builder = StringBuilder();
builder.append("count=");
builder.append(1);
String text = builder.toString();

Text immutable = Text.fromString("hello");
Int byteLength = immutable.length();
Int codePoints = immutable.codePointCount();
String plain = immutable.toString();

Bytes bytes = Bytes.fromString("abc");
bytes.set(1, 90);
Int first = bytes.get(0);
Int byteCount = bytes.length();
```

- `StringBuilder()` 创建空构建器；`append` 接受 `String`、`Bool`、整数、`Float`、`Double`、`Char`，返回构建器自身；`toString()` 返回新 `String`；`length()` 返回当前字节长度。
- `StringBuilder` 是可变引用类型；适合循环拼接，均摊 O(1) 追加。
- `Text` 是不可变 UTF-8 文本；`fromString` 复制 `String` 内容；`length()` 返回字节数；`codePointCount()` 返回码点数；`toString()` 返回等值 `String`。完整 API 见第 6 部分 §4.6。
- `Bytes` 是可变字节缓冲区；`fromString` 复制字节；`get` / `set` 按字节索引，越界 panic；`push` 追加一个字节；`append` 追加 `Bytes` 或 `Byte[]`；`slice(start, end)` 返回新 `Bytes`；`length()` 返回字节数。
- `Text` / `Bytes` / `StringBuilder` 都由 GC 管理；`Text` 与 `String` 之间转换会复制内容。

### 9.8 复杂度

| 操作 | 复杂度 |
| --- | --- |
| `String.length` | O(1) |
| `String.substring` | O(n) |
| `String.indexOf` | 最坏 O(n·m) |
| `String.split` / `replace` | O(n) |
| `StringBuilder.append` | 均摊 O(1) |
| `StringBuilder.toString` | O(n) |
| `new T[count]` 创建 | O(n)（零初始化） |
| `T[]` 下标 / `length` | O(1) |
| `T[].join` | O(n) |
| `Result.isOk` / `isErr` / `value` / `error` / `unwrapOr` | O(1) |
| `List.push` | 均摊 O(1) |
| `List.insert` / `remove` | O(n) |
| `List.get` / `set` | O(1) |
| `Map` / `Set` 查找、插入、删除 | 平均 O(1)，最坏 O(n) |
| `Map.keys` / `values` | O(n) |
| `Set.at` | O(n) |

### 9.9 成员解析规则

- 内建类型成员是语言预定义成员，不能被用户扩展方法覆盖。
- 内建成员按静态接收者类型解析；`null` 接收者调用非 `?.` 成员时 panic。
- `length()` 在不同类型上含义不同：`String` 按字节，`T[]` / `List` / `Set` / `Map` 按元素/键值对数量，`Text` 按字节。
- `Result` 的 `isOk` / `isErr` / `value` / `error` / `unwrapOr` 是内建成员，见 10.1。
- 容器方法不返回可空值，除非签名明确写出 `?`；越界通过 panic 报告；`Map.get` 是缺失键返回 `null` 的例外。

## 10. 错误处理

### 10.1 Result

```x
Result<Int, String> ok = Ok(1);
Result<Int, String> fail = Err("missing");
```

- `Result<T,E>` 是值类型；`T` 是成功值类型，`E` 是错误值类型。
- `T` 可以是 `void`，表示没有成功值；`E` 不能是 `void`。
- `Ok(value)` 构造成功值；`Ok()` 用于 `Result<void,E>`；`Err(error)` 构造失败值。
- 构造器按目标类型推断；没有目标类型时，`Ok(1)` 或 `Err("x")` 无法确定另一侧类型，必须显式写类型或由上下文提供。
- `Result` 是 `@mustUse`：`Result` 值必须被返回、赋给变量/字段/容器、用 `try` 传播，或调用其成员；作为裸表达式语句丢弃是编译错误。
- `Result` 不提供 `==` / `===`；使用成员检查。
- `Result` 可以出现在变量、参数、返回值、字段、容器和闭包中。

成员：

```x
Bool isOk()
Bool isErr()
T value()          // 仅 T 非 void；Err 时 panic
E error()          // 仅 E 非 void；Ok 时 panic
T unwrapOr(T fallback) // 仅 T 非 void
```

- `isOk()` / `isErr()` 总是安全。
- `value()` / `error()` 只在已确认分支调用；错误分支读取成功值或成功分支读取错误值是程序错误，运行时 panic。
- 需要安全解包时使用 `try` 或先检查 `isOk` / `isErr`。

### 10.2 try 传播

```x
Result<Config, AppError> load(String path) {
    String text = try File.read(path);
    Config config = try parse(text);
    return Ok(config);
}
```

- `try expr` 只用于 `Result`。
- 成功时解包为 `T` 并继续；失败时执行当前作用域的 `defer` / `errdefer`，然后从当前函数或闭包返回 `Err`。
- 外层函数或闭包必须返回 `Result<_, E2>`；`E` 必须可赋给 `E2`；否则编译错误。禁止隐式字符串化。
- `Result<void,E>` 的 `try` 作为表达式语句使用；它不产生值。
- `try` 是前缀运算，作用于紧邻的前缀表达式；优先级见 7.2。
- `try` 不能用于构造器、`deinit`、`main` 或 `defer` / `errdefer` 体。
- 闭包内使用 `try` 时，错误从闭包返回，不穿透到外层函数；闭包的目标返回类型必须是 `Result`。
- `try` 不展开栈、不打印日志、不调用全局观察器。
- `try` 可以嵌套：`try try parse(text)` 先解包外层 `Result`，再解包内层 `Result`。

### 10.3 defer / errdefer

```x
Result<void, IoError> copy(String from, String to) {
    File input = try File.open(from);
    defer input.close();

    File output = try File.create(to);
    defer output.close();
    errdefer File.remove(to);

    Byte[] buffer = new Byte[4096];
    while true {
        Int n = try input.read(buffer);
        if n == 0 {
            break;
        }
        try output.write(buffer, n);
    }
    return Ok();
}
```

- `defer Statement` 在当前作用域退出时执行；`errdefer Statement` 只在当前函数或闭包以 `Err` 返回时执行。
- 执行时机：正常作用域结束、`return`、`try`、`break` / `continue`（含带标签形式）。`goto`、`throw`、进程退出不执行。
- `errdefer` 执行条件：函数或闭包以 `Err` 值返回，包括 `try` 传播、显式 `return Err(...)` 和返回一个运行时为 `Err` 的 `Result` 变量；正常 `return Ok(...)`、普通 `return`、`break` / `continue` 不执行。
- 同一作用域内按注册顺序的逆序执行（LIFO）。错误返回时 `defer` 和 `errdefer` 都执行；正常退出只执行 `defer`。
- `defer` / `errdefer` 体可以是花括号体或单条非声明语句；花括号体是清理体，不是独立语句。
- `defer` 体在注册时确定作用域，在执行时读取变量当前值；不得分配闭包。示例中的 `close` / `remove` 返回 `void`；清理调用返回 `Result` 时必须显式处理，未处理的 `Result` 仍按 `@mustUse` 产生诊断。
- `defer` / `errdefer` 体（含嵌套花括号体）不得包含 `return`、`break`、`continue`、`goto`、`try`、`throw`、`defer` 或 `errdefer`；清理必须非抛出。
- `errdefer` 只能出现在返回 `Result` 的函数或闭包中；否则编译错误。
- `defer` / `errdefer` 只能出现在函数体、控制体或闭包体中；不得作为 `if` / `while` / `for` 的单条语句体。顶层和类型体不允许。
- `defer` / `errdefer` 的单条语句体不得是局部声明；需要局部变量时使用花括号体。
- 循环体内注册的清理在每轮迭代结束时执行；`break` / `continue` 退出当前迭代时执行当前迭代已注册的清理。
- `defer` 不能替代对象生命周期管理；ARC/GC 负责对象，`defer` 负责文件、锁、事务、socket 等外部资源。

### 10.4 throw 与 fatal

- `throw` 是 fatal/panic：打印诊断和调用栈，然后终止进程；不是可恢复错误。
- `throw` 不展开栈，不保证执行 `defer`、`errdefer` 或 `deinit`。
- 数组越界、空引用解引用、失败的 `as`、除零、移位越界等隐式 fatal 路径同样终止进程。
- 可恢复错误必须使用 `Result` + `try`；禁止用 `throw` 表达预期内错误。

### 10.5 错误观测边界

- 本方案规定 `Result` 的构造、传播和处理，以及 `defer` / `errdefer`。
- 日志、诊断、取消、超时、`ErrorKind` 和边界转换由错误处理规范规定。
- 错误观测是边界行为，不是控制流；不得引入全局通知中心或隐式恢复。
- 错误类型 `E` 可以是枚举、结构体、类或 `Error` 协议实现；`E` 不能是 `void`。
- 未处理的 `Result` 必须产生编译诊断；边界处必须显式转换（CLI 退出码、HTTP 状态码、任务失败等）。

## 11. XDK 与入口

### 11.1 XDK 导入

```x
import xdk.text;
import xdk.collections;
import xdk.net.http;
```

- `xdk.` 是保留命名空间；用户包不得使用该前缀。
- XDK 包路径可以多级；包名取路径末段，例如 `xdk.net.http` 的包名是 `http`。包名只用于包身份和诊断，不绑定命名空间别名。
- 未导入即使用 XDK 类型或静态入口必须编译失败。
- `T[]` 属于语言自带语法，不要求导入 `xdk.collections`。
- `List` / `Set` / `Map` 必须导入 `xdk.collections`；`Text` / `Bytes` / `StringBuilder` 必须导入 `xdk.text`。
- XDK 包版本和 `min_runtime_abi` 必须与运行时兼容；不兼容时编译失败，不得静默降级。
- XDK 包目录、能力边界和完整 API 见第 6 部分。

### 11.2 入口

```x
static void main(final String[] args) {
    ...
}
```

或：

```x
static Int main(final String[] args) {
    return 0;
}
```

- 入口必须是顶层 `static` 函数，名为 `main`。
- 入口必须接收一个 `String[]` 参数；参数名任意；`final` 可选。
- 入口返回 `void` 时退出码为 0；返回 `Int` 时返回值作为进程退出码。可移植退出码范围是 0..255；其他值由平台截断。
- 入口必须是公开的（默认公开或显式 `public`）。
- 入口不能是泛型函数，不能有额外参数，不能有默认参数或可变参数。
- 一个程序只能有一个匹配签名的入口；其他 `main` 重载是普通函数。
- 入口可以在默认包或工程清单指定的包中；其他包的 `main` 不能作为入口。
- `args` 是运行时创建的新数组，元素是参数字符串；修改数组元素不影响进程原始参数。

### 11.3 启动顺序

1. 初始化运行时和 GC。
2. 按 4.3 初始化顶层字段、静态字段和单例。
3. 调用入口。
4. 入口返回后，进程按退出码终止；不保证执行全局 `deinit`。

初始化阶段 panic 时，进程终止，入口不会被调用。入口内 panic 时，进程终止，不展开栈。

### 11.4 工程入口解析

- 工程清单可以指定入口文件和入口包。
- 没有工程清单时，入口文件是当前目录的 `main.x`。
- 入口文件必须包含匹配签名的 `main`；缺失或重复时是编译错误。
- 工程清单不属于本方案；清单格式和字段由工程配置规范规定。

## 12. 实现边界

以下能力当前实现不保证或未强制；不得作为已支持能力依赖。本节只列基础语法边界；对象模型的发布门槛见第 2 部分第 16 节，未通过不得发布。

- `Int128` / `UInt128` 尚未提供真实的 128 位后端布局；不得依赖其宽度和溢出行为。
- `switch` 不要求 `case` 为编译期常量；非枚举 `switch` 不检查穷尽性；枚举 `switch` 按第 2 部分 8.5 检查穷尽性。
- `&&` / `||` 短路；`??` 仅在左侧为 `null` 时求值右侧。
- `Result` 仍以 GC 对象表示，`Ok` / `Err` 每次分配；语言语义是值类型，错误观测的完整规则见错误处理规范。
- `Result` 的 `@mustUse`、`try` 的错误类型可赋值检查和 `defer` / `errdefer` 的 LIFO 执行为**强制语义**；实现门槛：第 10 节验收通过前不得宣称符合（非承诺至验收通过；原因：实现进度；依赖后果：依赖该检查的代码在通过前不受保护）。
- `try`、`new T[count]`、标签 `break` / `continue` 从 v2.0.0 起保留，v3.0.0 继续有效；当前编译器可能尚未全部实现，验收按第 13 节执行。
- `new` 表达式语法已并入本方案，对象语义仍以第 2 部分为准。
- 泛型不支持约束、默认类型实参、可变类型参数；`Result` 作为类型实参需要单态化支持。
- `Text` / `Bytes` 的 XDK API 仍为 experimental；签名可能变化。
- `String.toUpper` / `String.toLower` 只处理 ASCII。
- `String.length` 按字节计数；需要码点计数时使用 `Text.codePointCount`。
- `Char` 是 32 位标量值，不参与算术；与整数的转换由 XDK 提供。
- `goto` 的作用域限制和清理语义为**强制语义**（实现门槛同上，验收通过前不宣称符合）；不得依赖 `goto` 做资源清理（否决该用法）。
- `as` / `as?` 不支持数值类型转换。
- 本方案不提供隐式流敏感收窄；可选值必须显式 `as` / `??` 解包。
- `Map` / `Set` 的键类型限制为 `String`、整数和简单枚举。
- 当前运行时的 `Map.get` 在缺失键时返回零值；本方案要求返回 `null`，并新增 `getOr`；迁移期不得依赖缺失键返回零值。
- 泛型函数跨包实例化需要模板或中间表示；当前工具链可能要求同次编译包含泛型函数体。
- 字符串插值对对象类型要求 `toString()`；当前实现可能只支持标量、`String` 和 `null`。
- 元组为 v3.1.0 新增：元素访问越界检查、逐元素相等、可空元组 `?.` 与元组插值必须完整实现；未完成的实现不得静默接受部分形式。
- `main` 的退出码在非 0..255 范围内的平台行为可能不同。
- 跨包成员可见性和 `protected` 方法调用的完整检查见第 2 部分实现边界。
- `defer` / `errdefer` 的清理体禁止控制转移、`try` 和 `throw`；该限制为**强制语义**（实现门槛同上，验收通过前不宣称符合）。
- `Result` 的 `value()` / `error()` 只在已确认分支安全；当前实现可能以断言而非 panic 报告误用。

| GEN-01 | 泛型函数 | 显式实参、推断、冲突、未绑定、重载、单态化、无限展开诊断均符合第 8 节；`Result` 类型实参可实例化 |

## 附录 A：基础语法文法

本附录使用 EBNF；`{ X }` 表示零次或多次，`[ X ]` 表示可选。换行和分号规则见 1.6；文法中 `[ ";" ]` 表示可选显式分号。

```ebnf
CompilationUnit   = [ PackageDecl ] { ImportDecl } { TopLevelDecl } EOF ;
PackageDecl       = "package" QualifiedName [ ";" ] ;
ImportDecl        = "import" QualifiedName [ "as" Identifier ] [ ";" ] ;
QualifiedName     = Identifier { "." Identifier } ;

TopLevelDecl      = { Annotation } { TopLevelModifier }
                    ( TopLevelFunction | TopLevelField | TypeDecl ) ;
TopLevelModifier  = "public" | "protected" | "private" | "static" ;
TopLevelFunction  = "static" Type Identifier [ GenericParams ]
                    "(" [ ParamList ] ")" Block ;
TopLevelField     = [ "static" ] [ "final" | "const" ] Type Identifier
                    [ "=" Expression ] [ ";" ] ;
TypeDecl          = { Annotation } { TypeModifier } TypeDeclBody ;
TypeModifier      = "public" | "protected" | "private" | "abstract" | "final" ;
TypeDeclBody      = ClassDecl | StructDecl | ProtocolDecl | EnumDecl
                  | SingletonDecl | ExtensionDecl | AnnotationDecl ;

ParamList         = Param { "," Param } ;
Param             = { Annotation } [ "final" ] Type Identifier ;
GenericParams     = "<" GenericParam { "," GenericParam } ">" ;
GenericParam      = Identifier ;
TypeArgList       = TypeRef { "," TypeRef } ;

Type              = TypeRef ;
TypeRef           = PrimaryType { "[]" | "?" } ;
PrimaryType       = FunctionType | NamedType | TupleType ;
FunctionType      = ReturnType "(" [ TypeRef { "," TypeRef } ] ")" ;
ReturnType        = "void" | NamedType | TupleType ;
TupleType         = "(" TypeRef "," TypeRef { "," TypeRef } ")" ;
NamedType         = QualifiedName [ "<" TypeArgList ">" ] ;

Block             = "{" { Statement } "}" ;
Body              = Block | Statement ;
Statement         = LocalDecl
                  | ExprStatement
                  | Assignment
                  | IncDecStatement
                  | IfStatement
                  | WhileStatement
                  | DoWhileStatement
                  | ForStatement
                  | SwitchStatement
                  | DeferStatement
                  | BreakStatement
                  | ContinueStatement
                  | ReturnStatement
                  | ThrowStatement
                  | LabeledStatement
                  | GotoStatement
                  | EmptyStatement ;

LocalDecl         = ( "final" | "const" ) Type Identifier [ "=" Expression ] [ ";" ]
                  | "var" Identifier "=" Expression [ ";" ]
                  | Type Identifier [ "=" Expression ] [ ";" ] ;
ExprStatement     = Expression [ ";" ] ;
Assignment        = Assignable ( "=" | "+=" | "-=" | "*=" | "/=" | "%="
                  | "&=" | "|=" | "^=" | "<<=" | ">>=" ) Expression [ ";" ] ;
IncDecStatement   = ( "++" | "--" ) Assignable [ ";" ]
                  | Assignable ( "++" | "--" ) [ ";" ] ;
Assignable        = Identifier | MemberExpr | IndexExpr ;

IfStatement       = "if" Expression Block [ "else" ( IfStatement | Block ) ] ;
WhileStatement    = "while" Expression Block ;
DoWhileStatement  = "do" Block "while" Expression [ ";" ] ;
ForStatement      = "for" ForHeader Block ;
ForHeader         = Identifier "in" Expression ;
SwitchStatement   = "switch" Expression "{" { CaseClause } [ DefaultClause ] "}" ;
CaseClause        = "case" Expression ":" { Statement } ;
DefaultClause     = "default" ":" { Statement } ;
DeferStatement    = ( "defer" | "errdefer" ) Body ;
BreakStatement    = "break" [ Identifier ] [ ";" ] ;
ContinueStatement = "continue" [ Identifier ] [ ";" ] ;
ReturnStatement   = "return" [ Expression ] [ ";" ] ;
ThrowStatement    = "throw" Expression [ ";" ] ;
LabeledStatement  = Identifier ":" Statement ;
GotoStatement     = "goto" Identifier [ ";" ] ;
EmptyStatement    = ";" ;

Expression        = TernaryExpr ;
TernaryExpr       = CoalesceExpr [ "?" Expression ":" Expression ] ;
CoalesceExpr      = LogicalOrExpr [ "??" CoalesceExpr ] ;
LogicalOrExpr     = LogicalAndExpr { "||" LogicalAndExpr } ;
LogicalAndExpr    = BitOrExpr { "&&" BitOrExpr } ;
BitOrExpr         = BitXorExpr { "|" BitXorExpr } ;
BitXorExpr        = BitAndExpr { "^" BitAndExpr } ;
BitAndExpr        = EqualityExpr { "&" EqualityExpr } ;
EqualityExpr      = ComparisonExpr { ( "==" | "!=" | "===" | "!==" ) ComparisonExpr } ;
ComparisonExpr    = RangeExpr [ ( "<" | "<=" | ">" | ">=" ) RangeExpr
                  | ( "is" | "as" | "as?" ) TypeRef ] ;
RangeExpr         = ShiftExpr [ ( "..<" | "..." ) ShiftExpr ] ;
ShiftExpr         = AdditiveExpr { ( "<<" | ">>" ) AdditiveExpr } ;
AdditiveExpr      = MultiplicativeExpr { ( "+" | "-" ) MultiplicativeExpr } ;
MultiplicativeExpr= UnaryExpr { ( "*" | "/" | "%" ) UnaryExpr } ;
UnaryExpr         = ( "!" | "-" | "+" | "~" | "try" ) UnaryExpr
                  | PostfixExpr ;
PostfixExpr       = PrimaryExpr { PostfixSuffix } ;
PostfixSuffix     = "." MemberSelector
                  | "." IntegerLiteral
                  | "?." MemberSelector
                  | "?." IntegerLiteral
                  | [ "<" TypeArgList ">" ] "(" [ ArgList ] ")"
                  | "[" Expression "]" ;
MemberSelector    = Identifier ;
PrimaryExpr       = Literal | Identifier | "self" | "super"
                  | "(" Expression ")" | TupleLiteral | ArrayLiteral | MapLiteral
                  | NewExpr | LambdaExpr | InterpolatedString ;
ArgList           = Expression { "," Expression } ;
ArrayLiteral      = "[" [ Expression { "," Expression } ] "]" ;
TupleLiteral      = "(" Expression "," Expression { "," Expression } ")" ;
NewExpr           = "new" TypeRef "(" [ ArgList ] ")"
                  | "new" TypeRef "[" Expression "]" ;
MapLiteral        = "[" Expression ":" Expression
                    { "," Expression ":" Expression } "]"
                  | "[:" "]" ;
LambdaExpr        = "(" [ LambdaParam { "," LambdaParam } ] ")" "->" ( Block | Expression ) ;
LambdaParam       = [ "final" ] Type Identifier ;
MemberExpr        = PrimaryExpr "." MemberSelector
                  | "self" "." MemberSelector
                  | "super" "." MemberSelector ;
IndexExpr         = PrimaryExpr "[" Expression "]" ;
Literal           = IntegerLiteral | FloatLiteral | CharLiteral
                  | StringLiteral | "true" | "false" | "null" ;
InterpolatedString = "$\"" { InterpPart } "\"" ;
InterpPart        = StringCharNoBrace
                  | "{" Expression "}"
                  | "{{" | "}}" ;
Annotation        = "@" Identifier [ "(" [ ArgList ] ")" ] ;
```

文法说明：

- `<` 的类型实参解析只在被调用表达式后、且到匹配 `>` 的 token 序列能解析为类型实参并紧跟 `(` 时生效；否则 `<` 是比较运算符。
- 函数类型与命名类型的区分：返回类型后紧跟 `(` 时按函数类型解析。
- `TypeRef` 的 `[]` / `?` 可以连续出现；`T?[]` 是“可空 `T` 的数组”，`T[]?` 是“可空数组”；`T??` 归一为 `T?`。
- `new T[count]` 是数组创建表达式；`value[index]` 是下标表达式。解析按 `new` 后是 `(` 还是 `[` 区分。
- `Block` 只作为 `Body`、函数体、lambda 体、构造器/方法体或清理体出现，不作为独立 `Statement`；独立 `{}` 是语法错误。
- `?.` 只用于可空成员访问；调用仍是 `?.` 后接成员再调用。`?` 只用于类型可空后缀和三元运算。
- `InterpolatedString` 的词法约束见 1.4.4：`{Expression}` 求值并格式化，`{{` / `}}` 产生字面量 `{` / `}`；`StringCharNoBrace` 是除 `"`、未配对 `}` 和换行以外的任意源字符，细节由词法规定。
- `++` / `--` 只以 `IncDecStatement` 的语句形式出现在文法中；表达式文法不含自增自减，`Int a = i++;` 由本附录文法拒绝，与 6.1、6.4 一致。
- Lambda 单表达式体 `-> Expression` 是 `-> { return Expression; }` 的缩写；文法层面两种形式并存，语义按 7.7 等价处理。
- 元组类型与元组字面量至少两个元素；`(T)` 与 `(e)` 分别是类型与表达式的括号形式，不是元组。
- 函数类型与声明的参数列表最外层括号是参数表；参数表内嵌套括号且含至少两个顶层元素的类型是元组类型：`Int((Int, String))` 是接收元组的函数类型，`Int(Int, String)` 是双参数函数类型。
- `.` 后跟整数字面量仅用于元组元素访问；位置越界是编译错误。`?.` 后跟整数字面量仅用于可空元组。
- `try` 是前缀运算，`try expr` 只用于 `Result`。
- `TypeDeclBody` 的文法在第 2 部分附录 A；本附录只定义基础语法。
- 文法接受的构造如果违反语义规则，类型检查阶段必须拒绝；不得因为文法接受就视为合法。
