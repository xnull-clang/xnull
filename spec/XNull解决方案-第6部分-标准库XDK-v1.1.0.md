## 1. XDK 是什么

- XDK（XNull Development Kit）是 XNull 的标准库：语言内建能力（类型、语法、运行时语义）之外的一切**源码可直接调用的公共 API**。
- 三层分工：
  1. **语言层**（S1/S2）：语法、类型系统、内建类型与字面量——无 API；
  2. **运行时语义层**（S3/S5/S6）：内存、错误、并发的语义与不变量——只约束行为，不约束 API 名字；
  3. **XDK 层**（本部分）：把语义合同落成具体包、类型、函数。
- 设计原则承袭语言：显式、可预测、无隐式魔法；所有可失败操作返回 `Result`；资源在使用点显式关闭；无全局可变状态；无反射。

### 1.4 架构总览（开发者知情权）

**知情权原则**：XDK 是开发者与运行时之间的全部接口面。开发者有权一次性了解 XDK 的能力边界、包间关系、与运行时服务的依赖路径、以及哪些行为跨越 FFI 边界。本节是权威视图；包结构定稿后，架构图随规范版本发布，包不得隐藏对运行时服务的依赖。

#### 1.4.1 分层架构

```text
┌────────────────────────────────────────────────────────────────┐
│                        XNull 应用代码                            │
└───────────────────────────┬────────────────────────────────────┘
                            │ 唯一入口：XDK 公共 API（合同原则见第 3 节）
┌───────────────────────────▼────────────────────────────────────┐
│ XDK 包层                                                        │
│                                                                │
│  errors     tasks      sync      runtime    collections  text   │
│  错误协议   任务/组     互斥/通道   诊断/退出   容器算法   文本    │
│  分类/观测  Context    原子       时间/环境   特化容器   格式化   │
│                                                                │
│  sys（文件/目录/子进程）    net（网络，讨论点 3-g）    ui（远期） │
└──────┬──────────────┬───────────────┬──────────────┬───────────┘
       │              │               │              │
   Result 错误流   spawn/取消      诊断/退出       句柄/租约
   （S5 契约）    （S6 机制）     （S5 §4.3）    （S3 §18/§19）
┌──────▼──────────────▼───────────────▼──────────────▼───────────┐
│ 运行时服务层（语义归第 3/4/5 部分；实现归编译器与运行时）           │
│                                                                │
│  任务调度器 │ ARC/GC（判定表 DET-01）│ 弱表（内部）│ 安全点        │
│  诊断通道（无分配）│ FFI 合同层（租约验证）│ 终结链               │
└───────────────────────────┬────────────────────────────────────┘
┌───────────────────────────▼────────────────────────────────────┐
│              操作系统 / 原生世界（C ABI，第 7 部分 FFI 规范）      │
└────────────────────────────────────────────────────────────────┘
```

要点：

- 应用代码**只**通过 XDK 包层使用运行时能力；没有绕过包层的公共通道（诊断输出、退出都在 `runtime` 包内）。
- 包层与运行时服务层之间的四条竖线是全部依赖路径：错误流、并发控制流、进程控制流、资源流——每一层合同都有编号出处，可审计。
- 运行时服务层不直接暴露给应用代码；其行为合同由第 3/4/5 部分规定，XDK 只负责"翻译成 API"。

#### 1.4.2 通讯结构

```text
任务间数据流     任务A ──Channel<T>（有界、挂起点可取消）──▶ 任务B
任务间共享       任务A ──Mutex<T>.withLock / Atomic*──▶ 共享状态
取消信号流       TaskGroup.cancel / ctx.withDeadline
                     ──▶ 子任务 Context ──▶ checkCancel() ──▶ Err(Cancelled)
结果交付流       任务闭包 Result<T,E> ──join()──▶ 调用方（原样交付，不降级）
错误传播流       XDK API ──Result──▶ 调用方 ──try/显式转换──▶ main 退出码 / FFI 错误码
诊断流           XDK / runtime ──diagnose(单行、无分配)──▶ 进程诊断输出
FFI 双向流       XNull ──租约+错误码（Result 不跨界）──▶ 原生
                 原生 ──弱表入口（运行时 ABI，第 3 部分 §22）──▶ 运行时
```

| 包 | 对外能力 | 依赖的运行时服务 | 规范依据 |
| --- | --- | --- | --- |
| `errors` | 错误协议、分类、观测 | 诊断通道 | 第 4 部分（S5） |
| `tasks` | 任务、任务组、上下文 | 调度器、安全点、GC external root | 第 5 部分（S6）、S3 §11 |
| `sync` | 互斥、通道、原子 | 调度器（挂起）、原子计数 | 第 5 部分（S6）、S3 §11.3 |
| `runtime` | 诊断、退出、时钟、环境 | 诊断通道、进程控制 | 第 4 部分 §4.3 + 本部分 §4.4 |
| `collections` | 算法与特化容器 | 内存分配（ARC/GC） | S1 §9 + 本部分 §4.5 |
| `text` | 编码、格式化、解析 | 内存分配 | S1 §9.2/§9.7 + 本部分 §4.6 |
| `sys` | 文件、目录、子进程 | 句柄合同（§18/§19）、FFI 合同层 | S3 §18 + 本部分 §4.7 |
| `net` | Socket、协议 | 句柄合同、调度器（异步 I/O） | 本部分 §4.7 |

| 包 | 职责 | 内容来源 | 状态 |
| --- | --- | --- | --- |
| `xdk.errors` | 错误协议、分类、辅助函数 | S5 第 2—3 节 | 定案 |
| `xdk.tasks` | 任务、任务组、上下文 | S6 第 3 节 | 定案 |
| `xdk.sync` | 互斥、通道、原子 | S6 第 7 节 | 定案 |
| `xdk.runtime` | 诊断输出、进程退出、时间、环境 | S5 §4.3（诊断）；其余本部分 §4.4 | 定案 |
| `xdk.collections` | 容器算法与特化容器 | S1 §9 内建容器 + 本部分 §4.5 | 定案（A+B 组合） |
| `xdk.text` | 文本编码、格式化、解析 | S1 §9.2/§9.7 + 本部分 §4.6 | 定案 |
| `xdk.sys` | 文件、目录、进程、平台接口、内嵌资源读取（§4.8） | S3 §18 资源句柄合同 + S9 §5.6 | 定案 |
| `xdk.net` | Socket、协议栈 | 本部分 §4.7 | 定案（独立包） |

**定案 1-a（包数量与粒度）**：维持 8 个包（不含 ui）；`sync` 不并入 `tasks`（并发一族但职责不同：任务生命周期 vs 共享状态保护）；`sys` 不拆 `io` / `process`（首版同包，特化需要时再拆）。
**定案 1-b（`runtime` 与 `sys` 边界）**：时间、环境变量、进程退出、诊断归 `runtime`（"运行时可见面"，不触碰 OS 资源句柄）；文件、目录、子进程、Socket 归 `sys` / `net`（"操作系统面"，全部走句柄合同）。

## 3. 全库合同原则

以下七条是所有 XDK API 的强制约束（规范性）：

1. **错误合同**：一切可失败操作返回 `Result<T, E>`；`E` 遵守错误类型规则（S5 §2）；禁止用 panic 表达可恢复失败。
2. **资源合同**：持有 OS 资源的类型必须提供 `close()`；关闭失败不等于未关闭（S5 §4.4）；句柄不得依赖 `deinit` 作唯一关闭路径（S3 §18）。
3. **取消合同**：可阻塞操作的参数含 `Context`（S6 §3.3 惯例）；挂起点可取消且以 `Cancelled` 报告。
4. **命名合同**：包全小写单词；类型 PascalCase；方法小驼峰动词开头；布尔读访问 `isX` / `hasX`；私有内部名 `_name`（S2 §6.1）。
5. **无隐式合同**：无全局可变单例（`singleton` 仅用于真正全局唯一且不可变的场合）；无隐式初始化/清理钩子；无隐式线程局部状态。
6. **稳定性行**：每个 API 标注稳定性（stable / preview / internal）；preview 可在次版本变更，internal 非承诺——对应 S2 §15.1.2 的"非承诺入口"思想。
7. **架构知情原则**：XDK 必须随规范发布架构总览（分层图、通讯结构、能力与依赖矩阵，见 1.4）；每个包必须声明其依赖的运行时服务与跨 FFI 边界的行为；包不得隐藏对运行时服务的依赖，未登记的依赖路径视为合同违规。开发者有权从文档完整了解 XDK 的能力与结构，无需阅读实现。

## 4. 逐包合同

### 4.1 `xdk.errors`（来源 S5）

- 类型：`Error` 协议（`kind()` + `describe()`）、`ErrorKind` 枚举（14 项，语义见 S5 附录 A）。
- 函数：`wrap`（丢弃换新）、`mapErr`（转换）、`report`（边界观测输出）。
- **定案 3-a-1**：`report` 返回原 `Result`（以支持 `return report(r)` 链式写法），观测输出作为副作用。
- **定案 3-a-2**：原因链用**约定字段**——错误结构体自带 `cause: Error?` 字段；协议不增成员（保持 `Error` 协议最小面）。

### 4.2 `xdk.tasks`（来源 S6）

- 类型：`Task<T>`、`TaskGroup`、`Context`。
- 合同：结构化并发（组是唯一 spawn 入口）、组关闭唯一终结路径、取消/超时错误面（S5 第 5、6 节）。
- **定案 3-b-1**：`Context` 传递按"首参数惯例"（规范惯例，非编译器强制）；编译器强制检查**本版本否决**，如需引入走次版本提案并附误用证据。

### 4.3 `xdk.sync`（来源 S6）

- 类型：`Mutex<T>`（`withLock` 作用域化）、`Channel<T>`（有界、挂起点可取消）、`AtomicInt` / `AtomicBool` / `AtomicRef<T>`。
- **定案 3-c-1**：`AtomicRef<T>` 的 `T` 限定为引用类型（对象引用）；首版原子类型为 `AtomicInt` / `AtomicBool` / `AtomicRef<T>`，值类型原子（`AtomicU64` 等）随用例追加（次版本）。

### 4.4 `xdk.runtime`

| 能力 | API（定案） | 依据 |
| --- | --- | --- |
| 诊断输出 | `diagnose(String)`（单行、无分配通道，S5 §9） | S5 §4.3 |
| 进程退出 | `exit(Int)`（不执行 defer，对齐 S1 §10.3） | S1 §10.3 |
| 时间 | `nowMono()`（单调时钟）、`nowWall()`（UTC 毫秒时间戳，可回拨） | S6 第 6 节需要时钟 |
| 环境变量 | `env(String) -> String?`（不可变快照） | 本部分 §1.4.3 |
| 任务转储 | `dumpTasks()`（实现侧诊断，非承诺） | S6 §8 |

- **定案 3-d-1**：时间与环境变量归 `runtime`（运行时可见面，不触碰 OS 句柄）；本地时区格式化属 `text` 包职责。
- **定案 3-d-2**：`nowWall` 合同为 UTC 毫秒精度、允许回拨；需要单调性时用 `nowMono`。更高精度不承诺。

### 4.5 `xdk.collections`

- **定案 3-e（与内建容器的关系）**：采纳 **A + B 组合**——内建容器（`T[]`、`List<T>`、`Map<K,V>`、`Set<T>`、`StringBuilder`）保持现状不动；`xdk.collections` 提供算法函数（排序、分组、去重、查找）+ 特化容器。
- 首版特化容器清单：`RingBuffer`、`OrderedMap`、`BTreeMap`、优先队列（`PriorityQueue`）；清单随实现层立项冻结，追加属次版本。
- 备选方案 C（内建容器下沉）已被否决并留痕于索引 §6 决议记录，不再复议。

### 4.6 `xdk.text`

- S1 §9.2/§9.7 已有 `String` / `Text` / `Bytes` / `StringBuilder` 内建。`xdk.text` 提供：编码转换、显式格式化（超出内建插值的格式控制）、解析（整数/浮点/自定义格式）。
- **定案 3-f-1**：格式化采用 **builder 式**（链式构造器），不采用 printf 式格式串。
- **定案 3-f-2**：正则入首版（`Regex` 类型 + 编译期可检查的字面量形态归文法次版本，动态编译形态入本包）。

### 4.7 `xdk.sys` 与 `xdk.net`

- `xdk.sys`：依据 S3 §18 资源句柄合同——文件（打开/读/写/close）、目录、子进程、平台信息。
- `xdk.net`：**定案 3-g-1**——网络独立成包（服务端语言定位，生命周期与 `sys` 的本地资源不同）。
- **定案 3-g-2（I/O 形态）**：同包双形态——任务感知异步形态为默认（携带 `Context`，挂起不占线程，S6 §2.2）；同步形态为显式 plain API（`sys` 内命名为无 `Async` 后缀的基础函数，阻塞分类随包文档声明，S6 §9）。

### 4.8 `xdk.sys` 资源读取（v1.1.0 追加）

内嵌资源 = 产物内 `resources/` 前缀下的只读文件（打包规则见第 8 部分 §5.6）。**定案 3-g-3**：资源读取 API 归 `xdk.sys`，不新开包——它与文件 API 同属"数据访问"族，共享路径规则与错误面。

| API | 签名 | 语义 |
| --- | --- | --- |
| `resourceExists` | `resourceExists(String) -> Bool` | 路径合法且资源存在；不存在返回 `false`（不报错） |
| `readResource` | `readResource(Context, String) -> Result<Bytes, Error>` | 取全部字节；缺失 → `NotFound`；路径非法 → `InvalidArgument` |
| `readResourceText` | `readResourceText(Context, String) -> Result<Text, Error>` | UTF-8 解码后返回 `Text`；非法字节 → 按 S5 附录 A 的解码/输入类错误报告 |
| `listResources` | `listResources(Context, String) -> Result<List<String>, Error>` | 列出前缀下的全部资源路径（`/` 分隔、字典序升序）；前缀不是目录 → 空列表 |
| `resourceSize` | `resourceSize(String) -> Int?` | 字节数；缺失返回 `null` |

**强制约束**：

1. 路径以 `resources/` 为根，分隔符固定 `/`；绝对路径、`..` 段、空段、反斜杠 → `InvalidArgument`；
2. **只读**：不提供写入、删除、重命名；返回值不是句柄，无需 `close()`——资源随产物存在，生命周期与进程相同，故不触发第 3 节资源合同的 `close()` 要求；
3. **可取消**：`readResource` / `readResourceText` / `listResources` 首参为 `Context`，挂起点可取消并以 `Cancelled` 报告（S5 第 5 节）；
4. **不隐式缓存**：每次调用读取一次；内部缓存不得改变可见语义（同一路径在进程生命周期内内容恒定）；
5. **不混淆来源**：只读产物内嵌资源，不回退到文件系统——同路径文件存在于工作目录也不读取。内嵌资源与工作目录文件是两个来源，混用会让部署行为依赖当前目录；
6. **缺失是可恢复错误**：一律返回 `Result` 错误，不得 panic（第 3 节第 1 条）；
7. **不得用文件 API 读内嵌资源**：产物可为单文件可执行体，文件 API 的路径空间与资源空间无关。

## 5. 版本化

- **定案 4-1**：XDK 版本与语言版本解耦——语言 v3.x 期间 XDK 独立版本化（本部分自 v1.0.0 起）；XDK 破坏性变更不连坐语言版本。
- **定案 4-2（反向约束）**：合同原则（第 3 节）的变更受语言规范的合同保护（如资源合同与 S3 §18 联动），不能单方面削弱。
- **定案 4-3（声明机制）**：XDK 要求"语言版本 ≥ 某值"的显式声明机制归工程配置规范（第 8 部分）。
- **定案 4-4（次版本追加）**：v1.1.0 以次版本追加 §4.8，未删除或改写任何 v1.0.0 合同（向后兼容）；按 v1.0.0 合同编写的工程无需改动。

## 8. 验收矩阵

| 编号 | 领域 | 验收要点 |
| --- | --- | --- |
| XDK-01 | 包结构 | 8 包（含 `net`）齐备；依赖矩阵符合 §2 分层与依赖方向；包名与第 4/5/7 部分的 `xdk.*` 引用一致 |
| XDK-02 | 合同原则 | 第 3 节七条对全部包生效；违反任一条（隐藏全局状态、隐式缓存、panic 逃逸、静默降级等）的用例被拒绝 |
| XDK-03 | errors | `ErrorKind` 14 项齐备；`wrap` 丢弃换新、`mapErr` 转换、`report` 返回原 `Result`；原因链走 `cause` 约定字段且协议不增成员 |
| XDK-04 | tasks | 组外 spawn 不可达（唯一 spawn 入口是组）；组关闭是唯一终结路径；取消与超时错误面与 S5 一致；`Context` 首参数为惯例（编译器不强制） |
| XDK-05 | sync | `Mutex.withLock` 作用域化（锁不可泄漏出作用域）；`Channel` 有界且挂起点可取消；`AtomicRef<T>` 的 `T` 限引用类型，值类型原子被拒绝 |
| XDK-06 | runtime | `diagnose` 单行输出；`exit` 不执行 `defer`；`nowMono` 单调、`nowWall` 为 UTC 毫秒可回拨；`env` 为不可变快照 |
| XDK-07 | collections | 内建容器语义不变；算法函数与首版 4 个特化容器（`RingBuffer`/`OrderedMap`/`BTreeMap`/`PriorityQueue`）可用 |
| XDK-08 | text | builder 式格式化；编码转换与整数/浮点解析；`Regex` 动态编译形态可用且编译失败为可恢复错误 |
| XDK-09 | sys/net | 文件/目录/子进程遵守 S3 §18 句柄合同（`close()` 必达）；双形态 I/O：异步默认（携 `Context`）+ plain 同步显式；网络独立成包 |
| XDK-10 | 资源读取 | §4.8 五 API 与七条强制约束逐条有对应用例：路径非法（绝对路径/`..`/空段/反斜杠）→ `InvalidArgument`；缺失 → `NotFound` 可恢复；`listResources` 字典序；返回值非句柄无需 `close()`；挂起点可取消；不回退文件系统；文件 API 读不到内嵌资源 |
