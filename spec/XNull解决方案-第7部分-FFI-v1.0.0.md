## 0. 核心立场

- FFI 是**合同约束的跨语言接口**，不是任意原生函数的直接调用（S4 §6、S3 §19）。没有 `extern`、`unsafe` 块和裸指针语法；一切原生交互必须经本部分规定的合同入口。
- 本部分是第 3 部分 §19 的**完整化**：第 3 部分规定内存维度（句柄、租约、存活），本部分补齐调用形态、布局验证、运行时 ABI 命名、错误码与阻塞分类四块。
- **名称归属**：本部分出现的 `xdk.*` 包名与 API 名（`xdk.sys`、`@unsafe` 等）以第 6 部分（XDK v1.0.0）为准；本部分只规定跨语言合同本身。属性名（`@ffiEntry` 等）与 `layout(c)` 的落点已定案：绑定层声明文件，不进语言文法（附录 B）。

## 1. 定位与范围

### 1.1 范围

本部分规定 XNull 与原生世界（以 C ABI 为基准）的交互合同：FFI 模型与合同面、调用租约、类型布局与边界表示、回调与 trampoline、运行时 ABI 稳定命名、跨边界错误码、阻塞分类合同、受控入口形态、安全不变量。

### 1.2 不规定

- 绑定生成器的实现形态（手写声明、代码生成工具均合规，产物必须满足本部分合同）；
- 运行时内部实现（分配头结构、GC 算法——见第 3 部分 §15）；
- XDK 包结构、API 命名与归属（第 6 部分定稿）；
- 工程配置中的链接选项、构建集成（第 8 部分）。

## 2. FFI 模型与合同面

### 2.1 三个合同面

跨边界数据只允许三种形态（细化第 3 部分 §19）：

1. **值传递**：标量、经布局验证兼容的 `struct`（须 `layout(c)`，§3.3）、封送副本；
2. **句柄传递**：不透明句柄 + 显式生命周期合同（§4.3）；
3. **缓冲区传递**：`Bytes` / 标量数组的原始字节区，边界期间运行时保证存活（§4.4）。

不在三形态内的类型（引用、闭包、`Result`、可选、容器、`String` 直接移交）被合同层拒绝（§3.6）。

### 2.2 调用租约

每个 FFI 入口必须显式声明**调用租约**——谁持有、何时释放（第 3 部分 §19；验收 MEM-11"无租约声明的入口被拒绝"）：

```x
// 入口声明形态；落点归 xdk.sys 绑定层（第 6 部分 §4.7）
@ffiEntry(cName = "sqlite3_open")
@lease(path = .borrow, db = .transfer)      // 逐参数租约：借出 / 移交
@errorCode(codeParam = .result)             // 错误码出参（§7.1）
@blocking(.unaware)                         // 阻塞分类（§7.3）
Int ffiSqliteOpen(Bytes path, Handle db);
```

合同规则：

- 租约**逐参数**声明，缺省视为合同违规（编译/合同层拒绝）；
- `.borrow`（借出）：所有权留在 XNull 侧，原生仅在本次调用期间可用；调用返回前原生不得保留指针；
- `.transfer`（移交）：所有权交予原生；必须有对称的归还入口声明（`.reclaim`），或显式声明"永不归还"（进程生命周期对象，须写明理由）；
- 与第 3 部分 §19 联动：任何形态下 XNull 对象引用不得作为跨语言地址。

### 2.3 能力边界

- 不承诺"任意原生函数直接调用"；每个入口都是声明式合同对象，经合同层校验（对齐 S4 §6）；
- 不使用 FFI 扩展虚增语言本体能力（S4 §6）：原生能力进入 XNull 后必须适配本语言的错误、资源、取消合同，不得引入平行的机制；
- 内核/驱动/裸机等超出本合同的能力须新增专门合同，本部分不覆盖（S4 §6.4）。

## 3. 类型布局与边界表示

### 3.1 总则

- 布局兼容必须**逐类型验证**；XNull 字段槽与目标 ABI 不默认相同（第 3 部分 §19）；
- 实现布局承诺（第 2 部分 §3.6/§15.3）：`struct` 字段按声明序、8 字节槽、标量占 8 字节、无对象头。这些是实现布局，**不是跨边界承诺**——跨边界以本节为准。

### 3.2 标量映射

| XNull 类型 | C 基准 | 备注 |
| --- | --- | --- |
| `Int` / `UInt` | `int64_t` / `uint64_t` | 固定 64 位（第 1 部分 §2.1） |
| `Int64`…`Int8` 系列 | 对应宽度定宽类型 | |
| `Float` / `Float64` | `double` | `Float32` → `float` |
| `Bool` | `uint8_t`（0/1） | 非 0 值读取归一为 1 |
| `Char` | `uint32_t`（Unicode 码点） | |
| 指针宽标量 | 无对应 | 不提供指针宽整型；地址操作不存在（第 1 部分 §0.7） |

### 3.3 `struct` 与 `layout(c)`

- 跨边界值传递的 `struct` 必须显式标注 `layout(c)`（示意名，落点归第 1/2 部分文法或绑定层）：字段按声明序、C 自然对齐；未标注的 `struct` 只能走封送副本或句柄；
- `layout(c)` 字段类型限于标量与嵌套 `layout(c)` 结构体；含引用、可选、容器字段的拒绝；
- 递归值包含被拒绝（对齐第 2 部分 STRUCT-01）。

### 3.4 `String` / `Text` / `Bytes`

- 边界表示统一为 `ptr + byte_len` 对：`String` / `Text` 是不可变 UTF-8（第 1 部分 §9.2），借出时以 `const char*` + 长度交付，**不以 NUL 结尾作合同**（长度显式）；
- `Bytes` 可变缓冲区借出为 `void*` + 长度；原生写入不得超出声明长度；
- 移交（`.transfer`）只允许 `Bytes`（所有权明确）；`String` / `Text` 不可移交（不可变且由运行时管理），需持久化时由绑定层复制到 `Bytes`。

### 3.5 数组与缓冲区

- 标量数组（`T[]`，T 为标量或 `layout(c)` 结构体）可借出：`ptr + count`，边界期间运行时保证存活（第 3 部分 §19）；
- 多维数组（嵌套数组）不直接跨边界；按逐行缓冲区处理；
- pin 义务：边界期间被借出对象不移动——这是合同层与运行时的联动义务。

### 3.6 不跨边界类型清单

`Result`、可选类型、引用类型对象、闭包、`List` / `Map` / `Set` 等容器、`String` / `Text` 直接移交、元组（实现内联但无跨边界合同）。违规入口被合同层拒绝（验收 FFI-01）。

## 4. 调用租约与句柄生命周期

### 4.1 借出

- 借出参数的生命周期 = 本次调用；返回后指针失效，由合同文本声明；
- 原生不得保留借出指针副本用于异步使用；需要异步持有的必须走移交或复制。

### 4.2 移交

- `.transfer` 后 XNull 侧不再释放；原生侧成为所有者；
- `.reclaim` 入口声明归还路径：原生把所有权交回，XNull 侧恢复管理（典型：缓冲区填充完成）；
- "永不归还"仅限进程生命周期对象，须在租约文本中显式声明理由。

### 4.3 不透明句柄

- 原生资源在 XNull 侧表示为**不透明句柄类型**（实现细节归绑定层；close 合同对齐第 3 部分 §18：显式 `close()`、重复关闭安全、不依赖 `deinit`）；
- 句柄不跨任务共享（第 3 部分 §18）；跨任务经第 5 部分共享规则（通道传递 + 所有权移交语义）；
- 句柄值不得参与算术、排序比较、序列化。

### 4.4 缓冲区存活合同

- 借出的缓冲区在调用期间被运行时保证存活且不移动（pin）；
- 边界期间写入仅限声明范围；越界写入是原生侧合同违规：**检测到即终止进程**（定案，§9）；不承诺检测全部越界写（非承诺；原因：越界检测需插桩，性能成本不可接受；依赖后果：未检测到的越界写造成的后果不保证）。

## 5. 回调与 trampoline

### 5.1 形态

- 闭包不能作为 C 函数指针直接传递（第 2 部分 §14.5）；跨边界回调由绑定层生成 **trampoline**：符合目标 ABI 的 C 函数，内部调用 XNull 闭包 `fn(env, args...)`；
- trampoline 是合同对象：声明参数/返回的边界表示、错误路径（§7.1）、阻塞分类（§7.3）。

### 5.2 生命周期合同

- trampoline 创建时把 `env` 登记为运行时根（第 3 部分 §19；入口 `task_root_bind`，§22）；销毁时注销；
- trampoline 生命周期显式管理：原生持有期间有效，销毁合同与句柄一致（§4.3）；
- 已注销的 trampoline 再被原生调用是原生侧合同违规。

### 5.3 回调内限制

- 回调内不得超出其声明分类阻塞（§7.3）；
- 回调内 panic：合同层捕获后终止进程（对齐第 5 部分——panic 不做任务级隔离；回调是嵌入侧的根边界）；
- 回调不得对同一原生重入并借出同一缓冲区（重入别名违规由合同文本提示）。

## 6. 运行时 ABI 与嵌入

### 6.1 稳定命名

第 3 部分 §22 的运行时入口集赋予跨 FFI 稳定命名（示意前缀，定稿可调）：

| 入口 | C 符号（示意） | 来源 |
| --- | --- | --- |
| 分配 | `xrt_alloc` | 第 3 部分 §22 |
| 计数 | `xrt_retain` / `xrt_release` | 第 3 部分 §22 |
| 弱表 | `xrt_weak_bind` / `xrt_weak_read` / `xrt_weak_clear` | 第 3 部分 §22 |
| 屏障与根 | `xrt_write_barrier` / `xrt_register_root` / `xrt_unregister_root` / `xrt_safepoint` | 第 3 部分 §22 |
| 任务根 | `xrt_task_root_bind` / `xrt_task_root_unbind` | 第 3 部分 §22 |

- 符号与签名一经定稿冻结为 ABI 承诺，变更走主版本；
- 编译器生成代码与原生侧只经这些入口管理内存，不得绕过分配头（第 3 部分 §22）。

### 6.2 弱表入口的开放方式

- 弱表是运行时内部机制，入口**只对 FFI 合同层开放**（第 3 部分 §16/§19）：原生代码不得直接调用弱表符号，只有本部分合同生成的绑定层代码可以；
- 典型用途：原生侧缓存 XNull 对象的弱引用。

### 6.3 嵌入

- 原生程序反向嵌入 XNull 运行时属**非承诺入口**：本部分只承诺 ABI 符号与最小初始化顺序合同（safepoint 可用前不得创建对象）；完整嵌入 API 在 1.x 内**否决**（原因：嵌入式 API 面尚未验证；依赖后果：依赖完整嵌入 API 的项目不受支持），新增需独立合同。

## 7. 错误码与边界转换

### 7.1 错误码合同

- `Result` 不跨语言边界（第 4 部分 §7.3）：进入 FFI 的签名不得含 `Result` 参数/返回值；
- XNull 调用原生：错误以**错误码出参**交付（§2.2 示例的 `@errorCode`）；绑定层把错误码映射为本地错误类型：
  - 已知码 → 按语义映射到 `ErrorKind` 分类（第 4 部分附录 A）；
  - **未知码 → `Internal`**，禁止静默映射为 `Ok`（第 4 部分 §7.3；验收 BOUND-02）；
  - 基准约定：`Int32` 出参、`0 = ok`；超出错误码通道的复杂错误（错误结构体）走句柄 + getter 形态。

### 7.2 取消 / 超时映射

- 原生侧向 XNull 报告的取消/超时必须映射为 `Cancelled` / `Timeout` 分类，**不得降级为 `Internal`**（第 4 部分 §7.3；验收 BOUND-03）；
- 原生侧无法取消的调用不得声明为可取消；FFI 入口的阻塞分类（§7.3）决定其能否携带 `Context`。

### 7.3 阻塞分类与专用执行器

落实第 5 部分 §2.2 的必接接口：

- **逐 API 阻塞分类清单**：每个 FFI 入口必须声明 `.aware`（任务感知，挂起不占线程——仅限经调度器实现的入口）或 `.unaware`（任务无感知，占线程直到返回）。清单随包文档发布（第 5 部分 §9），是验收项（SCHED-01）；
- **长阻塞专用执行器合同**：预期长阻塞的 `.unaware` 入口必须提供"提交给专用执行器"的伴生形态（提交后返回任务句柄，线程池隔离），避免占死调度线程；
- 分类声明错误（`.unaware` 实际长阻塞等）为实现层合同违规。

## 8. `@unsafe` 与受控入口

- 第 1 部分 §0.6 为 `xdk.sys` 预留 `@unsafe` API 形态。本部分定案：`@unsafe` 标注的入口是**合同层豁免的受控入口**——允许表达绑定层无法静态验证的操作（原生内存直接读写等），但必须：
  1. 显式声明前提条件与违规后果（合同文本）；
  2. 仅存在于 `xdk.sys` / 绑定层（第 6 部分 §4.7），应用代码不可创建 `@unsafe` 入口；
  3. 验收单独成类（FFI-04）。
- 这是"无 `unsafe` 块语法"与"实现层需要逃生舱"之间的定案：危险被隔离在带合同的库层入口，而不是语言语法。

## 9. 安全不变量

| 编号 | 不变量 | 依据 |
| --- | --- | --- |

| INV-FFI-2 | `Result` 签名经 FFI 暴露被拒绝；未知错误码映射 `Internal` 非 `Ok` | 第 4 部分 §7.3、BOUND-02 |

## 10. 验收矩阵

| 编号 | 领域 | 验收内容 |
| --- | --- | --- |
| FFI-01 | 合同面 | 三形态外的类型（`Result`/闭包/容器/`String` 移交等）被拒绝；无租约声明被拒绝；未知错误码映射 `Internal` 而非 `Ok` |
| FFI-02 | 布局 | `layout(c)` 结构体逐字段布局与 C 基准一致；未标注结构体只能封送/句柄；标量映射表逐项正确 |
| FFI-03 | 租约 | `.borrow` 返回后指针失效可见；`.transfer` 后 XNull 不释放；`.reclaim` 归还路径正确；缓冲区边界期间 pin、越界写有报告 |
| FFI-04 | `@unsafe` | 受控入口仅存在于绑定层；合同文本完整；应用代码不可创建 |
| FFI-05 | trampoline | 回调创建登记根、销毁注销；注销后调用被检测；回调内 panic 终止进程；错误码出参映射正确（取消/超时不降级） |
| FFI-06 | ABI | 稳定命名符号可被原生代码链接；签名与 §6.1 一致；原生侧只经 ABI 管理内存 |
| FFI-07 | 阻塞分类 | 全部入口有分类声明；长阻塞入口有专用执行器伴生形态；分类与实际行为一致（SCHED-01 联动） |

## 11. 实现边界

- 绑定层产物（声明、trampoline、封送代码）必须可机械核验其合同声明；不可核验的入口视为无租约（拒绝）；
- pin 的实现方式（不移动 / 临时搬迁计数）是实现细节；合同只要求"边界期间地址稳定"；
- 本部分验收通过前，S4 能力缺口表中"跨语言调用"相关行维持"部分落实"状态（内存合同已有，调用合同以本部分为准）。

## 附录 A：决策留痕

1. **租约三分法**（借出/移交/归还）：把第 3 部分 §19 的"谁持有、何时释放"落成逐参数可机械核验的声明；比"全部手动管理"或"全部复制"更能表达真实绑定需求（如 sqlite 句柄移交、缓冲区填充归还）。
2. **`layout(c)` 显式标注**：延续"布局不默认兼容"（第 3 部分 §19），把承诺变成显式动作；未标注者自动降级为封送，安全默认。
3. **`ptr + len` 不以 NUL 结尾**：`String` 长度按字节已知（第 1 部分 §9.2），NUL 结尾是 C 的历史约束，不应成为跨语言合同；需要 C 字符串时绑定层复制加 NUL。
4. **错误码基准 `Int32` 出参 + 0=ok**：覆盖绝大多数 C 库；复杂错误走句柄 + getter，不为此放宽 `Result` 禁令。
5. **回调 panic 终止进程**：与第 5 部分"panic 不做任务级隔离"同构；嵌入场景的隔离需求归实现层（进程外隔离），不在语言合同内。
6. **嵌入（反向）非承诺**：避免在实现前承诺完整嵌入 API；只冻结 ABI 符号与最小初始化顺序。
