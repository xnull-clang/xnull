## 0. 决策治理：三态与措辞禁令（2026-11-05，对全部规范生效）

用户原则：**所有支持点必须有唯一方向，不允许模棱两可的行为。**

任何能力、行为、API、配置项、边界情形，只允许三种状态：

| 态 | 定义 | 文档要求 |
| --- | --- | --- |
| **定案** | 支持；行为唯一确定，不存在"两种都可能" | 必须有验收行覆盖；实现可被据此判定合规/不合规 |
| **否决** | 不支持；明确拒绝 | 必须留痕（决策附录或本索引）+ 一句理由；不得只写"未定义" |
| **非承诺** | 不保证；必须写明三要素 | ① 不保证什么 ② 原因 ③ 依赖它的后果；验收行标注"不测" |

**禁用措辞**（出现即视为缺陷，审计扫描）：倾向、待定、待议、待确认、备选、视情况、可能（表达语义时）、建议（表达规则时）、通常、一般（表达行为时）、实现定义、未指定。术语"候选函数"（重载解析）不在此列。

**允许的写法**：`定案 N-X`、`否决（留痕于…）`、`非承诺（原因：…；依赖后果：…）`。

**状态流转**：定案 ↔ 否决 需版本记录与理由；非承诺升级为定案需补验收行；任何转换不得静默发生，须在 §3 一致性检查记录留痕。

**待决项的唯一合法容器**：§8 待办事项——必须带编号、责任方（用户/实现层）、触发条件；"尚未决定"不得散落在正文中。

## 7. v3.2.0 修订记录（2026-11-05）：内存管理归属收敛

决策：地址符、指针、智能指针、弱引用、强引用等内存管理能力由编译器与运行时全权负责，源码不得显式编写。策略由编译器按判定表决定（DET-01），运行时执行管理动作。

1. **弱引用彻底移除**：`weak` 字段修饰符从语言删除（S1 保留字表、S2 文法与全部条款）；弱表保留为运行时内部机制（S3 §7/§16），入口只对 FFI 合同层开放。
   - 多语言开发不受影响：FFI 边界的引用强度是合同问题（S3 §19 句柄与调用租约）；原生侧弱观察走运行时 ABI 弱表入口（S3 §22）；参照 JNI `NewWeakGlobalRef` 模式（运行时 API，非源码语法）。
   - 语言内替代模式（S2 §15.8）：树/父子双向强引用（强环由策略分类归 GC，不泄漏）；观察者用事件注销或 ID+注册表；缓存用显式失效。
2. **`@arc` / `@gc` 降为内部注解**（S2 §15.1.2）：源码不得出现，使用是编译错误；仅限实现预览与调优实验；非承诺入口，不进验收矩阵；长期调优走实现侧编译选项（S3 §23）。
3. **版本处理**：语言未实现、未对外发布，破坏性变更折叠为 v3.2.0；v3.1.0 归档。

条款落点：S1（§0.6 拒绝清单、§0.7、§1.3 保留字、§7.7）；S2（决策摘要、§2 修饰符表、§3.2、§4.4/4.5、§5.5、§6.1、§7.1/7.5/7.6、§9、§10、§12、§13、§15.1/15.1.1/15.1.2/15.6/15.8/15.9/15.10、§16 边界、§17、§18 验收、附录 A）；S3（§4、§7、§16、§25 MEM-02）。

覆写处置补充（2026-11-05）：覆写不列入演进候补。理由：类方法全静态派发，调用结果只看静态类型，读码即知行为；一旦引入覆写，构造器内 `self.method()` / `deinit` 派发规则、协议 vtable 单一多态入口都要重新论证，且会连带产生对抽象方法的需求。需要多态走协议（vtable）；需要定制行为走组合。GUI / FFI 场景若出现真实压力，优先考虑协议钩子（如 `xdk.ui` 生命周期合同 `onAttach` / `onDetach` / `dispose`）或组合注入，不打开覆写。

**GUI 生命周期处置（归入 P1 XDK 规范，`xdk.ui` 设计要求）：**

区分两个概念：手动**内存**管理（语言不提供，是设计目标，不是缺陷）与显式**生命周期合同**（GUI 必需，属标准库设计任务）。`xdk.ui` 规范必须定义：

- 显式生命周期协议：`onAttach` / `onDetach` / `dispose` 由框架按确定顺序驱动；`dispose` 后对象不可用（框架校验）；
- 资源释放走 `dispose`（确定性），`defer` / `errdefer` 承担作用域级资源，`deinit` 仅作最后防线（GC 类对象的 `deinit` 时机不确定，不得承载资源释放语义）；
- 事件订阅显式注销，`dispose` 级联注销子项；视图树双向强引用（环由策略分类归 GC，不泄漏）。

先例：Flutter `dispose`、Android `onDestroy`、Swing `dispose`——托管内存 GUI 框架全部走显式生命周期合同，XNull 的显式气质与之一致。**这不阻塞任何语言层工作，是 `xdk.ui` 规范的设计输入。**

**状态机处置（无需语言层改动）：**

数据枚举（带载荷）+ 穷尽 switch（S2 §8.5）就是 Rust/Kotlin sealed-class 级别的状态机构建块：无 `default` 时必须覆盖全部状态，新增状态导致所有未处理 `switch` 编译错误——状态完整性由编译器保证。状态转移守卫、迁移表等属库层（组合 + Lambda 注入可表达）。登记为示例集任务：GUI 状态机示例（数据枚举 + 穷尽 switch + 生命周期协议组合），用于验证表达力并回应评审。

### 10.4 已定型的设计思想（防走样，改动需过版本流程）

- 显式、可预测、拒绝隐式：无隐式数值转换、无流敏感收窄、类继承不复写、错误必须走 `Result`。
- 内存管理能力由编译器与运行时全权负责：策略由编译器按判定表决定（DET-01），管理动作由运行时执行；源码不得表达引用强度、地址、指针或回收策略。
- 无访问器模式：字段直接读写，计算/校验用动词方法。
- 函数与 Lambda 统一规则（S1 §7.10）。
- 组合优先于继承：灵活性出口是协议、Lambda 注入、extension、枚举 + 穷尽 switch、factory。
